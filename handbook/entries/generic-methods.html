12  Обобщённые методы

java
generics
generic-methods

Собственные параметры метода записываются перед возвращаемым типом: static <T> T identity(T value). Метод может быть статическим или методом экземпляра, находиться в обычном либо обобщённом классе. Метод T get() в Box<T> использует параметр класса и не объявляет собственного. [9]

12.1 Объявление и вызов

final class Values {
    static <T> T identity(T value) { return value; }
}

В методе клиента:

String text = Values.identity("Java");
Number number = Values.<Number>identity(25);

Явный аргумент типа при вызове стоит перед именем метода. Он выбирает T = Number, хотя переданное значение после упаковки имеет класс Integer. identity возвращает то же значение ссылки, не создавая копию объекта. Параметр метода действует независимо от параметров окружающего класса; совпадающие имена обозначали бы разные параметры и затеняли друг друга. Для класса и метода удобнее выбирать разные имена.

Граница проверяется в объявлении метода. Вызов identity("Java") не разрешает добавить в его тело value.length(): этот метод должен работать и с другими допустимыми аргументами типа. Если операция нужна общему телу, её следует выразить границей или переданным объектом.

Обобщённый метод не обязан возвращать T: у static <T> void swap(T[] values, int i, int j) параметр связывает элементы массива и временную переменную. Разбор тела — Перестановка элементов. Границы индексов и существование массива проверяются отдельно от связи типов.

Собственный параметр возможен и у конструктора:

final class Measurement {
    private final double value;
    <N extends Number> Measurement(N source) {
        value = source.doubleValue();
    }
    double value() { return value; }
}

Measurement здесь обычный класс. Конструктор принимает допустимый числовой тип и сохраняет преобразованный double; после создания объект не приобретает аргумента типа N. При source == null вызов метода завершится NullPointerException. Если связь с конкретным N нигде больше не нужна, параметр конструктора можно объявить просто Number.

12.2 Граница для сравнения

Объявление границы Требование к аргументу типа
<T extends Comparable<T>> Сравнение с тем же T
<T extends Comparable<? super T>> Сравнение с T или его супертипом

Метод compareTo возвращает отрицательное число, ноль или положительное число; порядок определяется знаком результата, модуль может различаться. Обе границы позволяют написать тело выбора большего:

static <T extends Comparable<? super T>> T larger(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}

Возвращается один из аргументов, при равенстве — левый. Ненулевые значения и согласованный порядок остаются условиями вызова. Полные правила порядка: Глава 15.2. [20]

12.3 Вывод аргумента и тип результата

Вывод учитывает аргументы вызова, границы и целевой тип. Несколько появлений T требуют согласованного типа, но он может быть общим супертипом аргументов. Он не обязан совпадать с фактическим классом возвращённого объекта.

Пусть Person implements Comparable<Person>, а Student extends Person наследует этот способ сравнения. У методов совпадает тело larger; объявления различаются границей:

static <T extends Comparable<T>> T strict(T a, T b)
static <T extends Comparable<? super T>> T flexible(T a, T b)
Вызов с двумя Student Результат проверки
Person p = strict(a, b) Допустим с T = Person
var p = strict(a, b) Статический тип p — Person
Student s = strict(a, b) Недопустим: Student не реализует Comparable<Student>
Demo.<Student>strict(a, b) Явный аргумент нарушает ту же границу
Student s = flexible(a, b) Допустим с T = Student

Гибкая форма принимает унаследованный compareTo(Person) и сохраняет Student в результате. Причины вывода подробно разобраны в Граница унаследованного сравнения. [21]

Полная программа: Demo.java. Из каталога java/comparison распакованного комплекта:

javac --release 25 -Xlint:unchecked -d out Demo.java
java -cp out Demo

Три строки true показывают возвращение второго объекта для результата Person, результата Student гибкой версии и результата с var. В каталогах java/comparison-target-error и java/comparison-explicit-error лежат отдельные варианты для двух отвергаемых вызовов. Их компилируют той же командой в соответствующем каталоге; выполнять программу с ошибкой компиляции нельзя.

12.4 Полные примеры и запуск

Скачать исходники примеров. В README комплекта собраны готовые команды и ожидаемые результаты. Комплект содержит самостоятельные программы из теории: коробку и мостовой метод, сравнение Person/Student, операции над массивом и списками, проверяемое исключение, сумму произведений в четырёх языках. Названия каталогов отделяют успешные программы от примеров намеренной ошибки. После распаковки все перечисленные ниже каталоги находятся внутри generics. Java-примеры рассчитаны на JDK 25; javac, java и javap должны относиться к одному JDK.

Каталог Что запускается

В каталогах java/swap, java/maximum, java/copy, java/capture находится отдельный Demo.java; используются те же команды javac и java, что для примера сравнения выше. В java/checked имя файла и запускаемого класса — EarlyCheckedDemo:

javac --release 25 -d out EarlyCheckedDemo.java
java -cp out EarlyCheckedDemo

Этот пример выводит 7, empty, дальше; отказ пропускает оставшуюся часть try, а catch позволяет продолжить выполнение.

Для Java-версии dot из java/dot:

javac --release 25 -Xlint:unchecked -d out Demo.java
java -cp out Demo

Получаются 11.0, 12.0, 1.0, Complex[re=11.0, im=1.0]. Вторая и третья строки относятся к реализации с zero() = 1.0: она проходит проверку типов, но меняет результат суммы и пустого входа. Во всех версиях используется сумма произведений без комплексного сопряжения; объяснение — Контракт арифметических операций.

12.5 C++20: требования к выражениям и длине

Файл main.cpp включает необходимые заголовки, концепт DotElement, варианты dot для std::vector<T> и std::array<T, N>, действительные и комплексные данные. Из каталога cpp:

g++ -std=c++20 -Wall -Wextra -pedantic main.cpp -o dot
./dot

Вывод: 11, (11,1), 11. Первые две строки — динамические векторы, третья — массивы с размером в типе. T{} должен быть нейтральным элементом сложения. Концепт проверяет допустимость выражений; нейтральность T{} остаётся требованием к выбранным операциям и значениям. [17]

Отдельный negative.cpp вызывает вариант для массивов длины 2 и 3:

g++ -std=c++20 -fsyntax-only negative.cpp

Компилятор не может вывести единый N. У варианта для vector длина проверяется при выполнении; для него разные размеры не являются ошибкой подстановки типа. [18]

12.6 C#: статические операции интерфейса

Program.cs использует IAdditionOperators, IMultiplyOperators, IAdditiveIdentity из System.Numerics. Эта форма требует C# 11 и .NET 7 или новее; поставляемый Dot.csproj выбирает C# 11 и .NET 10. Конфигурация комплекта использует установленный SDK 10.0.1xx и его библиотеки: внешних пакетов у этого примера нет. Из каталога csharp:

dotnet run --project Dot.csproj

Программа печатает 11, <11; 1> и отдельно компоненты 11 1. Для Complex не нужен порядок «больше»: ограничения требуют только операции, используемые вычислением. Объяснение модели: Обобщения C#. [19]

12.7 Python: запуск и проверка аннотаций

В каталоге python находятся последовательные варианты одного вычисления:

Файл Назначение
python_dot.py Обычный dot без аннотаций, с числовыми + и *
python_typed.py Тот же цикл с аннотациями Sequence[float | complex]
python_negative.py Передача строки аннотированной числовой функции

Из каталога python:

python3 python_dot.py
python3 python_typed.py

Каждый из этих файлов печатает 11.0, (11+1j), 0. У пустых последовательностей результат — начальный целый ноль. Аннотированный вариант требует Python 3.10 или новее для формы X | Y. Его описание допускает действительные, комплексные и смешанные входы; оно не связывает конкретный тип каждого вызова с точным типом ответа. Полный разбор: Динамический полиморфизм Python. [22]

Для статической проверки нужен отдельно установленный Pyright:

pyright --project pyrightconfig.json

Конфигурация использует строгий режим, целевую версию Python 3.12 и включает python_typed.py вместе с вариантом Protocol ниже. Обычная функция без аннотаций и примеры намеренных ошибок в этот набор не входят.

Отрицательную программу проверяют и запускают независимо:

pyright --pythonversion 3.12 python_negative.py
python3 python_negative.py

Анализатор отвергает строковый элемент вместо числа. При обычном запуске аннотации не останавливают вызов: умножение строки на float приводит к TypeError. Интерпретатор не запускает Pyright автоматически.

12.7.1 Переданные операции и Protocol

python_protocol.py передаёт операции отдельным объектом. Arithmetic[T](Protocol) связывает типы элементов, входов и результатов операций; реализации для float и complex подходят по структуре, без наследования от Arithmetic. Объявления параметров типов в квадратных скобках требуют Python 3.12 или новее. Объяснение протокола: Структурный контракт операций. [23]

python3 python_protocol.py

Первые два результата — 11.0 и (11+1j). Третья строка 2 показывает число умножений, сохранённое объектом FloatArithmetic после первого вычисления. Наличие состояния у объекта операций не меняет связь типов протокола. В отдельном python_protocol_negative.py метод WrongArithmetic.zero() возвращает str вместо float:

pyright --pythonversion 3.12 python_protocol_negative.py
python3 python_protocol_negative.py

Анализатор отвергает присваивание WrongArithmetic переменной Arithmetic[float]. Прямой запуск доходит до сложения строки с числом и завершается TypeError. Это проверка структуры выбранного объекта операций; математическую правильность начального значения его сигнатуры не доказывают.
