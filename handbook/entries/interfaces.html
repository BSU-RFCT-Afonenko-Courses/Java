10  Интерфейсы

java
java-core
java-interfaces

class C implements I делает класс C подтипом интерфейса I. Переменная типа I может хранить ссылку на экземпляр C; доступные операции определяются типом I, а тело переопределяемого метода экземпляра выбирается по фактическому классу ненулевого получателя. Совпадение методов без объявленной связи типов не даёт такого подтипа. Объяснение: Глава 13.

interface Sender {
    void send(String message);
}

final class ConsoleSender implements Sender {
    @Override
    public void send(String message) {
        System.out.println(java.util.Objects.requireNonNull(message, "message"));
    }
}

Sender sender = new ConsoleSender();
sender.send("Java"); // Java

Абстрактную операцию интерфейса реализует открытый метод public. Конкретный класс предоставляет все требуемые реализации сам или получает подходящие методы по наследованию. Класс с оставшимися абстрактными методами объявляется abstract. У интерфейса нет конструкторов и полей экземпляра; непосредственное new Sender() запрещено. [17]

10.1 Формы членов

Объявление внутри интерфейса Условие и действие
void send(String message); Неявно public abstract; тело предоставляет реализация
default void reset() { ... } Открытый метод экземпляра с общим телом; допускает переопределение
static Sender console() { ... } Открытый статический метод; вызов через имя объявившего интерфейса
private void part() { ... } Закрытый помощник, имеющий текущий экземпляр this
private static void check() { ... } Закрытый помощник без текущего экземпляра
int LIMIT = 10; Неявно public static final; инициализатор обязателен

static- и private-методы не наследуются реализующим классом и подинтерфейсом. Закрытый метод нельзя объявить default или abstract. Для метода интерфейса недопустимы protected, доступ внутри пакета, final, synchronized, native. default и static доступны с Java 8, private — с Java 9. [72]

final у ссылочного поля запрещает замену ссылки и сохраняет возможность изменения объекта по ней. Например, у поля int[] VALUES = {1, 2} доступна запись VALUES[0] = 9. Константу читают через имя интерфейса; отношение подтипов для этого не требуется.

10.2 Несколько интерфейсов

interface Readable { String read(); }
interface Writable { void write(String value); }
interface Storage extends Readable, Writable {}

Storage объединяет две роли. Его конкретная реализация предоставляет обе операции и может передаваться как Storage, Readable или Writable. Класс может непосредственно перечислить несколько ролей: class C implements Readable, Writable. Реализация двух родительских интерфейсов по отдельности ещё не делает этот класс подтипом Storage.

Несколько интерфейсов не добавляют полей экземпляра. Один метод может реализовать одинаковые сигнатуры двух ролей, если его результат совместим с обоими объявлениями. Несовместимые результаты, например int read() и String read(), препятствуют такой реализации.

10.3 Выбор реализации по умолчанию

Ситуация для одной операции Результат
Подходящий метод экземпляра объявлен в классе или унаследован от суперкласса Действует метод класса с соблюдением требуемого доступа
Подинтерфейс переопределяет метод суперинтерфейса Действует более конкретное объявление
Подинтерфейс заменил default абстрактным объявлением Конкретный класс должен предоставить реализацию
Два независимых интерфейса предоставляют конфликтующие тела Требуется явное переопределение
Суперкласс объявил абстрактный метод с той же сигнатурой Совпадающий default не освобождает конкретный подкласс от реализации

В собственном переопределении можно вызвать доступное тело непосредственного суперинтерфейса формой A.super.method():

interface A { default String label() { return "A"; } }
interface B { default String label() { return "B"; } }
final class Both implements A, B {
    @Override
    public String label() {
        return A.super.label() + B.super.label();
    }
}

new Both().label() возвращает "AB". Без переопределения класс не компилируется. Независимое абстрактное объявление также может конфликтовать с default. Для методов, эквивалентных неприватным методам Object, тела default запрещены. [72]

10.4 Контракт и делегирование

Документация операции определяет допустимость null, порядок, результат, исключения и изменение состояния. Типы параметров и результата сами этих условий не устанавливают.

В Reminder поле Sender sink хранит ссылку на получателя, а sink.send(message) делегирует ему отправку. Реализация Sender в самом Reminder для такого использования не требуется. Поле final запрещает замену сохранённой ссылки; состояние получателя определяется его собственными операциями.

Общее тело default sendAll(String[]) из теории вызывает send в порядке массива. При первом исключении обход прекращается; предыдущие отправки сохраняются. Поведение на {"A", null, "B"}: Методы по умолчанию.

10.5 Обобщённая и функциональная роль

@FunctionalInterface
interface Source<T> {
    T get();
}
Source<String> source = () -> "Java";
System.out.println(source.get()); // Java

T связывает аргумент типа с результатом get; в Source<String> результат имеет тип String. Функциональный интерфейс не объявлен sealed и имеет один требуемый абстрактный метод после учёта совместимых объявлений и методов Object. Статические, закрытые и default-методы не увеличивают это число. @FunctionalInterface поручает компилятору проверить это свойство; для самой лямбды аннотация необязательна. Обобщённое объявление: Глава 11. Лямбда и её целевой тип: Глава 19.

10.7 Примеры записей и вариантов данных

Программы создают и сравнивают записи, нормализуют компоненты, защищают массив копиями и различают варианты результата поиска. Команды запуска и описание опытов находятся в инструкции к примерам записей. Полные исходники доступны в архиве записей.

Для DispatchStatsDemo и SenderContractDemo нужен также архив отправителей: эти программы используют реализации Sender из другого комплекта. После распаковки каталоги records/ и interfaces/ должны находиться рядом; совместная команда компиляции приведена в инструкции к примерам записей.
