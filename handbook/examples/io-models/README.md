# Модели ввода-вывода

Байтовые и символьные потоки. Буферизующие обёртки. Состояние `ByteBuffer`.
Последовательная и явная позиция файлового канала. Асинхронное чтение,
`Future` и обработчик завершения.

Каждая программа выделяет одну сторону модели. Запуски выполняются
из этого каталога; относительный путь входного файла отсчитывается от него.
Исходники предназначены для JDK 25.

```bash
javac --release 25 -encoding UTF-8 -d out StreamLayersDemo.java BufferStatesDemo.java FileChannelDemo.java AsyncReadDemo.java
```

## Слои потока

```bash
java -cp out StreamLayersDemo
```

Программа трижды открывает одну последовательность UTF-8 из памяти:
`Ада\nБоб\n`. Первый обход считает байты; второй декодирует их и считает
единицы `char`; третий получает строки через `BufferedReader`.

```text
Байтов: 14
Единиц char: 8
1: Ада
2: Боб
```

Один кириллический знак этих имён занимает два байта UTF-8 и одну единицу
`char`; два перевода строки тоже участвуют в первых двух подсчётах.
`readLine()` возвращает содержимое строки без её разделителя.

Для чтения файла передайте его путь:

```bash
java -cp out StreamLayersDemo data/utf8.txt
```

Файл должен содержать корректный UTF-8; его содержимое не должно меняться
между тремя открытиями. `open` выбирает `FileInputStream`, а алгоритмы
подсчёта работают через те же типы `InputStream` и `Reader`. Методы подсчёта заимствуют
поток на время вызова. Каждый открытый источник закрывается в `main`;
символьная обёртка закрывает нижележащий байтовый поток. Созданный
декодер сообщает об ошибочной последовательности байтов исключением.
Файл `data/utf8.txt` содержит тот же текст `Ада\nБоб\n`, поэтому
результат совпадает с чтением из памяти. Для другого файла передайте
его путь. Символ за пределами основной плоскости Unicode занимает
две единицы `char`, поэтому этот подсчёт не равен числу таких символов.

## Состояние буфера

```bash
java -cp out BufferStatesDemo
```

Буфер вместимостью восемь получает байты `10`, `20`, `30`.
После `flip()` из него извлекаются первые два. `compact()` переносит
остаток `30` в начало и оставляет следующую позицию для записи равной
единице. Добавление `40`, `50` и второй `flip()` дают последовательность
`30`, `40`, `50` для чтения.

В конце `clear()` устанавливает `position=0`, `limit=8`. Абсолютное
чтение `get(0)` по-прежнему получает `30`: данные в ячейках сохранены.
Само абсолютное чтение не сдвигает позицию. Напечатанные состояния
позволяют сопоставить границы доступной области с содержимым массива.

## Синхронный файловый канал

```bash
java -cp out FileChannelDemo data/ascii.txt
```

Первый вызов `read(buffer)` получает до четырёх байтов и сдвигает позицию
канала на фактически прочитанное количество. Второй вызов
`read(buffer, 1)` начинает чтение с байтовой позиции 1 и сохраняет текущую
позицию канала. Обе операции возвращают свой результат непосредственно
вызывающему потоку; заполнение порции закончено к возврату из `read`.

Шестнадцатеричный вывод показывает именно байты. Граница порции может
разделить многобайтовый символ UTF-8. Программа выводит фактическое число
байтов каждого отдельного чтения: оно может быть меньше вместимости
буфера. Позиция за концом файла даёт `-1` и пустую порцию.

Файл `data/ascii.txt` содержит `abcdefgh` и перевод строки LF.
При заполнении обеих четырёхбайтовых порций первое чтение даст
`61 62 63 64`, второе — `62 63 64 65`; позиция канала после первого
чтения равна 4 и после второго остаётся равной 4. Программа печатает
фактический результат, поскольку договор чтения допускает частичную
порцию. В `data/utf8.txt` те же смещения обозначают позиции байтов
и могут попадать внутрь кодировки кириллической буквы.

## Асинхронное завершение

```bash
java -cp out AsyncReadDemo future data/ascii.txt
java -cp out AsyncReadDemo callback data/ascii.txt
```

Режим `future` заказывает две независимые порции с позиций 0 и 4,
используя отдельный буфер для каждой. `get()` получает число прочитанных
байтов и при необходимости ждёт. Печать в порядке позиций задаётся
основным потоком; фактический порядок завершения операций может отличаться.
Между заказом операции и получением её результата буфер этой операции
остаётся недоступным для обработки программой.

Режим `callback` передаёт обработчик `CompletionHandler`. Его `completed`
получает результат чтения и превращает содержимое буфера в текст отчёта;
`failed` передаёт отказ. `CompletableFuture<String>` связывает готовность
отчёта с основным потоком. Вызов `report.get()` ждёт отчёта,
подготовленного обработчиком. До окончания этого ожидания консольная
программа продолжает работать, а канал остаётся открытым.

Для `data/ascii.txt` полные порции режима `future` имеют байты
`61 62 63 64` и `65 66 67 68`. Режим `callback` заказывает только первую
порцию. Шестнадцатеричные значения позволяют сопоставить файловые позиции
с полученными данными без дополнительного декодирования.

Для пустого файла результат чтения равен `-1`, область данных пуста.
Это нормальный конец входа: `Future.get()` возвращает `-1`, а обработчик
получает его через `completed`. Для файла из одного байта первая порция
может содержать этот байт, чтение с позиции 4 уже получает конец входа.

Операция может завершиться ещё до печати сообщения о возвращении
управления из `read`. Наблюдение одной быстрой операции не устанавливает
общую длительность ожидания. Эти программы позволяют проследить порядок
вызовов и владение буфером; измерения производительности в них отсутствуют.
Канал закрывается после получения результатов. При досрочном выходе
закрытие завершает оставшиеся операции отказом.

Каждый из четырёх исходников содержит полную программу. Опыты предназначены
для чтения, запуска и объяснения наблюдений; самостоятельные файловые
задачи имеют отдельные условия и заготовки.
