# Примеры равенства, хеширования и порядка

Программы показывают идентичность объектов, поиск по равному ключу,
коллизии, изменение ключа и определение уникальности в дереве. Перед запуском
предскажите результат по состоянию объектов, затем сопоставьте его с выводом.

## Компиляция и запуск

Команды выполняются из каталога `handbook/examples/equality` с JDK 25.
В [архиве примеров](../equality-examples.zip) этот каталог называется
`equality/`; после распаковки перейдите в него. `javac` и `java` выбираются
из одного JDK. При нескольких установках можно указать полный путь
к каждой команде.

```bash
javac -encoding UTF-8 -d out *.java grade/Student.java
java -cp out IdentityDemo
java -cp out ValueEqualityDemo
java -cp out OverloadedEqualsDemo
java -cp out LawFailuresDemo
java -cp out HashEqualityDemo
java -cp out MutableKeyDemo
java -cp out ArrayEqualityDemo
java -cp out OrderDemo
java -cp out TreeEqualityDemo
```

`StudentId` — общий неизменяемый ключ: конструктор принимает ненулевую
строку, сохраняет её без нормализации, `equals` и `hashCode` используют
одинаковое строковое значение с учётом регистра.

`grade.Student` хранит код, имя и балл. Код и имя ненулевые; после `strip()`
они должны оставаться непустыми и не содержать `;`, CR или LF. Балл
принадлежит диапазону 0..100. Для `null` возникает `NullPointerException`,
для остальных нарушений этих ограничений — `IllegalArgumentException`.
Стандартное равенство записи сравнивает все три компонента.
В комплект включено полное объявление из примера записи участника,
поэтому внешние исходники для этих команд не требуются.

## Идентичность и равенство данных

[IdentityDemo.java](IdentityDemo.java) создаёт две строки `"Ada"`
и копирует ссылку на первую. Затем создаёт две вкладки с одинаковым
адресом; `Tab` наследует `Object.equals`. Вывод:

```text
false
true
true
false
true
```

Первые три ответа относятся к строкам. Последние два — к сравнению
разных вкладок и вкладки с самой собой.

[ValueEqualityDemo.java](ValueEqualityDemo.java) сравнивает записи
`s1/Ada/90`, `s1/Ada/95`, `s1/Ada/90`, затем сохраняет версии и коды
в отдельных множествах и обновляет карту по `StudentId`. Вывод:

```text
true
false
true
2
true
false
95
1
```

Множество записей различает две версии сведений. Множество кодов
обнаруживает повтор `s1`. Карта сохраняет одну запись с новой оценкой.

## Ошибки определения equals

[OverloadedEqualsDemo.java](OverloadedEqualsDemo.java) содержит
`equals(OverloadedId)`. Перед запуском определите, какую сигнатуру
компилятор выберет для аргументов с типами `OverloadedId` и `Object`.
Вывод:

```text
true
false
```

Второй вызов использует унаследованный `Object.equals(Object)`.
Выражения аргументов в обоих вызовах обозначают один и тот же второй объект.

[LawFailuresDemo.java](LawFailuresDemo.java) сначала проверяет
`StudentId` с равным ключом, строкой и `null`. Затем неправильный
`LooseId` признаёт себя равным строке, которая отвергает его при обратном
сравнении. Последние три вызова проверяют близость баллов 80, 81, 82.
Вывод:

```text
true
false
false
true
false
true
true
false
```

`LooseId` нарушает симметрию. Близость с разностью не более единицы
нарушает транзитивность и поэтому вынесена в отдельный метод `near`.

Отказ компиляции при неверном `@Override` можно получить отдельно:

```bash
javac -encoding UTF-8 -d out rejected/EqualsParameter.java
```

Ожидается ошибка у метода `equals(EqualsParameter)`: такой метод
не переопределяет `equals(Object)` из `Object`.
Этот файл не входит в общую команду компиляции работающих опытов.

## Поиск по хешу

[HashEqualityDemo.java](HashEqualityDemo.java) добавляет два равных
`StudentId("s17")` в множество, накапливает счётчики `s17` и `s18`,
затем добавляет различные ключи `"Aa"` и `"BB"` с одинаковыми хешами.
Вывод:

```text
false
true
true
true
false
true
1
2
2
true
false
2
```

Один идентификатор в первом множестве соответствует двум объектам.
Последнее множество сохраняет два различных значения с одинаковым хешем.

[MutableKeyDemo.java](MutableKeyDemo.java) помещает в карту ключ с кодом 1
и меняет его код на 2. Определите перед запуском, какие сведения
сохранены в узле при вставке и какие будут вычислены заново при поиске.
Для реализации `HashMap` в OpenJDK 25 ожидается:

```text
stored
null
1
true
stored
stored
```

После изменения ключа поиск возвращает `null`, но обход видит запись
и ту же ссылку на ключ. Эти результаты характеризуют данный диагностический
опыт. Общий контракт `Map` не определяет поведение после изменения
данных равенства ключа. Последняя строка относится к новой карте:
ключ удалён до изменения и затем добавлен заново.

## Составные значения

[ArrayEqualityDemo.java](ArrayEqualityDemo.java) сравнивает разные массивы,
записи с массивным компонентом, `ScoreVector` с защитными копиями и вложенные
массивы. Последние три строки относятся к операциям `Objects` с `null`.
Вывод:

```text
false
true
false
true
true
true
false
true
true
true
false
0
```

`RawScores` использует идентичность массива. У `ScoreVector` равенство
и хеширование основаны на элементах; копия при создании и копия при чтении
сохраняют внутреннее состояние `[80, 90]`. Во вложенных массивах
`Arrays.equals` сравнивает ссылки на внутренние массивы, а `Arrays.deepEquals`
переходит к их элементам.

## Порядок и уникальность

[OrderDemo.java](OrderDemo.java) сортирует записи `s2:70`, `s3:90`,
`s1:90` по убыванию балла и возрастанию кода. Затем сравнивает коды
`s10` и `s2`, целые граничные значения и отсутствующую строку.
Вывод:

```text
s1
s3
s2
true
2147483647
-1
true
0
```

Число `2147483647` получено переполнением `Integer.MIN_VALUE - 1`.
Следующее число `-1` — правильный знак `Integer.compare` для этой пары.

[TreeEqualityDemo.java](TreeEqualityDemo.java) использует разные правила:
только балл, балл с кодом и все компоненты записи. Перед запуском
определите, какие пары дают ноль в каждом правиле. Вывод:

```text
false
false
true
1
2
false
0
3
1
второе значение
```

`TreeSet` по одному баллу содержит одного представителя двух участников
с баллом 90 и считает второго найденным. Список сохраняет обоих.
Сравнение балла и кода даёт ноль для разных имён одного кода; добавление
имени позволяет множеству различить все три записи. В `TreeMap`
сравнение только по баллу приводит к замене значения существующего ключа.
