Ссылочные значения

Присваивание, передача аргументов, отсутствие значения

Семантика присваивания

  • Присваивание и копирование ссылочных значений.
  • Передача аргументов по значению.
  • Массивы, компоненты и глубина копирования.
  • Ограничения final и неизменяемость строк.
  • UTF-16, строковые диапазоны и накопление текста.
  • Отсутствие значения, null и статический анализ.

Перед следующим экраном задать исходный массив int[] pages = {5, 7}, назвать int[] saved = pages и последующую запись saved[0] = 9. Предложить прогноз для pages[0]; затем открыть код и результат.

Копирование ссылки

int[] pages = {5, 7};
int[] saved = pages;
saved[0] = 9;
System.out.println(pages[0]); // 9

Присваивание скопировало ссылку на массив. Поэтому запись через saved меняет число, которое затем читается через pages.

Сопоставить прогноз с результатом 9. Студент с опытом C++ может мысленно увидеть копирование контейнера. Попросить назвать, какое значение хранится в pages и куда его записало присваивание.

Числовое значение в двух переменных

Отдельный опыт с числом:

int count = 5;
int savedCount = count;
savedCount = 9;
после копирования       после savedCount = 9
count:      5           count:      5
savedCount: 5           savedCount: 9

Присваивание записывает значение в выбранную переменную. У count и savedCount свои места хранения.

Общий объект

int[] — ссылочный тип; переменная хранит ссылку на объект массива. После int[] saved = pages:

pages ─────┐
           ├──> A: [5, 7]
saved ─────┘

Скопирована ссылка на A. Массив остался один. saved[0] = 9 находит этот объект и меняет его компонент: обе переменные по-прежнему дают доступ к массиву [9, 7].

Присваивание новой ссылки

Продолжим после исправления первого компонента:

saved = new int[]{1, 2};
pages ───────> A: [9, 7]
saved ───────> B: [1, 2]

Создан второй массив, а новая ссылка записана только в saved. pages сохранила прежнее значение. Левая часть присваивания определяет, что изменяется: переменная saved или компонент saved[0].

Копирование контейнера в C++

std::array<int, 2> pages{5, 7};
auto saved = pages;  // новый контейнер с копией элементов
auto& view = pages;  // ссылка на существующий контейнер

saved[0] = 9 меняет копию; view[0] = 9 меняет исходный контейнер. В Java присваивание int[] копирует ссылочное значение, поэтому pages и saved дают доступ к одному массиву.

Ссылка C++ типа T& связывается с объектом; присваивание через неё действует на этот объект. Переменная Java ссылочного типа может получить другую ссылку. [7], [8]

Передача аргументов по значению

Копирование числового аргумента

static void addPage(int count) {
    count++;
}

Вызов с int count = 5;:

кадр main            кадр addPage
count: 5             count: 5 → 6

addPage(count) создаёт отдельную переменную параметра и передаёт ей значение 5. После возврата переменная count в main содержит 5.

Возвращаемое значение

Для count < Integer.MAX_VALUE:

static int nextCount(int count) {
    return count + 1;
}
int count = 5;
count = nextCount(count); // 6

Метод возвращает число. Присваивание в вызывающем коде записывает его в переменную count. Параметр принадлежит отдельному вызову метода. Глава 7

Копирование ссылочного аргумента

Создан новый массив int[] pages = {5, 7};. Методу передаётся существующий непустой массив:

static void correctFirst(int[] data) {
    data[0] = 9;
}

При correctFirst(pages) значение ссылки копируется в новый параметр:

кадр main                кадр correctFirst
pages ───────┐           data ──────┐
             └───────────┬──────────┘
                         v
                     A: [5, 7]

Изменение общего объекта

После data[0] = 9:

кадр main                кадр correctFirst
pages ───────┐           data ──────┐
             └───────────┬──────────┘
                         v
                     A: [9, 7]

Обе ссылки сохранились. Изменилось число внутри A. После возврата параметра data уже нет, а pages[0] равно 9.

Предложить назвать точное место записи: компонент объекта A. Подчеркнуть, что одинаковые ссылочные значения находятся в двух разных переменных. Копирование ссылки при вызове не копирует сам массив. До следующего экрана назвать тело replace: data = new int[]{1, 2}. Попросить предсказать pages[0], затем открыть экран с состоянием.

Присваивание параметру

С тем же pages, указывающим на [9, 7], вызовем:

static void replace(int[] data) {
    data = new int[]{1, 2};
}

После присваивания внутри replace:

кадр main                кадр replace
pages ──> A: [9, 7]       data ──> B: [1, 2]

Новая ссылка записана в параметр. После возврата pages[0] всё ещё 9.

Состояние после вызова

Запись в методе Место изменения Что видно после возврата
data[0] = 9 Компонент общего массива Через pages читается 9
data = new int[]{1, 2} Переменная параметра pages указывает на прежний массив

При вызове метода в Java значения аргументов присваиваются новым переменным параметров. Для ссылочного аргумента это создаёт ещё один путь к существующему объекту. [5]

Если при прогнозе студент ожидал 1, вернуться к двум кадрам: какая инструкция могла бы записать новое значение именно в переменную pages вызывающего метода? В приведённом теле такой инструкции нет.

Массив и его компоненты

Создание и начальные значения

int[] counts = new int[3];       // [0, 0, 0]
String[] titles = new String[3]; // [null, null, null]

Созданы два объекта массива. Числовые компоненты получили нули, ссылочные — null: ни один компонент titles ещё не указывает на строку.

counts ──> [0, 0, 0]
titles ──> [null, null, null]

Чтобы компонент titles указывал на строку, ему нужно присвоить ссылку на строковый объект.

Диапазон индексов

Для int[] pages = {5, 7}; значение pages.length равно 2. Допустимы индексы 0 и 1: 0 <= index && index < pages.length.

int first = pages[0];  // 5
// int third = pages[2]; // ArrayIndexOutOfBoundsException

Длина объекта массива фиксируется при создании. Переменной можно присвоить ссылку на массив другой длины; прежний объект от этого не изменит число компонентов.

Переменная расширенного for

int[] pages = {5, 7};
for (int count : pages) {
    count++;
}
System.out.println(pages[0]); // 5

На каждом шаге в count попадает очередное число. Запись в эту локальную переменную не меняет компонент массива. Для изменения компонентов нужна запись по индексу, например pages[i]++.

Копия массива чисел

Начальное состояние этого опыта — снова [5, 7]:

int[] pages = {5, 7};
int[] copy = pages.clone();
copy[0] = 9;
pages ──> A: [5, 7]
copy  ──> B: [9, 7]

clone() создал новый массив и скопировал значения компонентов. Для int[] это числа, поэтому их последующие изменения независимы. [6]

Поверхностная копия массива

int[][] — массив, компоненты которого ссылаются на массивы int[]:

int[][] weeks = {{5, 7}, {4}};
int[][] copy = weeks.clone();
weeks ──> W: [ ──┐, ──┐ ]
                 │    │
                 v    v
             A:[5,7] B:[4]
                 ^    ^
                 │    │
copy  ──> C: [ ──┘, ──┘ ]

Внешние массивы W и C разные. Их компоненты содержат ссылки на те же строки-массивы A и B.

Изменение общей строки

copy[0][0] = 9;
System.out.println(weeks[0][0]); // 9
weeks → W[0] ──┐
               ├──> A: [9, 7]
copy  → C[0] ──┘

Первый индекс выбирает ссылку на строку A. Второй — число внутри A. Внешний массив был скопирован, но оба пути всё ещё приводят к одному числу.

Замена ссылочного компонента

Продолжим после предыдущего присваивания:

copy[0] = new int[]{1, 2};
weeks → W[0] ──> A: [9, 7]
copy  → C[0] ──> D: [1, 2]
weeks → W[1] ──┐
               ├──> B: [4]
copy  → C[1] ──┘

Изменён компонент внешнего массива C. Первая строка weeks сохранилась, а вторая строка по-прежнему общая. Глава 8

Сопоставить две левые части: copy[0][0] и copy[0]. Попросить пройти по стрелкам от переменной до места записи. Предложить перечислить созданные заново и общие объекты: по ним определяется глубина копирования.

Переменная final

final int[] pages = {5, 7};
pages[0] = 9;              // допустимо
// pages = new int[]{1, 2}; // ошибка компиляции

Переменная pages получает значение один раз. Объект массива сохраняет изменяемые компоненты: final на этой переменной не запрещает запись в них и не распространяется по ссылкам на весь граф объектов.

Неизменяемость строк

Строковое значение

String title = "Java";
String saved = title;
title = title + " course";
до присваивания           после присваивания
title ─┬→ "Java"          title ───→ "Java course"
saved ─┘                  saved ───→ "Java"

String неизменяем: содержимое существующего объекта сохраняется. Присваивание записало в title результат конкатенации; через saved по-прежнему читается "Java".

Использование результата

String title = "  Java  ";
title.strip();
System.out.println(title.length()); // 8

title = title.strip();
System.out.println(title.length()); // 4

strip() возвращает строковое значение без крайних пробельных символов. Первый вызов не сохранил результат. Для требуемого изменения переменной понадобилось присваивание. [3]

Неизменяемость и создание объекта

Неизменяемость String сохраняет содержимое существующего объекта. Строковая операция может вернуть ссылку на этот же объект:

String title = "Java";
System.out.println(title.concat("") == title); // true

Контракт concat гарантирует прежнюю ссылку при пустом аргументе. Контракт strip() задаёт содержимое результата после удаления крайних пробельных символов; тождественность ссылок им не гарантируется. [3]

Сопоставить текущий concat("") с уже разобранным strip(). Различить два утверждения: исходный объект не изменился и результат обязан быть новым объектом. Первое следует из неизменяемости; второе требует отдельного контракта и в общем случае неверно.

Совместное использование строкового значения

Если два участника хранят одну строку с названием книги, каждый наблюдает одно и то же содержимое. Операция над строкой не меняет название у второго участника. Для сохранения текста ему не нужна защитная копия.

При накоплении большого отчёта та же неизменяемость означает последовательное получение новых строковых значений. Для совместного использования удобно стабильное значение; для накопления текста — изменяемое рабочее состояние. [1]

Вернуться к общему массиву из первой части: запись через одну ссылку была видна через другую. Предложить то же ожидание для строки и попросить объяснить различие через доступные операции. Затем рассмотреть отчёт, который растёт по одной записи: каждый новый результат содержит уже собранный префикс. Предложить построить текст в локальном накопителе и передать готовую строку.

Тождественность объекта и равенство текста

String a = "Java";
String b = new String("Java");
System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
a ──> S1: "Java"       b ──> S2: "Java"

== сравнивает ссылочные значения. equals для String сравнивает последовательности единиц UTF-16.

Индексация UTF-16

String text = "A😀B";

Схема кодовых единиц, по которым индексируется String:

индекс:    0       1       2       3
UTF-16: [0041]  [D83D]  [DE00]  [0042]
точки:  U+0041  └─ U+1F600 ──┘  U+0042

text.length() равно 4; text.codePointCount(0, text.length()) равно 3. У 😀 одна кодовая точка и две кодовые единицы UTF-16. Индексы методов String обычно измеряются кодовыми единицами. При проходе по кодовым точкам позиции меняются так: 0 → 1 → 3 → 4.

Провести по четырём ячейкам слева направо. Две средние относятся к одной кодовой точке. Сопоставить индекс char и кодовую точку. Видимый знак может состоять из нескольких кодовых точек. Индексы String отсчитывают единицы UTF-16; внутреннее хранение строки определяется реализацией.

Кодовая единица и кодовая точка

text.charAt(1);      // один char: старший суррогат \uD83D
text.codePointAt(1); // кодовая точка U+1F600, число 128512

char содержит одну 16-битную кодовую единицу. Для кодовой точки за пределами основного диапазона Unicode нужны два char.

Поэтому charAt(1) не извлекает целый знак 😀. [2], [3]

Полуоткрытый диапазон

Для String title = "Java";:

границы: 0   1   2   3   4
         | J | a | v | a |
             └───────┘
               [1, 3)
title.substring(1, 3); // "av"
title.substring(4);    // ""

Начало включено, конец исключён. Для двух границ требуется 0 <= begin && begin <= end && end <= title.length(). Длина результата в UTF-16 равна end - begin.

Изменяемый накопитель

StringBuilder builder = new StringBuilder();
builder.append("Java");
builder.append(": ").append(12);
String report = builder.toString();
builder.append(" страниц");

builder теперь содержит "Java: 12 страниц", а report — "Java: 12". append изменяет накопитель; toString даёт строковый результат, который последующие изменения накопителя не меняют. [4]

Отметить границу передачи результата: report уже можно отдать другому методу, пока builder продолжает изменяться. Для неизменяемой строки сохранность содержимого обеспечивается её операциями. Для накопителя она зависела бы от договорённости всех получателей общей ссылки.

Отсутствующее значение

Состояния строковой переменной

Запись Что известно Вызов length()
String text = ""; Есть пустая строка Возвращает 0
String text = null; Ссылка не указывает на объект Бросает NullPointerException
String text; Локальная переменная ещё не получила значение Чтение до присваивания запрещено компилятором

null — специальное ссылочное значение. Оно позволяет передать отсутствие, но смысл этого отсутствия должен задавать договор программы.

Договор обработки отсутствия

В этой программе отсутствие комментария считается текстом нулевой длины:

static int commentLength(String comment) {
    if (comment == null) {
        return 0;
    }
    return comment.length();
}

Результаты: для null — 0, для "" — 0, для "Java" — 4. Такой договор намеренно объединяет два случая. Если их нужно различать, одного возвращаемого числа недостаточно.

Порядок проверки

if (comment != null && !comment.isEmpty()) {
    System.out.println(comment);
}
Значение comment Левый операнд Правый операнд
null false Не вычисляется
"" true false
"Java" true true

&& вычисляет правую часть только при истинной левой. Проверка существования объекта предшествует обращению к нему.

Аннотация Nullable

Аннотация из Checker Framework:

import org.checkerframework.checker.nullness.qual.Nullable;

static int length(@Nullable String text) {
    return text.length(); // возможно разыменование null
}

@Nullable допускает отсутствие значения у параметра. Nullness Checker видит противоречие: объявленный договор допускает null, а тело метода обращается к строке без проверки.

Компиляция, анализ и выполнение

Действие с этим методом Результат
Обычный javac -proc:none, библиотека аннотаций доступна Метод компилируется
Компиляция с Nullness Checker Диагностика возможного разыменования null
Выполнение такого метода с аргументом null NullPointerException

Аннотация сама не добавляет проверку в тело метода. Анализатор использует её вместе с потоком управления; JVM исполняет полученный код. Настройка: Java: аннотация отсутствия и анализатор. [9]

Уточнение типа после проверки

Заменим прежнее тело length: для отсутствующей строки возвращаем 0.

static int length(@Nullable String text) {
    if (text == null) {
        return 0;
    }
    return text.length();
}

Если выполнение продолжается после проверки, text указывает на существующую строку. Анализатор учитывает проверку, а при выполнении null обрабатывается явной ветвью.

Предложить различить три события по времени: найденное противоречие при статическом анализе, выполнение ветви проверки и исключение при небезопасном разыменовании.

Копия массива строк

String[] notes = {"Java"};
String[] saved = notes.clone();
notes[0] += " course";

Что скопировал clone()? Какой объект был общим? Что теперь содержит saved[0]? Изменился бы результат, если бы переменная notes была final?

Замена строкового компонента

после clone               после notes[0] += " course"
notes → [ ─┐ ]            notes → [ ──> "Java course" ]
           ├→ "Java"
saved → [ ─┘ ]            saved → [ ──> "Java" ]

Массивы разные; сначала их компоненты содержали одну ссылку. Конкатенация создала строку с новым содержимым; присваивание сохранило ссылку на неё в компоненте первого массива. Исходная строка "Java" сохранила содержимое. saved[0] равно "Java". final у переменной notes не запрещает это изменение компонента.

Дополнительные разборы

Копирование вложенных массивов

Для существующего weeks без null среди строк:

int[][] copy = new int[weeks.length][];
for (int i = 0; i < weeks.length; i++) {
    copy[i] = weeks[i].clone();
}

Созданы внешний массив и отдельная копия каждой строки. Их числовые компоненты независимы от исходных. При допустимых null нужна отдельная ветвь: вызов clone() у отсутствующей строки завершился бы исключением.

Общность вложенных объектов

Если weeks[0] и weeks[1] указывали на один массив, предыдущий цикл создаст две разные копии:

до:     weeks → [A, A]
после:  copy  → [B, C]   B и C содержат одинаковые числа

Для сохранения отношения «одна общая строка» потребуется помнить, какой исходный объект уже скопирован. Глубина и сохранение общих ссылок являются разными требованиями к копии. Глава 8

Распаковка отсутствующей ссылки

Integer pages = null;
// int count = pages; // NullPointerException при распаковке

Integer является ссылочным типом. Получение int требует числового значения; null не превращается в ноль. Сравнение оболочек через == может сравнивать ссылки. Примитив и его оболочка

Интернирование и задача сравнения

System.out.println("Ja" + "va" == "Java"); // true

Константные строковые выражения интернируются, поэтому здесь ссылки совпадают. Для сравнения содержимого строк, включая текст из файла, применяется equals.

Кодовая точка и видимый знак

String a = "\u00E9";
String b = "e\u0301";
System.out.println(a.equals(b)); // false

Одна кодовая точка и сочетание буквы с комбинируемым знаком могут выглядеть одинаково. Для сопоставления таких форм нужны согласованные правила нормализации; для деления на воспринимаемые знаки — правила границ графем. Дополнение: нормализация и регистр
