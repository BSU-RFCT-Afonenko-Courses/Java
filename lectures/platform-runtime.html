Предпосылки создания Java

В начале 1990-х разработчики Java искали способ выполнять программы на разных устройствах. Затем та же потребность возникла при распространении программ по сети между разными системами.

В описании Java 1996 года переносимый байткод и одинаковые правила основных типов связываются с выполнением одной программы на разных платформах. [1], [3]

Компиляция и запуск

Компактный исходный файл

Сохраним в Hello.java, выберем JDK 25:

void main() {
    IO.println("Hello");
}
java Hello.java

Вывод — Hello. main задаёт начальное действие, void означает отсутствие возвращаемого значения, IO.println печатает строку. Команда компилирует исходник для этого запуска.

Перед опытом проверить выбранную версию java --version. При нескольких установках использовать путь к JDK 25, например /usr/lib/jvm/java-25-openjdk/bin/java Hello.java. Все последующие команды берутся из этого же JDK. Предложить изменить текст и повторить прямой запуск. Компактный файл неявно объявляет класс. Для именованного пакета требуется явное объявление класса.

Суммирование компонентов массива

За два дня прочитано 5 и 7 страниц. Метод получает массив и возвращает сумму первых двух компонентов:

static int total(int[] pages) {
    int sum = pages[0] + pages[1];
    return sum;
}

int[] обозначает массив целых; pages[0] и pages[1] читают компоненты с индексами 0 и 1. В этом опыте массив существует и содержит два компонента. Ожидаемый результат — 12.

Исходный файл

Файл Reading.java; команды далее используют тот же JDK 25:

static int total(int[] pages) {
    int sum = pages[0] + pages[1];
    return sum;
}

void main() {
    int[] pages = {5, 7};
    int sum = total(pages);
    IO.println(sum);
    IO.println(sum / 2.0);
}

Точка входа и библиотека

main создаёт массив, вызывает total, печатает сумму и среднее. Компилятор помещает методы в неявно объявленный класс Reading. Для вызова нестатического main среда создаёт объект этого класса.

Метод total объявлен static: его вызову отдельный объект не требуется. Параметр pages получает ссылку на массив, return возвращает число. IO.println — обращение к стандартной библиотеке. Правила языка задают смысл выражений; библиотека предоставляет готовые операции; JVM исполняет код классов.

При загрузке JVM получает представление класса. Проверка устанавливает, что код удовлетворяет требованиям JVM; подготовка создаёт статические поля и их начальные значения. Инициализация выполняет предусмотренные языком начальные присваивания и код инициализации класса.

Разрешение символических ссылок

В классе есть ссылки на другие классы, поля и методы — например, на библиотечный println. При разрешении JVM связывает такие символические ссылки с конкретными сущностями среды.

Разрешение является частью связывания и может происходить по мере обращений. Часть зависимостей может разрешаться уже после начала main, когда программа впервые использует соответствующие классы, поля и методы. [12]

Развести три вопроса: есть ли определение класса; допустимы ли инструкции; существует ли метод, который требуется вызвать. Предложить ситуацию: класс найден, но вызываемый метод из него удалён. Ошибка обнаруживается при разрешении обращения к этому методу.

Проверка байткода

Инструкция iadd должна получить два целых значения со стека операндов. Проверка байткода отслеживает совместимость таких действий с типами и устройством метода.

Выражение pages[0] - pages[1] также удовлетворяет требованиям к типам операндов. Оно вычисляет разность, поэтому для задачи суммирования формула ошибочна. Требование «сложить страницы» задаёт условие задачи; проверка байткода устанавливает допустимость инструкций JVM.

Исследование файла класса

В Reading.java восстановлен массив {5, 7} и повторно выполнен javac. Инструкции метода total доступны через javap:

javap -c -p -l Reading

-c показывает инструкции, -p — все методы и поля, -l — доступные таблицы строк и локальных переменных. [14]

Сложение в исходнике и классе

static int total(int[] pages) {
    int sum = pages[0] + pages[1];
    return sum;
}

Сначала читаются два числа, затем вычисляется сумма, сохраняется в sum и возвращается вызывающему коду.

Кадр вызова

При вызове total возникает его собственный кадр:

локальные переменные           стек операндов
0: pages — ссылка на массив    пуст
1: место для sum

Параметр pages этого статического метода занимает локальную позицию 0. Инструкции кладут промежуточные значения на стек операндов и снимают их. Кадры вызовов образуют стек данного потока. [13]

Слово «стек» встречается в двух масштабах. Стек потока содержит кадры вызовов; стек операндов принадлежит одному кадру и обслуживает вычисление. Попросить указать на схеме, какие значения принадлежат вызову total.

Код метода и состояние вызова

Если main снова вызовет total(pages) с тем же массивом [5, 7], JVM создаст новый кадр и снова выполнит уже загруженное тело метода.

Что хранится Где в модели JVM После возврата из total
Байткод total и сведения о методе Общая область методов Доступны для следующего вызова
Параметр pages, локальная sum, промежуточные значения Кадр вызова в стеке потока Кадр завершён
Компоненты массива [5, 7] Общая куча Массив доступен из main

Область методов хранит определения, общие для вызовов. Каждый вызов получает собственное состояние, поэтому два выполнения одного байткода могут работать с разными аргументами. [13]

Абстрактная машина JVM

В модели JVM каждый вызов получает локальные переменные и стек операндов. Куча является общей областью для объектов и массивов; каждый поток имеет собственный стек вызовов.

Реализация может использовать регистры, встраивать вызовы и устранять ненужные выделения памяти. Она должна сохранить наблюдаемое поведение программы; физическое размещение данных и последовательность машинных инструкций определяются реализацией. Вызов метода и объект в куче

Исполнение в HotSpot

Продолжительность нагрузки

Наш main вызывает total один раз, печатает результат и завершает процесс. Теперь представим сервис: он получает очередную пару чисел и снова вызывает тот же метод. Пользователю по-прежнему нужна сумма, но код исполняется многократно в одном процессе.

Именно повторное выполнение даёт среде наблюдения о нагрузке и возможность окупить работу по улучшению машинного кода. HotSpot использует эти наблюдения для JIT-компиляции. Спецификация JVM допускает различные стратегии исполнения, включая работу без JIT.

Многоуровневая JIT-компиляция

байткод метода
  → интерпретация / код с профилированием
  → наблюдения о повторных вызовах и путях
  → JIT-компиляция выбранного кода
  → машинный код в последующих выполнениях

Интерпретатор выполняет действия байткода. JIT-компилятор создаёт машинный код во время работы процесса. В HotSpot многоуровневая компиляция сочетает быстро скомпилированный код с профилированием и более затратную оптимизацию. Полученный машинный код хранится в кеше кода (code cache) и может использоваться многими вызовами. Создание кода расходует время процессора, хранение — память процесса. [4]

Профиль выполнения

Наблюдение Как оно помогает
Частые вызовы или повторения цикла Найти код, где оптимизация может окупиться
Частота ветвей Организовать код с учётом обычного пути
Типы получателей вызовов Выбрать оптимизацию для встречавшихся случаев

Наблюдавшиеся типы позволяют специализировать вызов, например встроить реализацию с проверкой предположения. По журналам компиляции и машинному коду можно определить, какие оптимизации выполнены в данном процессе. [2]

Предложить два возможных результата компиляции total: отдельное машинное тело или встраивание в вызывающий код. Установить выбранный вариант в конкретном запуске позволяют диагностические данные JVM для этой нагрузки.

Встраивание методов

Компилятор может встроить действия total в вызывающий код. Тогда видны вместе получение массива, чтение компонентов и использование суммы; часть промежуточной работы может стать ненужной.

Оптимизация обязана сохранить результат, исключения и другие наблюдаемые эффекты. Нативные компиляторы C++ также встраивают вызовы. HotSpot может выбирать встраивание с учётом профиля текущего процесса.

Прогрев среды

Начало процесса Продолжительная работа
Загрузка нужных классов Часть классов уже загружена
Первые выполнения кода Накоплены наблюдения о нагрузке
Компиляция ещё требует ресурсов Можно использовать подготовленный код

Прогрев — изменение состояния среды при выполнении нагрузки. Чтобы сравнивать измерения, отдельно учитывают запуск и участок работы после выбранного прогрева; его длительность проверяют для этой нагрузки.

Выделение памяти и сборка мусора

Если для каждого запроса создаётся новый int[], среда выделяет память для очередного массива. Когда прежние объекты становятся недостижимы, сборщик мусора может освободить их память.

создание объекта → использование → потеря достижимости
                                      → возможное освобождение GC

Выделение памяти и сборка расходуют ресурсы. Сборка может приостанавливать приложение; возможность выполнять часть работы одновременно с ним зависит от выбранного сборщика. Недостижимость объекта позволяет освободить его память; момент освобождения определяется работой сборщика. [5]

Указать путь к массиву A из main после возврата из total. Затем мысленно убрать все нужные программе пути к объекту. Попросить назвать, какое условие для освобождения памяти изменилось.

Время выполнения процесса

Для команды java Reading измерим время от запуска процесса до его завершения. В этот интервал входят:

запуск JVM → загрузка классов → main: массив, сумма, печать → завершение
|<--------------------- полное время процесса --------------------->|

Полученное время в миллисекундах относится ко всей команде. Даже если сложение станет вдвое быстрее, загрузка и вывод двух строк останутся. По полному времени нельзя определить, сколько занял один iadd.

Десять запусков команды создают десять процессов JVM. Десять вызовов total внутри одного процесса используют уже загруженный класс и могут выполняться при разных состояниях JIT-компиляции.

До показа экрана предложить два способа повторить расчёт: заново запустить команду или повторить вызов в работающей программе. После прогноза показать схему и сопоставить повторяемые действия.

Пропускная способность и задержка

Теперь сервис получает пары чисел и возвращает суммы. В модельном журнале после прогрева за 10 секунд завершены 1000 запросов. Его пропускная способность за этот интервал — 100 запросов/с.

Один из запросов принят в 2,000 с, ответ отправлен в 2,150 с:

приём запроса → ожидание обработки → вычисление → отправка ответа
2,000 с                                                    2,150 с
|<--------------------- задержка 150 мс ------------------------->|

Частное 10 с / 1000 = 10 мс получено из общего времени наблюдения и числа завершённых запросов. Этот запрос ждал 150 мс: одновременно в системе могли находиться другие запросы. Для задержки собирают времена отдельных запросов; распределение показывает и обычные, и редкие долгие ожидания.

До показа экрана дать только 1000 запросов за 10 секунд и спросить, известна ли задержка каждого. Затем показать времена одного запроса и сопоставить с ответом. Приостановка приложения во время GC может увеличить ожидание нескольких запросов сразу; среднее число завершений скрывает этот эпизод. JMH отдельно демонстрирует скорость повторений и выборку длительностей вызовов метода. Граница запроса сервиса может быть шире такого вызова. [15]

Числовая семантика

Переполнение целого произведения

Пусть нужно вычислить квадрат числа записей:

int count = 50_000;
long first = count * count;
System.out.println(first); // -1794967296

Оба операнда имеют тип int, поэтому умножение выполняется как int. Математическое 2500000000 выходит за его диапазон; сохраняются младшие 32 бита. Уже полученное отрицательное значение расширяется до long.

Числовое повышение

long second = (long) count * count;
System.out.println(second); // 2500000000
count * count         → умножение int  → -1794967296 → long
(long) count * count  → умножение long →  2500000000

У int фиксирован 32-битный диапазон со знаком, у long — 64-битный. Выбранная платформа не меняет это правило. Более широкий тип назначения не возвращает сведения, потерянные во время операции. [9], [11]

Предложить перенести приведение наружу: (long) (count * count). Результат останется отрицательным, потому что меняется уже вычисленное значение. Попросить указать типы операндов непосредственно перед умножением в обоих вариантах.

Тип деления

int sum = 5;
double first = sum / 2;          // 2.0
double second = (double) sum / 2; // 2.5

Сначала определяется операция по типам операндов. Целое деление отбросило дробную часть, затем 2 преобразовалось в 2.0.

В исходном Reading делитель 2.0 имеет тип double, поэтому среднее вычислялось с плавающей точкой ещё до печати.

Двоичное представление дробей

System.out.println(0.1 + 0.2);       // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3); // false

double хранит значения в конечном двоичном формате. Эти десятичные дроби представляются приближённо, а операции округляют результат. Переносимость сохраняет правила вычисления, включая такое округление. Глава 4

Распространение программы

Явное объявление класса

Для именованного пакета объявим класс явно. Отдельный вариант Hello.java:

package course;

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

Здесь public делает точку входа доступной, static позволяет вызвать её без объекта, String[] args принимает аргументы командной строки. System.out.println — ещё одна библиотечная форма печати.

Сопоставить с первым компактным файлом. Действие печати осталось тем же; новая явная структура нужна для имени course.Hello. При переходе к этому варианту сохранить показанный файл целиком на месте компактного.

Имя класса и путь поиска

Из каталога с новым Hello.java, JDK 25:

javac -d out Hello.java
java -cp out course.Hello

Вывод — Hello. Опция -d out задаёт корень результата: out/course/Hello.class. Опция -cp out задаёт корень поиска, а course.Hello — полное имя класса.

Пакет организует имена классов. Среда находит определение по имени и пути поиска, поэтому исходный файл и запускаемый класс задаются по-разному.

Среда выполнения приложения

Для запуска нужен класс, скомпилированный из нужного исходника, совместимая версия среды и правильный путь поиска. Если программа использует дополнительные библиотеки, их совместимые классы тоже должны быть доступны.

Файлы данных и нативные библиотеки должны быть доступны на целевой системе. Обращения к ним требуют соответствующих прав доступа и настроек ОС; эти условия входят в договор поставки программы.

Пользователю можно передать приложение вместе со совместимой средой выполнения. Например, jpackage создаёт пакет приложения с образом среды выполнения (runtime image); полный JDK с компилятором пользователю такого пакета не требуется. [8]

Дополнительные материалы

Строгость вычислений с плавающей точкой

Начиная с Java 17, выражения с плавающей точкой всегда вычисляются строго; strictfp больше не меняет результат. double сохраняет двоичное представление с ограниченной точностью; точность библиотечных функций определяется их собственными требованиями. [10]

Отрицательное целое деление

Выражение Результат
Java -5 / 2 -2
Java -5 % 2 -1
Python -5 // 2 -3
Java Math.floorMod(-5, 2) 1

Java округляет целое частное к нулю. Для циклического индекса следует выбрать операцию, которая даёт требуемый диапазон остатка. Деление и остаток

Повторение в измерительном опыте

Если вычисленный результат не используется, оптимизатор может удалить расчёт. Написанный вручную цикл повторений тоже способен изменить операцию: компилятор видит всю серию и может объединить или вынести часть работы.

В опытах JMH использование результата и устройство цикла определяют, какая работа сохраняется после оптимизации. [16], [17]

Деоптимизация

Оптимизированный код может опираться на проверяемое предположение о встречавшихся типах или путях. При его нарушении HotSpot способен восстановить состояние и продолжить выполнение через интерпретатор, а позднее получить другой машинный код.

Такая деоптимизация меняет стоимость исполнения, сохраняя допустимое поведение программы. [2]

Двоичная совместимость

Старый класс обращается к методу с определённым именем и типами. Изменение тела метода может сохранить возможность связывания; удаление необходимого метода способно привести к NoSuchMethodError при разрешении обращения.

Если новое тело возвращает другой результат, связывание может пройти успешно, а поведение клиента изменится. Совместимость поведения проверяют по договору библиотеки. Двоичная совместимость
