Равенство при поиске

Сравнение строк

Для созданных строк a, b и ссылки alias:

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
System.out.println(alias == a);  // true

== над ссылками проверяет общий объект. String.equals сравнивает содержимое, поэтому два разных объекта могут представлять одно значение. В Python этим вопросам соответствуют is и ==. Идентичность и равенство содержимого.

Унаследованное равенство

class Token { int code = 17; }
Token first = new Token();
Token second = new Token();
System.out.println(first.equals(second)); // false

Object.equals проверяет идентичность. Поля двух Token равны, но унаследованный метод их не читает. Тип идентификатора должен сам определить равенство по коду, если поиск должен находить отдельный объект с тем же кодом.

Соглашение equals

Для ссылок x, y, z, отличных от null:

Свойство Требование
Рефлексивность x.equals(x) истинно
Симметрия x.equals(y) совпадает с y.equals(x)
Транзитивность Из x ~ y и y ~ z следует x ~ z
Устойчивость Неизменные сведения дают прежний ответ

x.equals(null) ложно. Транзитивность позволяет использовать один объект как представителя группы равных значений. Близость баллов «разность ≤ 1» не подходит: 80 близок к 81, 81 — к 82, а 80 и 82 различаются.

Коллизия

StudentId aa = new StudentId("Aa");
StudentId bb = new StudentId("BB");
System.out.println(aa.hashCode() == bb.hashCode()); // true
System.out.println(aa.equals(bb));                  // false
Set<StudentId> keys = new HashSet<>();

Коллизия — совпадение хешей неравных объектов. Проверка равенства различила два ключа, поэтому оба сохранены. Постоянный хеш также может быть корректен, но направляет все ключи в одну область и ухудшает поиск.

Изменяемый ключ

В следующем типе доступна запись в данные равенства:

    @Override public int hashCode() { return code; }

Естественный порядок

Comparable<T> задаёт метод int compareTo(T other):

System.out.println("Ada".compareTo("Lin") < 0); // true
System.out.println("s10".compareTo("s2") < 0);  // true

Отрицательный результат означает «раньше», положительный — «позже», ноль — одно положение по сравнению. Существенен знак, точные −1 и 1 не требуются. String сравнивает кодовые единицы UTF-16; после общего s символ 1 предшествует 2. Языковой алфавитный порядок требует сравнения с учётом локали.

Внешнее правило порядка

Ведомость требует сначала больший балл, при ничьей — меньший код. Этот порядок применяется к полным сведениям участников и позволяет показать рядом разные записи с одинаковыми баллами.

Comparator<Student> задаёт сравнение для выбранного отчёта:

final class ReportOrder implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        int byScore = Integer.compare(b.score(), a.score());
        return byScore != 0 ? byScore : a.id().compareTo(b.id());
    }
}

Обратный порядок аргументов Integer.compare ставит больший балл раньше. Код сравнивается только при равенстве баллов. equals записи сохраняет своё правило по всем компонентам.

Сортировка списка

var rows = new ArrayList<>(List.of(
    new Student("s3", "Ann", 90), new Student("s2", "Lin", 70),
    new Student("s1", "Ada", 90)));
rows.sort(new ReportOrder());
for (Student row : rows) System.out.println(row.id());
// s1
// s3
// s2

Переполнение при сравнении

int a = Integer.MIN_VALUE;
int b = 1;
System.out.println(a - b > 0); // true
System.out.println(Integer.compare(a, b) < 0); // true

Математическая разность меньше минимального int; после переполнения получается Integer.MAX_VALUE. Вычитание дало неверный знак порядка. Integer.compare сравнивает весь диапазон без этой ошибки.

Перестановка аргументов должна менять знак, а отношение «раньше» должно быть транзитивно. У равных по сравнению объектов знаки сравнений с любым третьим объектом совпадают.

Ноль сравнения в TreeSet

Student b = new Student("s2", "Lin", 90);
var set = new TreeSet<Student>(byScore);
set.add(a);

System.out.println(queue.pollFirst()); // Lin
System.out.println(queue.pollFirst()); // null
queue.removeFirst(); // NoSuchElementException

pollFirst сообщает пустоту специальным результатом; removeFirst — исключением. Для цикла до исчерпания пустота завершает обработку. Для операции, требующей существующей головы, пустота нарушает условие вызова.

Работа с одним концом через push/pop даёт LIFO: после добавления Ada, затем Lin первым извлекается Lin.

Развитие каталога

Небольшой каталог можно хранить списком и искать код обходом. Когда поиски становятся частыми, индекс по коду сокращает повторную работу. Если одновременно нужен порядок поступления, список и индекс придётся обновлять согласованно.

Отчёт добавляет ещё одно требование: сохранить сведения на выбранный момент. Его снимок должен пережить последующие изменения каталога. Более быстрый поиск и воспроизводимый отчёт получают ценой дополнительного хранения и явных правил обновления.

Начать с редкого поиска в небольшом списке: затраты на сопровождение отдельного индекса могут превышать экономию на поиске. Затем увеличить число поисков и вернуться к примеру замены Student в списке при старом значении карты. Попросить выбрать единственное хранилище текущих сведений или описать согласованное обновление двух структур. Для отчёта отделить текущий индекс от намеренно сохранённой прежней версии. Структуры выбираются заново при изменении нагрузки и договора клиента.

Приоритетная очередь

var queue = new PriorityQueue<Integer>();
queue.addAll(List.of(30, 10, 20, 10));
while (!queue.isEmpty()) System.out.println(queue.poll());
// 10, 10, 20, 30 — по одному числу в строке

Голова — минимум по естественному порядку или компаратору. Повторения сохраняются; среди равных приоритетов представитель выбирается произвольно. Итератор не задаёт отсортированный обход всей очереди. poll поддерживает минимум и удаляет его: полный такой просмотр опустошает очередь. [4]

Равенство контейнеров

List<String> a = new ArrayList<>(List.of("Ada", "Lin"));
List<String> b = new LinkedList<>(List.of("Ada", "Lin"));
System.out.println(a.equals(b)); // true

List сравнивает последовательность, Set — состав, Map — соответствия. У двух разных ArrayDeque с одинаковыми элементами equals ложно: общего равенства последовательностей интерфейс Deque не задаёт. Для сравнения порядка можно получить списки и применить List.equals.
