Параметризация контейнера

Обобщённое программирование позволяет описывать алгоритмы и структуры данных независимо от конкретных типов обрабатываемых значений. Один параметр типа связывает места объявления, которые должны согласованно использовать выбранный тип.

final class ObjectBox {
    private final Object value;
    ObjectBox(Object value) { this.value = value; }
    Object get() { return value; }
}

Object — общий супертип ссылочных типов. Поле может хранить ссылку на строку, упакованное число или другой объект. Конструктор копирует полученную ссылку, get() возвращает её.

У выражения box.get() статический тип Object, заданный объявлением метода. Для обращения к методам строки клиенту потребуется приведение.

Приведение результата

ObjectBox box = new ObjectBox("Java");
String text = (String) box.get();
System.out.println(text.length()); // 4

Компилятор разрешает привести Object к String, но соответствие проверяется при выполнении. Приведение не создаёт строку из другого значения: оно проверяет уже существующий объект.

Здесь коробка действительно содержит строку. После успешной проверки переменная text получает ту же ссылку, и вызов length() возвращает 4.

Параметр типа

final class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
}

Одно имя T связывает тип поля, аргумента конструктора и результата get(). При использовании Box<String> компилятор проверяет все три места согласованно со String.

T — параметр типа в объявлении. Конкретный String или Integer при использовании класса — аргумент типа.

Сопоставить T в типах поля, параметра конструктора и результата get с аргументом String в показанном типе Box<String>. Все три места проверяются с учётом одной связи типов.

Вывод аргумента типа

Допустимый вариант создания строковой коробки:

Box<String> title = new Box<>("Java");
String text = title.get();

У выражения title.get() теперь тип String. Ручное приведение не нужно: соответствие содержимого проверяется по контракту Box<T>.

Альтернативная попытка создания той же переменной:

Box<String> title = new Box<>(25); // ошибка компиляции

Запись <>, называемая «ромбом» (diamond), поручает компилятору вывести аргумент типа. Она не отменяет проверку: ожидание Box<String> и целочисленный аргумент конструктора согласовать невозможно.

При var компилятор выводит статический тип локальной переменной из инициализатора. У second нет целевого Box<String>: для аргумента null выбирается Object. У third тип уже задан правой частью.

Ссылочные аргументы типа

Box<Integer> edition = new Box<>(25);
int number = edition.get();

Аргумент обобщённого типа должен быть ссылочным: Box<Integer> допустим, Box<int> — нет. При передаче 25 происходит упаковка, при присваивании результата переменной int — распаковка.

В этом опыте сохранён Integer со значением 25, поэтому распаковка даёт 25. Если создать new Box<Integer>(null), чтение вернёт null, а попытка распаковать его в int вызовет NullPointerException.

Общий объект в контейнере

Книга может быть выдана читателю. Состояние представим одним полем:

final class Book { boolean borrowed; }

Book book = new Book();
Box<Book> stored = new Box<>(book);
book.borrowed = true;
System.out.println(stored.get().borrowed); // true
System.out.println(stored.get() == book);  // true

Конструктор сохранил ссылку book, поэтому поле коробки и переменная ведут к одной книге. Присваивание меняет её borrowed; чтение через stored.get() видит это изменение. final запрещает заново присвоить ссылку полю коробки. Поле borrowed самой книги остаётся изменяемым.

Обобщённые методы

static <T> void swap(T[] values, int i, int j) {
    T saved = values[i];
    values[i] = values[j];
    values[j] = saved;
}

Метод объявляет собственный параметр <T> перед возвращаемым типом. Он связывает тип элемента массива и тип временной переменной. При передаче String[] компилятор выводит аргумент типа из вызова.

Для String[] names = {"Ada", "Lin"} вызов swap(names, 0, 1) оставляет в массиве {"Lin", "Ada"}. Метод переставляет сохранённые ссылки. Он принимает существующий массив и индексы его элементов.

Числовая граница

static <T extends Number> double twice(T value) {
    return 2.0 * value.doubleValue();
}

Тело обобщённого метода проверяется по объявленным ограничениям. Граница T extends Number разрешает doubleValue(), потому что этот метод объявлен в Number; строку передать нельзя.

twice(3) возвращает 6.0: вызов doubleValue() преобразовал число, затем обычное умножение вычислило double. Для большого целого это преобразование может потерять точность. Контракт Number предоставляет числовые преобразования; выражение value + value для произвольного T не определено.

Порядок значений

System.out.println("Ada".compareTo("Lin"));   // -11
System.out.println("Java".compareTo("Java")); // 0
System.out.println("Lin".compareTo("Ada") > 0); // true

compareTo возвращает отрицательное число, если получатель меньше аргумента, ноль при равенстве в выбранном порядке и положительное число, если больше. Алгоритм проверяет знак: например, -11 < 0.

Comparable<T> объявляет метод int compareTo(T other). У String это Comparable<String>: строка сравнивается со строкой. Строки сравниваются по единицам UTF-16 до первого различия: у A значение 65, у L — 76, поэтому здесь результат -11. Если одна строка — начало другой, раньше идёт короткая.

Спросить, почему проверка результата на -1 не годится. Нулевой результат означает эквивалентность в выбранном порядке; такой результат могут дать два разных объекта. [18]

Выбор большего значения

static <T extends Comparable<T>> T larger(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}

System.out.println(larger("Ada", "Lin")); // Lin

Граница делает нужную операцию доступной в теле метода: значение T можно сравнить с другим T. Оба аргумента и результат связаны одним параметром; возвращается один из переданных объектов. При равенстве выбирается left.

Вызов предполагает ссылки, отличные от null, и согласованный порядок.

Сначала связь входов и результата, затем требуемая операция. Аргументы, отличные от null, и согласованность порядка — условия использования метода. [11], [18]

Верхняя граница подстановочного аргумента

static double sum(List<? extends Number> values) {
    double total = 0.0;
    for (Number value : values) {
        total += value.doubleValue();

    return total;

Унаследованное сравнение

У участника Person есть результат rank; большее число означает более высокий результат. Integer.compare(x, y) возвращает знак сравнения двух int; Student наследует заданный через него порядок:

class Person implements Comparable<Person> {
    final int rank;
    Person(int rank) { this.rank = rank; }
    public int compareTo(Person other) {
        return Integer.compare(rank, other.rank);
    }
}
final class Student extends Person {
    Student(int rank) { super(rank); }
}

У студента есть compareTo(Person), способный принять другого студента. Отдельный Comparable<Student> от наследования не появляется.

Проследить унаследованный метод: получатель Student, параметр Person. Сравнение использует только значения rank.

Вывод целевого типа

Student a = new Student(1);
Student b = new Student(2);
Person person = larger(a, b);   // допустимо, T = Person
Student student = larger(a, b); // ошибка компиляции

Прежняя граница <T extends Comparable<T>> допускает первый вызов: оба студента являются Person, а Person сравним с Person. Результат имеет тип Person, хотя возвращённый объект — тот же b.

Последнее присваивание требует сохранить Student в результате. Выбрать T = Student нельзя: он не реализует Comparable<Student>. Вывод вынужден выбрать Person, который слишком широк для этой переменной.

Сравнение с супертипом

Заменим прежнее объявление larger следующим. Это альтернативная сигнатура: обе версии имеют одинаковое стирание и не образуют перегрузку. Используем тех же a и b с рейтингами 1 и 2:

static <T extends Comparable<? super T>>
T larger(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}

Student student = larger(a, b); // допустимо, T = Student
System.out.println(student == b); // true

Изменена граница, тело осталось прежним. compareTo потребляет второй объект, поэтому достаточно сравнения с T или его супертипом. Comparable<Person> подходит к Comparable<? super Student>.

Результат сохраняет статический тип Student и ссылку на b. Условия применения те же: аргументы, отличные от null, и согласованный порядок.

Источник и приёмник

static <T> void copy(List<? extends T> source,
                     List<? super T> target) {
    for (T value : source) {
        target.add(value);
    }
}

T связывает два разных контейнера: каждое значение из источника должно быть допустимо для приёмника. Например, элементы List<Integer> можно дописать в List<Number>.

Памятка PECS (producer extends, consumer super) связывает источник значений с extends, приёмник — с super. Выбор границ зависит от того, какие значения метод читает и какие записывает.

Создание начального значения

Общее тело не располагает выбранным конструктором для T. Создание начального значения можно предоставить ему отдельной операцией интерфейса.

Попросить определить тип результата операции, которая предоставляет начальное значение для вычисления с элементами типа T.

Сумма попарных произведений

Для двух векторов одинаковой длины требуется вычислить

\[ \operatorname{dot}(a,b)=\sum_{i=0}^{n-1} a_i b_i. \]

Для действительных значений \([1,2]\) и \([3,4]\) получаем \(1\cdot3+2\cdot4=11\). Алгоритму нужны сложение, умножение и начальный ноль; устройство цикла от вида чисел не зависит.

Для комплексных чисел здесь задана билинейная сумма без сопряжения. Эрмитово скалярное произведение потребовало бы ещё операции сопряжения.

Попросить назвать операции до показа следующего интерфейса.

Контракт арифметики

interface Arithmetic<T> {
    T zero();
    T add(T left, T right);
    T multiply(T left, T right);
}

Для результата прежнего twice хватало преобразования в double. Здесь число должно сохранить свой тип и, у комплексного значения, мнимую часть. Arithmetic<T> предоставляет операции с результатом T.

Один T связывает аргументы и результаты сложения и умножения, а zero() создаёт подходящее начальное значение. Конкретную арифметику алгоритм получает отдельным объектом. В этом примере ссылки на элементы, объект арифметики и результаты операций отличны от null; операции сохраняют переданные элементы.

Вернуться к twice: там doubleValue было достаточно для его результата, здесь требуется сохранить исходный тип вычисления.

Алгоритм с переданными операциями

static <T> T dot(List<T> left, List<T> right, Arithmetic<T> arithmetic) {
    if (left.size() != right.size()) {
        throw new IllegalArgumentException("Different vector lengths");
    }
    T result = arithmetic.zero();
    for (int i = 0; i < left.size(); i++) {
        T term = arithmetic.multiply(left.get(i), right.get(i));
        result = arithmetic.add(result, term);
    }
    return result;
}

Параметр T связывает элементы обоих векторов, арифметику, промежуточный результат и ответ. Равенство длин проверяется при выполнении; списки предполагаются отличными от null. У двух пустых списков цикл не выполняется и возвращается zero().

Прочитать цикл как «произведение → прибавление». Спросить, какой результат будет у двух пустых списков при корректном zero().

Действительные значения

    public Double zero() { return 0.0; }
    public Double add(Double a, Double b) { return a + b; }
    public Double multiply(Double a, Double b) { return a * b; }
}
double value = dot(List.of(1.0, 2.0), List.of(3.0, 4.0),
                   new DoubleArithmetic());

В реализации известен конкретный Double, поэтому доступны распаковка и обычные числовые операции. Общий метод dot вызывает три метода Arithmetic<T>. Вычисление double приближённое: порядок накопления суммы может влиять на округление.

Шаблоны C++

В C++ зависимые операции шаблона проверяются с учётом выбранного аргумента. Поэтому общий алгоритм может использовать выражения a + b и a * b, если они допустимы для подставляемого типа.

В Java тело метода опиралось на объявленный Arithmetic<T>. Для C++-версии того же dot нужно описать, какие выражения и действия над значениями требуются от самого T.

Концепты (concepts) в C++20 позволяют записать эти требования рядом с объявлением шаблона. Здесь проверяются выражения над T. Подстановочные аргументы Java ? extends и ? super задают отношение неизвестного аргумента типа к указанному типу.

Сопоставить место предоставления операций: объект Arithmetic и выражения над выбранным аргументом шаблона.

[13]

Требования к элементу вектора

template<class T>
concept DotElement = std::semiregular<T> && requires(const T a, const T b) {
    T{};
    { a + b } -> std::same_as<T>;
    { a * b } -> std::same_as<T>;
};

concept DotElement именует условие допустимости типа. В него входят std::semiregular<T> — создание, копирование и присваивание значений — и requires, проверяющее выражения для константных операндов. std::same_as<T> требует результата именно типа T.

Для алгоритма нужно ещё, чтобы T{} означало нейтральный элемент сложения. Проверка допустимости выражения не доказывает это математическое свойство; оно остаётся смысловым условием.

Попросить сопоставить требования с будущими действиями цикла: создание result, чтение, умножение, сложение, присваивание.

Сумма произведений в C++

template<DotElement T>
T dot(const std::vector<T>& left, const std::vector<T>& right) {
    if (left.size() != right.size()) {
        throw std::invalid_argument("Different vector lengths");
    }
    T result{};
    for (std::size_t i = 0; i < left.size(); ++i) {
        result = result + left[i] * right[i];
    }
    return result;
}

Форма цикла совпадает с Java-алгоритмом. Вместо вызовов переданного объекта используются операторы выбранного типа. Проверка длины остаётся условием выполнения, а соответствие DotElement — условием применения шаблона.

Сопоставить условия для константных операндов с типом параметров const std::vector<T>&.

Подстановка числовых типов

                std::vector<double>{3.0, 4.0});

Объект с арифметикой передавать не требуется: подходящие операции уже доступны для выбранных типов. Отсутствие сопряжения сохраняет тот же контракт суммы произведений, что и в Java.

Сопоставить литералы с Java-примером, чтобы сравнивался один алгоритм на одинаковых данных.

Размер как аргумент шаблона

template<DotElement T, std::size_t N>
T dot(const std::array<T, N>& left, const std::array<T, N>& right) {
    T result{};
    for (std::size_t i = 0; i < N; ++i)
        result = result + left[i] * right[i];
    return result;
}

В std::array<double, 2> аргумент double — тип, а 2 — значение. Оба параметра функции содержат один N: массивы длины 2 и 3 не позволяют вывести его согласованно, вызов отвергается до запуска.

У Java List<T> и C++ vector<T> длина хранится в объекте и проверяется при выполнении. У std::array<T, N> длина входит в тип, поэтому несовпадение размеров обнаруживается при проверке вызова.

Сопоставить T и N, затем разные места проверки. Концепт описывает допустимые выражения; подстановочный аргумент Java — отношение типов. [14]

CLR — среда выполнения .NET — сохраняет аргументы построенных обобщённых типов. List<int> и List<string> — различные типы времени выполнения. Аргументами могут служить и ссылочные типы, и типы значений.

Console.WriteLine(typeof(List<int>) == typeof(List<string>)); // False

typeof получает описание типа для среды выполнения. Для подстановок ссылочных типов CLR может использовать общий машинный код, сохраняя сведения о каждом построенном типе. Допустимые операции над T компилятор устанавливает по ограничениям обобщённого объявления.

Разделить два свойства: сохранение аргументов построенных обобщённых типов в CLR и возможность записать + в обобщённом методе.

Контракты обобщённой арифметики

Часть объявления метода Dot<T> в C# 11 и .NET 7+:

where T : IAdditionOperators<T, T, T>,
          IMultiplyOperators<T, T, T>,
          IAdditiveIdentity<T, T>

Ограничение where T перечисляет интерфейсные контракты для типа T. Три интерфейса из System.Numerics сообщают, что для T доступны сложение, умножение и нейтральный элемент сложения.

Сумма произведений использует сложение, умножение и нейтральный элемент; отношение «больше» в вычислении отсутствует. Комплексные числа предоставляют все три требуемые операции.

Попросить сопоставить каждый интерфейс с одной операцией Arithmetic в Java. Обратить внимание на три аргумента операторного интерфейса: левый операнд, правый операнд и результат.

[16]

Сумма произведений в C#

static T Dot<T>(IReadOnlyList<T> left, IReadOnlyList<T> right)
    where T : IAdditionOperators<T, T, T>,
              IMultiplyOperators<T, T, T>,
              IAdditiveIdentity<T, T>
{
    if (left.Count != right.Count)
        throw new ArgumentException("Different vector lengths");
    T result = T.AdditiveIdentity;
    for (int i = 0; i < left.Count; i++)
        result += left[i] * right[i];
    return result;
}

Ограничения разрешают +, * и T.AdditiveIdentity в теле метода. Операции предоставляет контракт типа; отдельный объект арифметики, как в Java-примере, не передаётся. IReadOnlyList<T> предоставляет чтение по индексу и число элементов Count.

Сопоставить операции: zero → AdditiveIdentity, multiply → *, add → +. Версии: C# 11, .NET 7 или новее.

[16]

Подстановка числовых типов

var real = Dot(new double[] { 1, 2 }, new double[] { 3, 4 });
var complex = Dot(new Complex[] { new(1, 1), new(2, 0) },
                  new Complex[] { new(3, 0), new(4, -1) });

Получаются 11 и 11 + i. Complex из System.Numerics предоставляет требуемые операции. Алгоритм использует сложение и умножение; его ограничения допускают числовые типы без отношения «больше».

При var компилятор C# выводит локальный тип из инициализатора: у real это double, у complex — Complex. Статические типы переменных сохраняются.

Сопоставить одинаковые данные с Java и C++. Версии, которые сделали эту форму возможной: C# 11 и .NET 7. [16], [17]

Динамический полиморфизм Python

def dot(left, right):
    if len(left) != len(right):
        raise ValueError("Different vector lengths")
    result = 0
    for a, b in zip(left, right):
        result = result + a * b
    return result

У функции пока нет аннотаций. Python применяет * и + к фактическим объектам. zip перебирает пары до конца более короткого входа; предварительная проверка длины позволяет использовать все элементы обоих векторов. len возвращает число элементов последовательности.

Сначала прочитать тот же ход: начало, произведение, прибавление. Для какого нового типа этот код сможет сработать без изменения тела?

Подстановка числовых значений

print(dot([1.0, 2.0], [3.0, 4.0]))          # 11.0
print(dot([1 + 1j, 2 + 0j], [3 + 0j, 4 - 1j]))  # (11+1j)
print(dot([], []))                         # 0

У float умножение даёт действительное произведение, у complex — комплексное. Начальный целый ноль подходит для сложения в обоих случаях. У пустых входов он и остаётся результатом.

Для неподходящих объектов, например dot(["3"], [4.0]), выполнение дойдёт до операции и получит TypeError при умножении строки на float.

Предложить проследить, когда целый ноль становится float или complex. Отдельно разобрать пустой вход, где ни одна операция не меняет result. Перед следующим экраном поставить задачу обнаружить строку в числовом входе до запуска функции.

Аннотации числовых входов

Добавим описание для статического анализатора:

from collections.abc import Sequence
Number = float | complex

def dot(left: Sequence[Number], right: Sequence[Number]) -> Number:
    if len(left) != len(right):
        raise ValueError("Different vector lengths")
    result: Number = 0
    for a, b in zip(left, right):
        result = result + a * b
    return result

Sequence описывает последовательность с длиной и доступом к элементам. float | complex задаёт допустимые числовые типы. Анализатор допускает int там, где ожидается float, поэтому начальный 0 подходит. Аннотация допускает смешанные входы; ответ описан тем же набором типов. Точная связь типа каждого вызова через T здесь не задана. Запись | доступна с Python 3.10.

Попросить сравнить тело с обычной функцией: арифметические действия сохранились. Затем рассмотреть смешанный вход из float и complex: аннотация результата охватывает оба типа, отдельно тип каждого вызова через один параметр здесь не связывается. [21], [23]

Статический анализ Python

# Клиент аннотированной функции:
dot(["3"], [4.0])

Отдельный анализатор типов, например Pyright, отвергает строковый элемент вместо числа. Обычный Python не исполняет эту проверку аннотаций: прямой запуск снова дойдёт до умножения и завершится TypeError.

Структурный контракт Protocol позволяет описать отдельно передаваемый объект операций: Структурный контракт операций.

Сначала работала функция, затем был сформулирован контракт числовых входов и запущен отдельный инструмент. Аннотации помогают этому инструменту; операции при выполнении задаёт тело функции. [21], [22]

Согласование источников и операций

В Java-версии dot один T связывает оба вектора с объектом арифметики. Сигнатура уже реализованного метода:

static <T> T dot(List<T> left, List<T> right, Arithmetic<T> ops)
left.get(i): T ─┐
               ├→ ops.multiply(...): T → ops.add(result, ...): T
right.get(i): T ┘                                result: T

Замена обоих List<T> на List<?> разорвала бы эту связь. У каждого списка оказался бы свой неизвестный тип элемента; передать прочитанные значения в multiply(T, T) компилятор уже не разрешил бы. Для печати Object достаточен, для выбранной арифметики требуется T.

Предложить пройти стрелки при T = Complex, затем при T = Double. После этого мысленно убрать T у одного источника: на каком вызове потерянное знание становится необходимым? Равенство длин по-прежнему проверяет тело метода, а правильность zero — договор арифметики. Развёрнутый разбор: Согласование источников и операций.

Дополнительные свойства обобщений

Независимые параметры типов

Запись record объявляет носитель компонентов с конструктором и методами чтения. Здесь компонентам нужны независимые типы:

record Entry<K, V>(K key, V value) {}

Entry<String, Integer> result = new Entry<>("passed", 12);
String key = result.key();
int value = result.value();

K связывает ключ конструктора с результатом key(), а V связывает значение с результатом value(). Эти два типа могут различаться.

Число параметров определяется отношениями между данными. Один параметр связывает несколько мест одним типом; два независимых параметра позволяют выбрать эти типы отдельно.

Спросить, что изменится в контракте пары, если обе части обозначить T. Двум параметрам можно сопоставить как разные, так и одинаковые типы.

[29]

Захват неизвестного типа во вспомогательном методе

static void repeatFirst(List<?> values) { repeat(values); }
private static <T> void repeat(List<T> values) {
    if (!values.isEmpty()) values.add(values.get(0));
}

Захват подстановочного аргумента даёт неизвестному типу временное имя T. Метод добавляет в список элемент, прочитанный из этого же списка. Для изменяемого [A, B] получится [A, B, A].

Типы допускают действие; неизменяемый список может отклонить add. Захват неизвестного типа.

Попросить указать происхождение добавляемого элемента. Если предлагают заменить его строкой, вернуться к неизвестному типу входного списка. Имя T сохраняет связь с этим входом внутри вспомогательного метода.

Ограничения представления типов при выполнении

В общем классе нельзя непосредственно написать new T() или new T[n]: выбранный аргумент типа не предоставлен исполняемому коду как готовое описание создаваемого класса или массива. Для произвольной ссылки Object проверка instanceof Box<String> не позволяет установить параметризацию коробки и запрещена.

Та же граница проявляется в перегрузке: методы с параметрами List<String> и List<Integer> получают одинаковую форму после стирания. Одного различия аргументов типа недостаточно, чтобы объявить такие две перегрузки.

Для создания нового объекта или массива вызывающий код может передать фабрику либо описание создаваемого класса.

Попросить назвать, каких сведений о типе недостаёт каждой из запрещённых операций. Сопоставить создание объекта, проверку класса и выбор перегрузки. Адресные разборы: Глава 14.

Структурный контракт операций

Объект операций позволяет, например, считать выполненные умножения, сохраняя обычную арифметику float. Анализатору можно описать требуемую структуру такого объекта:

from typing import Protocol

class Arithmetic[T](Protocol):
    def zero(self) -> T: ...
    def add(self, a: T, b: T) -> T: ...
    def multiply(self, a: T, b: T) -> T: ...

Параметр T связывает входы и результаты операций. Класс реализации может подойти по структуре без наследования от Arithmetic. Объявления параметров в такой форме доступны с Python 3.12.

Комплексная арифметика Java

record Complex(double re, double im) {}

final class ComplexArithmetic implements Arithmetic<Complex> {
    public Complex zero() { return new Complex(0.0, 0.0); }
    public Complex add(Complex a, Complex b) {
        return new Complex(a.re() + b.re(), a.im() + b.im());
    }
    public Complex multiply(Complex a, Complex b) {
        return new Complex(a.re() * b.re() - a.im() * b.im(),
                           a.re() * b.im() + a.im() * b.re());
    }
}

Сложение и умножение создают новые значения; переданные числа не меняются. Complex хранит две компоненты, а Arithmetic<Complex> предоставляет операции для прежнего цикла dot.
