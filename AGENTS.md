# Инструкции для автора и агента

Сохраняйте пользовательские рабочие деревья, незакоммиченные изменения и открытые PR. Последние прямые указания пользователя имеют приоритет над историческими планами и примерами.

## Вход в принятую программу

Начинайте с [docs/README.md](docs/README.md), [реестра решений](docs/refactoring-plan.md), [стартового поручения](docs/refactoring-start-20261030.md) и [регламента](docs/release-execution-regulation-20261103.md). Принятые решения задают требования; исследовательские схемы и примеры не становятся обязательным API автоматически. При подготовке handoff 29 октября продукт не запускается; исполнительная сессия на другой машине выполняет принятый объём с 30 октября по стартовому поручению.

[Матрица агентского исполнения](docs/agent-execution-proposal-20261029.md) — **единственный нормативный источник моделей, усилий и границ ролей**, принятый решением 75. Старые общие назначения усилий и таблицы прежних планов заменены в этой программе. GPT-6 Sol (`gpt-6-sol`) исключён, в том числе как резерв. Standard обязателен; Fast/Ultrafast самостоятельно не включать. Глобальную конфигурацию моделей менять нельзя.

До роли подтвердите собственный запуск первичными метаданными по [переносимой процедуре допуска](docs/model-admission.md). Сохраните собственные ID чата и исходного хода; после возобновления и перед приёмкой проверяйте весь исходный интервал без сдвига начала. При отсутствии подтверждения соответствующая роль останавливается. У файла/контракта в одной фазе один владелец; рецензент не принимает свою работу. Весь код, включая стартеры, эталоны и тесты, пишет технический исполнитель; учебный автор определяет цели, допустимые решения и обязательный контракт.

Не возобновляйте исторические сроки, очереди и START чтением старых документов. Их точные сохранённые редакции доступны в [Git history](https://github.com/BSU-RFCT-Afonenko-Courses/Java/tree/f5d97be630c92f187f78ac9903b3c48ec03f9c99/docs). Принятые учебные единицы сохраняют статус с учётом последующих прямых замечаний; нового общего педагогического пилота нет.

Применяйте [методику](docs/authoring-methodology.md) и [образцы](docs/authoring-examples.md) в текущем объёме. Полномочия на репозитории, зависимости, проверки, публикацию и сохранность данных перечислены в регламенте: обычные разрешённые шаги не требуют повторного согласования. Системный запрос прав всё ещё возможен; обход ограничений и потеря данных сверх принятых исключений не разрешены.

## Язык новых текстов

Новые README, документацию и описания PR пишите только по-русски. Перед работой прочитайте [общее языковое правило](https://github.com/Afonenko-Course-Tools/quarto-course/blob/main/docs/russian-language-policy.md). Команды, идентификаторы API, пути, имена пакетов и URL сохраняйте буквально.
