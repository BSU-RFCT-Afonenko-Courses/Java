В Java основной список теперь содержит десять существующих авторских лабораторных. 87 технических страниц сохранены как добровольная навигация к банку, без искусственных обязательных работ на 100 баллов. Основные условия, слоты и веса не переписывались. Отдельной тренировочной выдачи внутри PrairieLearn пока нет; доступ через книгу сохранён.

Настройка подпроектов стала простым списком каталогов. Каждый дочерний проект выбирает формат своей обычной конфигурацией Quarto. Небольшой настоящий пример подтвердил совместную выдачу HTML и Revealjs из настроек документа и профиля.

Исправлен дефект, мешавший новой публикации пройти обработку PrairieLearn. Малый сквозной пример дошёл до конечного ZIP, корректных ссылок README и сохранения приватности студенческой выдачи. Это проверка маршрута, ещё не полная сборка обоих курсов.

Подготовка курса стала проще: по умолчанию выполняется одна студенческая сборка. Убраны собственные списки неизменных поставляемых файлов и запреты ручной правки сгенерированных материалов. Полезные проверки содержимого, истории Git и учебного поведения сохранены. Существующая проверка действительно запустила генератор материалов во временном проекте и подтвердила его результат.

Редактор кода уже существовал в PrairieLearn. Вместо нового режима исправлен конкретный лишний переключатель upload у однофайлового задания. Задания со свободным набором файлов сохранили загрузку. Фактический интерфейс изменённого вопроса ещё нужно увидеть в новой выдаче.

Ранее выполненная очистка учебных идентификаторов и ссылок от `j25` сохранена. UUID и файлы учебных проектов не регенерировались. Старую опубликованную выдачу этот этап пока не заменял.

## Публикация и типы

Исправление названий прошло настоящий экспорт маленькой книги: название работы и название вопроса различаются как задумано автором, служебные ID/атрибуты Pandoc и книжная нумерация в них не попадают. Авторские числа, Unicode и текст условия сохраняются.

Для этого устранён подтверждённый конфликт расширений. QRC законно переписывал HTML после Core, а Core отвергал результат по собственным SHA и признакам неизменности промежуточных файлов. Теперь потребитель читает конечный результат после обычных post hooks Quarto. Собственные SHA выходов и ресурсов и их повторные проверки удалены. Границы путей, ролей и приватности сохранены; независимая рецензия выявила три дефекта первой версии, они исправлены до успешного экспорта.

Следом устранён конкретный пробел `any` при передаче ресурсов: Core описывает фактический ресурс единой схемой, PrairieLearn использует выведенный из неё тип. Существующая проверка подтвердила выдачу ресурса и сохранение параметров и якоря ссылки. Внешний старый экспортёр и Pandoc AST всё ещё требуют типизации; весь стек пока не имеет максимального покрытия.

Завершён и следующий шаг: существующий тип пакета Core сохранён через три промежуточных слоя до записи PrairieLearn. Именно там он терялся и превращался в `any`. Новый парсер не потребовался. Два синхронизируемых кеша заменены одной записью; выбор старого варианта API убран. Независимая рецензия, затронутая компиляция и повтор маленького публичного экспорта прошли. Пять устаревших проверок совместимости и внутренней обвязки удалены, полезные проверки выдачи и учебные случаи сохранены.

Вопрос о библиотеках остаётся предметным. Часть `any` возникала в нашем коде при передаче уже типизированных данных — её удалось убрать без замены зависимости. В других местах поставляется сжатый код библиотеки без согласованного набора типов. Это ещё не означает, что сама библиотека плохо типизирована. Для YAML сначала предлагается убрать собственное восстановление происхождения настроек и отдать обычное объединение настроек Quarto; проект такого изменения подготовлен, реализации пока нет. Для оставшихся зависимостей код и настоящие типы должны поставляться вместе. Массовая замена парсеров до удаления ненужного слоя сохранила бы основную сложность. [Отдельный разбор вариантов](../../reports/discussion-20261104-typed-libraries-yaml.md).

## Performance и проверка решений студентов

Параллельный чат получил Platform, Gradle/JUnit, Gateway и Performance. Первый чат остановлен системным фильтром с сообщением о возможном cybersecurity risk. По прямому запросу пользователя создан новый, он установил исход старых исполнителей и продолжил работу; прежние отказы сохранены. К промежуточному срезу Performance уже измерил настоящий малый Quarto render напрямую и через свой CLI: 1,18 и 1,76 секунды. Обе выдачи совпали, завершение и потоки зафиксированы корректно. Разница одного запуска ещё не показывает устойчивую стоимость инструмента. Прежняя проблема остановки по сигналу этим опытом не закрыта.

Попытка включить наблюдение выявила проблему самого Performance ещё до Quarto. Сначала в новом рабочем каталоге не были подготовлены зависимости. После их штатной установки собственное копирование всего дерева зависимостей отвергло обычные ссылки пакетного менеджера Deno. Эта лишняя копия убрана: используются установленные модули, отдельно остаются изменяемые файлы запуска. Независимая рецензия прошла. Это второй подтверждённый случай, когда дополнительная обвязка противоречила нормальному поведению базового инструмента; первый был с обработкой HTML после Core.

После исправления один публичный summary успешно завершился за 2,706 с и дал тот же HTML. Инструмент увидел команду Quarto render — 0,972 с — и вложенный Pandoc — 0,212 с. Эти интервалы нельзя складывать. TS/Lua agents выполнились, но внутренних размеченных операций в малом примере нет; полное покрытие наблюдения не заявляется. Фазовые задержки полного курса пока не измерены. Затронутая проверка типов отдельно осталась незавершённой из-за отсутствующих служебных деклараций Node; фиктивными типами это не закрывали и новые установки не запускали.

В Platform подготовлены обычная компиляция Gradle и чтение стандартных результатов JUnit вместо собственной обвязки и контрольных списков файлов. Реальные случаи правильного решения, неверного ответа, исключения и ошибки компиляции проверялись. Адресная рецензия также помогла исправить потерю максимального балла класса и обработку штатных пустых контейнеров JUnit. Однако общий пакет **ещё не принят**: полная независимая рецензия прервана системным фильтром, новая контейнерная поставка не проверена. На 21:00 её запуск так и не выполнен: локально Docker недоступен, на согласованной VM не прошёл вход root с имеющимися ключами. На VM ничего не передавалось и не запускалось. Для Gateway подготовлено предложение о границах ответственности. Изменений входа пользователей или обмена оценками на сервере не было.

## Чего этот срез не обещает

Полная новая установленная выдача Java/SP и студенческий интерфейс пока не приняты. Собственные SHA удалены ещё не из всех downstream маршрутов. Отдельная Native практика и архитектурная граница Gateway остаются видимыми вопросами. Максимальное покрытие типов всего стека ещё не достигнуто.

Для выполняемых ячеек есть сохранённый малый сквозной пример с вычисленным текстом, таблицей и изображением в конечных материалах. Это не приёмка всей книги. Cache/freeze остаются штатными механизмами Quarto: собственную гарантию обнаружения любых изменённых входов не добавляем. Повторное использование кеша внутри одного профиля наблюдалось; корректность всей новой студенческой и преподавательской выдачи с общим кешем ещё не принята. Отдельные выходные каталоги сами по себе этого не доказывают.

Перенос баллов не задерживает работу над курсом. Исходные данные сохраняются; текущее приблизительное распределение по 97 работам не будет источником переноса.

## Что предлагаю обсудить вечером

Ближайшую задачу предлагаю сформулировать так: **экспорт одной лабораторной действительно ограничен её материалами, затем эта работа пройдена глазами студента** — книга, вопрос PrairieLearn, редактор или загрузка, проверка ответа и понятный результат.

Обнаружено конкретное препятствие: нынешний публичный выбор работы выбирает выдаваемую работу, но предварительный захват и render всё равно охватывают всю книгу. Это установлено по коду, без нового запуска. Поэтому обещать дешёвую проверку одной настоящей лабораторной сейчас нельзя. Следующий Source-шаг должен убрать эту глобальную связь, используя штатные возможности Quarto, с сохранением нужного банка, ссылок и приватности. Это направление поиска задержек, а не уже измеренная причина всех прежних тайм-аутов. [Точный разбор](../../reports/one-java-lab-public-route-20261104.md).

В этот же ограниченный проход стоит включить измерение этапов через Performance с явно указанным покрытием наблюдения: прежние малые запуски в режиме off ещё не показывают внутреннюю причину задержек полного курса. Затем можно принимать полную новую выдачу десяти работ. Пока студенческий маршрут не принят, локальные исправления сами по себе не означают готовность курса к выпуску.

Главный оставшийся риск к 10 ноября — соединить подготовленные части в действующий курс и обычную контейнерную проверку решений. Полная выдача и контейнер пока не приняты, а доступ для контейнерного опыта остаётся открытым вопросом. Поэтому следующий проход стоит оценивать по работающему студенческому маршруту; число удалённых тестов или `any` само по себе не будет критерием готовности. Перенос старых баллов этот маршрут не блокирует.

Для Gateway предлагается оставить вход из Moodle, переход в PrairieLearn и доставку готовой оценки обратно. Курс, попытки и файлы должен вести PrairieLearn. Сейчас Gateway также участвует в выборе вариантов, согласовании и защите работ; эти функции нельзя потерять при упрощении. На обсуждение выносится порядок: сначала обычные лабораторные, затем отдельный перенос функций защиты, либо сразу оба маршрута. Это предложение, решение ещё не принято.

После текущего удаления контроля конечных ресурсов остаются собственные снимки и хеши исходников, проектных файлов и отдельных заданий. Следующий проход по ним нужен как согласованное изменение производителя и всех потребителей. Удаление одного сравнения оставляет прежнюю обязательную обвязку в другом месте. Новых механизмов вместо Docker, Quarto или Gradle для этого не предлагается.

Для совместного решения предлагаю три конкретных пункта:

1. Следующий проход ограничить одной настоящей лабораторной: убрать глобальный capture/render в её маршруте, увидеть её глазами студента и измерить доступные этапы. Затем переходить к десяти работам; дальнейшие общие переделки не подменяют эту приёмку.
2. Определить, достаточно ли к ближайшему выпуску добровольной практики через книгу или отдельная тренировочная выдача PrairieLearn обязательна уже к 10 ноября. Второй вариант требует ещё не реализованного договора выдачи; сейчас он не готов.
3. Для Gateway выбрать владельца выбора вариантов, согласования и защиты: переносить эти функции вместе с обычными лабораторными или сохранить их действующий маршрут до отдельного этапа. Предлагаемая конечная роль Gateway — вход, переход в PrairieLearn и обмен готовой оценкой.
