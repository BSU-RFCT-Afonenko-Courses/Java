### Дополнительный вопрос пользователя о metadata Quarto

Пользователь спросил, не потребует ли отказ от собственного восстановления происхождения путей фиктивных документов в render. Прежний physical-path proposal удалял scalar markers/origins, но сохранял это acquisition/copy — полной схемой «без технических документов» он не является.

Публичный inspect документирован для реального project/document. Installed Quarto `toInputRelativePaths` перебазирует строки условно, при существовании baseDir/value; effective metadata не даёт универсального происхождения произвольного path. Поэтому нельзя просто resolve(dirname(input), value) и обещать эквивалентность всех inherited/missing/decoy cases. В рендер добавлять фиктивные документы не поручено и не предлагается. Два предметных варианта для обсуждения: реальный авторский документ проекта (если он нужен как документ) как Native context; либо отдельный явный single-file project descriptor с путями относительно его каталога, без наследования/origin resolver, оставляя Quarto обычные metadata настоящих документов. Второй вариант — новое предложение root, НЕ принятое решение и не реализация. Вопрос о границе authoring contract решить до удаления acquisition, не строить очередной synthetic probe для доказательства возможности удалить старый probe.
