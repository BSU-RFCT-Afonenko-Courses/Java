## Общие требования

- Язык материалов и описаний коммитов/PR — русский. Java 25 без preview.
- Пять проектов: theory, tasks, lectures, practice, handbook. Корневой портал связывает их QRC. Все структуры и идентификаторы выстроить заново логически; не сохранять старые ID, aliases и обратную совместимость. Существующие материалы использовать как источник содержания.
- Первый семестр: типы/операторы, управление, массивы, строки, классы, наследование/интерфейсы, generics, коллекции, функциональные интерфейсы/streams, исключения, ввод-вывод.
- 127 согласованных задач Java (124 коротких + 3 проекта) распределить ровно в 10 основных и 3 резервные лабораторные. Резерв добровольный; замены не прибавляются к нагрузке. Старые 11 × 180 минут не являются текущим бюджетом.
- Новые лабораторные: только текстовые условия, канонический банк и штатные метаданные/ссылки. Не создавать starter, graders, проектную обвязку или платформенную поставку.
- Редакция 30 рефератов первого семестра приоритетна над прежними 30; второй семестр сохранить. Старые защиты и постановки не переносить ради совместимости; новые темы формировать заново по согласованной редакции.
- Источники: пользовательские PDF EPAM и Шилдта, переданный банк, адресное веб-чтение. Сохранять авторство и обозначать адаптацию. Большие защищённые веб-тексты не копировать без разрешающей лицензии. Если веб-инструмент не читает источник — пробовать браузер.
- Справочник сверять с официальной документацией Java 25/API/JDK; собственные учебные пояснения отделять от цитат.
- Для тем System Practice — действующие внутренние заглушки с названием и ожидаемым навыком, без вымышленных внешних адресов.
- Инструменты, _extensions, CI, providers/installed-packages/UPSTREAM не менять. Конфигурацию состава учебных страниц обновлять штатно.
- Изоляция: редактировать только этот worktree; коммиты и push только собственной ветки. Новый PR поверх ветки PR №7; без merge.

## Проверка

Содержательная полнота, ясность prerequisites, однозначность условий, атрибуция и версии, разумная нагрузка, отсутствие дубликатов ID, QRC-переходы, student/full и визуальный просмотр новых слайдов. Примеры Java проверять компиляцией с --release 25 и запуском. Автоматическую проверку авторского покрытия тем не вводить.

### Task 1: Карта семестра и границы проектов

Создать theory/semester-one.qmd с предметной картой, prerequisites и новой логической системой тем и связей пяти проектов; добавить в оглавление theory и на портал. Создать theory/development/system-practice.qmd с адресными заглушками. Выбрать чистую структуру путей и ID; старые Git-страницы заменить логичными заглушками System Practice без aliases. Создать docs/semester-one-status.md с редакционной очередью и нерешёнными вопросами нагрузки. Обновить этот план только при содержательной необходимости. Проверить карту и новые QRC-цели, выполнить штатную сборку. Отдельный коммит.

### Task 2: Канонический банк и лабораторные 10+3

Перенести все 127 карточек из handoff в тематические QMD банка tasks; назначить новые смысловые sec/exr IDs; старые номера карточек использовать только при работе с исходным пакетом, не переносить как идентичность курса. Использовать штатный exercise-bank без target/project-check. Создать 13 текстовых лабораторных с выбором задач, целями, prerequisites, временем и ссылками. У каждой задачи ровно одно основное место; не дублировать условия в номерных работах. Не включать прежний пилот и legacy-демонстрации в новый учебный маршрут. Пользовательская отмена совместимости важнее прежнего плана сохранения; инструментальные пакеты остаются неизменными. Обновить tasks оглавление/индекс и карту. Проверить модель/сборку. Отдельный коммит.

### Task 3: Редакция рефератов

Создать 30 согласованных тем в логичных тематических документах с новыми смысловыми ID. Никаких aliases, таблиц совместимости и сохранения старых защит ради legacy. Семестр 2 не наполнять в этой работе; не включать его старые страницы в новый первый семестр. Новых проверяющих проектов не создавать. Число рефератов на студента и бюджет защиты оставить открытыми; обязательные положительные time значения модели обозначить рабочими оценками, не утверждённым бюджетом. Обновить индекс и связи с теорией. Сборка student/full и отдельный коммит.

### Task 4: Теория и справочник основ

Полностью проработать соответствующие разделы theory и handbook: платформа/запуск, базовый язык и управление, числа, ссылки, массивы, строки. Использовать пользовательские книги и их адресное чтение, понятные определения, разобранные примеры, типичные ошибки, вопросы самопроверки; избегать замены содержания голой библиографией. Новая логичная структура и смысловые ID без aliases. Справочник даёт API/сигнатуры/поведение Java25. Связать с банком, лабораторными, рефератами. Проверить код и собрать. Отдельный коммит.

### Task 5: Теория и справочник объектов

Классы/методы/инициализация, наследование/интерфейсы/композиция, equals/hashCode, record/sealed как ограниченное углубление, generics/стирание. Связанные понятия и предпосылки, крупные сравнения с C++ и Python, разделяя правила/интерпретации; точные первичные источники для исторических утверждений либо не делать таких утверждений.
