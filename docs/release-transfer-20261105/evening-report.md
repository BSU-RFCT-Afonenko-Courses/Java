Открытые проверки теперь описываются рядом с условием обычным текстом. Вместо второй таблицы с отдельными полями входа, действия и ожидания используется один блок для условия, README стартового комплекта и PrairieLearn. Настоящий пример из задачи о галлонах:

**Для преподавателя: действующий вход и предлагаемая очистка**

Moodle остаётся точкой входа. Общий публичный HTTPS-прокси направляет пути входа в Gateway, а обычные страницы, файлы и Workspace — в PrairieLearn. Gateway проверяет подписанный запуск, хранит состояние входа и передаёт доверенную личность приватному Bridge. PrairieLearn создаёт собственную сессию, а приватный Bridge выполняет зачисление и выдаёт штатные права. Лабораторные, ответы, попытки, оценки и Workspace обслуживает PrairieLearn; Gateway не проксирует весь учебный трафик.

Обычный студент не получает дополнительных полномочий. Instructor получает Editor курса и Student Data Editor экземпляра. Доверенный email владельца даёт Administrator даже при Moodle Learner. Email определяет права, но не объединяет личности: идентичность связана с регистрацией Moodle и её пользовательским идентификатором. Текущий вход не отзывает существующие назначения.

После импорта один завершающий настоящий вход студента из Moodle подтвердил доступ ко всем десяти лабораторным Java. Отдельная сверка базы подтвердила отсутствие дополнительных прав студента, сохранность преподавательских и административных прав владельца и неизменность аудита назначений. Это HTTP-проверка, а не подтверждение браузерного интерфейса.

В режиме login-only выключены собственный портал, задания, worker и обмен оценками. Но старый код оценивания, таблицы и grading-режим по умолчанию остаются. Это расхождение с найденным прямым требованием от 4 ноября: небольшой адаптер входа без совместимости со старыми потребителями.

Предложение очистки независимо рецензировано; реализация ещё не начиналась. Рекомендую сохранить существующий небольшой Python-адаптер входа и удалить из продукта старую учебную композицию: портал, назначения заданий, approval/capacity, AGS, очереди, worker, учёт попыток и grading-режим по умолчанию. История остаётся отдельно; совместимость с прежними потребителями не сохраняется.

Целевая граница ответственности:

| Компонент | За что отвечает |
| --- | --- |
| Moodle | Подтверждённая личность, роль, email и запуск курса |
| Gateway | Проверка LTI, прежний устойчивый UID и кратковременное состояние одного входа |
| Приватный адаптер PrairieLearn | Привязка к существующему курсу, зачисление, единственная политика прав и штатный аудит |
| PrairieLearn | Пользователи, учебные сессии, задания, ответы, оценки, файлы и Workspace |

```text
Moodle → Gateway: проверка LTI
       → PrairieLearn: собственная сессия
       → приватный адаптер PL: зачисление и права
       → штатный список работ
```

Постоянный реестр пользователей Gateway и часовую SSO-сессию предлагаю убрать. Один запуск сохраняет неизменяемые личность, роль, email, регистрацию и конкретный курс. Завершающий переход требует токен именно этого запуска и сверяет сохранённую привязку с текущей конфигурацией. Изменившийся курс требует нового входа. Сейчас курс берётся из текущей конфигурации — это ещё одна предлагаемая поправка.

В предлагаемой схеме запуск окончательно потребляется до запроса зачисления. Сбой или неизвестный результат требуют нового перехода из Moodle; старый токен не возобновляется. Уже созданный native-аккаунт, сессия или выданные права не откатываются. После успеха остаётся сессия PL: старая cookie Gateway не должна восстанавливать вход после выхода из PL. Выход из PL не означает выход из Moodle.

Для простоты предлагаю одну активную попытку входа на браузер и профиль курса. Новый запуск отменяет прежний; опоздавший callback не удаляет новую cookie. Учебных вкладок может быть несколько. Это явный технический выбор, открытый для вашей коррекции. Автоматическое понижение прежних прав не вводим без решения о политике отзыва.

Переход предлагаю выполнить короткими шагами: удалить старую композицию и согласовать один фактический приватный API; подготовить небольшой auth-store, сохранив старую БД отдельно; сверить прежние личности, права и историю; проверить три роли, браузерный переход, повтор токена, смену курса и сбой зачисления. При переключении прежние cookie Gateway прекращают работать. План отката должен возвращать прежнюю конфигурацию, сохраняя пользователей и студенческие работы; сам откат ещё предстоит проверить.

Собственный fork авторизации PL сейчас не предлагаю: штатная LTI 1.3 замена для используемого Community не подтверждена. Удаление старого административного endpoint также не должно удалить действующее назначение прав владельца, аудит или блокировку параллельного зачисления.

**Что упростили и что действительно проверено**

Структуру условия Core извлекает из готового Pandoc AST. Изображения и остальные локальные ссылочные ресурсы передаются готовыми байтами по общему правилу. Собственного парсера PNG или PDF нет. Малый пример вычислимых ячеек подтвердил таблицу, изображение, встроенное значение и штатный кеш.

Первый полный экспорт остановился на raw-узле значка штатного блока скачивания; импорта тогда не было. Исправление отделяет целый служебный блок по существующему признаку Download, не возвращая HTML-парсер и не ослабляя запрет неподдерживаемых raw-узлов. Исправление прошло малую совместную проверку, затем — полный повтор Java. Сравнимого замера ускорения курса пока нет.

В Download удалены лишний ранний режим и копии запросов; в PrairieLearn уменьшено повторное чтение готовых файлов с сохранением проверки конфликтов. В Site собственный разбор итогового HTML заменён библиотечным AST. Нативная модель Core поддерживает HTML/Reveal. Смешанная HTML/PDF-сборка с активным Core сейчас отклоняется; отдельный Presentation-фильтр имеет другую область форматов. Это ограничение отражено явно: прежний тест незаметно выбирал только первый HTML-формат.

Все три группы задач прошли предметные рецензии и адресные JDK/JUnit-проверки. Полного контейнерного прогона всех 128 задач не было. Готовый комплект подтвердил 118 открытых блоков и точное подключение частного кандидата проверяющего контейнера для 118 задач. Кандидат проверен на JUnit-отчётах, приватности и инфраструктурных отказах, но не опубликован как OCI и не принят для production grading.

CI Core, Download, расширения PrairieLearn, Platform и Gateway прошли. Последний CI Site и окончательный статус проверок курсов пока недоступны из-за сетевого сбоя: неизвестный результат не считаем ни успехом, ни отказом. Исправления тестов Site опубликованы; его рабочий пакет сохранился. Повторный экспорт ради неизменных пакетов не нужен.

Пилот System Practice собран: 7 ручных заданий и 5 работ. Именно такой состав уже задан исходниками; прежнее ожидание 3/2 относилось к маленькому прототипу. Для чистого клона потребовались три штатных каталога ссылок из других частей курса. После их обычной сборки экспорт и проверка комплекта прошли. Пилот импортирован в отдельный локальный курс с сохранением прежних ID, прав и зачислений. Один отдельный вход из Moodle подтвердил доступ прежнего студента к пяти работам SP. Это доступ через существующую native-сессию и зачисление, а не проверка отдельной SP-регистрации Gateway или исторического переноса.

Браузерная проверка Moodle остаётся непринятой: вы пропустили установку доверия тестовому сертификату из-за недоступного sudo; предупреждение не обходили. Цикл Workspace нового стенда «сохранить → остановить → продолжить» остаётся непроверенным: для него нужен аутентифицированный браузер после установки доверия CA. Отдельного обходного механизма не создавали. Старый сервер PrairieLearn остановлен, прежние права владельца на нём не подтверждены.

На 6 ноября подготовлена стратегия сопоставления прежних личностей и курсов, изолированного восстановления и отката с сохранением новых ответов. Исторические UID, принадлежность System Practice БГУ и успешное восстановление старой базы ещё требуют проверки. Production не переключался. Для вашей рецензии нужны понятность условий и ошибок, удобство трёх форм и комплектов, преподавательские действия и предложение очистки Gateway.

**Повторная архитектурная сверка**

Свежий обзор Sol/ultra подтвердил: направление соответствует запросам вторника, но объявлять архитектурную очистку завершённой нельзя. Помимо старой композиции Gateway, остались собственные механизмы квалификации, повторная работа Pandoc и нетипизированные границы. Ниже — подтверждённые места и короткие предложения, без новой системы контроля поверх проекта.

Требование убрать собственные хеши и доказательства пока выполнено не полностью. В обязательной проверке пакета Platform пересчитывает SHA файлов схем; сборка Docker дополнительно сверяет SHA исходников поверх уже закреплённого OCI-образа. Проверка Workspace также самостоятельно разбирает Git objects/index и пересчитывает их хеши. В курсах остались старые validators и поля release-proof; штатный CI их уже не вызывает. Рекомендация — удалить собственную квалификацию и её старые потребители, сохранив функциональную проверку пакета, проверку мест применения патчей и необходимые штатные операции Git. Криптография LTI и прежний алгоритм UID — отдельные действующие функции, а не доказательства свежести сборки.

В Core остаются собственные оболочки квалификации операции, происхождения и принадлежности захваченных данных. В просмотренном пути нового хеширования не найдено, но считать все механизмы доказательств удалёнными нельзя. Часть защищает реальное разделение преподавательских, студенческих и приватных входов; необходимость каждого повторного сравнения за это окно не установлена. Следует отдельно сократить дублирование, сохранив эту границу.

Явные и скрытые вызовы `quarto inspect`:

| Где | Что осталось | Оценка |
| --- | --- | --- |
| Site: корень | Один при подготовке проекта | Нужны эффективные настройки, ресурсы и выбранные входы; доступность готового контекста ещё требует сверки |

Это статическая сверка путей вызова; общий счётчик процессов не измерялся. Удалять все вызовы вслепую нельзя: эффективные профили и выбранные входы должны сохраниться. Сначала переиспользовать уже полученные данные внутри существующей операции; новый кеш или реестр не нужен.

Полный экспорт Java занял 11 минут 19 секунд. Это исходная точка, а не доказанное ускорение. В ветке с самопроверками видно три построения артефактов, каждое повторно переводит Markdown в JSON и обратно через Pandoc: статически не менее шести запусков на задачу, ещё без разбора отдельных фрагментов. Их собственное время не измерено. Предложение — повторно использовать готовый AST и результат в рамках текущей операции, после проверки необходимости каждого прохода; не вводить свой кеш или хеши.

Типизация тоже не завершена: `any` остаётся в содержимом узла Pandoc, части проверки контракта пакета и параметрах экспортера PrairieLearn. Их следует сужать на существующих границах и проверять реальные входные значения, без нового общего AST-фреймворка. Ограничение Core HTML/Reveal и QRC HTML нужно показывать автору явно, чтобы выбор формата не становился неожиданным поведением.
