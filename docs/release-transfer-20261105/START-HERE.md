## Принятые решения

- Студенческая выдача Java — только 10 лабораторных. Через них доступны все 128 задач. Сохранены 35 обязательных слотов и 41 прежний кандидат; 87 дополнительных задач добровольные, с нулевыми компонентами обязательного балла. Самостоятельный маршрут банка не создаётся. Канонические условия остаются авторскими исходниками и включаются в лабораторные.
- Видимые названия — читаемый русский текст. Технические ключи, UUID и студенческие связи сохраняются.
- Формат ответа определяется разрешённым составом: один фиксированный файл — один редактор со стартером и настоящим именем; два — два редактора; три и более на одном уровне — файлы; вложенная структура — ZIP. Свободный состав допускает файлы и ZIP. Предметная проверка Java сохранила разрешённые вспомогательные классы: фактическая выдача имеет 126 маршрутов files-or-zip и 2 обязательных ZIP. Это не подсчёт файлов стартера и не разрешение сужать условия ради редактора.
- Course-project использует компактный иерархический YAML. Загрузчик читает каждый участвующий YAML один раз за операцию. Обычный путь относится к конечному code-project; явный `{path: ..., base: config}` — к YAML объявления. Path/base заменяется атомарно. Не возвращать copyTree, synthetic QMD, per-project inspect, CST/origin markers, DTO происхождения или патч Quarto.
- Собственные SHA, snapshots, inventories, receipts и freshness fences удаляются у производителей и потребителей. Функциональные файлы, роли, targets и bytes остаются. Не заменять их mtime/inode, новым proof, registry или собственным пакетным менеджером. Штатные Git/Docker/Quarto механизмы сохраняются.
- Единица выпуска и обновления — весь курс. Малые проверки имеют явный состав исходников; отдельной архитектуры обновления лабораторных нет.
- Студент входит по существующей ссылке Moodle в PL, затем самостоятельно переключается между открытыми лабораторными. Приём закрывает преподаватель вручную. Новые заявки, очереди согласования и обсуждение порядка входа не нужны. Существующая Moodle-ссылка в этом пакете не проверялась. Окончательное упрощение Gateway до небольшого адаптера ещё не принято.

## Что подтверждено

Полный штатный экспорт Java завершился за 1183,86 секунды, с исходным Site collect и действительным составом курса. Получены 10 лабораторных, 128 задач, 128 архивов/README; проверены обязательные политики, UUID, фактические HTML controls, публичные файлы и приватность. Автоматический runtime предусмотрен у 118 задач, у 10 — ручная проверка без фиктивного runtime. Полный экспорт выполнен на Java `8e9d618`; последующая дельта `859c5f7` меняет только установленный Download и его pin и проверена отдельно.

Основной чат выполнил настоящие compile/runtime/string/toolerror сдачи через изолированный PL. На точных `b792911` / образе `8e9cd111` подтверждены публичный контекст, LF/diff, отсутствие ложного «не получено» и missing-points warning, честный infrastructure no-score и reopen. Финальная сборка с более короткими строками — другой кандидат; её UI ещё не принят.

Потребители прочитали фактические Java128/SP3 пакеты. Настоящий Gradle дал эталон 1 и стартер 0; Circle ZIP с дополнительными классами и отдельным пакетом дал 1. Workspace с настоящим seed сохранил Git index, HEAD, рабочие файлы и пояснение после реального stop/start. Эти результаты не заменяют Native student-route приёмку.

Core, основной PL/Download, SP migration, Platform/Gateway и Performance имеют независимые технические рецензии в указанных границах. Незавершённые CI-дельты публикуются отдельно и такой приёмки не имеют.

## Что осталось открытым

1. Общий CI: PL — resource fixtures и типы `source/effectiveBase`; Download — набор зависимостей/проверка временных заявок; SP student-render — отсутствующий объявленный `project-maintenance-start.zip`. Последние сохранённые журналы находятся в reports/ci-*-failed.log. Не объявлять эти проблемы исправленными по факту коммита или нового PR.
2. Финальный UI: runtime narrow и Circle wrong/reference/reopen. Synthetic Circle с двумя редакторами проверяет fixed-two control и feedback, но не заменяет реальный свободный upload Circle из полного курса.
3. Actual optional 0/0 submit/reopen. На 3306 пройден обычный student view с действующими правилами доступа: лабораторная → добровольная binary-truth-table. Попытка прикрепления ZIP прервана OOM, итогового результата сдачи нет.
4. Оба маршрута SP в живом PL, особенно Workspace save → close → resume → resubmit. Изолированный worker подготовлен; фактический контейнер существует, но UI и публикация порта ещё не приняты.
5. Финальная интеграция, проверка необходимых изменённых участков и общий handoff. Новый Performance имеет собственные типизацию/адресные тесты, но ускорение полного курса, покрытие внутренних фаз и TERM recovery не доказаны.

## Сохранность и стоимость продолжения

Сохранять все worktrees, исходные dirty, PR, UUID и студенческие данные. Ни один существующий PR не закрывать и не сливать ради уборки. Публикация WIP не разрешает автоматически продолжать реализацию.

Известные успешные неизменные R0–R6, полные матрицы, render/inspect/hash/build не повторять ради статуса. Переносимый отчёт должен использовать имеющиеся результаты; новый запуск обосновывается конкретной дельтой, отказом или ещё не проверенным свойством. Полный экспорт за 19:44 не является доказательством ускорения.

Старые абсолютные пути в отчётах относятся к текущему локальному стенду; на другом устройстве используйте исходники PR и относительные пути пакета. Артефакты в `/tmp` не являются обязательным API. Полные сгенерированные поставки, node_modules, Docker layers, реальные студенческие данные и секреты не включены в Git. Их результаты и необходимые входы/скрипты сохранены.

`reports/` содержит исторические свидетельства, включая RED и незавершённые результаты. Некоторые progress/remaining поля записаны раньше итоговых коммитов. Не использовать их как сертификат свежести. `local-checks/` — временные квалификационные скрипты, а не production launcher; не запускать их автоматически, особенно сетевой Workspace worker.

Для будущей реализации: Sol6.1 Standard, medium для простых устойчивых задач, high для сложного кода и независимой рецензии. До роли — собственный первичный допуск по `docs/model-admission.md`, с сохранением исходного интервала. Глобальные настройки не менять. Постоянный Ultra не применять. Сессии и независимые субагенты могут общаться по явному разрешению пользователя; у файла/контракта один владелец, рецензент не принимает свою работу.
