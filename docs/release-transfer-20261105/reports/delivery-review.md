## Исходные замечания и их закрытие

1. **ЗАКРЫТО в b76b827: контрактные варианты одного submission блокируют даже starter.** Platform `tools/grading_job.py:176` вызывает общую `_selection` для всех `contractFixtures`; `:124–126` запрещают одинаковый `name` глобально. В принятом договоре `name` — submission, `target` — materialized fixture. Два случая с разными `tests/fixtures/bad1.java` и `bad2.java`, заменяющими один `Answer.java`, допустимы. Они проходят inventory, но prepare_job для `starter` завершается `JobError: Duplicate or colliding selected target`, до исполнения проверок. Это затрагивает обычные авторские наборы Java: например, array-average имеет несколько разных fixtures для `Main.java`. B `application/native-check-projection.ts:171` добавляет строки на каждую пару каждого случая, поэтому повтор полностью одинаковой пары между случаями также допустим. Малая правка: отдельная валидация/нормализация fixtures по `(target,name)` с объединением идентичных повторов; проверка уникальности submission и коллизий материализации внутри выбранного case. Сохранить byte/path/count/size bounds, неоднозначные conflicting pairs отклонять. Рецензент воспроизвёл двумя синтетическими строками; автор независимо получил RED в `delivery-review-fixtures-red.log`.

2. **СНЯТО прямым ruling root: гипотеза о совпадении actual дерева с delivery.files.** Исходная рецензия предлагала отклонять невыбранные физические файлы через полное равенство наборов путей. Пользовательский договор этого не требует: files служит функциональному чтению/копированию, а не сертификатом полноты/неизменности. Роли/публичность принадлежат Core/PL; имя произвольного Python-файла не устанавливает его роль. Синтетическая подстановка unlisted файла без конкретной утечки в B writer такого нарушения не доказывает. Поэтому первоначальная Important-классификация отозвана; восстанавливать membership gate не требуется. Containment, запрет symlinks/special files и manual-no-private-tests сохраняются.

3. **ЗАКРЫТО в b76b827: не замкнут reader удалённых receipts.** Platform `tools/check-integration.py:5` импортирует удалённый `validate_receipt_integrity`; `:10` ожидает `report['receipt']`, тогда как check-course уже выдаёт функциональный summary. Любой запуск, включая `--help`, падает ImportError. Малая правка: удалить этот obsolete CLI вместе с активными ссылками либо оставить действительно нужную инспекцию результатов без receipt qualification. Автор сообщил, что активных README/workflow callers уже нет; удаление целиком допустимо. ImportError воспроизведён напрямую.
