# План полной переработки курса Java

План от 15 октября 2026 года принят пользователем вместе с подходом для студентов с опытом C++ и композицией девяти лекций. Он охватывает все пять форм. Текущее уточнение закрепляет содержательную полноту опоры при упрощении объяснения и основной рассказ о JVM и производительности в первой лекции. Этот переносимый экземпляр включает последующее задание: на новой машине начать полную редактуру по принятому плану после короткой подготовки рабочей документации и ветки. Подготовка handoff сама учебный корпус не меняет. Основа — принятый пилот `62b7c8a` и [методика подготовки курса](../../authoring-methodology.md). Теория определяет содержательное развитие; остальные формы получают собственную композицию.

## Принятые основания

Курс опирается на уже имеющийся опыт C++. Общий ввод в переменные, выражения, ветвления, циклы, функции и программирование заново не проводится. Содержательная линия проходит через инженерные задачи, опыт эксплуатации и ошибки, причины создания и развития Java, затем показывает, как выбранные решения выражены в синтаксисе и семантике. Сходная запись не считается доказательством одинакового смысла; специфические правила Java получают достаточное объяснение.

Теория — самодостаточная книга с двумя взаимодополняющими функциями. Она объясняет задачи и причины решений и позволяет самостоятельно найти точные определения, формы записи, семантику, условия и примеры без чтения исторического экскурса. Эта книжно-справочная линия остаётся в самой теории; отдельный справочник служит быстрому адресному поиску. Тема допускает самостоятельный гипертекстовый вход: необходимые предметные сведения появляются на месте, ссылки помогают восстановить предпосылки. Примеры развиваются внутри темы, иногда главы. Единого приложения, общего шаблона глав, обязательных двух рубрик или двухколоночной схемы C++/Java и отдельной карты тем не требуется.

Сохраняется содержательное достижение пилота: понятны задача, выбранное средство, причина результата и его существенные условия. Началом темы может быть уже знакомая инженерная задача C++, требование или наблюдение; обязательного сюжета «наблюдение — затруднение — новое средство» нет. Подробность получает место по функции: механизм, полезное следствие, справочный ответ либо углубление. Принятый пилот `62b7c8a` повторно не переписывается ради шаблона; при полной редакции проверяются его новые входы и связи.

Упрощение объяснения с опорой на C++ сохраняет существенные понятия, механизмы, причины и ограничения текущей содержательной опоры. Сжатая таблица плана не исчерпывает материал. Содержание продуманно распределяется между основным рассказом, углублением, книгой и справочником; знакомый опыт аудитории позволяет яснее объяснить его. Прежняя форма, дубли, служебные комментарии и ошибки не подлежат обязательному сохранению; общего преимущества старой редакции и миграционных таблиц это правило не вводит.

Сравнение ведётся по конкретному механизму и на глубину, полезную для понимания задачи. Документированные мотивы разработчиков подтверждаются первичными источниками и отличаются от педагогического объяснения выбора. Первоначальный дизайн Java не смешивается с поздними generics, лямбдами и records; современный C++ не выдаётся за язык начала 1990-х. Рассматриваются приобретения, издержки и границы решений, без представления Java всеобщим исправлением C++. История каждого оператора и формальная сравнительная рубрика не требуются. Названия точно обозначают предмет; механический запрет союзов или противопоставлений не вводится.

Лекция выстраивает устный ход, справочник отвечает на адресный запрос. Введение к лабораторной восстанавливает решение знакомых теоретических задач; варианты и трассы появляются по необходимости. Самостоятельные задания требуют переноса понимания, оставляя архитектуру студенту. Проверки исходят из учебной цели: обязательные API допустимы по предметной необходимости, предпосылка не превращается автоматически в обязанность проверять вход.

Java 25 остаётся средой проверки без preview. Версионные условия сохраняются рядом с зависимыми от них утверждениями. Аннотации и `null` объясняются последовательно; смысл анализатора входит в теорию, настройка — в справочник. Рефлексия остаётся дополнительным материалом. Путь от исходника к приложению основной; подробности сборки и зависимостей относятся к углублению.

Первая лекция сохраняет существенное содержание текущих [лекции о выполнении](../../../lectures/platform-runtime.qmd), [главы о платформе](../../../theory/chapters/platform.qmd) и [главы о языках](../../../theory/chapters/languages.qmd): различение синтаксиса, семантики и реализации, состав платформы, управляемое выполнение, причины разделения представлений и границы переносимости. Сопоставление с нативной цепочкой C++ объясняет функции `javac`, классов и JVM. Один осмысленный пример может связать исходник и фактический байткод с фреймом, локальными переменными, операндным стеком и объектом в heap. Это модель JVM, без обещания конкретного физического размещения данных. Загрузка получает определение; связывание включает проверку и подготовку, а разрешение символических ссылок связывает определения. Пакет, classpath, зависимости и версия формата остаются понятными условиями запуска; подробные команды доступны в книге и справочнике.

В основной линии на примере HotSpot объясняются интерпретация, JIT и роль сведений о выполнении при выборе и оптимизации кода. Загрузка, сбор профиля и компиляция помогают различить запуск, прогрев и последующую работу; на результат влияют также оптимизации, сборка мусора и характер нагрузки. JIT — стратегия реализации, а не требование JVM. Утверждения «Java всегда медленная, потому что её интерпретируют» и «JIT гарантированно быстрее C++» разбираются через показанный механизм и границы наблюдения: результат зависит от программы, входа, реализации и условий, а отдельный запуск не характеризует язык в целом. Принцип исполнения остаётся основным; подробности профилирования и методика бенчмаркинга относятся к углублению.

Прежняя обязательная лекция «Основы языка» расформировывается. Числовая семантика в первой лекции поясняет гарантии переносимого поведения, сохраняя место для причин и устройства исполнения; массивы и строки во второй служат раскрытию ссылочной модели, а собственный класс в третьей развивает задачу сохранения состояния. Ветвления, циклы и формы методов используются на знакомых задачах. Их точные определения, формы записи, семантика и примеры остаются доступными в самой теории и в адресных статьях независимо от отбора в устный рассказ. Две нынешние презентации `values-absence` и `control-methods-data` служат материалом для нового отбора, а не частями для обязательного склеивания.

В углубление по смыслу переходят подробности загрузки и связывания, устройство и настройки JIT, методы профилирования и измерений, устройство областей памяти и настройка GC. Базовая модель JVM и причины такого исполнения остаются основными. Для последующих тем углубление включает числовые пограничные случаи, глубокое копирование и Unicode, сложную инициализацию, подробности закрытых семейств типов, специальные коллекции, сложные конвейеры и подавленные исключения. Подробная сборка, зависимости и рефлексия остаются дополнительными. Смысл анализатора `null` входит в основное объяснение, его настройка — в справочник; используемая аннотация получает достаточное пояснение при первом появлении. Эти границы проверяются по связности каждой лекции, без квот на отдельные темы.

Основная линия каждой лекции ориентируется на 80 минут; дополнения располагаются ниже законченного рассказа в той же презентации. В учебных материалах и notes отсутствуют тайминги, расчёты нагрузки и квоты. Существенные вопросы, причины выбора и результаты видны при закрытых notes.

Исторические опоры различаются по периоду: *The Java Language Environment* (1996), [глава 1](https://www.oracle.com/java/technologies/introduction-to-java.html) и [глава 4](https://www.oracle.com/java/technologies/architecture-neutral-portable-robust.html), раскрывает первоначальные цели и связь переносимости с моделью выполнения; [JSR 14](https://jcp.org/en/jsr/detail?id=14) — требования к позднему расширению типизации обобщённых библиотек; [JEP 126](https://openjdk.org/jeps/126) — цели лямбд и развития библиотек Java 8. Эти прочитанные первичные документы поддерживают соответствующие мотивы, но не заменяют актуальные спецификации семантики и не доказывают универсального превосходства решений. Сравнение обычного класса с `record` в таблице пока задаёт педагогический ход, без отдельного утверждения об историческом намерении его авторов. Устройство JVM сверяется по [JVMS 25, главе 2](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-2.html), пример профилирования и JIT — по [документации HotSpot](https://docs.oracle.com/en/java/javase/25/vm/java-hotspot-virtual-machine-performance-enhancements.html), ограничения инструментальной проверки производительности — по [OpenJDK JMH](https://github.com/openjdk/jmh). Эти источники объясняют механизмы и условия, без универсального ранжирования языков по скорости.

## 3. Перерабатывать тематическими этапами

В каждом этапе сначала доводить законченное теоретическое объяснение, затем согласовывать остальные формы. Единица авторского задания должна допускать независимое содержательное чтение.

1. **Выполнение, значения и ссылки.** Начать со знакомых по C++ задач запуска программы и обработки данных. Объяснить, зачем Java разделяет исходник, классы и исполнение, как работает JVM и чем модель отличается от знакомой нативной цепочки C++. Связать на понятном примере байткод с фреймом, операндным стеком и heap; раскрыть роли загрузки и связывания, интерпретации, JIT и профиля выполнения. Базовый разбор мифов о производительности сохраняется в основном рассказе, числовые правила поясняют гарантии вычислений. Затем развить различия значений и ссылок на примерах массивов и строк: присваивание, передача аргументов, разделяемое состояние и отсутствие значения. Управляющие конструкции и формы методов использовать по потребности задачи; их точные правила и примеры обеспечить в книжной линии теории и адресных справках. Подготовить первые две лекции. Работы с числами, массивами и строками отобрать по тому, что они учат понимать и применять именно в Java; знакомый алгоритм может освободить внимание для новой семантики. Дополнительные алгоритмы отбирать отдельно. Поздние средства моделирования данных вводить в собственном контексте. Согласовать две лекции, работы по классам и полиморфизму, дополнительные модели. Завершение: студент понимает семантику выбранных средств, их ограничения и самостоятельно определяет устройство своей программы.

До рендера рецензировать законченные объяснения, последовательности экранов, статьи и задания вместе с подготовкой. Проверять точность, причинные переходы, гипертекстовый вход, видимый рассказ и новые обязанности студента. Особые критерии принятого подхода:

- Знакомый опыт C++ помогает понять инженерную задачу; общий ввод в программирование не повторяется, а специфические синтаксис и семантика Java объясняются достаточно.
- Из самой теории можно получить точное определение, форму записи, условия, семантику и пример без предварительного чтения исторического экскурса; отдельный справочник ускоряет адресный поиск.
- Сравнивается конкретный механизм, обозначены границы аналогии и издержки. Исторический и современный C++ не смешиваются, первоначальный дизайн Java отличён от поздних возможностей, заявленные мотивы разработчиков подтверждены источниками.
- Сопоставление с содержательной опорой выявляет потери существенных понятий, механизмов, причин и ограничений. Проверяется их осмысленное размещение в основном рассказе, углублении, книге и справочнике; сжатая таблица и знание C++ не служат основанием для исключения нужного содержания.
- Первая лекция в основной линии объясняет причины разделения этапов, достаточную модель JVM, интерпретацию, JIT, роль профиля и границы выводов о производительности. Различаются абстрактная машина, выбранная реализация и результат конкретного наблюдения; подробности реализации не вытесняют ясное объяснение.
- Причинная связность достигается содержанием; нет искусственной необходимости придумывать затруднение, парный пример или историческую рубрику для каждого понятия.
- Пять форм решают собственные задачи: теория полна, лекция отбирает устный рассказ, справочник даёт точный ответ, введение восстанавливает знакомое решение, самостоятельная задача оставляет работу студенту. Принятый пилот сохраняется без повторной переписки ради шаблона.

Исторические утверждения проверять по фактически прочитанным первичным источникам, языковые правила — по соответствующим спецификациям и документации; педагогическая интерпретация должна быть обозначена своим статусом.
