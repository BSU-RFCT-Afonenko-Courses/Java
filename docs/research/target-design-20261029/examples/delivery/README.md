# Состав и обычная Gradle-сборка

[Общий build](profiles/java-junit/build.gradle) и [settings](profiles/java-junit/settings.gradle) — настоящие текстовые Gradle-файлы с обычными source roots/Jupiter. BOM задаёт версию JUnit один раз. Версии — кандидат новой системы по официальной документации 29.10.2026; установленные файлы курса не менялись. [Общая инструкция](profiles/java-junit/README.md) показывает отдельный канон пояснений рядом с профилем. Эти файлы не запускались.

[Author settings](author-full/settings.gradle) — самостоятельный пример разделения starter/reference по Gradle subprojects. Каталоги `contexts/*` намеренно не выданы за материализованный полный проект: настоящие selected full sources отсутствуют в прежнем исследовательском комплекте. Несколько `Main` не должны попадать в один source root. Альтернативы включаются только по явным объявлениям, не через scan всех папок.

[Inventory](reverse-array-inventory.json) вычислен по существующим байтам. Он отдельно перечисляет наблюдённые файлы прежнего комплекта и предлагаемые роли/targets нового дизайна. Поля этого JSON — исследовательская запись, не утверждённая схема. `PublicChecks`/старый demo wrapper показаны как переходный факт; они не выбраны новым универсальным runner. Два demo не объявляются полным оценочным набором. Исторический reference не объявляется принятым финальным эталоном.

Достаточная однофайловая сдача `Main.java` задаётся явно и независимо от `src/main/java/Main.java` в IDE. ZIP для Pages/PL содержит одно и то же каноническое student-содержимое, а не преподавательские решения. Настоящая новая материализация, README с разрешёнными native include/assets, PL execution и Workspace требуют реализации и приёмки.
