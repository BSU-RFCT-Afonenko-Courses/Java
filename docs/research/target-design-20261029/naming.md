## 3 Принятое общее правило

Общее правило принято вместе с A в решении 56; примеры имён иллюстрируют его, не закрепляют все точные имена/API:

- Опубликованная цель получает native-префикс по своему виду и содержательный суффикс. `#fig-…` — рисунок, `#tbl-…` — таблица, `#sec-…` — раздел; не любая роль автоматически становится новой глобальной целью. Составные смысловые имена сохраняются; видимые заголовки остаются русскими.
- Упражнение определяется один раз. Его повторное появление, назначение в работу и позиция fixed/choice — разные структурные связи. UUID, состав работы и идентичность слота не выводятся разрезанием строки ID. Нужная разовая карта и предусмотренный необязательный UUID сохраняют отдельный договор.
- Вложенное решение принадлежит упражнению по структуре/явной связи. Если на решение нужна отдельная опубликованная ссылка, у него может быть `sol-…`; это не обязательная автоматическая замена `exr-` на `sol-`. `course-role` — свойство роли, не новое пространство имён и не требование ID каждому Div.
- `refs`, `title-slide` и технические контейнеры рассматриваются по native-назначению. Им не навязывается глобальное курсовое имя; локальный ID не становится автоматически экспортируемой QRC-целью. Повторение локального `refs` на разных страницах не равно дублированию опубликованной цели в одном каталоге.
- Сайтоподобные каталоги и канон на странице темы сохраняются. Имена учебных QMD/каталогов должны быть содержательными, без номера выпуска; внутренний раздел не требует отдельного файла. Имя Java-файла следует Java-контракту (`Main.java`, `Book.java`), а `_metadata.yml`, `build.gradle`, `README.md` сохраняют назначение. Правило для QMD нельзя механически применять к этим именам.
- Отсутствующая цель, дубликаты опубликованных ID и несовместимая конфигурация остаются ошибками. Несовпадение согласованного именования project/ID — WARNING по 55, без исправления, переезда или вымышленного project.

Конкретные примеры имён иллюстративны; направление A и общее правило приняты, B/C сохранены как история сравнения. Не требуется кодировать весь путь в имени каждой секции/иллюстрации. Условный `object-models/book-selection` в A даёт `exr-object-models-book-selection`, в B — `exr-object-models--book-selection`, в C — `exr-book-selection`. Это пример составной темы, не предложение массово переименовать нынешний `objects`.

В A канонический QMD темы — `tasks/bank/arrays.qmd`, проект — `tasks/projects/arrays/reverse-array/`; происхождение включённого фрагмента не подменяет каноническую тему. В B явная граница сегментов не означает, что из ID вычисляются вложенность заголовков, принадлежность solution или назначение в работу. В C старое правило `exr-<theme>-<semantic-name>` действительно меняется: это отдельный авторский выбор, не косметическое сокращение.

Иллюстративный WARNING варианта A для **искусственного** несовпадения в строке реальной задачи; это не обнаруженный дефект и не утверждённый код диагностики:

```text
WARNING · tasks/bank/arrays.qmd:62 · exr-arrays-reverse-array
project фактически: /projects/arrays/forward-array
ID, ожидаемый от объявленного project: exr-arrays-forward-array
Имена находятся в виртуальной базе /projects/; физический корень: tasks/projects/.
Автоматическое исправление не выполнено.
```

Нынешний `/projects/arrays/reverse-array` согласован с ID в A. После выбора B при том же project ожидался бы `exr-arrays--reverse-array`; сейчас такого нарушения нет. Для C пример несовпадения `exr-reverse-list` против ожидаемого `exr-reverse-array` допустим лишь после согласования ограничения на связь имени и конечного каталога; без него оснований для WARNING нет. Если project отсутствует, ни один вариант не создаёт путь из ID. Известный источник/строка, фактическое/ожидаемое значения выводятся достоверно, унаследованному значению не приписывается строка упражнения.

## 5 Принятый выбор и оставшиеся границы

**Выбран A** прямой репликой пользователя «Выбираем А, продолжить прежнее правило». Проверка идёт из уже известного эффективного project к ожидаемому ID; составные тема/задача сохраняются, обратный разбор не нужен. Нынешний reverse-array согласован. B/C больше не являются открытым выбором этого обсуждения.

Сохраняются native Quarto, структура A, TS-канон и разовая сохранность студенческих данных. Точные имена полей, warning-код/подавление, нормализация Unicode/регистра, перечень экспортируемых целей и локализация происхождения остаются технической проработкой выбранного договора. Иллюстративный WARNING выше сохраняется как пример сообщения, не работающая диагностика; прочие архитектурные предложения не становятся принятыми вместе с именованием.

Проверка этого прохода — чтение правил, Git-истории, исходников и официальных документов. Новых сборок, переименований, изменений курса, CI и runtime не было.
