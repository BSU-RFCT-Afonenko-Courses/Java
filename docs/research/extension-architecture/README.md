# Исследование авторской модели и архитектуры курса

Этот пакет передаёт исследование из обсуждения в отдельную сессию Codex
на другом ПК. Сначала нужно завершить чат **«Выполни план публикации банков»**,
прочитать его итог и сохранить созданные там материалы. Успех экспорта не
является условием старта: неудачи и ограничения нужны как свидетельства.

## Начало работы

Используйте [стартовое поручение](start-prompt.md). Оно разрешает выполнить
исследование, начиная с T00; продуктовый рефакторинг и публикация курса в него
не входят. ОС и окружение, по сообщению пользователя, идентичны. Не нужно
заново готовить всё окружение без причины; фактическое состояние и доступность
необходимых инструментов всё равно фиксируются при запуске.

**PR содержит только документы. Его base `master` не является выбранной базой
курса для исследования.** Получите пакет отдельно, сохранив ветку и worktrees
с итогом предыдущей сессии. Актуальный Java, owner PR, локальный Performance,
teacher root, toolchain и evidence выбираются в T00 уже на том ПК.

## Документы и порядок работы

1. [Постановка и границы](design.md).
2. [Предварительный статический аудит Java](java-authoring-audit.md):
   наблюдения, конкретные расхождения и ограничения, которые нужно перепроверить.
3. [Новые свидетельства выпуска](publication-evidence-2026-10-27.md):
   просмотренная история новых PR/releases/CI, отказы и границы выводов.
4. [Гипотезы](hypotheses.md): **88 пунктов** — A01–A12 по авторской модели,
   H01–H60 по архитектуре и B01–B16 по выпуску и восстановлению.
5. [Методика](methodology.md): полнота кода, малый Java, native reference и perf.
6. [План и роли](plan.md): задачи, усилия, зависимости, результаты и приёмка.
7. [Передача контекста](handoff.md).

Порядок исполнения: **T00 → авторская модель всех подпроектов → ранний отчёт →
углублённый аудит контрактов, реализации и R02–R04 → адресные измерения → варианты
рефакторинга и независимое ревью**. Исследуются обе скорости работы; приоритет
у одиночной страницы. Фиксированного SLA нет. Десять минут не являются PASS.
R01 восстанавливает хронологию уже во время T00 и дополняет ранний отчёт;
новые роли выполняются волнами, без увеличения лимита четырёх агентов.

## Что получить

Понятные источники истины и типовые действия автора; оценку лишних конфигураций
и копий; схему полного IDE-проекта; цепочку эталон/экспорт/qualification/Docker/
баллы; обоснование функций и вызовов расширений; сравнимые измерения и варианты
упрощения с сохранением высокоуровневых свойств. Наличие guards или теста
само по себе не делает механизм обязательным; быстрое выполнение не оправдывает
утрату privacy, native поведения или функции курса.

Обновление 27 октября добавляет независимые release-линии и состав assembly,
ранние проверки optional-primary/ZIP/API и ID, сроки жизни модели и common
inputs, стоимость повторных попыток, strict/deferred admission и закрытие долга
qualification. Успех source release, render, экспорта, допуска и импорта
фиксируется отдельно. Новая существующая perf-матрица используется до новых
опытов; наличие замеров ещё не объясняет причину замедления.

## Проверка и ограничения пакета

При подготовке выполнены статическое чтение кода и GitHub evidence, независимое ревью документов
и проверка структуры/ссылок. Новые renders, tests, benchmarks, Docker jobs и
PrairieLearn export не выполнялись. Исторические утверждения аудита не являются
новым PASS. Будущие inputs не закреплены, teacher root не найден на компьютере
подготовки. Исследование должно восстановить его по итогу предыдущей сессии,
сохраняя закрытые данные вне публичных документов.

Большие логи и profiles хранятся отдельно; в документы попадают небольшие
индексы и выводы. Результаты закрытых проверок публикуются только в разрешённом
объёме. Исследование завершается предложением, без автоматической миграции,
release, серверного импорта, merge или удаления веток.
