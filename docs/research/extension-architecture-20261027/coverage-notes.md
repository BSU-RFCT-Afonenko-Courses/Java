# Полнота учёта и пределы обоснования

В выбранных parsed исходниках учтены 7538 функций и 65 301 callsite в 17 разделах владельцев. Проверены уникальность записей, принадлежность caller, исходные диапазоны и неизменность исходников. Для каждой учтённой функции есть подробная операция либо точное source dossier с локальным назначением и ограничениями.

Это не доказательство независимой необходимости каждого механизма. Назначение функции, минимальность набора тестов, частота проверки, полные межпроцедурные эффекты и фактическое runtime выполнение — разные вопросы.

## Что проверено

- Механическая полнота внутри заявленных parsed files; ошибок разбора и дубликатов ID не найдено.
- Дополнительные досье 6167 функций сверены с исходными диапазонами; остальные 1371 связаны с первоначальным подробным разбором Core/Presentation/Navigation.
- 9721 прямой TS/JS вызов связан с конкретной статической декларацией. У 55 580 callsites такого доказанного static callee ID нет; runtime dispatch этим проходом не наблюдался.
- Все 30 положительных и отрицательных примеров исследовательского анализатора прошли. Найденный пропуск `delete` исправлен; реальные выбранные bindings от исправления не изменились.
- Ссылка на досье не повышала semantic necessity или runtime status автоматически.

У 5318 функций независимая необходимость остаётся неизвестной. Для части понятна конкретная тестовая роль, но не доказаны самостоятельная ценность каждого регрессионного случая и частота его запуска. Неизвестность не означает ненужность.

## Почему автоматического описания недостаточно

Review обнаружило два показательных ограничения. Predicate уникальности IDs получил слишком широкое описание всей delivery family. У `_api_precheck` автоматически составленная стоимость перечисляла локальные файловые действия, пропустив compiler и Java процессы через helper. Конкретные объяснения исправлены; общий вывод — direct-syntax описание не доказывает отсутствие косвенных эффектов и не измеряет их цену.

76 групп совпадающих реализаций Core тестов не объявлены лишними: одинаковый текст может иметь разные fixture, замыкание и ожидаемый результат. Наличие теста также не доказывает минимальность всего набора.

## Границы области

Включены расширения Core, Presentation, Navigation, Performance, Publisher, QRC, Download, PrairieLearn, Print, Moodle, Cloud, выбранные grading/delivery/assembly части Platform и интеграция Java/Template/Cybersecurity. Совпадающие vendor копии связаны с владельцами; отличающийся исторический Template variant рассмотрен отдельно.

Учебные Java/C/CUE/Gradle программы, Markdown fences, непрозрачные assets, полный сервер и отсутствующая часть Cybersecurity не выдаются за полностью разобранные функции перечисленных языков. Поэтому полная приёмка всего исходного плана не объявляется.

Текстовые выводы и предложения можно использовать дальше; удаление guard, изменение lifetime либо утверждение ускорения требуют отдельного различающего случая. Механический inventory, подробные досье и проверочные сводки сохранены локально и в этот PR не включены.
