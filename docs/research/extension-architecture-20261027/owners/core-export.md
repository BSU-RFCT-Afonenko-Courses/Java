## Selected export: что действительно выбирается

`body-export/collect.ts:21–134` сначала inspect логического root (course.id), затем самостоятельного выбранного book с full+functional profiles. Создаётся nonce native profile: default project, JSON writer, only Core hooks, all-QMD inventory. Ownership проверяется по physical root один раз на input directory; nested owner исключается. После native inventory в render передаётся explicit выбранный bank input set. Это **весь native scope банка**, включая control QMD вне published chapters. Нативный JSON render/execute/include/filter/writer выполняется до выбора work.

Затем проверяются bank duplicate IDs; selected work и все её candidates остаются в result. Body capability guards, citation processing и resource packaging выполняются только для выбранных. Поэтому H19 подтверждена как поведение — один work вызывает JSON всего bank native scope. Это не доказательство возможности просто убрать неназначенные inputs: текущий contract требует bank duplicate detection, функциональные профили/includes/compute могут задавать состав, `inspect.fileInformation` не содержит всех exercise AST IDs. Альтернативе нужен owner-owned discovery результат с invalidation; дополнительный предварительный render может увеличить latency. Количество опубликованных chapters не равно bank input cardinality.

`buildBodies` сам render не запускает и принимает explicit DocumentResult/ReleaseResult. Caller отвечает за успешное завершение native command. Это public data API, не serialized pointer capability: в Body producer нет обязанности каждый раз загружать private NativeRun. Website full `body.publicExercises` может не иметь restricted условия; такой direct call правильно даёт BODY.PUBLIC_FACTS_REQUIRED. Source export имеет отдельную public identity projection и JSON context; её нельзя переносить в HTML или считать ослаблением student policy.

Native writer разрешает shortcodes после pre-ast capture: collect читает уже готовый JSON, индексирует full/public exercise nodes и actual public solutions. Public introduction берётся только из service projection, без full fallback. `buildBodies` отделяет keys/solutions/notes/Download links до public reference/resource проходов, выносит title/difficulty/time, сохраняет local fragment targets и supported Table Attr. Citeproc применяется к публичному condition+publicAnswer одного вопроса; citation-only witness и formatted pass дают до двух subprocess на содержащий citations question/introduction. Citeproc чужого/private блока и nocite не добавляются. Ресурсы читаются/хешируются/base64 упаковываются только выбранные public uses; closed schema и public omission являются разными проверками.

## Overlay activation и породившая её сложность

`collect.ts:62–106`: overlay нужен только если native bank config имеет больше одного pre-render либо post-render hook. Иначе используется generated profile и named retirement v2. Даже в этом route временный profile создаётся в source tree, но base config не меняется. В multi-hook route `startOwnedConfigOverlay` начинает lease, снимает source/vendor closure, хранит source/selection native preimages, получает native-computed execution config, заменяет authored `_quarto.yml`/yaml удержанным inode transaction и запускает singleton hook context. После успеха source inode возвращается, profile/lease quarantined, restoration record связывает old/new identity. Base bytes и mtime сохраняются; ctime может закономерно измениться и переводится из native representation.

Это не только «ещё один YAML файл». Подмена base config породила Linux x86_64 libc FFI (`openat/statx/pread/renameat2/fsync`), no-replace probe, same-owner checks, config+source quarantine, SOURCE/execution/restored roles, Deno/libc/helper/executable identities, full recursive source/vendor closure и recovery protocols. Эти safeguards нужны **при выбранной source-mutating реализации** для IN05–IN07; high-level RQ19 не предписывает сам overlay. H13 — зависимость механизма подтверждена; величина runtime доли не измерена.

Ограничения support фактически узкие: overlay требует Linux x86_64, единственную canonical libc, absence nonempty LD_* loader vars, same owner regular config, no unconditional `.local`, ровно один доказанный julia-engine contribution suffix. `deriveExecutionConfig` убирает только этот verified automatic suffix и book.render, сохраняет authored prefix. Native engine/plugins/compute существенны для outcome; общий source snapshot не означает независимость от них.

Успешный путь сам реставрирует source; abort лишь `t.recoverSource()` плюс close. При неудаче до activate/после prepare может сохраниться созданный lease/profile, orphan lease блокирует повтор; нельзя автоматически удалять чужие данные. 8.3 recovery короче отдельной 8.2.8 линии. Это сохраняющий данные отказ, но стоимость/понятность следующего recovery ещё не подтверждена опытом. Заявление комментария collect «permanent project config stay intact» верно для конечных bytes успешного пути, но не описывает временную inode mutation multi-hook route.

## JSON writer: selected 8.3 против истории

8.3 `owned-config-source.ts:179–191 nativeJsonOutputSlots` выводит temporary/final output recipe из **inspection** `frames[source].formats.json.pandoc['output-file']`, требует json format, scalar basename, regular unaliased source. Capture позднее проверяется `assertNativeJsonDocument` и actual `DocumentResult` relation; `finalNativeJson` проверяет relocated bytes. Следовательно, нельзя утверждать, что actual writer отсутствует вообще: actual event проверяется поздно, но ранний slot admission всё ещё зависит от формата inspection. Local `format: html` при forced `--to json` может не иметь formats.json в inspection.

Сравнение исходников устанавливает: поздний fix actual writer intents/context-v2 присутствует в линии 8.2.8 и отсутствует в ancestry выбранной 8.3. Это подтверждённое расхождение реализации, а не новый выполненный repro. В выбранной 8.3 **нет** actual-writer-intents prefix admission loop поздней линии. Поэтому H14 о повторной проверке накопленного intents-префикса для этого baseline неприменима в исходной формулировке. Перенос квадратичной формулы из 8.2.8 сюда был бы ошибкой. Остались nativeJsonSnapshot(slot set)/captured adapter scans и повторные full boundaries; их учитывать отдельно.

Raw batch код 8.3 уже `await Promise.all` map values и JSON stdin. Исторический commit 615987 не предок — это не факт текущего Promise-дефекта. withNativeArtifactBatch есть, pending/reentrant/expiry handling в выбранной resolve.ts проверяется отдельно; deferred unawaited promise на batch exit отвергается, а не превращается в ready batch.

## Currentness intervals, digest и FD

Full `withNativeOperation` держит one pointer identity, immutable exact inspection snapshot, raw phase и A/use/B; `op.check` локальный, expensive complete output admission memoized in phase (`validateCompletedExportScope`), свежий финальный check перед publish остаётся. `withNativeRunProof` reuse active batch; materialization publication отложена до B и original-union recheck. Не каждый nested helper делает новый full scan.

H15 имеет смешанный итог. Whole binding reserialization на каждом inspection accessor уже исключена freeze/admitBinding; append-only writer не перечитывает растущий store prefix. Но stable(p), refset sorting, source `.find`, selected row binding с initialInputFiles[n] и global metadata/common declaration повторяются d раз. `readSelectedCommonPath` фильтрует весь refs list каждый doc. Finish duplicate `.some` и selected canonical document representations создают O(d²)/O(n*d) lookup/encoding work без квадратичного числа subprocess. Считать функции hash, сериализованные bytes и вызовы external command отдельно.

H16 в форме «два полных постоянных source snapshots удерживают FD банка» опровергнута: sourceFiles/dependencies — JSON states/hashes, inspection snapshot — parsed objects/bytes, не открытые handles. Однако `nativeJsonSnapshot` удерживает все **присутствующие** temporary slot views до завершения проверки и, при уже существующем relocated final, ещё final view. Каждый `openNativeJsonOutput` держит root + ancestor directories + leaf FD и dlopen до close; число одновременно открытых FD:

`C + Σ_present-temp (depth(temp)+2) + Σ_temp-with-final (depth(final-relative)+2)`.

C — held config/source transaction/read views и libc/runtime; отсутствующие slots FD не держат. Память содержит соответствующие full JSON bytes, плюс source context/exact parsed inspection S. FinalNativeJson открывает final outputs последовательно, добавляя один текущий view. Две полные output snapshots одновременно здесь не установлены. Пик на ошибочном/промежуточном prefix с temp+final возможен; actual normal relocation timing и OS limit не измерены. Только отдельный small n=1/3 probe оправдан.

H18: `materializeProjects` и `resolveArtifact` окружают весь plan/read/commit в proof callback. `withNativeArtifactBatch` даёт многим запросам один lifetime. Прямой exported `materializeStarterArtifact` самостоятельно outer wrapper не открывает: planProjects вызывает assertCommonPathRun, но этот standalone proof завершается **до** последующего чтения student/common files. Внутри resolveArtifact это защищает outer proof, при direct helper это другая гарантия. Нужен explicit contract scope либо small direct-vs-bound mutation test; объявлять функции эквивалентными нельзя.

## Варианты без mutation base config, ещё не проектные изменения

1. **Существующий generated native profile для пригодного project.** Уже работает в singleton-hook route; сохраняет in-place include/resource/native project context и cache/freeze. Для multi-hook source profile merge не доказан replacement: stock Quarto1.11.5 `mergeProjectMetadata/mergeProfiles` конкатенирует arrays; Core поэтому выбрал overlay. Нельзя обещать, что metadata-file автоматически заменит project hooks. Вариант требует небольшого native profile precedence/null/scalar experiment; source YAML не переписывать.
2. **Disposable отдельный project root с обычной native config.** Источники копируются/материализуются с точным declared set, vendor pinned, выполняется штатный Quarto, результат возвращается как artifact. Сохраняет authored source/recovery и убирает source inode transaction; требует доказать relative paths, include rebasing, project ownership, namespace/crossrefs, computations, resources, currentness во время copy и cache/freeze. Это изоляция одного export, не новое универсальное build/cache/DAG.
3. **Согласованная авторская hook/profile модель с узким capture hook.** Native render authoring остаётся отдельным; selected export получает только необходимые owner-owned hooks. Требует явной compatibility semantics и проверки текущих callbacks/extra hooks; простое игнорирование author hook нарушает RQ11. Менять нынешний продукт этим исследованием не разрешено.

Сохранённые invariants для всех вариантов: exact chosen bank/functional profile and raw identities; duplicate IDs/slots; public/teacher separation; native writer/shortcode/crossref/citation semantics; selected resource provenance; current source bytes до commit; safe recovery чужих правок. Cost сравнивать latency author-cycle и total work отдельно, без переноса full export требований на plain HTML.
