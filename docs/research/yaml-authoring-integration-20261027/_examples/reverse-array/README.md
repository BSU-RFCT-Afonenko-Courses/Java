# Reverse-array: два варианта авторской записи и выдачи

Исследовательский пример от 28 октября 2026 года: реальные файлы собраны для просмотра и сравнения, рабочий курс не изменён.
Ключи YAML ниже — **предложение**, не поддержанный API установленного Core. Состав выписан и материализован как снимок; native metadata-мост и новый producer этим не реализованы.

**Это пример структуры.** Условие в baseline и целевом QMD-view — неизменённый старый снимок; его финальная проза не принята и требует только что запрошенной редакторской оценки, включая формулировки JDK/API, свободы организации и требований «представьте/покажите/объясните». Само условие здесь не редактируется.

## Что открыть

1. [Нынешний снимок QMD](canon/bank/arrays.qmd) — точное условие с прежними атрибутами, сохранённое для сравнения и происхождения.
2. [Предлагаемый общий QMD-view](views/target/bank/arrays.qmd) — короткий Div, Header первым, служебный YAML после него; маркер/поля предложены, parser не исполнен. Тот же текст подключён из [производного снимка](derived/statement-body.md), не из второго авторского канона; inline равно допустим.
3. [Вариант A: наборы рядом с проектом](canon/projects/arrays/reverse-array/_metadata.yml) или [вариант B: локальные именованные компоненты](alternatives/B/_metadata.yml).
4. [Общие определения](canon/_quarto.yml) и [наследуемые правила Java-проектов](canon/projects/_metadata.yml).
5. [Студенческий комплект](outputs/student/README.md) и [авторский исследовательский контекст](outputs/author-full/README.md).

B **заменяет** единственный локальный `_metadata.yml` того же проекта; это не два одновременно активных входа. Его локальные пути считаются от канонического проекта, а не от каталога `alternatives/B`.

| Вариант | Как записан выбор | Преимущество и цена |
| --- | --- | --- |
| A — наборы рядом | `demo` выбирает `tests/demo` и нужные `java-process`/`numeric-output`; `full` добавляет свой каталог | Для reverse-array короче путь от задачи к проверкам; рекомендован для сравнения как простой случай |
| B — локальные компоненты | Те же каталоги и зависимости сначала получают имена `reverse-demo`/`reverse-full`, набор выбирает имена | Полезно при повторном использовании компонента; добавляет имя и переход к его определению |

[Сопоставление A/B](comparison.json) фиксирует одинаковый выбранный demo-состав. Полный состав не признан эквивалентным: выбранные текущие full-источники недоступны, что явно отражено в [манифесте пробела](missing-full-input.yml).

## Что получилось на диске

Студентский каталог — готовая раскладка обычного Gradle-проекта, а не обещание пройденного `gradle test`:

```text
outputs/student/
├── README.md
├── build.gradle
├── settings.gradle
└── src/
    ├── main/java/Main.java
    └── test/java/
        ├── ReverseArrayDemoTest.java
        ├── PublicChecks.java
        └── coursesupport/
            ├── JavaProcess.java
            └── OutputNumbers.java
```

Авторский контекст сохраняет отдельную компиляцию стартера и исторического решения:

```text
outputs/author-full/
├── README.md
├── build.gradle
├── settings.gradle
├── gradle/author-contexts.gradle
├── src/main/java/Main.java
├── src/test/java/…                      # тот же demo и helpers
├── solutions/reference/src/main/java/Main.java
├── assessment/prairielearn/…            # observations и API-precheck отдельно
└── MISSING-FULL-INPUT.yml
```

Имя `author-full` обозначает проверяемую структуру будущего комплекта, **не готовый полный grader**.
[Исторический reference](canon/projects/arrays/reverse-array/solutions/reference/src/main/java/Main.java) — образец авторского решения из выпуска 18 октября, не выбранный финальный teacher input.
Недоступные текущие проверки не заменены demo. Оба `Main` не объединяются в один compilation context; [обычный Gradle-код](canon/components/gradle/java-junit/author-contexts.gradle) задаёт `test` и `referenceTest` раздельно.

## Один канон и состав выдачи

- Полное условие — в QMD; оба выходных README получены из него, без ручного повторного авторства условия.
- Локальный `_metadata.yml` выбирает каталоги наборов, объявленные helper-зависимости, решения и выдачи; внешние Maven-версии там не перечисляются.
- [Настоящий общий build](canon/components/gradle/java-junit/build.gradle) и settings хранятся один раз; Gradle разрешает внешние зависимости, YAML не генерирует скрипт.
- JavaProcess/OutputNumbers имеют один канон в `components/java`; выбранные копии попадают в студенческий test-каталог. Это объявленный состав, не автоматический вывод Java-import closure.
- В student включён только явно выбранный demo. Авторское решение, полный набор и PL API-precheck туда не добавлены.
- `ReverseArrayDemoTest` → `PublicChecks` — переходная механическая адаптация прежних normal/boundary, без нового случая или runner; окончательный вид обычных JUnit-тестов этим не утверждён.
- [PL observations и API-precheck](assessment-manifest.yml) сохранены отдельно от обычного JUnit/Gradle-контекста; их наличие не доказывает эквивалентность PL grading.
- [Inventory](inventory.json) и [происхождение источников](source-provenance.json) — производные свидетельства состава, преобразований и hashes, а не второй авторский реестр.

Студент сам выбирает глубину работы: условие и свой код → необязательный IDE-комплект → необязательная строгая самопроверка.
Для IDE/самопроверки предусмотрены JDK 25 и установленный Gradle **без Wrapper**, первоначальное разрешение зависимостей через сеть/cache.
Простой ответ остаётся `Main.java` из `src/main/java`; разрешённые дополнительные исходники — по контракту задания. Скачанный starter ZIP не обязывает сдавать ZIP и не равен Java-only `additional-sources.zip`.
Полный текст условия, API и критерии одинаковы при любом маршруте; demo не заменяет оценивание и не ограничивается числом попыток.

Два прежних случая — ввод `4 7 -2 7 0` с результатом `0 7 -2 7` и ввод `0` для пустого массива.
Пустой массив не равен пустому stdin; эта пара не доказывает сохранность исходного массива и не покрывает всё условие.

## Что проверено и что осталось

[Отчёт исполнителя](verification.json) разделяет статические проверки и исполнение:

- Проверены YAML-синтаксис, точный снимок условия, вывод условия в README, равенство копий по hashes и одинаковый явно выбранный demo A/B.
- JDK 25 отдельно скомпилировал стартер и исторический reference; reference прошёл только прежние normal/boundary CLI-входы. Это не JUnit, не полный grader и не доказательство сохранности массива.
- Gradle `compileJava` не дошёл до инициализации build из-за ограничения окружения `FileLockContentionHandler`; это не установленная ошибка build.
- `gradle test` не запускался: нужных Jupiter/launcher нет в cache, зависимости не загружались. Команды и полная автономность запуска пока не приняты исполнением.
- Native input/наследование кодовой папки, per-value origins/базы путей, работа нового producer и PL API/scoring/feedback не проверены этим примером. Исследование [границы native Quarto](../../reverse-array-example.md#где-заканчивается-native-quarto) остаётся применимым.

Это материал для выбора авторского вида и проверки границ, без нового решения о схеме, версиях библиотек или реализации курса.
