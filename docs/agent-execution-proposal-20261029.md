Историческое имя сохранено ради ссылок. Прежняя
[матрица от 29 октября](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/f5d97be630c92f187f78ac9903b3c48ec03f9c99/docs/agent-execution-proposal-20261029.md)
служит справочным источником; её сроки, START, очереди и процедуры допуска
не являются активными инструкциями. То же относится к старым планам
в `docs/superpowers` и прежним регламентам организации работы. Собственных
навыков в репозиториях нет; дополнительные `SKILL.md` не создаются и не
требуются. Чужие навыки в зависимостях не редактируются.

## Роли

Разрешены `gpt-6.1-sol` и `gpt-6.1-terra` с явно назначенным усилием.
Другие модели не являются резервной заменой. Используется Standard;
глобальные настройки моделей и режим скорости самостоятельно не меняются.
Покупки credits, платный API и платные evals текущим поручением не разрешаются.

| Работа | Назначение |
| --- | --- |
| Координация и интеграция | Sol/high |
| Критичные договоры: API, AST, полномочия, public/full, идентичность, grading и доставка | Sol/high |
| Ограниченная механика по устойчивому проверяемому договору | Sol/medium |
| Независимая рецензия изменённого поведения | Другой Sol/high |
| Ключевая архитектура и её независимая рецензия | Разные Sol/max |
| Ограниченная служебная работа | Terra с явно назначенным усилием и проверкой Sol/high |

Sol означает `gpt-6.1-sol`, Terra — `gpt-6.1-terra`. Max назначается только
ключевой архитектуре. Прежние разрешения более высокого усилия не являются
назначением для текущей технической работы. Учебные материалы Java и System
Practice фиксированы; отдельная содержательная работа требует собственного
поручения. Учебный автор определяет цели и обязательный договор, технический
исполнитель пишет код, стартеры, эталоны и тесты.

## Владение и параллельная работа

У файла и публичного договора в одной фазе один владелец. Автор и рецензент —
разные исполнители и контексты. Интегратор согласует установленные копии
расширений и корневые конфигурации. Сохраняйте чужие рабочие деревья,
незакоммиченные изменения, открытые PR и прежние данные.

Пакеты ограничиваются конкретной целью и договором. Число участников
определяется независимостью пакетов и ресурсами машины. Параллельные проверки
используют отдельные temp, outputs, Compose projects, порты и state;
запись в общий output или DB согласует владелец. Нагрузку измеряют,
избегая чрезмерного числа одновременных grader JVM.

## Проверка и передача

Проверяется содержательное поведение на публичных входах, реальные
производители и потребители, существенные отрицательные сценарии.
Независимый рецензент читает реальную дельту и проверяет затронутые гарантии.
Адресная проверка явно отличается от полной квалификации; неизменные проверки
не повторяются без нового основания. Обязательный TDD для каждой правки,
квитанции допуска, чтение полных стенограмм и самопроверка сообщений
не требуются; [назначение модели](model-admission.md) не создаёт отдельного gate.

Передача содержит цель и результат, исходный/выходной ref, владельца договора,
критерий готовности, команды и логи, открытые ограничения. Полные логи
и переписка не копируются в каждый контекст. Неопределённость остаётся
открытым ограничением. Готовность внешней интеграции подтверждает фактический
пользовательский сценарий, а не само наличие файлов.

## Продуктовые и системные границы

Инструменты запускаются из системного PATH; на Arch Task поставляется
пакетом `go-task`; исполняемый файл — `/usr/bin/go-task`, наличие `task`
не предполагается. Версии записываются информационно, совместимость проверяется
нужными возможностями. Системный tsc и TypeScript Compiler API принимаются
отдельно: нужны статический check, реальное AST-преобразование и запуск
установленного CLI с системным модулем. `tsc --version` этого не подтверждает.
Java grader сохраняет настоящий JDK 25 и `--release 25`.

Применяются публичные API и минимальные адаптеры. Сохраняются гарантии
public/full, capability/token/currentness/expiry и защиты физических путей.
Удаление legacy требует проверки потребителей и переноса уникальных
проверяемых гарантий на штатный вход. Измеряйте стоимость всей цепочки
на реальном потребителе; результаты применимых проверок переиспользуются.

Действия на VM требуют отдельного прямого разрешения владельца. Старые оценки
не переносятся, не исправляются и не пересчитываются без отдельного разрешения
после развёртывания и проверки. Текущий перенос ограничен пользователями
и правами; прежняя установка и данные сохраняются. Print/Cloud остаются вне
текущего технического объёма. Новые README, документация и описания PR —
по-русски, технические идентификаторы сохраняются буквально.
