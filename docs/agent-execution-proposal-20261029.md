# Предложение по агентскому исполнению и расходу подписки

**29 октября 2026 года. ПРЕДЛОЖЕНИЕ, ТРЕБУЕТ СОГЛАСОВАНИЯ; здесь не применяется.** Записка относится к будущей сессии на другой машине. [Регламент](release-execution-regulation-20261103.md), [решения 1–74](refactoring-plan.md) и [стартовое поручение](refactoring-start-20261030.md) сохраняют свои границы; прямые требования скорости 72, архитектуры 73 и сокращения повторных проверок 74 уже приняты отдельно.

**До согласования действуют нынешние AGENTS:** техническая работа — `gpt-6.1-sol/high`, учебное авторство и независимая содержательная рецензия — `gpt-6-astra/ultra`, с действующей процедурой первичного допуска и полного модельного интервала.

Предлагаемые назначения: постоянный координатор Sol 6.1/high для межрепозиторной работы; Sol 6.1 Medium для устойчивых ограниченных изменений, High для неопределённых и дорогих границ; технический рецензент — другой Sol с усилием по риску; Astra Medium/High по сложности предметного договора; ограниченные помощники Luna и Terra после малых проб. Для ключевых архитектурных пакетов заранее предусматриваются Astra/max и отдельная независимая Astra/max-рецензия по решению 73; обязательного провала Sol до них нет. Остальные xhigh/max/Ultra применяются адресно, без максимума всем. Настройки задаются явно в проекте/агенте после согласования, глобальные конфигурации не меняются.

## Какие данные относятся к включённой подписке

Официальная [Pricing](https://learn.chatgpt.com/docs/pricing), проверенная 29 октября, даёт следующие **приблизительные локальные сообщения за пять часов только для Plus/Standard Business**:

| Модель публичного ряда 6/6.1 | Точный ID | Опубликованный диапазон |
| --- | --- | --- |
| GPT-6 Astra | `gpt-6-astra` | 5–45 |
| GPT-6 Sol | `gpt-6-sol` | 15–150 |
| GPT-6 Luna | `gpt-6-luna` | 350–3000 |
| GPT-6.1 Sol | `gpt-6.1-sol` | 15–160 |
| GPT-6.1 Terra | `gpt-6.1-terra` | 35–285 |

Это не веса моделей, фиксированные пределы или прогноз нашего тарифа. На текущей странице Pro не имеет пятичасового лимита; действуют реальные окна аккаунта, возможны недельные ограничения. Terra присутствует в свежей canonical-странице. Точных коэффициентов «модель × effort» для включённой подписки не опубликовано; кредитные ставки и API-цены их не определяют.

У Sol 6.1 [нет long-context surcharge для включённой подписки](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Обычный расход контекста остаётся; API-коэффициент 2× при >272K нельзя переносить на подписку. Подтверждать доступность моделей, усилий и квоту нужно на целевой машине. Новых разрешений покупать credits, использовать платный API или проводить платные evals здесь нет.

**Standard обязателен по [прямому решению 72](refactoring-plan.md#decision-72).** Fast/Ultrafast самостоятельно не включать, даже ради срока: изменить это может только новое прямое указание пользователя. Ultra reasoning — другое понятие, этот запрет его автоматически не отменяет. Исследовательские сведения: По [Speed](https://learn.chatgpt.com/docs/agent-configuration/speed), Fast расходует included limits в **2.5×**, Ultrafast — в **8×** относительно Standard той же модели. Это не ускорение всей задачи в 2.5/8 раз. Для купленных credits/Enterprise PAYG множители другие — 2×/6×. Эти множители — сведения об услуге, не рекомендация её включать; доступность зависит от плана и среды.

В матрице Sol — **6.1**, Astra/Luna — **6**, Terra — **6.1**; в таблице свидетельств ниже сохранены названия сравнений из источников. Обязательны явные model/effort, а не случайное наследование Ultra. [Документация моделей](https://learn.chatgpt.com/docs/models) и [субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents) описывает возможности; конкретное распределение ниже — наша рекомендация.

| --- | --- | --- |
| Координатор | Sol/high постоянно для этого межрепозиторного выпуска | Бюджет, назначения, зависимости, состояние и риски; не написание всех пакетов одновременно |
| A: Core + нужные Presentation/Navigation | Sol/high для ранних TS/native metadata/origins/AST/API; medium для устойчивой ограниченной реализации | Семантика и публичные договоры; не новый экспортёр |
| B: QRC/Download/Publisher | Sol/medium по устойчивому договору; high для границ ресурсов, public/full и межрепозиторного поведения | Условия, README, student/full, ZIP и Pages |

| Ключевой архитектурный проект | Astra/max на выборочных ранних пакетах | Целостный дизайн, трудные межвладельческие/производительные границы по прямому приоритету 73; не весь код |
| Независимый архитектурный рецензент | Другой Astra/max на этих ключевых пакетах | Отдельный исполнитель и контекст; плановая проверка архитектуры, без обязательного предыдущего провала Sol |
| Учебный автор | Astra/medium для ограниченного однозначного договора; high для нового сложного/спорного | Цель, допустимые решения, обязательный API, доля самостоятельной работы; не код |
| Содержательный рецензент | Другой Astra/medium или high по той же сложности | Независимая приёмка каждого содержательно изменённого договора, без замены выборкой |
| Узкий помощник | Luna/high только для вспомогательного малого повторяемого пакета чтения с инструментами | Инвентарь/ссылки/журналы после малой пробы; без бесцельного поиска, кода и окончательных выводов |
| Необязательный визуальный/документальный помощник | Terra/medium после малой пробы и проверки Sol | Живой визуальный контроль Pages/PL, ясная служебная документация; не учебное авторство |

Плановые архитектурные Astra/max-пакеты и их независимая рецензия предусмотрены заранее по 73. Для прочих технических вопросов Astra — адресная эскалация нерешённой дилеммы после Sol, не обязательный турникет каждому PR или всему репозиторию. Xhigh/Max/Ultra не назначаются всем по умолчанию. Sol 6 — резерв при отсутствии 6.1 либо подтверждённом локальном недостатке, не плановая ступень экономии подписки; его неэффективность также не доказана.

Цель по [73](refactoring-plan.md#decision-73) — устойчивые публичные границы, локальные изменения, быстрые native/инкрементальные сборки и поддерживаемость; не вечный API, legacy-слой или проектирование исключённых Print/Cloud. Max — глубина, Ultra — отдельное делегирование; запрет Fast/Ultrafast относится к скорости.

Однозначные операции выполняют обычные команды, форматтеры и статический анализ, а не модель вместо инструмента. Performance принадлежит A/B и проверяется вместе с их изменениями. Один назначенный интегратор владеет установленными копиями расширений, закреплёнными версиями и корневыми конфигурациями; исходники и производные не правят одновременно разные владельцы.

## Четыре места и работа партиями

**До четырёх активных агентов, включая root:** координатор, два исполнителя, сменный проверочный слот — обычно Sol, Astra кратко по готовой предметной партии. Только root назначает бюджет/запись; у файла/контракта один владелец в фазе. Если партии для рецензии нет, слот можно занять подготовкой другого пакета и освободить к сроку независимой проверки. Root не подменяет отдельного E.

Первая волна — малый сквозной A/B/C: архитектура с performance и PL/grader/IDE, затем нужная выдача, четыре ранних случая. Полной переделки A/B/C не ждём. Массовый D начинается после малого устойчивого договора; заранее допустимы инвентарь и исправления без новых ключей. E рано готовит сверку/восстановление без переключения. Затем — весь активный Java/SP-состав, оба SP-маршрута, установленные потребители и реальный выпуск; четыре случая не замена полному составу.

Передача — шесть коротких полей: **цель/результат; входные коммиты; владелец/контракты; критерий готовности; ссылки на проверки; риски/следующее**. Не копировать полные логи и историю. Партия проверяет эталоны, ожидание незавершённого стартера, отрицательные контроли, student без эталонов и реальный сквозной маршрут; генерация сама по себе не PASS.

## Предметный пакет Astra вместо полного чтения кода

Sol готовит точный коммит и смысловую дельту; полное каноническое условие с нужным контекстом темы; обязательный интерфейс/стартер в объёме обязанностей студента; связь требований с ожидаемым/фактическим поведением, случаи и веса; результаты эталонов/отрицательных контролей; ссылки к существенному коду и вопросы. Ориентир — несколько содержательных страниц, не жёсткий токен-лимит и не новый инструмент.

Выбор кода подтверждает независимый технический Sol. Astra читает реальные условия/контракты, при необходимости ключевые assertions и любые первоисточники: пересказа Sol для PASS недостаточно. Контекст отдельный, без многодневной переписки/журналов; нормативные решения и ограничения доступны полностью по адресным ссылкам, AGENTS/skills не обрезаются. Автор и рецензент — разные агенты/контексты, собственный текст не принимают; параллельных Astra без нужды нет.

Механический перенос без смысловой дельты подтверждает Sol, без повторного Astra-чтения каждой задачи. Все содержательно изменённые договоры независимо принимаются в партиях. При изменении API, объёма готового кода, оценки/поведения нужна повторная содержательная проверка; после замечаний — только дельта и затронутый контекст. Если сведений недостаточно, риск остаётся открытым; проверка ради бюджета не сокращается.

## Калибровка и защита включённого ресурса

По [прямому требованию 74](refactoring-plan.md#decision-74) native-контекст получают пакетно по различающимся owner/input/profile/format/фазам; не inspect на каждое поле/Div/getter и не постоянная baseline/shadow-пара ради исследования. Актуальные результаты переиспользуются, полное дерево не хешируется на каждый status/чтение/несвязанную правку. Значимые изменения или неопределённость требуют адресной проверки по 41; финальная точная приёмка, восстановление и модельный допуск сохраняются. Конкретный кэш не выбран; один inspect на весь курс не обещается. При замерах учитывать число inspect, полных обходов/хеширований и основания повторов вместе со временем; здесь замеры не запускаются.

При начале на целевой машине проверить несколько настоящих пакетов, не турнир всех пяти моделей: детерминированный инвентарь — Luna; ограниченный QMD→README→PL по известному договору — Sol Medium; native/оценивание/миграция — Sol High. При конкретных пропусках эскалировать и проверять результат; это не условие допуска заранее предусмотренных архитектурных Astra/max-пакетов и не максимум всем. [Рекомендации OpenAI](https://developers.openai.com/api/docs/guides/deployment-checklist) связывают выбор усилия с проверяемым результатом.

Считать полноту, повторные исправления, время и наблюдаемый included usage, не одни токены. Лимиты общие для аккаунта: при одновременных чатах виден суммарный расход, округления и сбросы мешают точной атрибуции агентам. Процентов экономии или гарантированного резерва нет. Утром подтвердить реальную квоту; далее смотреть в существующих контрольных точках, не каждые пять минут. Если резерв финальной предметной приёмки под риском — прекратить необязательные Astra-исследования, продолжать независимую Sol-работу; обязательное авторство/рецензию без разрешения другой моделью не заменять.

## Граница предложения

Объём Pages/PL/IDE и Moodle/Gateway, исключение Print/Cloud, календарь, оценивание, сохранность данных и запрет исполнения здесь не меняются. До согласования исполнитель следует AGENTS. Эта записка не меняет модели/config, реестр и регламент; сейчас только документация.
