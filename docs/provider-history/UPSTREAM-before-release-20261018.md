# Происхождение технической поставки Java

Текущая локальная интеграция 17 октября 2026 года использует проверенный
набор неопубликованных кандидатов. Полная содержательная, визуальная и внешняя
приёмка курса выполняются отдельными этапами. Предыдущее описание сохранено
в [истории](docs/provider-history/UPSTREAM-before-20261016.md); его статусы
относятся к прежней редакции.

`providers.json` сохраняет поля `repository`, `tag`, `version`, `commit`
и `sourceZip` опубликованной базы. Отдельный раздел `candidate` задаёт точный
локальный коммит, `baseCommit`, поправку из репозитория и её SHA256.
`installed-packages.json` описывает фактически установленное содержимое
и области установки (`scopes`). Поле `extensionTree` относится к базовому
пакету, а `candidate` описывает применённые локальные изменения. Версия
в дескрипторе сохраняет номер исходного опубликованного выпуска.

## Проверка и воспроизведение

Рабочая копия курса уже содержит пакеты зависимостей. Локальная проверка ничего
не переустанавливает и не обращается к GitHub:

```sh
python3 tools/materialize-providers.py --check
python3 tools/test-materialize-providers.py
```

Для воспроизведения подготовьте в одном каталоге репозитории с именами
из поля `checkout` файла `providers.json`. Достаточно объектов опубликованных
тегов и соответствующих файлов Git. Локальный коммит кандидата не требуется
получать из GitHub. Материализатор проверяет соответствие тега точному SHA,
версию дескриптора, SHA256 сохранённой поправки и всё содержимое пакетов
кандидата. Пример:

```sh
python3 tools/materialize-providers.py --providers-root /absolute/release-checkouts --write
python3 tools/materialize-providers.py --check
```

Данные берутся из архива Git для точного опубликованного коммита и сохранённой
поправки. Изменения в рабочем дереве репозитория поставщика не используются.
Перед первой записью проверяется полный состав файлов во всех областях
установки. Неизвестная локальная правка, лишний файл или символическая ссылка
останавливает установку. Повторный запуск сохраняет состав и содержимое файлов.
Посторонние темы сохраняются. Во время проверки и записи другие процессы
не должны изменять каталоги зависимостей.

Прежние 16 локальных поправок сверены с опубликованной базой и фактическим
содержимым до интеграции. Все 16 поправок допускают обратимое применение
поверх нового кандидата; результаты сохранены в
[отчёте](docs/provider-history/local16-carry-verification.json). Шесть копий
`collect.ts` дополнительно содержат поля API, сохраняя прежнюю диагностику.
Предыдущие манифесты поставщиков, установленных пакетов и локальных поправок
сохранены в `docs/provider-history/`. Прежний `sync-providers.py` отказывается
заменять кандидата опубликованной базой.

## Среда исполнения и внешние системы

Коммит и контрольные суммы опубликованной Platform 2.1.0
в `CI/toolchain.json` сохранены. Новый локальный кандидат Platform имеет коммит
`72f24f2c7fe7f07461b3d348a0dd25465ef95b1c` и идентификатор конфигурации образа
`sha256:130e05e77ab1d7764dd126ed81fac73fc915530a071f73a0944b061a5f84107f`.
Точные хеши исходников и файлов среды исполнения, а также необходимое
дальнейшее действие во внешних системах записаны в `CI/local-candidate.json`.
Идентификатор конфигурации относится к локальному образу; опубликованная
контрольная сумма образа остаётся прежней.

```sh
export PL_PLATFORM_ROOT=/absolute/local/platform
export PL_LOCAL_IMAGE_ID=sha256:130e05e77ab1d7764dd126ed81fac73fc915530a071f73a0944b061a5f84107f
bash CI/check-projects-candidate.sh --preflight-only
# Полный локальный цикл после отдельной авторской приёмки:
CI_CHECK_OUTPUT=/absolute/outside-course bash CI/check-projects-candidate.sh
```

Этот сценарий проверяет точный SHA исходников и отсутствие локальных изменений,
хеши файлов среды исполнения и локальный образ `linux/amd64` через `inspect`.
Клонирование репозиториев, загрузка и публикация образов не выполняются.
Затем сценарий создаёт отдельный реестр сред исполнения с явно указанным
локальным кандидатом и проверяет всю выбранную поставку на хосте и в контейнере.
На этапе описанной интеграции выполнена только предварительная проверка.
Полная текущая сборка курса и проверка поставки требуют отдельной приёмки.

CI проверки решений для опубликованной поставки останавливается до получения
образов, пока в манифесте поставщиков указан локальный кандидат.
Для возобновления нужны отдельно разрешённые выпуски Platform и образа,
затем обновление привязок к опубликованным версиям. CI сборки проверяет полный
состав сохранённых пакетов зависимостей без получения неопубликованных коммитов. Реальные параметры Moodle/Gateway
и внешние точки входа сохранены; действующий сервис не изменялся.

Текущий кандидат поддерживает необязательную загрузку ZIP с дополнительными
исходниками Java и ограничениями размера и количества файлов, а также поиск
скомпилированных типов. Опубликованные версии и контрольные суммы сохранены.
Навигация вызывает штатный `Notes.open` Reveal на широком экране
и из меню на узком экране. Работу отдельного окна докладчика проверяют отдельно
и фиксируют результаты
в отчёте о визуальной приёмке; встроенная панель заметок эту проверку
не заменяет. Прежние результаты сборки и проверок средствами Quarto относятся
к прежним снимкам. Для текущих SHA нужны новые проверки.

Локальная поправка Presentation разрешает перенос длинных URL библиографии
Reveal и внутреннюю горизонтальную прокрутку таблиц на экранах до 600px.
Правило прокрутки действует только на узких экранах: печатные стили
и режим Reveal `print-pdf` исключены. Проверка доступа к прокрутке с клавиатуры
не заявлена. Исходные таблицы и учебный текст сохранены.

## Локальная техническая поправка 17 октября 2026 года

В Core добавлена настройка `course.assessment-time: false`, которая отключает
автоматическую вставку сводки времени в HTML. Она включена в конфигурациях
корня Java и всех пяти учебных форм для профилей `student` и `full`.
Отсутствие настройки и значение `true` сохраняют прежнее поведение расширения.
Данные `time`, `theory-time`, расчёты и передача Body сохранены.
Общая поправка к опубликованной базе, её SHA256 и точное содержимое пакетов
учтены в `providers.json`, `installed-packages.json`
и `docs/local-extension-patches.json`. Расширения установлены штатным
материализатором с применением этой поправки.

Локальный образ Java пересобран из точного снимка исходников Platform
с прежними SHA256 файлов среды исполнения и закреплённой контрольной суммой
базового образа. Новый идентификатор конфигурации указан выше
и в `CI/local-candidate.json`; поле `imageRebuild` сохраняет сведения
о происхождении сборки и идентификатор отсутствующего предыдущего образа.
Пересборка создала новый локальный образ. Опубликованные привязки сохранены.

Выполнены адресный тест настройки средствами Quarto, независимая техническая
рецензия, проверки воспроизведения пакетов зависимостей и контейнерные тесты
API, проверяющей программы и вложенной JVM. Первоначальные ограничения
Jupyter, локальных сокетов и Ansible RPC устранены настройками локального
окружения с повтором затронутых этапов. Итоговая сборка, визуальная проверка
и проверка поставки изменённого курса выполняются после стабилизации авторского
снимка; внешние Moodle/Gateway не изменялись.

Русские страницы используют штатный `language.skip-to-content`. Presentation
локализует точные штатные подписи поиска, ссылок на разделы и пустой панели
заметок; английский интерфейс и заданные автором подписи сохраняются.

## Очистка объявленных ресурсов Publisher

Локальный кандидат Publisher использует штатный список `inspect.files.resources`
корня и вложенных проектов. При повторной композиции очистка разрешает удалять
копии по точным путям объявленных ресурсов, включая README. Исходный ресурс
должен быть существующим обычным файлом внутри проекта и вне каталога
результата. Для неизвестных документов, служебных каталогов, пересечений
с исходниками и символических ссылок действуют прежние проверки.
Отбор и публичная проекция Core сохраняются. Если ресурс удалён или больше
не объявлен, оставшаяся копия защищённого документа по-прежнему останавливает
очистку.

Поправка прошла независимое чтение кода, адресные проверки, проверки профилей
средствами Quarto и повторную сборку с `--no-clean`. Первая серия проверок
средствами Quarto остановилась из-за отсутствующей локальной зависимости Core;
после настройки окружения затронутые проверки выполнены повторно.
Это техническая приёмка поправки; полная сборка и приёмка курса выполняются
отдельно. Опубликованный тег `v5.1.0`, версия дескриптора и исходный коммит
сохранены.
