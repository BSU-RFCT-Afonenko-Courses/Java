# Поставка лабораторных в PrairieLearn

Курс `java-semester-one` хранит условия в `tasks/bank/`, состав работ в
`tasks/labs/` и проекты в `tasks/projects/`. Первая часть пересмотрена по
учебному назначению задач. Текущая подборка не содержит случайных позиций:

| Работа | Обязательные задачи |
|---|---|
| Числовые вычисления | Приветствие, размер изображения, принадлежность интервалу |
| Управление обработкой данных | Подсчёт пробелов, экстремумы последовательности |
| Массивы и изменения данных | Обратный вывод, вычитание среднего строки, устойчивая перестановка строк |

Итого восемь обязательных позиций: 3/2/3. Дополнительные подключённые
карточки сохраняются в банке, но не входят в обязательный знаменатель.
Новая карточка `exr-numbers-image-size` использует проект `/projects/image-size`.
Техническая проверка экспорта и полного набора проектов должна подтвердить
эту подборку; статус находится в [журнале редакции](full-revision-progress.md).
Прежние результаты для 17 вопросов и случайных позиций 6/4/4 относятся
к прежнему составу и не подтверждают новую поставку.

Проект содержит:

- `student/src/main/java/Main.java` — компилируемую стартовую программу;
- `student/src/test/java/PublicExamplesTest.java` — публичные примеры запуска;
- `reference/Main.java` — авторское решение;
- `tests/junit/ContractTest.java` — закрытую оцениваемую проверку;
- `tests/fixtures/` и `tests/contract-cases.json` — ошибочные реализации и ожидаемые результаты их проверки.

Условие каждого задания определяет стандартный ввод, аргументы и наблюдаемый вывод. Выбор алгоритма и методов остаётся у студента. Задачи с заданными константами не требуют числовых CLI-аргументов. Для трёх матричных задач обязательный исходный пример выполняется при пустом вводе; дополнительные входы — строго 3×3 со значениями −3…3. Проверка сортировки включает переставленные строки и равные суммы.

Ссылки «Скачать стартовый проект» используют штатный `project-download` shortcode и мост `course-model: true`. Каждый архив содержит только каталог `student/`, включая публичные примеры; эталоны и закрытые проверки исключены и в student, и в full. Пути `project="/projects/…"` относятся к корню книги `tasks`, а не к корню всего сайта.

Отдельная manual-задача gradeapp имеет стартер из 17 публичных файлов с предоставленными `build.sh`, `build.cmd` и `wrapper/maven-wrapper.properties`; `.mvn` создаётся только локально. Студент реализует пять TODO; отчёт допускает цикл или Stream. Reference и закрытые проверки не входят в публичный ZIP.

Java 25 используется без preview. В среде с несколькими JDK явно задайте `JAVA_HOME` и `PATH` на JDK 25. Каждый пример запускает `Main` в новой JVM с UTF-8 вводом, EOF и ограничением времени и вывода. Это сохраняет обычную семантику консольной программы, включая статический `Scanner` и явное завершение процесса. Публичные примеры выполняются отдельно от закрытой оцениваемой проверки и не определяют балл. Эталон должен пройти проверки; стартовая программа компилируется, но её поведение не выполняет условие полностью. Ошибочные реализации обязаны терять полный балл. Сбой инфраструктуры отличается от ошибки решения.

При преподавательской проверке просмотрите диапазон промежуточных вычислений изображения, использование массивов и сохранение исходных данных там, где этого требует условие. Автоматическая проверка наблюдаемого результата не доказывает эти свойства исходника. Дополнительная часть про эхо не оценивается.

Расширения устанавливаются целиком штатным `quarto add` через `tools/sync-providers.py`; их исходные commit, состав и hashes закреплены в `providers.json` и `installed-packages.json`. Ручное изменение установленных файлов расширений не допускается. Runtime source и опубликованные OCI digests закреплены в `CI/toolchain.json` и `UPSTREAM.md`.

Для подготовки поставки используйте `CI/render.sh` и `CI/check-projects.sh` с точной выпущенной Platform в `PL_PLATFORM_ROOT`. Сборки student/full проверяют публичные материалы и преподавательскую проекцию; проекты и записи закрытой проверки исключены из ресурсов сайта. Экспорт и container verification выполняются для всей выбранной поставки, без сокращения списка вопросов и сценариев.

Запускайте команды из корня курса с Quarto 1.11.5, CUE 0.17.1, Python, JDK 25 и Docker. Внешний checkout Platform должен соответствовать `platform.commit` из `CI/toolchain.json`; каталог исходников providers содержит целые официальные репозитории версий из `providers.json`. Перед контейнерной проверкой войдите в GHCR с учётной записью, которой разрешено читать соответствующий пакет. Замените абсолютные пути путями своей установки:

```sh
export JAVA_HOME=/absolute/jdk-25
export PATH="$JAVA_HOME/bin:$PATH"
export PL_PLATFORM_ROOT=/absolute/prairielearn-platform
export CI_CHECK_OUTPUT="$(mktemp -d -t java-project-checks-XXXXXXXX)"
python3 tools/sync-providers.py --providers-root /absolute/provider/repositories
python3 - <<'PY'
import json, os, subprocess
from pathlib import Path
platform = json.loads(Path('CI/toolchain.json').read_text())['platform']
actual = subprocess.check_output(['git', '-C', os.environ['PL_PLATFORM_ROOT'], 'rev-parse', 'HEAD'], text=True).strip()
if actual != platform['commit']:
    raise SystemExit('Исходник Platform не совпадает с закреплённым commit')
subprocess.run(['docker', 'pull', platform['javaImage']], check=True)
PY
python3 -m pip install --requirement "$PL_PLATFORM_ROOT/requirements.txt"
bash CI/render.sh
bash CI/check-projects.sh
```

`CI_CHECK_OUTPUT` хранит manifest, inventory, delivery и результаты полного прогона вне исходного репозитория. Проверка проектов выполняет обе среды, `host` и `container`; обе должны пройти.

Для входа CI в GHCR используйте встроенный `GITHUB_TOKEN`; для задачи CI с проектами задайте `packages: read`. Фактический доступ к закрытым пакетам другой организации проверяется pull из Actions этого репозитория. Успешный локальный pull и локальный scope `read:packages` не подтверждают такое разрешение.
