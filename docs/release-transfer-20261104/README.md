## Как читать старые пути

| Путь на прежнем устройстве | Путь относительно корня Java PR |
|---|---|
| `/home/tolya/JavaCodex/java-release-20261110/reports/<путь>` | `docs/release-transfer-20261104/reports/<путь>` |
| `/home/tolya/JavaCodex/java-release-20261110/briefs/<путь>` | `docs/release-transfer-20261104/briefs/<путь>` |
| `../../reports/<путь>` в старой документации | Искать `<путь>` в [reports](reports/) этого пакета |
| `../briefs/<путь>` в старом отчёте | Искать `<путь>` в [briefs](briefs/) этого пакета |
| `/tmp/...`, старые owners/capture/output paths | Историческое место опыта; не предполагать наличие на новом устройстве |
| Абсолютные пути к исходникам Core/PL/Performance/Platform и других repos | Восстановить соответствующий checkout из source PR и сохранённых refs; не применять путь прежней машины буквально |

Исторические документы скопированы буквально: их внутренние ссылки не переписаны массово. Если старый относительный путь не открывается, используйте таблицу и точный список MANIFEST. Исходники продукта, зависимости и материализованные HTML/курсы восстанавливаются из отдельных source PR/штатных package mechanisms; этот пакет не заменяет эти repos. Новую машину нельзя считать квалифицированной по старому PASS.
