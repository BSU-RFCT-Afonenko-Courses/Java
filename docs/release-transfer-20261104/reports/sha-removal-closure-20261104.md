# Удаление собственных SHA: замкнутые границы следующей работы

**Остаточный механизм можно удалить согласованно во всех собственных producers, DTO, readers и тестах. Несовместимость со старым собственным reader — часть работы, а не причина сохранять SHA. Единица export/update — весь курс со всеми его вопросами.** Этот Source-аудит после отчёта на 21:00 не поручает реализацию или запуск курса. Предыдущее предложение `work-scope` не превращается в новую архитектуру incremental release: отдельная лабораторная допустима только как явно ограниченный Source fixture проверки.

Сейчас смешаны три вещи: физическая копия для запуска изменяемого технического input; передача выбранных файлов и их ролей; самостоятельное доказательство, что всё дерево/DTO/исполнитель осталось прежним. Последнее удаляется целиком, включая stat/membership/currentness fences, которые лишь продолжают ту же гарантию без SHA. Нельзя оставить их как замену удалённого digest.

**Целевой договор простой.** Quarto получает действительные physical inputs и своё effective metadata; Core возвращает разобранные project declarations, выбранные roles/targets и нужные bytes; PL пишет полный Native layout и узкие integration facts. Native PrairieLearn читает допустимые Native JSON/HTML/resources. Platform выбирает существующий native course/CI из своей конфигурации, Gateway — пользователя, activity, работу и существующее назначение/version. Изменение title/HTML/resource само не создаёт новый course, assignment или lab scope.

Минимальные функциональные данные:

- Внутри подготовки: owner/input/format/projection, effective project fields и physical paths; выбранные project/test/reference/scenario IDs и роли. Список нужных файлов — `{target, bytes, audience, role}`; размер можно получить из bytes. `rawSource`, operation UUID и reason остаются только при конкретном reader/diagnostic/lifecycle назначении, не как сертификат. Перечень всего checkout, SHA, подписи mtime/inode и inventories ради согласования inventories не нужны.
- В Native output: actual `infoCourse`, `infoCourseInstance`, `infoAssessment`, question JSON/HTML/resources/server files и необходимые grader descriptors. Для собственного integration output: logical course/instance/work references, slots/candidates, completion, assignment labels/relatedExercise и self-enrollment. Private tests/reference/cases остаются в их private grader input; Gateway не нужен их digest или полный source manifest.
- В runtime request: configured native binding, instance, user/work и существующие assignment ID/version, если операция назначение использует. Native numeric parents/FK, UUID, enrollment/access, tenant и принадлежность attempt/results/files сохраняются. Новый content revision ID, freshness registry, receipt или fake64 не вводятся.

**Предлагаются три смысловых изменения с конечной обязанностью каждого.**

1. **Native acquisition без собственной неизменности.** Перевести project path contract на Native effective physical paths по существующему [предложению](core-native-path-contract-proposal-20261104.md); удалить whole-owner `snapshot/rows/memberships`, source/runtime fingerprint admission, observed implementation-file freeze и их обязательные counters. Для existing authored input использовать реальный source; A1 instrumentation/copy удалить вместе с obsolete origin resolver. Для отсутствующего synthetic input сначала заменить caller действительным input либо оставить только минимальное writable staging для того конкретного запуска; не сохранять общую копию курса «для безопасности». Замыкание: те же выбранные functional fields/files/roles, полный owner/course scope, штатный Quarto; никаких новых freshness checks.
2. **Один договор выбранных файлов вместо project/hash inventories.** Core materialize/write, PL native selection/check/scenario/verification/job inputs и Download schema читают actual files/bytes/roles. Удалить SHA/raw-source reconstruction, legacy normalized projections и digest-only DTO/tests одновременно у writers/readers. Точное назначение starter/trusted tests/reference/cases и real grading scenarios сохраняется; сравнение выбранных facts требуется только для конкретного конфликта, не для доказательства неподвижности всего Source. Download читает свои requests один раз, ZIP получает переданные bytes. Замыкание: public/private partition, target collision/containment, выбранные runtime/test параметры и результаты настоящей проверки; без универсального project inventory/certificate.
3. **Полная изменяемая поставка курса.** PL native-only writer прекращает full output inventories, course/check/scenario hashes и final receipts; Platform/Gateway schemas/startup/sync/wire/storage readers согласованно переходят на функциональные поля выше. Убираются SHA suffix path, binding-by-hash, hash-driven migration, lab identity и outbox validity. Сохранённые assignment/recognition/pending records связываются с уже существующим context; нельзя терять их, пересоздавать parents/назначения или менять оценки. Это одна consumer closure полного курса, не новый exporter framework и не отдельный release каждой лабораторной. Реальная deployed история пока неизвестна; её неоднозначность требует отдельного решения о данных перед live-переключением, но не блокирует удаление obsolete Source contracts.

Старый exporter не является отдельным действующим CLI: оба публичных entrypoints идут в `nativeEntry`, единственный product caller общего `exportCourse` — `native-course.ts:524`. Он передаёт `content`, `checks`, `nativeInputs`, `nativeAnswers`, `nativeResponseSlots`, `nativeVerification`, `nativeBody:true`, `deferPublish:true`; `result` не передаёт. В writer остались смешанные `result?/content?`, `nativeInputs?`, `nativeSelection`/`legacyTests`/`readSelected`/`runtimeDescriptor` ветви. `result?.model` удаляется; для остальных fallback надо требовать полноту actual `nativeInputs` выбранных automatic questions, затем удалять ветку, переписывая собственные caller/tests. Добавление всё более точных compatibility types сохраняет ненужный вход. Действительный native writer, full-course content, UUID/slot/grading semantics при этом остаются.

## Какие проверки исчезают, какие остаются

Удаляются assertions, единственный смысл которых — SHA consistency, immutable captured rows, stat/membership freshness, output certificate, old DTO shape или hash-driven migration. Конкретные места: Core `tests/condition-materialization-a2.ts:337–339` (`ARTIFACT_DIGEST`), `artifact-target-guards-a2.ts:283`, SHA-поля `artifact-raw-origin.ts`/`artifact-origin-dto.ts`, `assignment-closing-source-fence.ts`, `native-empty-supporting-scratch.ts`, hash/counter sections `static-batch-checkpoint.ts`/`native-context-scaling.ts`; PL `native-raw-origin-values.ts:133–155`, `native-reference-projection.ts:107`, digest checks `native-verification-inventory.test.ts`, legacy-only types `native-legacy-boundary-types.ts`; Download `ownership.ts:53`. Это перечень требований к удалению/переписыванию, **не разрешение механически удалять весь mixed test file**.

Platform `test_delivery_verification.py`, `test_delivery4*.py`, `bridge/native-course-payload.test.mjs`, Gateway `test_delivery_v3.py` требуют переписывания certificate/migration expectations. В `test_lab_results.py`, `test_native_integration.py`, recognition/ACL/outbox tests нужно сохранить user/attempt/FK/pending-grade поведение и отвязать fixture identities от content hash. Сохранить настоящие учебные grading cases, target/private alias refusal, Native допустимые поля, stable UUID/parents и полный набор вопросов курса. Одна ограниченная лабораторная fixture не доказывает course performance/acceptance.
