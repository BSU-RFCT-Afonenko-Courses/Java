# Следующий JDK slice: второй version process в official preflight

Source-only, 4 ноября. Использована существующая карта [pattern-pass Platform](pattern-pass-platform-20261104.md), строки grade.py558–617 и принятое [single compilation](platform-single-compilation.md). Прежние full-toolchain byte passes и `gradle --version` уже сняты; их повторно не предлагаю. Рассмотрен сохранённый Platform9b (`9b82e29bffd77cc462ffdef23cd3b96ca041db92`), без live/deployed claims.

**Один оставшийся дубль:** `preflight` в `/home/tolya/JavaCodex/java-release-20261110/platform/images/java25-grader/grade.py:599–614` на каждом job после `java -version` запускает ещё JVM `com.sun.tools.javac.Main -version` и проверяет строку `javac 25`. Предлагаемый узкий runtime diff — оставить этот compiler diagnostic только вне `PL_CONTAINMENT=official`. Первый `java -version`, его проверка и возвращаемый `output.strip()` остаются; следовательно текст `toolchain` в результатах не меняется. Нового cache/receipt/qualification нет. Это один удаляемый процесс на official job по Source, не измеренное ускорение.

**Нижний слой:** Dockerfile задаёт exact digest base image и официальный grading JDK path. Image installer связывает установленный JDK с authenticated source/lock; complete-native завершает actual copy и вызывает `_hardened_tool_state()` с byte verification. Перед каждым official preflight `grade()` уже вызывает `_admit_java_job()`: installed lock/release JDK25, metadata и root-owned/non-writable grading/build paths/roles проверены. `_grading_java()` для official возвращает конкретный hardened path, а не host PATH. Это Source аргумент о поставленном и защищённом JDK; installer явно **не запускает Java/Gradle**, поэтому byte admission не выдаётся за функциональный smoke test. Последний остаётся отдельным image/CI evidence, а не обязанностью каждого student job.

**Предметные границы:** сохраняются config/grading/goals/scoring, compiler options/source selection, sole production compilation, actual API checks, student files, role/containment checks и runtime error handling. Host diagnostic остаётся прежним: произвольный host compiler не полагается на official image pins. Не предлагается просто удалить обе проверки и ждать ошибки student compilation: общий ненулевой javac exit сейчас может классифицироваться как student invalid, поэтому такой более широкий шаг требует отдельного рассмотрения infrastructure failures.

**Consumers и hash coupling:** `preflight` вызывается из `grade()` один раз; compiler-version output отдельно не возвращается и не используется в score/evidence. Возвращаемый `toolchain` получен от первой JVM и передаётся в `_execute`/результаты без изменения. Но изменение любых байтов grade.py требует обновить runner pins: baked view в `tools/prepare_native_toolchain.py:27,110–122` проверяет `RUNNER` и присваивает его трём Java profiles; source `runtime-profiles.json` также содержит Java runnerSha256. Поле затем входит в existing dependencyHashes/dependencyHash. Старые profile/image artifacts/history нельзя молча переписать или считать совместимыми с новым runner.

**Точные две основные точки следующего slice:**

- `/home/tolya/JavaCodex/java-release-20261110/platform/images/java25-grader/grade.py` — условие только вокруг второго compiler-version process.
- `/home/tolya/JavaCodex/java-release-20261110/platform/tools/prepare_native_toolchain.py` — существующий runner pin/baked view coupling, без нового механизма.

Честный исполнимый patch дополнительно требует companion обновления Java runnerSha256 в существующем source runtime-profiles manifest и обычного image release. Поэтому это **Source plan**, не обещание законченного total≤2-file production diff и не разрешение незаметно обойти pins. До GO на companion manifest и image qualification Source не менять. DB/production approval не обходятся; текущие grades/student state не мигрируются.

Новых Java/Gradle/build/hash/tests/network/inspect запусков не было; product Source и mainstate не изменены.
