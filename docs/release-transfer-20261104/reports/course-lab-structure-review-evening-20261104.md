## Решение

**APPROVE** для данной A3 Source-дельты. Блокирующих замечаний в пределах
проверенного изменения нет. Отдельная Native практика остаётся открытой
producer-задачей; данное решение не объявляет её доставленной.

В `tasks/_quarto.yml` остаются ровно десять прежних `sec-lab-*` из
`tasks/labs/index.qmd`, в его исходном порядке: numbers, control, arrays,
text, objects, polymorphism, generics, collections, pipelines, files.
Удалены только 87 `sec-unit-*` из `works`. Три авторские reserve-страницы
отделены в навигации как «Добровольные подборки». Diff не меняет списки
путей четырёх технических групп: 8 + 22 + 22 + 35 = 87 страниц остаются
достижимы через `book.chapters`. Раздел банка с прежними `bank/*.qmd`
также сохранён отдельно.

Выборочное чтение механической дельты охватило обе формы исходной
обёртки: с прежним пояснением добровольности и без него, включая
arrays/array-average, arrays/cyclic-matrix-shift, files/remove-java-comments,
projects/timetable-interfaces-project, collections/word-frequency,
exceptions/queue-exceptions, numbers/binary-truth-table и text/sum-text-digits.

остальным страницам не создаёт обязательной нагрузки. Прочитанный diff
конфигурации и сводка дельты согласованы с этим однородным преобразованием.

Адресный diff `tasks/labs`, `tasks/bank`, `projects` пуст относительно

## Независимость банка от технических обёрток

Прочитан настоящий Core Source в
`core-native-bridge/_extensions/course-core/release/collect.ts:100–144`:
сбор Div-деклараций из `definitions` выполняется независимо от накопления
контейнеров `task-items`. Позднее отдельное условие начинает сбор assessment,
только если есть его metadata либо контейнеры. В
`release/publication.ts:161` assessment обрабатывается после сбора facts
упражнений. В `tasks/bank/arrays.qmd` у упражнения остаются собственные ID,
target, project, project-check и условие. Удаление технических обёрток не
удаляет источник сбора банка. Этот вывод относится к Source-контракту Core;
сам по себе он не доказывает выпуск всего банка в отдельный Native маршрут.

## Запрос к владельцу PL

Описанный в отчёте исполнителя запрос предметно обоснован и имеет ясную
границу: отдельный добровольный доступ из существующих exercise IDs,
вне основных `works`, их номера, pass/completion и зачётных баллов, с
переиспользованием вопросов, UUID, проектов и grader. Чтение настоящего
PL Source подтверждает текущий пробел: `application/declarations.ts:128`
разрешает только title/self-enrollment/works/publishing; `native-entry.ts:122`
выбирает `works` как assessments; `export-course.ts:712–733` создаёт для
каждой выбранной работы Homework/Exam с grading, completion и общим номером.

Запрос правильно адресован producer и требует согласованной правки parser,
Native selection/materialization, exporter и публичного примера. Если нужен
Core body отдельного упражнения, согласовать именно эту зависимость с Core.
Это достаточная постановка следующей партии, но ещё не принятый новый ключ
YAML/API или подтверждённый Native payload. Рецензент новых ключей, весов,
фиктивных assessment и реализаций этого контракта не добавлял.
