# Native publication: независимое Source review чистого договора

**NEEDS_CHANGES: три конкретных уточнения до implementation.** Сам breaking vertical slice поддерживаю; backcompat старых proof/receipt/API не требуется. Source, runtime, compiler, tests, hash, network и budgets не менялись. Frozen recovery и Download d417 не затронуты.

Прочитаны [design](native-publication-clean-contract-20261104.md), [consumer map](native-publication-consumer-contracts-20261104.md) и адресные actual anchors Core5f/PL4d/Download d417/Site850. Проверка не является новым consumer census или runtime acceptance.

## Необходимые исправления

1. **[P1] Закрыть actual PL type graph, а не вывести `PublicationInspection` из сохраняющего `any` decoder.** Design объявляет canonical typed mapping и результат из существующего `decodePublicationBusiness`, но production scope PL перечисляет только `native-publication.ts`, `native-input.ts`, `public.ts`. Actual `application/native-business.ts:212–340` принимает `input:any`; `readNativeRaw` возвращает `config:any` (примерно132–140), `decodeBusiness` объявляет `assessment:any` (271). Следовательно, `ReturnType<typeof decodePublicationBusiness>` переносит `any` в `business.assessment`/`business.raw.config`; actual CLI `entrypoints/inspect-grading.ts:55–98` их действительно потребляет, используя дополнительные `any`. Typed Core input на call site не исправляет signature самого decoder.

   **Patch requirement:** включить `native-business.ts` и нужный существующий declaration/policy consumer в замкнутый type scope либо определить более узкий честный public result из реально проверенных выходов. Параметр общего parsed-input decoder должен быть actual Core input type; assessment — inferred schema output, непроверенная configuration — unknown до существующего decoder. Не ставить ручной typed return поверх `any` и не выдавать новый `ReturnType<any-producing-function>` за completed typing. Compiler graph должен включать actual `inspect-grading` entry и generated/imported consumers, а не только public exports.

2. **[P1] Уточнить, какую запись/очистку действительно откладывает close boundary.** В design `publish`/Site outputs обещаны после успешного Core closing; `discard` описан как освобождение собственного draft. Actual Download `runtime.ts:101–147` pre/prepare вызывает `clearOwned`, удаляя ZIP/manifest **до** нового closing, затем чистит requests и прежний receipt. Site вызывает этот API в `compose.ts:337–342,436–439`; кроме того `cleanOutput` выполняется432/443, а mounts копируются в post около555–580 **до** `finalizeDownloads` около660. У Site это уже реальная ранняя мутация, а не просто «конечная запись после close». Одна новая deferred функция сама по себе не меняет эти routes.

   **Patch requirement:** назвать отдельно Native preparation/requests cleanup и deferred archive publication. Зафиксировать, что `prepareNativeDownloads` не вызывает final-output cleanup/write; его draft владеет только уже materialized Download bytes/options/именным snapshot и не содержит live Core closures. Старый pre-hook должен иметь явную выбранную судьбу в public/entrypoints/Site callers: удалить преждевременный archive cleanup из Native preparation либо честно оставить его отдельным existing pre-render side effect, без обещания сохранности предыдущих outputs на closing failure. То же касается уже выполненных Native render/Site mount writes: или обозначить их как ранние существующие результаты, или показать конкретное допустимое переупорядочение. Новый transaction/rollback framework не нужен. `discard` должен быть безопасен до/после попытки publish: не удалять прежние/чужие outputs и не выдавать partial publish за rollback; при write failure именной manifest оставляет owned cleanup для следующей операции. Повторное publish/использование discarded draft должно иметь однозначный отказ/одноразовое потребление, без повторного Core acquisition.

3. **[P2] Сделать обещанную одно-capture acceptance конкретной, без переключения capture authority.** Design требует проверить обе Site ветви с/без Download и noPL/inactive PL на одном actual capture без повторного render. Existing Site fixtures реально задают Download pre/post/filter/config в authored `_quarto.yml` (`tests/site-public-operation.ts:62`, `site-native-pipeline.ts:64`); branch выбирается фактическим `config["project-download"]` (`compose.ts:287`). Core closing/currentness проверяет source/config/capture факты. Из текста пока не следует, как один и тот же current capture законно представляет две такие конфигурации. Подмена config argument либо изменение captured `_quarto.yml` между вызовами не квалифицирует настоящие обе ветви.

   **Patch requirement:** выбрать существующую маленькую fixture и описать реальное размещение независимых owners в одной invocation (например, root/child с заранее authored разными ветвями), либо сузить один actual run до одной ветви, а вторую проверить существующим Source/control способом с честным пределом. Аналогично назначить noPL/inactive path без fake live view. Не обещать повторное использование expired view/A1 batch. Closing-failure assertion должна проверять отсутствие **новых archive writes** и discard handle, сохраняя явные early-output ограничения из issue2. Это уточнение будущего плана; новых запусков сейчас нет.

## Что в design уже обосновано

- Это не facade над `validateRelease`: ordinary route отдельно выделяет Core semantic facts и PL partial business inspection, удаляет installed-contract proof scan/construction/parse, repeated release passes, ZIP SHA и artifacts receipt family. Именной ZIP manifest/CRC остаются собственными нужными механиками writer.
- Actual PL full `assertNativeSeedTargets`/grading-component qualification находятся в `native-adapter.ts:320–371`; новый inspector их не вызывает. При этом existing `decodePublicationBusiness` всё ещё выполняет syntax parsing `projectChecks`, materialization и `seed-targets` (`native-business.ts:198–203,322`). Это остаточный metadata vet, не full seed relation qualification; итоговый report не должен объявить удалёнными вообще все seed/check parses. Нужные public/private materialization policies сохраняются.
- Сохранённый handle присваивается **внутри** callback до outer closing, поэтому shown catch способен вызвать discard и при closing rejection. Existing Core lifetime `operation.ts:2357–2399` проверяет active/failed A1 batches, делает closing guard/hostGuard и только потом возвращает callback result. Новый shared acquisition обязан сохранить этот фактический порядок, а не выпускать archive draft наружу раньше него.
- Post-close catalog/course/inspection должны быть plain owned data. Existing Core catalog строится из privately parsed `complete.catalog` и рекурсивно immutable (`operation.ts:2555`, `document/condition.ts:13–18`); такой уже принадлежащий Core snapshot можно возвращать как data без нового full schema/freeze/proof. Borrowed methods/project contexts после callback не переносятся в draft или Site DTO. Type readonly само по себе ownership не доказывает; ownership source нужно сохранить при выделении builder.
- Граница отдельной PL delivery/Platform persisted identity не скрыта. Source currentness/acquisition signatures, teacher/student artifact roles, A1 lifetime и path protections остаются отдельными реальными условиями. Их сохранение не доказывает cache freshness и не обнаруживает arbitrary unmarked profile-dependent computed text; эти ограничения design назвал корректно.

## Итоговый scope для delta review

Нужно дополнить уже предложенный vertical slice реальным PL decoder typing, явными pre/post cleanup semantics и достижимой future fixture acceptance. Новые certificate/receipt/hash/registry/cache/proof механизмы не требуются. Исторические внешние артефакты не мигрировать; неизменность содержимого курса не превращать в новую publication authority. После этих точечных поправок возможен delta review того же design без runtime и без общего нового аудита.

Дополнительно подтверждено, что это **реальное удаление лишнего gate**: `withNativePublication` сохраняет Core semantic checks exact coverage/course/projection/declared targets/assessment membership/visibility/public solution (32–41), но ordinary inspector не вызывает прежний `validateRelease` или full `validateCourse` и не зависит от copied `genuineReleaseProof`. PL relation grading/seed qualification отделена от остающегося syntax parsing (49/58/62). Удаляются proof construction/parse/forwarding, receipt family и per-ZIP SHA, без replacement certificate. Core владеет canonical metadata/session types; PL — checked inspection output; Download — draft/options/request consumer view; Site импортирует эти actual owners (79–87). Отдельная persisted PL delivery/Platform identity ветвь не затронута данным approval.

Незакрытых требований к этой design delta не найдено.
