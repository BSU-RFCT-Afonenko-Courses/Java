## Основной вывод

Сохранять нужно достоверность **записанного** времени, статуса и владельца процесса. Полный inventory инструмента/курса, лексическое «покрытие» установленных пакетов, SHA всех binaries на каждый diagnostic run, автоматический экспорт всех trace views и непрерывная проверка всей process group — отдельные наши решения. Они не следуют из Native Quarto/Pandoc и не делают измерение полным. Часть из них можно убрать из обычного наблюдения и оставить на фактической границе подготовки/установки или явной глубокой диагностики.

Самый конкретный новый кандидат actual924 — `/proc` scanning в normal render supervisor с шагом10 ms, пока child ещё работает. Второй — package coverage full project walk при обычном summary, хотя итог complete остаётся false. Доказаны исполняемые Source пути и частота по конструкции; время этих двух расходов **UNKNOWN**. Сохранённые SP captures не измеряли именно general `renderCommand/runOwnedProcess` путь, поэтому переносить на него их малый preparation/report overhead нельзя.

Для Java128 причина900 s не установлена. Она не доказана ни количеством initial hashes, ни inclusive spans малого SP, ни числом QMD. ABI1 Performance в неудачном Java запуске не активировался; приписывать timeout сегодняшнему Performance supervisor/normalizer неверно. Необходимость содержательных checks можно пересмотреть отдельно от отсутствующего измерения их wall cost.

## Реальная необходимость метрических границ

Нужны следующие свойства, и Native нижний слой не может восстановить их за инструмент:

- Различать TS monotonic wall и Lua process CPU (`src/agents/{ts/agent.ts:23,lua/agent.lua:3–4,33}`), executor/run identity и калиброванную/локальную шкалу. Inclusive nested intervals нельзя складывать или объявлять self/startup. Процессные parent/child receipts пересекаются.
- На ingest проверять sequence, begin/end identity, конечные неотрицательные timestamps, дубли/aborted, drop/incomplete/error counters (`src/protocol/validate.ts:2–42`, `analysis/normalize.ts:143–263,313–418`). Иначе испорченный/неполный trace выглядел бы точным временем. Это semantic correctness, не требование неизменности исходников курса.
- Missing summary/status/timing остаётся unknown/partial. Timing924 `launchers/tool.ts:124–144` измеряет только spawn→полученный status; initial null и старые receipts без timing нельзя превращать в0. Standalone SIGTERM остаётся UNKNOWN: прежний fixtureFAIL30 s, short ad9 discriminator не полный baseline и не signalPASS. Новых signal опытов аудит не проводил.
- Native code/signal и отказ диагностического слоя хранить раздельно; `render.ts:167–181,247–255` и `run.json` позволяют видеть native outcome независимо от data validity. `VALID` относится recorded semantics, `coverageComplete=false` — честная неполнота scope. Собирать «полное покрытие» через всё больше Source scans не требуется для полезной статистики.
- Защита output/staging от попадания в публикацию и случайного перезаписывания чужого run (`runner/storage.ts:25–108,145–181`) имеет реальную пользовательскую цель: logs/paths/profiles не публиковать как учебные ресурсы. Это не основание для full content SHA курса.

`validateEvent` не закрывает неизвестные поля exact key whitelist; это проверка используемых semantics. Её не следует описывать как наш JSON allowlist всего Native AST. TypeScript types не заменяют этот внешний telemetry boundary, но после единственного ingest можно передавать уже проверенные интервалы/агрегаты без повторного построения того же matcher в каждом exporter.

Для максимальной own TS типизации здесь есть **отдельный незакрытый долг**, который нельзя скрыть словом strict: `src/protocol/validate.ts:4` приводит неизвестный объект к `Event`, но для `span_id`/`operation_id` строки28–32 устанавливают только truthiness, а не тип string. Следовательно, существующий guard не доказывает весь возвращаемый Event DTO. Исправление typing не должно автоматически добавлять новые runtime refusals: честно описать реально доказанную часть/unknown и затем сузить у фактического consumer либо отдельно согласовать изменение публичного telemetry контракта. Новый validator или percentage-coverage framework не требуется. У generic wrappers `agent.ts:128–159` остаются `any/as T` для сохранения call signature; generic signature сама по себе не подтверждает runtime semantics всей async/coroutine цепи.
