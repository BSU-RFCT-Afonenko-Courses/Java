# Download → Site: фактически потребляемый publication contract

Source-only карта для architecture owner. Download final `d41705f` (typing относительно671), Site850; существующие [pattern map](pattern-pass-export-20261104.md), [identity map](hash-mechanism-consumer-review.md), [Site typed review](site-typed-core-pl-review.md). Адресно прочитаны только три актуальных prod-файла: Download `infrastructure/siblings.ts`, `infrastructure/runtime.ts`, Site `application/compose.ts`. Ни compiler/runtime/network/census, ни Source edits. Backcompat не задаётся как требование нового design; новых DTO/adapters/schema здесь нет.

Важно направление: Site вызывает Download, а catalog/release metadata возвращаются callback в Site. В callback второй аргумент назван `proof`, но фактически Download передаёт **release-объект** `{proof, validationPasses, metricsBefore, metricsAfter}`, а не голый NativeReleaseProof.

Самые прямые couplings для нового design: (1) release proof в Download нужен для существующего release pass и уходит только в callback/receipt; (2) Site Download-ветвь фактически требует catalog coverage, а release хранит для отчёта; (3) Site без Download имеет собственный двухпроходный route с иным PL validation. Нельзя молча объявить их одинаковыми, но сохранение старого certificate/adapter wire не является заданной целью breaking design.
