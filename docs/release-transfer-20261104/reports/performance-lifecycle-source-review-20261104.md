### 3. [P2] Process observation объединяет два stream состояния и не публикует open/EOF/failed факты своевременно

`src/runner/process.ts:269–276` выводит **оба** состояния как `streamsFinished && !failure ? "eof" : "open"`. `tee:142–186` сообщает только общий failure; индивидуальные EOF/open/failed не обновляются. Наконец, unrelated later supervisor failure может превратить оба действительно закрытых stream в open.

Это ошибка factual instrumentation/contract, не предложение менять group/PTY machinery. **Минимальное исправление:** хранить отдельные stream facts; existing pumps публикуют actual open/EOF/first log/read/write/close failure немедленно. Snapshot получает отделённую копию этих facts, а общий `failure` не переписывает уже известное состояние другого stream. Callback после actual acquisition должен позволять render видеть open до status. Partial publication и teardown при этом остаются независимыми; новый framework/supervisor не нужен.
