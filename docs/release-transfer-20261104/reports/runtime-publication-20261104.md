## Получившееся поведение

`tools/publish-receipt.py` создаёт только `runtime-image.json` и `published-runtime-profiles.json`. Они содержат реальный source commit/version и OCI image references по ролям Java/fish/Community/Workspace. `runtimeProfilesSha256`, generated lock и dependency/runner/shared-file inventories не создаются. Publisher не импортирует подготовительный installer и не требует `.native-toolchain`.

`tools/release_assembly.py` удалён целиком: нет сравнения полного Git tree/index/файлов, overlays, повторного recheck или собственной authority assembly. Удалены обязательные calls в `build-course.py`/`stage_courses.py`, V2 assembly provenance и deferred admission policy. Нет fallback/no-op recheck. Исторические собственные tests equality/forgery/overlays/preparation удалены; публичные launch/staging/privacy tests сохранены и приведены к новой границе. Удалена старая CI задача exact c020 lock-assets/private-stage, проверявшая прежний installed code, а не новый candidate.

CI собирает обычный Docker context и проверяет public grader behavior. Новый image smoke `test_plain_image.py` предоставил writer grader; локально Docker не проверялся. Dockerfile-specific ignore разрешает только runtime/profile/grader/helper source inputs; корневой `.dockerignore` дополнительно исключает сохранённый `.native-toolchain`. Старые on-disk caches/data не удаляются.

Схема runtime-image-v3 больше не содержит runtimeProfilesSha256. Published profiles v2 уже имела обычные profile objects и отдельный Workspace image и новой собственной registry системой не заменяется. Существующий checked-in runtime-image2.2.0 сохранён как историческая запись прежней публикации; её image/source refs не переписаны под новый candidate и не выдаются за новую публикацию.

## Остаток

Удалён именно runtime/source/toolchain inventory слой. Старые course delivery/provenance/verification hashes в build-course/stage/Gateway по-прежнему существуют и не являются новым целевым API. Их закрытый producer/mandatory-reader пакет требует выбора Native/Gateway границы совместно с главным владельцем PL. Новая hashless PL поставка с нынешними readers несовместима; обход admission не предлагается. Типизация реальных новых service/SQL границ пока не выполнена, поскольку новый wire ещё не выбран; пустые generic DTO не введены. Ни аутентификация, ни configuration среды, ни live DB, ни старая VM/история не менялись.
