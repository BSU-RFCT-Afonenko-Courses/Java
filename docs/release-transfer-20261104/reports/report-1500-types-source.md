# Типизация расширений: материал к обсуждению в 15:00

На 4 ноября типизация продвинулась прежде всего на границах между нашими расширениями и на входах из JSON. Теперь больше значений проходят путь от проверенного входа до настоящего результата API без потери типа посередине. Это помогает компилятору находить перепутанные аргументы и несовместимые результаты до запуска курса. Это не означает, что весь стек типизирован, что исчезли все `any` или что принятые исходники уже установлены в production. Ниже отдельно описаны сделанные изменения и оставшиеся ограничения. Новых проверок для подготовки этого текста не проводилось.

В **Core** закрыта важная граница Native owner и A1 context. JSON inspect остаётся неизвестным значением до проверки реально потребляемых полей; после этого код получает настоящий owner DTO. Произвольные поля metadata сохраняются, а не отбрасываются ради удобной маленькой схемы. Для operation context сохранено более сильное требование к input, а A1 не заставляет поставщика передавать поле, которое сам не использует. Эта работа не меняет происхождение, роль и срок жизни контекста. Отдельно локальный обход condition переведён на `unknown`: он извлекает URL Link/Image и обходит остальные контейнеры, сохраняя индексируемые объекты, массивы и строки. Полный собственный Pandoc union ради этого не вводился.

В **PrairieLearn** основной результат — связь consumer-кода с реальными публичными типами Core. Lazy loader, capture, lease, operation, планы, condition, bindings и inventory больше не описываются независимым приблизительным интерфейсом. Типы результатов сохраняются дальше при materialization, подготовке course/export, записи файлов и обработке feedback. В legacy scoring устранены отдельные разрывы, но произвольный upstream JSON не объявлен доверенным. Сохранилось и предметное различие между приватным owner proof и обычным чтением физических файлов: это разные возможности, которые нельзя уравнять одним типовым утверждением. Небольшой computed-consumer опыт подтвердил конкретный путь Table/Image/inline → README/ресурсы/ZIP, однако он не заменяет проверку всего курса или grading.

В **Download** типизирована цепочка operation → plan → materialization/inventory с использованием настоящих sibling API. Для late envelope, MetaString и Attr используются фактические существующие проверки, без выдуманной полной AST-модели. Затем разобран early-filter: preflight и рекурсивный обход получают `unknown`, а recognizer/request/location сохраняют только те свойства, которые действительно потребляет алгоритм. В этом файле убраны явные `any`, casts и `key!`, но неизвестные Native узлы и дополнительные поля не превращены в закрытый список вариантов. Последний небольшой срез удалил внутренний JSON round-trip ownership signature: sources сохраняются из уже типизированного `OwnedRequestState`, вместо позднего parse с потерей типа. Саму signature/currentness гарантию эта правка не удаляет и не оправдывает заново.

В **Site** typed facade связывает вызовы Core и PL с фактическими модулями и их публичными параметрами. Второй proof, для которого нет достаточного договора, честно остаётся `unknown`; он не переименован в genuine Core proof. Отдельное решение пользователя разрешило удалить alternate-audience inspect при уже имеющемся разделении output конфигурацией. Это самостоятельное изменение поведения, а не следствие улучшения типов. Существующие12 output/profile пар сохранили конфигурацию без переименования. Полное совместное хранение двух новых выдач и production acceptance новым проходом не проверялись; cache isolation этим тоже не обеспечивается. Другие provider overloads и state/config JSON ещё требуют адресного разбора.

В **QRC** SearchRow стал небольшим потребляемым DTO: href/text проверяются существующей границей, дополнительные metadata остаются неизвестными и сохраняются. Publish получает окончательные обработанные rows без второго чтения и JSON.parse. Для одинакового физического index path сохранена прежняя семантика последних записанных rows. Post inspect/config boundary теперь держит JSON неизвестным до узких guards; проверяется только выбранное значение output после прежнего ENV/nullish выбора. Здесь были явно разрешены проверки record и типа выбранного output, поэтому неверно говорить, что runtime-проверок вообще не добавлялось. Это конкретизация внешнего входа, не повторная полная валидация config. Lua Attr cleanup отдельно убрала сортировку map перед Native Pandoc; это семантическая очистка, не TS-покрытие.

В **Performance** закрыта внешняя Event JSONL граница: вместо `as Event` проверяются потребляемые поля и optional значения, неизвестные дополнительные поля сохраняются. Это не делает типизированными все executor, launcher и report paths. Улучшения streaming logs и представления команд решают другие задачи и не засчитываются в типизацию. Текущая работа по interruption/partial reports также должна приниматься отдельно: Source review, завершённый control и фактическое recovery — разные свидетельства. Незавершённому опыту нельзя присвоить PASS только потому, что его schema или компилятор не возражают.

Заметная часть работы состояла в удалении ложных утверждений. Убраны отдельные casts там, где можно сохранить тип производителя, две Navigation suppressions переназначения function bindings заменены typed wrapped const. Но Navigation FFI doublecast пока оставлен открыто: реальные parse5 declarations есть в vendor, а их внутренние imports не образовали рабочий declaration graph в текущем checker. Первый отказ сохранён. В Core YAML ситуация другая: происхождение точного vendor build и соответствующих declarations ещё не подтверждено. Ни ручной AST, ни системная версия библиотеки не выдаются за решение этих пробелов.

Открытый **Platform** долг включает service signatures, query-specific PostgreSQL rows и цепочку decoded results. Публичный PostgreSQL Source получен, но installed declaration composition ещё не собрана. Callback generic сам по себе не проверяет форму строки запроса. Собственные browser JS, CLI/tools и оставшиеся тестовые fixtures также не объявлены закрытыми. Тестовые `any` удалялись адресно, когда скрывали несовместимость изменяемого API; общего «озеленения» всего test-кода не проводилось.

Для следующего обсуждения предлагаются три ограниченных выбора:

- Связать существующие parse5 declarations переносимым способом и снять FFI doublecast, сохранив реальную расширяемую модель библиотеки. Это отдельный scope после неудавшейся однофайловой попытки.
- Восстановить точное происхождение Core YAML bundle и matching declarations. Пока этого нет, продолжать Source plan, а не рисовать типовую совместимость.
- Для Platform сначала собрать настоящий service/PG checker graph, затем выбрать один конкретный query/result DTO. Не начинать с `queryRow<T>`, который лишь утверждает желаемую форму.

После отчёта дальнейшая работа останавливается для обсуждения. Ни один из этих пунктов не требует нового общего аудита, процентов покрытия, повторных Native прогонов или production переключения без просмотра пользователя.
