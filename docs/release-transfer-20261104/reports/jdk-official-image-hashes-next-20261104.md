# Official image: повторные SHA после admission

**Решение Source-only:** есть ограниченный кандидат — снять только повторное чтение/SHA runner, bundle и shared files в official `grade → preflight` после успешного `_admit_java_job`. Host/nonofficial и прямой `preflight` сохранить с полной проверкой. Это снятие собственной гарантии обнаружения изменения фиксированных image bytes, а не ослабление проверки студенческого входа. Реализация, проверки и новый image пока не выполнялись.

Источник: Platform `6491517b896b17119fd2ab44db1a2de2ff9c93b1`, clean при чтении; [предыдущая карта per-job reads](jdk-per-job-read-boundary-20261104.md). Прочитаны только соответствующие grade/admission, Dockerfile, baked-view и container/host callers. JVM/Gradle/Docker/hash/tests/network/production не запускались; Source/state не изменены.

## Какая сторона может писать

`images/java25-grader/Dockerfile:5–20` копирует runtime, runner и baked registry в `/platform`, затем делает `/platform`, `/operator`, `/javagrader` root-private `0700`; helper — root-owned executable вне `/grade`. `tools/grading_job.py:913–944` запускает exact `job[imageDigest]`, монтирует **только job в `/grade`**, с network none. Host-ветка `:896–910` импортирует runner из рабочего checkout и может передавать registry — это другая граница.

`grade.py:2640–2651`: сначала existing descriptor checks, remapping input UID/GID и `_admit_java_job`, затем preflight. Admission `:2020–2029` проверяет tool installation/ownership и разделение `nativebuild`/`sbuser`; `_grading_boundary_unchecked:364–402` требует supervisor UID0/container и реальный отказ доступа grading-role к build JDK. Непривилегированные student/test JVM идут через `runuser … sbuser … landlock_sandbox` (`:1281–1308`, `:1626–1658`), Gradle — `nativebuild` (`:2095–2148`). Копии JAR/adapter в private job (`:935–974`, `:1063–1072`) не открывают `/platform` для этих ролей.

Это **не read-only root filesystem**: supervisor/root или оператор с дополнительным mount может менять image files. Existing admission не проверяет `/platform` root mode заново; защита этой директории следует из контролируемой сборки/запуска, а не из самого слова official. Actual deployed mount overrides и текущая квалификация нового image здесь **UNKNOWN**. Один `PL_CONTAINMENT=official` вне этой композиции не является достаточным основанием отключить проверки.

Важная граница helper: `_admit_java_job → _grading_boundary` **уже исполняет helper до** последующего `preflight → _verify_landlock_helper`. Поэтому нынешний per-job SHA нельзя описывать как криптографический admission до его первого исполнения. Это не доказательство неисправности actual helper и не повод расширять текущую задачу новой attestation.

## Один следующий diff

В `grade.py` отделить existing byte-verification часть preflight от остальных existing checks; default оставить полным. Только caller `grade`, после успешного official admission **и при `registry is None`**, выбирает отсутствие повторного runner/bundle/shared SHA. Переданный registry и direct preflight остаются проверяемыми: library/test/host callers не получают автоматического bypass от environment. Новых manifests, cache, receipts, validators или runtime probes не нужно. Existing runner-pin companions при будущем изменении grade обновляются обычным способом; published image/history не переименовываются.

Не менять returned profile/bundle/toolchain, protocol, `dependencyHashes`/`dependencyHash`, feedback/scoring или statuses. `grade.py:2659–2672` уже строит evidence **из declared pins**, а не из локальных digest variables; consumers `tools/grading_job.py:1199–1248` сравнивают эту closure с registry. Поэтому формат и значения evidence сохранятся. Однако для official ветки это станет ссылкой на build-selected closure, **без прежней per-job повторной проверки bytes**; не называть её свежим byte-attestation. Host `runtime_evidence:151–175` и verification callers `:982–986` остаются со своими существующими SHA — данный diff их не убирает.

Наблюдаемое изменение: обычный заранее собранный image не перечитывает fixed bundle/JAR/shared/runner ради checksum; случайная root-side правка с сохранёнными declared pins перестаёт давать именно эти ранние checksum mismatches. Дальнейший missing/import/compiler failure должен оставаться infrastructure failure, но нельзя обещать обнаружение любой семантической root-side правки: это и есть снимаемая гарантия. Не найден student-writable путь, который требовал бы этих SHA в показанном official caller. Нештатный mount `/platform` — конкретный случай вне выбранной композиции, где прежняя проверка ещё полезна; фактический production mount здесь не установлен.

Не включать в этот diff `native_build` source/config/artifact/copy checks (`:2188–2220`, `:2331–2348`), private grading inputs, roles/UID, path/link checks, helper enforcement, JDK/Gradle admission или runtime version diagnostic. Там есть реальные job-local mutable inputs и отдельные consumers, даже если некоторые recipe SHA тоже повторяются.

**Стоимость:** устраняются byte-pass runner +16 bundle entries + profile shared entries на достигнутом preflight. Размеры, wall/CPU/RSS, filesystem cache и выигрыш **UNKNOWN**; предыдущий отчёт содержит Source counts, не benchmark. Новый runtime image не собран/не квалифицирован; автоматического security veto или production GO этот анализ не даёт.
