## Решение

Новый QRC pin не должен требовать наличия удалённого private `infrastructure/metadata.ts` и не должен снова обещать равенство HTML bytes. Для новых результатов достаточно убрать обязательную HTML byte comparison из этого offline gate, сохранив состав output файлов, фактическое содержимое ресурсов/копий, ZIP entries/bytes и существующий leak scan. IDs/targets/labels проверяет существующий предметный QRC путь и его регрессии. Создавать вместо удалённого helper второй HTML parser/comparator, normalization/hash/proof framework не нужно.

Это намеренное сужение гарантии offline инструмента. Оно **не доказывает семантическую эквивалентность произвольных двух HTML-деревьев**. Пропуск HTML content comparison нельзя записать как прежнее безусловное `equivalent: true`. Старое воспроизведение остаётся отдельным явно выбранным историческим режимом: он читает прежний pinned blob и сохраняет прежнюю ошибку, если blob действительно отсутствует. Автоматический fallback с исторической строгой проверки на облегчённую после ошибки `git show` недопустим: он скрывал бы неисправность выбранного режима.

## Минимальный пакет изменения

1. **Два offline tools.** В `validate-java.ts` и `recheck-repeat.ts` сделать прежний owner replay явным opt-in историческим режимом командной строки, не выводимым из наличия/ошибки private blob. В обычной ветви вообще не вызывать `loadOwnerNormalizer`; не требовать manifest только ради normalizer. Сохранить существующие positional workspace/snapshot/control аргументы. Историческая ветвь использует уже существующий manifest argument и прежний helper без изменения frozen SHA. Исторический mode и обычный mode выбираются до comparison; отсутствие historical blob остаётся отказом лишь выбранного replay.
2. **Один узкий параметр существующего comparator.** В `src/analysis/outputs.ts` добавить явный пропуск HTML content comparison для этих новых tools; default strict и старая historical ветвь остаются прежними. Проверять missing-file до пропуска. Остальные файлы и ZIP обрабатывать прежним путём. Не добавлять новый `OutputPolicy`, DTO schema/manifest version или дерево HTML. Этот параметр означает только «не сравнивать HTML bytes»; он не означает «HTML семантически совпадает».
3. **Честный результат.** Для новой ветви tools явно записывать `htmlBytesCompared: false` и результат сравнения проверенного содержимого; поле общего безусловного `equivalent` новой ветви убрать/переименовать по этому узкому смыслу, например `checkedContentEqual`. Exit 4 остаётся при missing/different проверенных outputs либо leaks. Старые historical reports и их `equivalent` не переписывать. `ownerNormalizer` и его policy text появляются только в historical result. Для repeat recheck не оставлять через `...original` старое `equivalent: true` как будто оно снова доказано: результат recheck должен явно заменить/исключить это поле в новой ветви.
4. **Repeat producer — только при его дальнейшем использовании для новых pins.** `tools/repeat-java.ts:46–60` передаёт тот же narrow option и пишет честный scope/result вместо общей эквивалентности. Без этой небольшой согласованной правки новый `repeat-java` всё ещё может отказать на harmless metadata order до offline recheck. Его Source correction входит в минимальный согласованный пакет, если планируется весь новый repeat workflow. Сами renders этим companion не назначаются.

Итого: три обязательных production файла (`src/analysis/outputs.ts`, два offline tools), четвёртый `tools/repeat-java.ts` для согласованного нового repeat workflow. `owner-normalizer.ts` остаётся изолированной исторической совместимостью; его безусловная зависимость у новых pins исчезает. Полное удаление этого файла потребовало бы прекратить прежний replay или скопировать нормализацию в Performance; это не меньший совместимый шаг. `types.ts`/config validator/scenarios/scaling/runner/protocol/process/installed providers менять не требуется. Новые flags/поля здесь — предложение конкретного интерфейса, реализация ещё не выполнена.

## Смысл, который уже проверяется по назначению

- **IDs, targets, labels, URLs и local/full.** QRC873 `tests/metadata-order.ts:18–54` проверяет оба порядка attrs через реальные `readPage/linkPages`: target DTO, title, HTML/text labels, href/ref/style/custom/deferred, local source/namespace/hidden/aria и full removal. `tests/local-linking.ts:28–56` дополняет known/imported/current targets, meaningful deferred/custom labels, full/default unknown-target и malformed ref/style. Production `pages.ts:26–67` проверяет IDs/native href/labels/anchor count; `linker.ts:23–44,83–88,107` сохраняет validation/escaping/probe removal и edits. Переиспользовать эти проверки; не возвращать HTML byte snapshots.
- **Resource/copy/ZIP.** Comparator оставляет file membership и non-HTML content, historical ZIP entries/bytes. `site-java/tests/site-native-pipeline.ts:185–207` уже проверяет реальные README final targets/download URL и выдачу root resource; `:214–223` — existing delivery bytes assertion. Эти тесты не становятся обязательным новым запуском companion. В рамках него нет замены ZIP writer/CRC или изменения copy paths/ownership.
- **Student privacy.** QRC full probe removal проверяется отдельно; `site-java/tests/site-project-native.ts:251–285` проверяет настоящие student/common bytes, private/reference separation и public/closed resource выдачу. Performance leak scan проверяет собственные instrumentation artifacts, а не весь учебный closed content. Сохранение этого scan не позволяет назвать новый offline result полным privacy proof. Existing owner проверки остаются предметным acceptance; произвольный HTML content drift новым gate не обнаруживается.

## Ограничения

Удаляется собственная цель равенства HTML bytes в новом gate; не добавляется доказательство, что любой изменённый HTML сохранил учебный смысл. Arbitrary text/ID/link drift между двумя сохранёнными outputs новый offline режим сам не обнаружит. Это осознанная цена удаления церемониальной общей гарантии, а не основание назвать пропуск проверкой. Предметная регрессия и финальная функциональная приёмка выбранного release остаются у реальных owners; новый общий DOM normalizer ради восстановления прежнего обещания не предлагается.

Стоимость прежнего offline loader/hash/whole HTML compare в секундах UNKNOWN; новые замеры не назначались. Удаление QRC runtime двух canonical passes уже рассмотрено отдельными accepted writer/reviewer reports и этим планом повторно не измеряется. Совместимость исторического798 зависит от доступности его Git objects и paths из manifest, как и раньше; отсутствие этих данных не лечится восстановлением helper в новом QRC pin.

Перед передачей снова прочитан весь собственный primary интервал от того же origin turn; `turn_context` строка 8 остаётся единственной записью и подтверждает обе пары `gpt-6.1-sol/medium`.
