## Вывод

Обычное исполнение Quarto не требует нашего нового frozen/proof/cachekey договора. R3 уже доказал engine → вычисленный Markdown/AST → пользовательский фильтр на R/Python. Исторические слова R3 «static требует нового договора» описывают **наше тогдашнее решение и отказ Core**, а не ограничение Quarto и не основание запретить computed. Разрешение вычислений при этом должно убрать реальные несовместимости собственной currentness с изменяемыми engine cache; одного удаления static gate недостаточно.

Нативная свежесть не означает автоматическое обнаружение изменений любых внешних данных. Автор вправе выбрать freeze/cache, исполнить отдельный документ, отключить cache или явно обновить его. Наша обвязка не должна заменять этот выбор blanket запретом или обещать более сильную свежесть, чем выбранный Native режим.

Есть **условный privacy риск при открытии computed**, уже подтверждённый R3 как cross-profile reuse: frozen произвольный текст `PROFILE=full` был повторно взят student render без исполнения. Это не установленная утечка Java/SP: текущая static admission вычисления отвергает, частные байты курса не наблюдались. Размеченные solution/test AST проходят собственную ролевую проекцию; произвольный **неразмеченный** текст, напечатанный ячейкой в зависимости от профиля, такой метки не имеет. Смена профиля/output-dir сама по себе не гарантирует иной execution result. Root уведомлён отдельно; новый общий gate не предлагается.

## Штатный контроль профиля и обновления

Минимальный безопасный авторский вариант для произвольного audience-dependent computed текста — в **существующем** student/author profile задать `execute: {freeze: false, cache: false}`. Это Native настройки, не новый режим нашего API. В pinned Source cache false выключает knitr hooks, а project thaw при freeze false не выбирается без явного `--use-freezer`. Один профиль может оставаться freeze:auto, если другой явно не читает общий freeze; разные output-dir без execute options этого не обеспечивают. Стоимость свежего исполнения определяется реальными ячейками, не измерена здесь.

Если нужно именно повторное engine-cached исполнение двух профилей, Native уже имеет отдельные **knitr `cache.path`** через `knitr.opts_chunk` и **Jupyter `JUPYTERCACHE`** через окружение. При общем project root сначала отключается общий project freeze; потом автор может выбрать разные literal cache paths / разные значения env при запуске соответствующего existing profile. Это не готовая автоматически доказанная схема profile interpolation: её нет в прочитанной обвязке, frozen Core env выбирается **до одной operation**, а не меняется по ходу callback. Общий mutable source tree нельзя молча сделать двумя audience cache roots. Наличие custom cache location не означает разрешение публиковать его как public resource.

Для явного обновления внешних данных: `quarto render document.qmd --cache-refresh --profile student` обходит project freeze как individual render и обновляет engine cache, если он выбран/установлен. **Один** `--cache-refresh` при global freeze не доказан refresh всего вычисления: parser `:20250`, metadata flags `:91290` меняют только `execute.cache`; thaw происходит раньше engine. Для обычного root/project render обновление можно запросить Native config `execute: {freeze: false, cache: refresh}`. `--no-execute` и `.ipynb` с уже сохранёнными outputs — отдельная Native семантика; их нельзя выдавать за свежее исполнение или запрещать только за происхождение не из текущей ячейки. Подробный engine→consumer разбор — отдельный owner отчёт.

## Два ограниченных следующих шага, без нового framework

1. **Сохранить Native project selection в SP Site вместо per-document fallback там, где уже выбран один поддерживаемый web target.** Existing `application/compose.ts` + `infrastructure/config.ts`, reuse уже существующего J design. Нужна явная совместимость старого string-list subprojects и native formats; никакого молчаливого html выбора. Не добавлять cache refresh. До реализации — только Source/config решение; после diff максимум одна existing small composed fixture с global freeze hit и поздним consumer, бюджет60s, без курса/новых kernels. Это проверяет wrapper question, не повторяет R3 engine experiments. Mixed-format fallback, который нельзя выразить одним выбранным target без изменения accepted API, оставлять отдельным точным остатком.
2. **После текущего owner-admission пакета снять remaining whole-tree currentness с native engine caches на general computed route, сохранив selected input/config/role authority.** Сначала определить в existing engine/config результатах реальные cache/supporting paths и late-resource consumers; не заводить registry и не угадывать owner по suffix. Начальный Source-only budget20min, production потолок3files. Если existing producer не даёт нужной границы — записать конкретный gap, не добавлять новый общий validator. После согласованного diff максимум2 адресных lifecycle cases на уже установленном R: первый записывает cache, второй повторно потребляет поздний public AST/resource при выбранном Native refresh/reuse; общий cap60s, no retry/новый kernel. Нативные R3 data/include/profile cases не повторять. Privacy assertion относится к маркированным ролям и выбранному авторскому профилю, не к автоматическому обнаружению секретного текста в arbitrary output.

Ни один шаг не начат и не утверждён как готовая правка. Actual student files/результаты и grading/goals/scores не должны меняться. Static route fix другого owner не оценивался по dirty diff. Новые runtime guards ради unknown/type coverage, cachekey/proof framework и общий запрет computed не нужны.
