**Редактор существует, но overrides его почти везде выключают.** Java default — editor/Java; 127 из 128 карточек явно задают upload, одна (`exr-numbers-short-circuit-and`) наследует editor после адресной A4 правки. Среди 118 проверяемых проектов 76 имеют один фиксированный primary source: **1 editor, 75 ещё upload**. Их source-profile-selected starter — UTF-8, без NUL, ≤1 MiB; это кандидаты существующего editor-контракта, не подтверждение установленного UI. Ещё 29 имеют free-primary (`primary-required:false`), включая 26 физически однофайловых starter: текущая собственная PL validation допускает для них только upload. Это ограничение нынешней реализации, а не принятое требование сохранять upload: собственный контракт разрешено менять без обратной совместимости, редактор должен стать режимом по умолчанию. Ещё 13 имеют несколько фиксированных primary sources и 10 — manual; все сейчас upload. Число файлов не равно числу вопросов: editor строит по контролу на каждый `b.files`, а free-primary делает перечисленные primary filenames необязательными для загрузки и принимает остальные исходники через ZIP с относительными путями; свобода имён и пакетов ограничена условием конкретного задания. Поэтому нельзя включать редактор по одному лишь числу файлов. Literal `FileMode`/`tasksettings` в адресно прочитанных authored Java QMD/YAML и PL Source не найден; действующий договор называется `submission.mode`, а настройки вопроса возникают из defaults и атрибутов. SP имеет иной default upload: шесть явных upload и один workspace, Java editor-default на него не распространяется.

Адресные примеры free-primary: `exr-numbers-argument-sum-product` имеет один `Main.java`, но условие сохраняет класс запуска `Main` без пакета и свободные вспомогательные классы/пакеты (`bank/numbers.qmd:231`, `:238`; `_quarto.yml:2562`). Поэтому `primary-required:false` само по себе не разрешает переименовать обязательный API или класс запуска: оно позволяет представить разрешённое решение целиком ZIP-архивом, без отдельного файла с ожидаемым upload filename. `exr-arrays-cyclic-matrix-shift` имеет один `Study.java` с каноническим входом `Study.shift(int[][],int,int)` (`bank/arrays.qmd:188`, `:217`; `projects/arrays/cyclic-matrix-shift/starter/src/main/java/Study.java:1`); этот API сохраняется, а внутреннее решение и дополнительные классы могут лежать в других файлах. Физически один starter не означает обязанность сдать только один файл.

Для editor с сохранением такой свободы нужно согласованно изменить существующую validation ветку `export.ts:933–938` и представление/приём исходников: нынешний editor всегда создаёт контролы для фиксированных `b.files` (`:944–976`), upload разрешает эти имена как optional вместе с архивом (`:978–985`), а отдельный ZIP уже поддерживается и рядом с editor (`:992–996`). Нельзя только убрать запрет и обязать присылать нетронутый starter вместе с заменяющим решением: сохранённый учебный stub способен конфликтовать с исходниками из ZIP. Контракт должен однозначно определять, какие отредактированные primary sources участвуют в сборке, как разрешены их отсутствие/замена допустимыми именами и как добавляются файлы/пакеты, сохраняя обязательные API задания. Конкретный UI и новая схема здесь не разработаны и не внедрены; это граница согласованной Source-задачи, а не основание оставить upload навсегда.
