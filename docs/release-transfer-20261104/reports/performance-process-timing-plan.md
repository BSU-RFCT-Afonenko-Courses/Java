**Что именно измеряется.** Разность одного локального монотонного clock в launcher: synchronous spawn + ожидание native child status, включая минимальное host bookkeeping/listener registration и возврат status в JS. Включает startup/preload самого binary child, но не отделяет его от полезной работы/I/O/ожидания descendants. Не включает launcher bootstrap/argv/data-dir preparation до spawn и final receipt/activation reads после status. Вложенные child envelopes перекрываются; суммировать их как общий wall нельзя. Абсолютные start/end и epoch alignment не предлагаются; duration не создаёт global timeline или новый Event span. Launcher самого агента сейчас не устанавливает; попытка использовать Metrics/Span API здесь потребовала бы новый agent/executor/буфер/flush и была бы крупнее двух локальных clock reads.

**Существующий экспорт уже переносит поля.** `src/report/run.ts:165,214` читает process JSON и целиком записывает его в `causal.json`; `src/report/perfetto.ts:100,165` сохраняет process receipts в metadata. Native spawn failure/прерванный launcher до final write оставляет initial null; неизвестное время не превращается в успешное измерение.

**Стоимость/риск.** Два monotonic reads и несколько полей в уже существующем final write на requested launcher; новых процессов/watchers/files/синхронизации/обходов/hash/guards нет. Его overhead пока unknown. Основной риск — неверно назвать envelope startup/CPU/critical path либо суммировать overlapping parent/child durations; doc/scope это ограничивает. ## 4 ноября: Source-only inherited mask анализ и следующий discriminator

Новых native experiments/курсов/сети/production edits нет. Exact Linux semantics проверена по установленным `/usr/share/man/man7/signal.7.gz` и `man2/sigprocmask.2.gz`, `execve.2.gz`: mask является атрибутом потока, наследуется через fork и сохраняется через exec; disposition caught сбрасывается при exec, ignored сохраняется. Process-directed TERM может быть доставлен любому потоку, где он не blocked. Поэтому один process-leader SigBlk недостаточен для многопоточного Deno.

**Существующая цепочка.** Signal fixture host не вызывает `Deno.addSignalListener(SIGTERM)`: его top-level imports — runtime resolution/cache-info/Quarto paths и prepareLaunchers; тела других Deno.test не исполняются при filter. Host repro также не ставил SIGTERM listener. В standalone launcher listeners устанавливаются **после** native spawn: native не мог унаследовать mask, впервые изменённую именно последующими listener registrations launcher. Наследование ранее установленной outer-host/timeout/sandbox mask остаётся гипотезой. В owned-group supervisor, напротив, listeners ставятся до setsid/helper spawn и сигнал посылается группе; это отличается по topology/доставке и не доказывает per-child path.

Read-only `/proc` текущего exec дал bounded ancestor chain `python3 PID3 → bash PID2 → codex PID1`: у всех трёх leader SigBlkHasSIGTERM=false, SigIgnHasSIGTERM=false; codex SigCgtHasSIGTERM=true. Данные в [performance-exec-signal-masks.json](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/4254ee1f961b0d0ff6c13e1ebf46d5399bd493f2/docs/release-transfer-20261104/reports/performance-exec-signal-masks.json). Это **не** старые host/launcher/native PID и не все Rust worker threads, поэтому inherited-mask причина не доказана и не исключена для фактически неудавшегося repro.

**Локальный фактический Deno source.** В `/opt/quarto/bin/tools/x86_64/deno` найдены embedded JS sources (read-only mmap, без запуска binary); выдержки с offsets сохранены в [performance-deno-signal-source.json](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/4254ee1f961b0d0ff6c13e1ebf46d5399bd493f2/docs/release-transfer-20261104/reports/performance-deno-signal-source.json). Actual ChildProcess.kill проверяет waitComplete и синхронно вызывает `op_spawn_kill(rid, signo)`. AddSignalListener вызывает `op_signal_bind` и запускает poll loop; poll promise unref-нут, callback вызывается после `op_signal_poll`. Launcher всё это время имеет ref-ed child waitPromise; одного unref недостаточно для вывода, что polling сломан. Rust op bodies/точный sigprocmask путь не извлечены. Cached Tokio/signal-hook исходники есть в `.cargo/registry/src`, но их соответствие версии embedded Deno не установлено; они не используются как exact доказательство поведения binary. Никакого mask reset/runtime fix отсюда не следует.

**Предлагаемый минимальный следующий discriminator — пока НЕ запущен.** Один baseline repro ≤10 s/retry0 в прежней собственной tmp-копии; до TERM записать host Deno.pid, kill target=`host child.pid`, actual launcher Deno.pid и native child.pid/ready PID. Затем по этим **трём known PIDs**, без `/proc` общего сканирования, прочитать `/proc/PID/status` (Pid/PPid/NSpid, SigBlk/SigIgn/SigCgt/SigPnd/ShdPnd) и `/proc/PID/task/TID/status` всех существующих потоков. После одного TERM к записанному launcher PID — один повтор этих snapshots в существующем 2 s окне и прежние callback markers. Это разделит PID target mismatch, blocked delivery и callback dispatch; новые child/watchers/production guards/clock alignment не нужны. Завершение только known-PID cleanup; проверенные nonzero/spawnfailure cases не повторять.

| Возможное наблюдение | Что оно поддержит |
| --- | --- |
| kill target PID не совпадает с actual launcher PID/NSpid или PPid chain | Ошибка адресации/harness; inherited mask ещё не причина |
