## Причина и предлагаемое поведение

`release/collect.ts` рекурсивно склеивал весь `c` без учёта формы узла:
`Span` добавлял ID, классы и пары атрибутов; `Code` добавлял Attr; `Link`
добавлял Attr, адрес и подсказку. Работы использовали `text(ast.meta.title)`,
объявления вопросов — тот же обход inline-заголовка. Body имел второй
частный `inlineTitle`, уже обходивший Attr, но не отличавший книжный номер.

Первичный источник реального оформления — установленный Quarto:
`/opt/quarto/bin/quarto.js`, `formatChapterTitle()`, строки 153789–153813.
Он оборачивает название с ID в `quarto-section-identifier` и формирует
пару `chapter-number`, NBSP/Space, `chapter-title`; без ID эта пара остаётся
непосредственно в MetaInlines. Та же фактическая структура Quarto 1.11.5
сохранена в `tests/fixtures/native-public-introduction/sp-work-environment.json`
около строки 935. Поэтому проверка только отсутствия ID недостаточна:
номер главы тоже необходимо исключить.

Один `document/title.ts` читает содержимое известных native inline-узлов,
а не кортежи Attr/target/citation metadata. Он распознаёт указанную книжную
пару с пустыми ID, единственным служебным классом и без пар атрибутов.
Авторский текст внутри `chapter-title`, в том числе `24.0.8`, сохраняется.
Отдельный авторский Span с классом `chapter-number`, не составляющий эту
пару, сохраняет своё видимое содержимое. Числовые префиксы регулярным
выражением не удаляются; regex используется только для пробельного разделителя.

Публичный пример ожидаемого названия работы:
`24.0.8 Числа — ёж x < 3 ссылка α β`.
Ожидаемое название вопроса из настоящего book fixture:
`7. Число Main.java ссылка ёж`.
Идентификаторы, классы и URL в эти строки не входят. Условие сохраняет
авторское предложение `Авторское условие с числом 24.0.8.`.

Типы фактического транспорта остаются прежними: `PandocDocumentSchema.meta`
и late `title` содержат unknown; существующий `Body.Node.c` имеет `any`.
Новая функция сужает только этот внешний unknown и не вводит новую AST schema,
validator, casts или `any`.

## Выполненное и предложение проверки

Выполнено только чтение исходников/первичных метаданных и `git diff --check`
(без ошибок). Компилятор, Deno/Quarto execution, Native, exporter и сеть
не запускались. Положительный runtime результат не заявляется.
Тест написан до исправления; его выполнение RED не проводилось из-за прямого
ограничения координатора «до Source FROZEN не запускать».

Координатор выбирает одно короткое публичное исполнение и отдельное
минимальное подтверждение настоящей книги. Предлагаемые пределы до запуска:

1. Один `tests/native-readable-titles.ts` через существующий Quarto/Deno
   runtime, без всей suite и повторения прежних 40 roots: предел 5 секунд.
   Он проверяет оба названия в release facts и сохранение авторского текста.
2. Только tiny book fixture: один render двух страниц и один существующий
   ordinary Core → PL exporter проход с проверкой `infoAssessment.json.title`,
   `info.json.title` вопроса и `question.html`. Предлагаемый общий предел
   40 секунд wall time включая grace; при отказе сохранить первую диагностику
   и не повторять. Для PL нужны его существующие defaults/manual config,
   подключаемые в копии fixture; продуктовые PL файлы не меняются.

Шаг 2 проверяет реальную развилку, которую чистый AST fixture не доказывает:
Quarto фактически создаёт номер главы в meta.title, Core выдаёт название
работы независимо от названия вопроса, а exporter не добавляет оформление
в самостоятельное условие. Если координатор ограничится шагом 1, дефект
реального book→exporter остаётся не подтверждённым исполнением.

Предложенные пределы — новая адресная задача A4, не сброс прежних A1 бюджетов.
Полные Java/SP сборки и старые A1 проверки повторять не требуется.
