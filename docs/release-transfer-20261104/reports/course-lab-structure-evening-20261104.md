## Граница Native практики и запрос владельцу producer

Самостоятельная Native тренировка этой партией **не доставлена**. Сейчас
PL `application/declarations.ts:128` допускает в instance только
`title`, `self-enrollment`, `works`, `publishing`. `native-entry.ts:122`
выбирает assessment IDs из `works`, а `export-course.ts:712–733` превращает
каждую выбранную работу в Homework/Exam с grading/completion и общим порядком
номеров. Отдельный Native статус тренировки нельзя выразить конфигурацией
курса. Создание второго instance с теми же техническими лабораторными лишь
повторило бы неверную модель.

Один адресный запрос владельцу PL producer: добавить отдельное явное
объявление добровольной практики из **существующих exercise IDs банка**,
которое даёт отдельный доступ в Native, не добавляется к основным `works`,
их нумерации, pass/completion и зачётным баллам. Переиспользовать существующие
карточки, вопросы, UUID, проекты и grader; не требовать авторских фиктивных
100-балльных assessment-обёрток. Изменение должно охватить настоящий parser,
Native selection/materialization, exporter и публичный пример. Если producer
нуждается в отдельном Core body contract для упражнения, согласовать ровно
этот пробел с владельцем Core. Новые веса и пересчёт существующих результатов
в запрос не входят. До принятия этого контракта доступ к тренировке обеспечен
книгой и банком; отдельная PL тренировка не заявляется готовой.
