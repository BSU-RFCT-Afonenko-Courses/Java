# Gateway: граница Moodle ↔ Native, 4 ноября 2026

**Предложение: оставить Gateway только Moodle identity/launch/score exchange; Native PrairieLearn владеет курсом, доступом, попытками и файлами. Малого замкнутого product diff удаления course SHA до выбора этой границы не найдено.** Подготовлен Source design; product code не менялся.

Gateway подтверждает Moodle пользователя и activity, выдаёт ограниченный одноразовый переход в Native и доставляет полученный Native score в зарегистрированный Moodle lineitem. Сессии, handoff и durable AGS outbox остаются полезными функциями обмена. Каталог курса, policy назначения/approval/ёмкости, выбранные question pools и подсчёт completion не должны существовать второй моделью в Gateway. Native numeric IDs остаются внутренними DB/FK значениями, без legacy parents в новом API и без нового mapping registry.

В actual Source ordinary catalog launch может обходиться без persisted assignment. Но его startup не изолирован: общий loader требует course hashes/files, общий worker читает assignment/lab/outbox, Bridge выбирает binding по deliveryHash. Полный exporter дополнительно связан с provenance/stage/receipt gates. Поэтому убрать только Gateway loader либо exporter SHA — незамкнутый diff. Новый ordinary mode или сохранённый фиктивный SHA не предлагаются.

Существенная функциональная граница: Gateway сейчас реализует выбор/approval/ёмкости/reassign defense, Bridge применяет labels. Native ownership само по себе не создаёт эти возможности. Lab уже отправляет реальный Native weighted score, defense — число полностью закрытых обязательных slots; перенос owner должен сохранить оба смысла и не менять учебные критерии. Пока Native producer конкретного результата отсутствует, AGS по нему не отправляется. Временное отсутствие результатов уже разрешено пользователем.

Нужны три решения:

1. **Вход:** сохранить Moodle LTI identity → ограниченный Native handoff либо выбрать иной Native auth вход. Предлагается сохранить текущую концепцию; Moodle teacher не становится Native administrator или Student автоматически.
2. **Владелец workflow:** первым включить ordinary Native работы, оставив defense временно недоступным в новом входе, либо сначала перенести прежние defense функции к явно выбранному Native owner. Предлагается ordinary первым. Это выбор доступной функции, а не разрешение упростить критерии.
3. **Cutover:** определить целевые новые Native course/CI, Moodle activities и момент включения; pending old AGS sends остаются у старой системы либо отдельно останавливаются согласованной операцией. Новая система не обязана читать legacy hashes/parents; старая VM, история и файлы сохраняются. Миграция/поиск баллов в эту работу не входят.

Сейчас конечный безопасный пакет — это предложение и адресное приложение для независимой рецензии. После выбора можно закрыть новый producer/последний reader contract; routine binding references и имена полей решаются в Source без отдельного опроса пользователя. Независимый Platform JDK/Gradle пакет может продолжаться. Production, VM, live DB и конфигурация среды не читались и не менялись; runtime квалификация не заявлена.

## Что удалить и что можно делать сейчас

После выбора границы удалять whole-course SHA/files admission и зависимость runtime identity от него нужно согласованно в PL producer, Platform startup/update readers и всём выбранном новом Gateway wire/score/storage маршруте. У Gateway не остаются `load_delivery` как модель курса, gradingPayload validators, собственный catalog/assignment policy, `_slots` как второй вычислитель completion и `_lab_id` от bytes курса. Сетевой клиент, авторизованный scope, проверка ответов, durable outbox/retry/monotonic AGS timestamp остаются полезными функциями Moodle обмена.

**Независимый меньший продуктовый пакет удаления course SHA сейчас не установлен.** Admission-only с прежним hash в wire, одно удалённое сравнение, `start_worker=False` для catalog, permissive schema или новое поле-заменитель будут preparatory bypass, а не завершённое поведение. Отдельная типизация реальных wire/SQL rows возможна после определения контракта; объявить нынешние dicts generic DTO ради видимого diff не нужно.

Без пользовательского решения сейчас безопасно закончить Source design, точные схемы предлагаемого обмена для review и перечень внешних поведенческих проверок; этот отчёт — конечный текущий пакет. Код Gateway, schemas/runtime.sql, auth, config, DB и основной state не менялись. Независимая работа Platform по JDK/Gradle не зависит от этой развилки и может продолжаться у своего writer.

## Детали реализации после выбора границы

Предпочтительный wire без нового реестра использует существующие logical `courseId` + `instance`, `workId` и подтверждённого `userUid`. Bridge разрешает их через собственные configured bindings; Native numeric IDs остаются внутренними DB/FK значениями. Нынешний binding содержит `deliveryPath/courseInstanceId`, а uniqueness проверяется по hash/instance. В новом contract нужны однозначность courseId/instance, сверка разрешённого CI и tenant/access, отказ при неоднозначности. Один instance key либо CI UUID без course scope этого не доказывает. Точные поля/имена схем — routine Source-дизайн после выбора owner; отдельного пользовательского решения о каждом reference не требуется. Второй mapping registry и fallback по старому hash/numeric parent не предлагаются.

Ordinary identity/launch/score exchange потребует PL integration output, Platform native binding/startup/update/ordinary wire, Gateway consumer/outbox schema и удаления старых обязательных readers маршрута. Для существующего полного exporter пути сюда входит course coupling provenance/stage/receipt из последней строки карты. Defense/recognition не должны оставаться скрытым обязательным startup/outbox путём. Собственные runner/helper/toolchain inventories и per-job provenance могут лежать вне этого пакета, однако малый замкнутый executable diff текущим исследованием не доказан. Это ещё не implementation plan.

## Проверки будущего пакета и текущие пределы

Для будущего ordinary пакета нужны адресные внешние проверки на вымышленных данных: title/HTML/resource edit при прежнем Native parent/UUID; startup и explicit update-existing без course SHA; повторный Moodle launch того же пользователя; чужой course/instance/activity/user отклоняется; weighted grade и regrade A→B→A сохраняют различимые AGS events после restart; pending grading не становится нулём; duplicate delivery не создаёт второго события; catalog не читает/не пересылает defense историю. Источник проверок поведения уже есть в `gateway/tests/test_catalog.py`, `test_lab_results.py`, `test_attempt_binding.py`, `test_restart.py`; это чтение tests, не их повторный запуск и не квалификация нового дизайна.

Границы риска: shared privileged Bridge не теряет Native ACL/tenant проверки при удалении hash; content edit не равен изменению work/slot/points/seed/UUID; logical reference не означает сохранение исторического numeric parent; выбранный новый auth/cutover не доказан чтением Source. Работоспособность live composition, runtime стоимость и сохранность конкретных historical rows остаются UNKNOWN. Прежние tests/image labels и заданная модель агента не являются runtime attestation нового решения. Независимый review организует координатор.
