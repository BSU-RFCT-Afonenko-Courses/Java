## Что действительно изменено

Core `withNativePublication(expectation, selection, use)` разделяет существующее acquisition/lifetime/closing machinery с NativeOperation. Common course/coverage/assessment/role/path semantics извлечены из validateNativeRelease в release/publication.ts. Ordinary API не читает installed adapter contract inventory, не исполняет grading/seed validators и не создаёт release proof. Это отдельный путь, не фасад над validateRelease. Assignment capture здесь отказывается, полный course-export API остаётся отдельным потребителем validateNativeRelease.

Publication содержит actual captured root/outputDirectory/identity/catalog, borrowed document/condition/resourceInventory/withProjectContracts/assertCurrent и Core-owned adapterInputs/checkSources. Borrowed getters/методы истекают вместе с настоящим callback. NativeOperation currentness, pointer/private/physical/runtime/environment/profile checks, A1 acquisition/failure fences и closing порядок остаются. Initial whole-owner snapshot и общий currentness механизм не удалены этой задачей.

Для обычных business paths проверяется actual canonical owned physical path с существующими exclusions; initial snapshot membership больше не требуется как отдельное publication условие. Missing path даёт RELEASE.SOURCE_POLICY, исключённый path также; symlink/foreign path продолжает отказываться существующим Core ownedPhysical. Не добавлены новые hashes/registry/schema authority.

PL `inspectPublication(publication)` читает inputs непосредственно из Core capture, без prepared PL correlation/adapter.validateCourse/proof. Сохраняются собственная syntax/normalization, assignment/порог, membership всех PL members и common-file paths до projection. Полная pricing/seed qualification не вызывается. При course.adapters без PL documents пуст, Core course остаётся реальным. Role authority относится к отмеченному/выбранному контенту и файлам; arbitrary unmarked profile-dependent computed text и Native cache freshness не получают новой гарантии.
