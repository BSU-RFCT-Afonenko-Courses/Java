## Основания и границы

[Условие Circle](../java/tasks/bank/polymorphism.qmd), строки 35–55: абстрактный TwoDShape, закрытые width/height/name, конструктор базового класса и открытые getters/area; Circle наследует TwoDShape, открытый Circle(double), размеры равны диаметру, имя равно `circle`; допустимы конечные `0 < r <= 1e150`. Площадь конечна и имеет погрешность не более `max(1e-9, 1e-12*|πr²|)`. Способ вычисления свободный. Неверные входы проверять не требуется. Демонстрация и объяснение super остаются ручной частью.

Прямые исходники: [стартер Circle](../java/tasks/projects/polymorphism/circle-subclass/starter/src/main/java/Circle.java), [стартер TwoDShape](../java/tasks/projects/polymorphism/circle-subclass/starter/src/main/java/TwoDShape.java), [эталон Circle](../java/tasks/projects/polymorphism/circle-subclass/reference/src/main/java/Circle.java), [эталон TwoDShape](../java/tasks/projects/polymorphism/circle-subclass/reference/src/main/java/TwoDShape.java). [API-допуск](../java/tasks/projects/polymorphism/circle-subclass/api/src/api/java/ApiContract.java) уже проверяет абстрактность TwoDShape, доступность методов, открытый конструктор Circle и возможность присваивания Circle базовой ссылке. Эти проверки не дублируются оценочными случаями и не дают баллов ([решение 60](../java/docs/refactoring-plan.md#decision-60)). Прямой вызов через TwoDShape в [TaskBinding](../java/tasks/projects/polymorphism/circle-subclass/observations/src/test/java/TaskBinding.java) сохраняется. ## Набор случаев

**Ровно 6 оценочных JUnit leaves: 2 открытых + 4 скрытых.** Один случай — создание одного Circle для указанного радиуса и согласованное чтение размеров, имени и площади через базовый тип. У этого случая несколько assertions, но один исход; отдельное свойство не становится отдельным баллом. Параметризованный метод со скрытыми радиусами даёт четыре случая, а не один. Контейнер, API-допуск и повтор демонстрации в знаменатель не входят.

Для каждой строки свойства одинаковы: `getWidth() == 2*r`, `getHeight() == 2*r`, `getName().equals("circle")`; `area()` конечна и близка к `E = Math.PI*r*r` с `delta = max(1e-9, 1e-12*abs(E))`. E и delta вычисляются непосредственно в JUnit из входа; таблица поясняет ожидания и не предназначена для второго машинного реестра expected. Округление Math.PI и произведений значительно меньше заданного относительного допуска; сверхточного совпадения с эталоном нет.

Точное сравнение размеров не заменяется допуском площади: условие задаёт именно удвоенный радиус, и выбранное умножение на 2 представимо для этих входов.

## Assertions и обратная связь

Внутри каждого leaf — обычные JUnit `assertEquals(expected, actual, message)` для размеров/имени, `assertTrue(Double.isFinite(actual), message)` для конечности и `assertEquals(E, actual, delta, message)` для площади. Все значения читаются у созданного объекта; ожидаемые берутся из входного радиуса, а не из ошибочного getter. Никакого общего boolean с конъюнкцией. Для сообщения о конечности допустимо указать полученное значение: это предикат, а не искусственное числовое expected. Чтобы показать несколько нарушенных свойств одного объекта, допустим обычный `assertAll` с этими assertions; он не добавляет случаев или веса.

Короткие сообщения: «Ширина круга должна равняться диаметру», «Высота круга должна равняться диаметру», «Имя фигуры должно быть circle», «Площадь должна быть конечной», «Площадь круга должна соответствовать радиусу с заданным допуском». Радиус уже присутствует в имени leaf. Expected/actual/delta поступают из assertions; вручную повторять числа в сообщениях и карточках не нужно. Успешные assertions не превращаются в поток observations. Ошибка конструктора для допустимого входа — ошибка исполнения именно этого случая с контекстом радиуса; не маскировать её под несовпадение площади или под заранее созданные провалы остальных случаев.

## Законные решения, знаменатель и риски

Чтением проверена [альтернатива namespace](../java/tasks/projects/polymorphism/circle-subclass/alternatives/namespace/src/main/java/Circle.java) и её [базовый класс](../java/tasks/projects/polymorphism/circle-subclass/alternatives/namespace/src/main/java/TwoDShape.java): размеры задаются через super, площадь вычисляется из ширины, дополнительных совпадений с внутренними именами тест не требует. Дополнительные классы с совпадающими простыми именами библиотек не являются дефектом решения: исполнитель сохраняет штатную корректную привязку trusted-кода. Также законны хранение собственного радиуса и Math.pow(r, 2), если соблюдены конечность и численный допуск; видимость базового конструктора protected сохраняет допустимость. Это анализ совместимости по исходникам, не runtime PASS.

[Имеющийся wrong-контроль](../java/tasks/projects/polymorphism/circle-subclass/negative-controls/wrong/src/main/java/Circle.java) вычисляет площадь по диаметру. Ожидаемый будущий результат — 2/6: четыре немалых радиуса отвергаются, два малых укладываются в абсолютный допуск. Нельзя искусственно ужесточать малые случаи ради 0/6 этого контроля. Стартер бросает TODO в базовом конструкторе: при достоверном выполнении полного набора ожидается 0/6, но это прогноз по исходникам, не новый результат измерения.

Будущий знаменатель меняется **с 3 на 6** согласно [решению 65](../java/docs/refactoring-plan.md#decision-65): исходы шести радиусов равновесны; одного провала достаточно для 5/6 автоматической части, без группового all-pass и без изменения 80/20. Признанные прежние зачёты, best и ручная часть не пересчитываются. При неполном/недостоверном отчёте дробь из пришедших исходов не объявляется итогом.

[Исследование R1](../../java-research-20261103/run-ultra-01a1a144-b034/R1/report.md) уже установило ограничение Transform на некоторые стандартные overload и assertAll. Совместимость обычного JUnit и показ expected/actual/delta остаются отдельной технической задачей Platform; авторский договор не подстраивается под boolean-ограничение старой обвязки. Перед выпуском исполнителю нужно подтвердить шесть реальных leaves и полноту результата, согласованность открытой выдачи и независимую содержательную рецензию. Обязательный договор радиуса/площади однозначен; неуточнённый exact формат демонстрации не оценивается автоматически. Публичность конструктора TwoDShape не уточняется до public по образцу эталона.

Итоговая проверка допуска перед передачей: прочитан весь доступный исходный интервал этого агента от указанного turn_id; 1 запись turn_context, все верхние и вложенные назначения gpt-6-astra/medium согласованы. Исходная точка не сдвигалась. Локальные ссылки отчёта проверены на наличие адресуемых файлов.
