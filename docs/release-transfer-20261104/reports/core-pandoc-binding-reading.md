## Что действительно хранит Core

Все пути Core ниже относительно `core/_extensions/course-core/`.

- `runtime/assignment-admission.ts:19–26`: actual имя — `AssignmentRuntimeWitness`; `CoreAssignmentRuntimeWitness` в прочитанном текущем Source не найден. Поля: `executable`, `environment`, `profiles`, `outputDirectory`, `inputs`, `implementationFiles`. Ни `pandoc`, ни version/selection result нет. Комментарий строки18 прямо отличает наблюдённый запуск владельца от external producer qualification.
- `runtime/operation.ts:286–325`, `nativeRuntimeIdentity`: разрешает requested Quarto через path/PATH, canonicalizes physical executable и связывает signature/опциональный SHA256 **этого файла**. Это не обход каталога runtime и не идентичность всего Quarto/Pandoc toolchain. Счётчик `runtimeHashReads` сам по себе не означает, что Pandoc уже квалифицирован.
- `assignment-admission.ts:175–205`: preparation получает эту Quarto identity, делает frozen input env с удалением project/script transport и наложениями `QUARTO`, profiles, no-network и `DENO_NO_PACKAGE_JSON`; существующий owner inspect работает с этим executable/env. После inspect identity Quarto сравнивается ещё раз. `:249–255` кладёт в witness Quarto executable/env и пустой `implementationFiles`. Selected Pandoc из inspect не извлекается.
- `operation.ts:205–214` — strict persisted schema тех же полей. `:1630–1680` пополняет `implementationFiles` только наблюдёнными assignment declarations под вычисленным native `../share`, используя path/signature. Это Lua/прочие observed implementation dependencies; выбор бинарного Pandoc в `bin/tools` из этого списка не получается.
- `infrastructure/invocation.ts:8–15` также идентифицирует Quarto invocation, env digest/cwd/profiles; selected Pandoc не возвращает. `infrastructure/process.ts:8` выбирает assignment Quarto либо ordinary env/fallback.
- `runtime/assignment-execution.ts:125–126,129–215` хранит exact Quarto authority: executable, owner cwd, закрытый набор argv, frozen env/разрешённые overlays. Разрешённые Core Pandoc argv в `:173–194` относятся к Markdown→JSON, JSON→GFM и citeproc; JSON→HTML PL сюда не входит. Менять executable в этом guard на произвольный Pandoc нельзя.

## Где выбранный Pandoc существует сейчас

В прочитанной установленной копии `/opt/quarto/bin/quarto.js:26669–26705` private `toolsPath/pandocBinaryPath` выбирает `QUARTO_PANDOC` как файл или directory+binary, с warning/fallback при отсутствующем пути; fallback зависит от config tools path и OS/architecture. `/opt/quarto/bin/quarto.js:26556–26557` получает bin/tools из `QUARTO_BIN_PATH`. Это actual resolver, но не доступный Core service.

Shell launcher `/opt/quarto/bin/quarto:22–121,167–172` устанавливает dev/bundled composition, bin/share и Deno DOM env; поэтому входной frozen env Core/PL не равен автоматически effective env Pandoc child. Связывать только `QUARTO_PANDOC` или строить путь от ambient `QUARTO_BIN_PATH` недостаточно. Absolute `/opt/...` здесь — адрес прочитанного файла, не proposed production path.

`quarto.js:190301–190355`: перед passthrough выполняются version requirement и debug reconfiguration checks. Затем private resolver выбирает binary, argv становится `args.slice(1)`, env2 передаётся native child; CLI выходит с native code. В `:190423–190425` экспортирован только `quarto4 as quarto`; private resolver не экспортирован. Импорт bundle не даёт безопасного resolver API: CLI ветви вызывают `Deno.exit`. Результат прежнего owner inspect не сохранён как отдельное свидетельство применимости всех этих guards к будущему прямому запуску.

Это согласуется с уже сохранёнными33 exact1:1 pairs и argv/cwd, но не доказывает эквивалентность окружения, warnings или guard failures. Median .287–.290s — parent lifetime вне child envelope, не чистый startup/CPU/critical path.

## Конкретный producer для frozen native scope

Уточнение координатора снимает прежнюю чрезмерную рамку: моделировать изменение debug config/override между body и повторять CLI checks в frozen operation не нужно. Выбор делается один раз после existing успешного owner inspect, с тем же Quarto/env и уже принятыми version/profile/currentness. Это новый небольшой selected-path API, а не expose несуществующего поля.

`/opt/quarto/bin/quarto:123–126` public `--paths` выводит две строки: bin и share. Он не возвращает tools dir, выбранный Pandoc или effective child env и выходит до Deno/JS guards. Новый вызов `--paths` здесь не нужен: bin берётся из frozen `QUARTO_BIN_PATH`, проверенного на совпадение с `dirname(runtime.executable)`; tools layout известен из target Source (`quarto.js:26556–26557,26664–26705`). Никакой `/opt` в product code не появляется.

Предлагаемый алгоритм `operation.pandocBinding(auxiliary.environment)` возвращает один закэшированный immutable record либо `undefined` для старого CLI. Переданная map должна совпадать с уже frozen host environment операции; одно сравнение при binding связывает имеющиеся данные, не запускает новый `assertCurrent` и не повторяется для body:

1. На первом обращении, сразу после existing PL `operation.assertCurrent()`, взять Quarto executable из `complete.state.assignment.runtime.executable`, actual version из существующего owner witness и frozen environment/cwd той же live composition. Не запускать ещё один guard/version/inspect. Нет assignment witness, версия отличается от exact1.11.5, отсутствует/не совпадает абсолютный canonical `QUARTO_BIN_PATH`, неизвестна OS/arch — `undefined`. Для первого bounded patch достаточно Linux x86_64/aarch64; другие платформы продолжают CLI.
2. Fixed bundled composition: имя physical launcher `quarto`, штатные `bin/quarto.js` и share layout; dev Source `resolve(bin,'../../../src/quarto.ts')` отсутствует, `QUARTO_DEBUG` не true, `QUARTO_FORCE_VERSION` пуст. Нестандартные shell controls (`QUARTO_ACTION/TARGET/DEV_MODE/IMPORT_MAP_ARG`, профилирование TS, заранее экспортированные shell option/cache variables) либо нестандартный share/config layout дают `undefined`. Это небольшая eligibility ветка над frozen данными плюс адресные stat для выбранных известных путей, один раз; не новый registry/content scan/hash. Одного имени/каталога недостаточно для произвольного wrapper: оптимизация допускается в уже квалифицированной штатной composition, неизвестный wrapper остаётся CLI.
3. Если frozen `QUARTO_PANDOC` непуст: поддержать absolute file и absolute directory+`pandoc` по exact `toolsPath` semantics `:26676–26699`. При relative, missing, неразрешимом/необычном пути вернуться к CLI — он сохранит warning/fallback/error, повторять warning в Core не требуется. Без override выбрать `join(bin,'tools',Deno.build.arch,'pandoc')`; candidate должен существовать как файл. На этом выбор завершён, path не ищется по ambient PATH и не перевыбирается для следующего body. Ошибка eligibility/read возвращает CLI, а не новый Core diagnostic.
4. Record: `{ executable, environment, cwd, diagnosticTool }`, где diagnosticTool — прежний Quarto tool; argv не расширяет полномочия assignment. Для PL разрешён только existing JSON→HTML tuple. Environment — **тот же existing frozen auxiliary env**, допущенный по совпадению с launcher результатом; cwd — фактический frozen cwd PL composition, не произвольно подставленный owner root (прежний PL spawn наследовал cwd).

Нужные launcher deltas видны в `/opt/quarto/bin/quarto:24–26,94,102–109,167–182`: `QUARTO_ROOT=resolve(bin,'../../..')`, `QUARTO_BIN_PATH=bin`, default share при отсутствии, `DENO_DOM_PLUGIN` из `QUARTO_DENO_DOM` либо `bin/tools/<arch>/deno_dom/libplugin.so`, default `QUARTO_DENO=bin/tools/<arch>/deno` при пустом значении, `DENO_TLS_CA_STORE=system,mozilla`, `DENO_NO_UPDATE_CHECK=1`. Для этого дизайна выбрана консервативная ветка: допускать только frozen env, где эти значения уже совпадают с launcher результатом; иначе CLI. Environment переиспользуется буквально, shell не эмулируется; расширять env compatibility ради patch не нужно. `execProcess` (`quarto.js:7831–7836`) наследует env, passthrough не задаёт иной cwd/data-dir; `quarto4(...,env2)` у обычного entrypoint вызывается без env2 (`:190406–190417`).

## Предел ≤2 Core +≤3 PL production files

- Core `runtime/operation.ts`: локальный producer/Promise-cache и member `pandocBinding` public operation; использует existing complete assignment/owner witness и host lifecycle, без нового persisted state. Снимок host env уже держится в `withCurrentNativeOperation` для `hostGuard`; передать эту map в publicOperation вместо повторного ambient lookup. `NativeOperation=ReturnType` уже экспортирован `public.ts:116`; второй Core файл необязателен, возможен только type export. `assignment-admission.ts` и `assignmentChild` менять не требуется.
- PL `application/native-course.ts`: после existing `:254–258` создать base auxiliary, один раз получить binding с его frozen environment, затем создать `Object.freeze({...baseAuxiliary,pandoc:binding})`; не мутировать исходный object. PL `application/native-auxiliary.ts`: необязательное immutable поле binding в типе, прежние `before/after/environment` без новых проверок; snapshot и producer используют одну frozen env map. PL `application/export.ts`: для native binding выбрать executable/env/cwd, удалить лишь `pandoc` из existing argv; иначе прежний command. Piped stdin/stdout/stderr и порядок before/output/after/exit/writingFailure (`:108–138`) сохраняются. В `ExternalToolFailure` сохраняется logical Quarto tool и прежние поля, даже когда executable — Pandoc.

Рекомендуется консервативная ветка eligibility с existing env equality и CLI fallback. Она снимает12 CLI проходов у поддержанной frozen composition; fallback не объявляется ошибкой и не добавляет preflight в loop. Initial owner inspect уже успешно прошёл version/reconfiguration; per-body повторение удаляется намеренно. Не требуется новый framework, proof или validation loop.21 Core Markdown/GFM conversions остаются прежними. Проверяемый остаточный риск — правильность определения штатной composition и точность launcher env equality; это предмет одного diff/review, а не отсутствие готового getter.

## Одна содержательная ограниченная приёмка будущего patch

Один адресный сценарий существующего native JSON→HTML converter с двумя последовательными body одного live operation: до qualification настроен поддерживаемый custom Pandoc override, отличный от bundled binary, env соответствует eligibility; producer binding должен сохранить именно его, ambient env внутри операции не меняется. Через существующую command seam подтвердить, что оба child используют **тот же binding**, exact `--from=json --to=html5 --mathml`, прежние stdin bytes, согласованные cwd/effective env и прежний порядок auxiliary before/output/after; во втором child вернуть nonzero+stderr и проверить сохранение `ExternalToolFailure` с logical Quarto tool/stdout/stderr/cause. В этом сценарии не должно быть per-body Quarto CLI/version/hash/preflight. Это проверяет полезную границу и отказ, а не магическое число digest или benchmark курса. Никакой такой сценарий сейчас не выполнялся; дизайн не подтверждает actual installed release или величину выигрыша.
