## Основной вывод

Повторяется не только SHA-проверка. Наша обвязка соединяет пригодность Native курса, точность учебной проекции, происхождение release assets, неизменность всего checkout и сохранность результатов в один обязательный пропуск. Эти задачи имеют разные владельцев и сроки жизни. Для обычной синхронизации Native не нужны весь этот пропуск, полный byte inventory и hash как runtime identity. При этом доверенный код проверяющего, непубликация hidden данных, tenant/user access и история заданий остаются реальными требованиями.

Снятие общего пропуска не означает снятие всех ограничений. Чужой путь ZIP, возможность студента писать trusted inputs, публикация поддельного expected и присвоение чужого результата — предметные дефекты. Хеш всего курса их сам по себе не предотвращает; отдельная защита конкретной границы не должна заставлять Native курс навсегда иметь тот же набор байтов.

## Что не следует из этих находок

- Canonical JSON не обязательно удаляет Native поля; closed DTO/воссоздание объекта и byte hash — разные ограничения. Actual schema3/4 sidecar не Native info JSON. Native тоже имеет свои схемы: «шире» не означает произвольный некорректный JSON.
- Same UUID в новом numeric Native course не сохраняет старые FK/results. Нужен прежний parent record, а не новый course с прежним текстом UUID.
- Stage каталог по commit может оставаться удобным deploy artifact; он не обязан становиться identity session/assignment/results.
- Runtime SHA не аутентифицирует автора; unsigned manifest можно пересчитать. Это не причина снимать проверку конкретного source→destination файла или token hash.
- Per-slot completion/choice и native average имеют разную семантику. Удаление проверки, обслуживающей этот перевод, без сохранения перевода изменит цели/баллы и выходит за техническую оптимизацию.
- Этот проход не подтверждает Kernel/OCI containment, live image, актуальные Gateway rows, отсутствие pending outbox, признание оценок или оба транспорта в настоящем Moodle.
- На независимом просмотре QRC найден ещё один межпроектный consumer: actual Performance924 `tools/owner-normalizer.ts` извлекает private QRC `infrastructure/metadata.ts` через `git show` и исполняет его ради offline byte-comparison. Это не runtime/privacy контракт QRC. Старый manifest798 продолжает читать исторический blob; новый QRC pin после удаления helper требует companion изменения offline normalizer/его tests/docs. Восстанавливать runtime sorting ради этого старого сравнения не следует. Подробности — [QRC review](qrc-native-metadata-review-20261104.md).

## Следующие ограниченные изменения

1. **Stable native context для ordinary work.** Разделить выбор configured native CI/assessment/UID и legacy SHA request. Сохранить настоящие Native access/enrollment/assessment checks и запрет обхода assignment-managed work; существующие rows/history/events не мигрировать и не пересоздавать. Первый Source diff не обещает cutover и AGS migration. Изменение metadata при тех же native IDs не должно становиться новым курсом или скрывать результаты. Без concrete configured Source/version live путь не переключается.
2. **Один предметный package boundary.** Сначала пересмотреть обязательность whole-course freeze/closed Native inventory, затем удалить self-validation созданного receipt и per-info hashing vendored schemas там, где они не обслуживают отдельного consumer. Сохранить реальное scenario outcome/coverage и privacy/upload/points mapping, которое Native само не выражает. Не создавать новый verification receipt для подтверждения удаления старого.
3. **Official runtime отделить от host diagnostic.** Рассмотреть удаление per-job runtime closure/двух version JVM и перенос stable helper compilation в image. Подготовленный image + фактические writable roles/paths задают границу; host остаётся явно диагностическим и не подменяет tool failure нулевой оценкой. Уже принятый one-production-compilation не переоткрывать.

Для этих изменений до кода нужен точный ограниченный consumer diff, после — только адресные проверки меняющегося поведения, без повторного полного R4/Java128/image rebuild ради статуса. В этом source-only проходе новая стоимость не измерялась; численного обещания ускорения нет.
