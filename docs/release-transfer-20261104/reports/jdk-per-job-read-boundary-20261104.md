# JDK649: build/install против per-job reads

Source-only трассировка текущей official цепочки `images/java25-grader/grade.py`, installer/complete-native и объявленных runtime profile files; продолжает [JDK candidate evidence](jdk-official-preflight-20261104.md), не общий Platform audit. Никакие inventory/hash/JVM/Gradle/Docker/tests/network/production команды не исполнялись; Source/state не менялись. Файлы и counts ниже — из кода/manifest, не измеренный filesystem traffic.

**Ответ про lib/modules:** per-job Python admission не читает его bytes для SHA. `grade()` → `_admit_java_job()` → `_verify_native_toolchain()` с default `verify_bytes=False` и `_hardened_tool_state(verify_bytes=False)`. Для build JDK `/opt/native-jdk/lib/modules` сверяются size/mode/owner/type/link и manifest membership; для grading JDK `/usr/lib/jvm/java-25-openjdk-amd64/lib/modules` — stat identity/size/mode/path ownership. Полный byte hash есть в installation ветвях и default `_hardened_tool_state(verify_bytes=True)`, но единственный найденный прямой production caller с этим default — image `complete-native.py`, не per-job grade. Это не утверждение, что сама JVM не открывает modules при исполнении.

Точный bundle для Java junit/mutation — `runtime/java25-junit-v1`: PlatformApiPrecheck.java, PlatformJUnitAdapter.java; feedback/Transform.java; feedback/module/module-info.java; module org/prairielearn/feedback Assertions/Gate/ProjectionAccess и internal Scope/State/Timeouts; feedback/projection-admissions.json; json-simple1.1.1 и junit-platform-console-standalone1.14.1 JAR; upstream JUnitAutograder.java/LICENSE/AutograderInfo.java. **Включая LICENSE**, это все16 declared entries, хешируемые preflight. Shared обычных двух Java profiles: `runtime/student_feedback.py`, `runtime/junit_result.py`. Native baked profile наследует их и добавляет три NATIVE_RECIPE files; это Source derivation `baked_view`, не чтение live image config.

Сводно по common official admission: lock читается минимум дважды как JSON (`_verify_native_toolchain`, `_hardened_tool_state`); native profile затем читает его bytes как sharedFile SHA и native build recipe повторяет SHA. Нет основания переносить эти чтения lock на размер lib/modules. Runner/bundle/shared SHA остались per-job независимо от official image выбора; снятие второй JVM их не сняло.

Это карта для следующего high решения, **не рекомендация удалить security checks**. Число достигнутых повторов зависит от runtime/path/ранних отказов; Python/JVM/OS естественные execution reads, filesystem cache, wall/CPU/RSS/размеры новых проходов не измерены. Не утверждаются live image/DB/production acceptance или текущий overall bottleneck. Существующие JDK/role boundaries не менялись. Own роль/model/effort неизменны; [origin reference](core-condition-walk-types-admission-20261104.json).
