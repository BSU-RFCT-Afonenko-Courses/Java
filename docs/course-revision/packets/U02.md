## U03/U04: канонический изменяемый Book

Ранний **plain** тип — `course.examples.plain.Book`, пакетная видимость полей `String title`, `boolean borrowed`, конструктор `Book(String)`. Он используется только в первой главе для mutation/rebinding и null. Следующий reusable тип — отдельный файл `course/examples/objects/Book.java`, полный исходник:

```java
package course.examples.objects;

public final class Book {
    private final String title;
    private boolean borrowed;

    public Book(String title) {
        if (title == null || title.isBlank()) {
            throw new IllegalArgumentException("nonblank title required");
        }
        this.title = title;
    }

    public String title() { return title; }
    public boolean borrowed() { return borrowed; }

    public void borrow() {
        if (borrowed) {
            throw new IllegalStateException("already borrowed");
        }
        borrowed = true;
    }
}
```

Не заменять на `new Book()` и не обращаться к закрытому `book.borrowed`. Для U03 после введения полного `Box<T>` нужен такой клиент:

```java
Book book = new Book("Java");
Box<Book> stored = new Box<>(book);
stored.get().borrow();
System.out.println(book.borrowed());   // true
System.out.println(stored.get() == book); // true
```

Полный контекст действительно собран и запущен в evidence `contracts/book-box-alias-u03`: `BoxAliasDemo.java`, package `course.examples.generics`, import `course.examples.objects.Book`, вложенный `static final class Box<T>` с `private final T value`, `Box(T)`, `T get()`. Box хранит значение ссылки; `borrow` меняет общую книгу. Второй borrow → `IllegalStateException`, затем `borrowed()` остаётся true. Название Book — ненулевое и не blank, без нормализации title; повторное создание с тем же названием не объединяет экземпляры.

`ComparisonDemo.Person` и его `Student extends Person` принадлежат U03 и демонстрируют сравнение. Они не record и не `grade.Student`. U02 не добавляет альтернативных полей/конструкторов этого generic-demo. U04 view/snapshot копирует структуру, не скрыто копирует Book: сохраняйте тот же canonical mutator/accessor. ## U04/U05/U07: каноническая запись и reflection

Файл `grade/Student.java` побайтно совпадает с текущим принятым определением application chapter:

```java
package grade;

import java.util.Objects;

public record Student(String id, String name, int score) {
    public Student {
        Objects.requireNonNull(id);
        Objects.requireNonNull(name);
        id = id.strip();
        name = name.strip();
        if (id.isEmpty() || name.isEmpty()
                || hasSeparator(id) || hasSeparator(name)) {
            throw new IllegalArgumentException("неверный код или имя");
        }
        if (score < 0 || score > 100) {
            throw new IllegalArgumentException("балл вне диапазона 0..100");
        }
    }

    private static boolean hasSeparator(String value) {
        return value.indexOf(';') >= 0 || value.indexOf('\n') >= 0
            || value.indexOf('\r') >= 0;
    }
}
```

`strip()` нормализует id/name; пустота, `;`, CR/LF в нормализованном поле и score вне 0..100 → IAE; null → NPE. Каталог отдельно запрещает повтор id после strip, case-sensitive. Record equality использует все три компонента и не заменяет уникальность id. Компактный конструктор сохраняет нормализованные параметры после нормального завершения.

Reader-visible reflection находится в `theory/chapters/data-classes.qmd#sec-j25-theory-data-classes-reflection`. Перед первой `Class<?>` объяснено: Class описывает тип, `?` — пока неизвестный аргумент типа; никаких wildcard-операций до U03. Полный `grade/ReflectionDemo.java` с import `java.lang.reflect.RecordComponent`:

```java
package grade;

import java.lang.reflect.RecordComponent;

public class ReflectionDemo {
    public static void main(String[] args) {
        Student student = new Student(" s1 ", " Ada ", 90);
        Class<?> type = Student.class;
        System.out.println(student.id());
        System.out.println(type.isRecord());
        for (RecordComponent component : type.getRecordComponents()) {
            System.out.println(component.getName() + ":"
                    + component.getType().getSimpleName());
        }
    }
}
```

Вывод: `s1`, `true`, `id:String`, `name:String`, `score:int` (каждое на отдельной строке). Экземпляр, объект Class и компоненты метаданных различены. Последний тип — `int.class`, не Integer. `int.class` — объект Class, описывающий примитивный тип; балл 90 остаётся значением int, а не экземпляром Object. Получение описания не упаковывает число в Integer. У обычного класса components=null, поэтому не обещать безусловный foreach для любого Class. Эта предпосылка/вывод не спрятаны в notes. Private reflection, DI/serializer/framework не добавлены.

Record shallow immutability: общий `int[]` через вход и accessor изменяется с обоих концов; две записи с разными `new int[]{1,2}` дают `equals=false`. Полные clone/view/snapshot коллекций остаются U04. Enum/sealed остаются коротким минимумом; эволюция третьего варианта и Smalltalk/Self — явно дополнительный опыт.
