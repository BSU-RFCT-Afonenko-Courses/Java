## Замороженные контракты

**Box / Book.** `course.examples.generics.Box<T>` final, один private final T
value, public Box(T), public T get(); базовый Box допускает null. Полный
`course.examples.objects.Book` побайтно воспроизводит accepted U02 declaration:
Book(String), title(), borrowed(), borrow() с повторным отказом до mutation.
Это не `course.examples.plain.Book`; нет `new Book()` и доступа к private полю.
Box<Book> сохраняет одну книгу: вызов borrow через get → borrowed true,
get()==book true. Повторный borrow → IllegalStateException, borrowed остаётся
true. Final ссылка не означает snapshot/deep copy/ownership/non-null.

**Сравнение.** `ComparisonDemo` в `course.examples.generics` определяет вложенные
Person(final rank, Comparable<Person>, Integer.compare) и Student extends Person.
Он отдельный от `grade.Student` record. Ненулевые аргументы, обе функции
возвращают один исходный объект; при равенстве выбирается первый. Strict:
`<T extends Comparable<T>>`; flexible:
`<T extends Comparable<? super T>>`. Все пять случаев имеют полные definitions
и раздельные inventory contexts:

| Вызов с a=Student(1), b=Student(2) | Результат | Inventory case |
|---|---|---|
| `Person p = strict(a,b)` | pass, T=Person; p==b true | `comparison-strict-person` |
| `var p = strict(a,b)` | pass, статический Person; kind(p)=Person | `comparison-strict-var` |
| `Student s = strict(a,b)` | compile-fail, incompatible inference bounds | `comparison-student-target` |
| `ComparisonDemo.<Student>strict(a,b)` | compile-fail, explicit Student нарушает bound | `comparison-explicit-student` |
| `Student s = flexible(a,b)` | pass, T=Student; s==b true | `comparison-flexible-student` |

Пять самостоятельных первоначальных author probes подтвердили каждый случай
actual JDK25; текущий source-derived `comparison-positive` дополнительно
проверил person/var/flexible в полном видимом файле. Полная негативная программа
не склеивается с compile-pass демонстрацией.

**PECS append.** Exact signature:
`static <T> void copy(List<? extends T> source, List<? super T> target)`.
Дописывание в конец, сохранение порядка source и прежнего prefix target;
source не меняется, пустой source ничего не делает. Source/target ненулевые,
разные независимые lists; alias/self-transfer/shared-view исключены. Target
mutable и поддерживает add; элементы non-null и допустимы для target.
Копируются значения ссылок; элементы не клонируются. Контракт не включает
atomicity/rollback и не требует обнаружения произвольных alias/view связей.
Source `[1,2]`, target `[0.5]` → source `[1,2]`, target `[0.5,1,2]`.
Integer→Number и Integer→Object разрешены; Number→Integer rejected.
Изменяемость не следует из wildcard: extends-view.clear() допустим; add
заранее выбранного ненулевого значения через extends запрещён. Приёмник
List.of компилируется, но отказывает с UOE при добавлении.

**Arithmetic / dot.** Единственная Java-сигнатура
`<T> T dot(List<T>, List<T>, Arithmetic<T>)` со связанными zero/add/multiply.
Ненулевые lists/elements/arithmetic/results, операции не мутируют вход.
Different lengths → IAE до zero/цикла. `[1,2]·[3,4]` →11.0; замена только zero
на1.0 при прежних add/multiply →12.0. Empty/empty → zero (0.0 либо1.0).
Complex `[1+i,2]` и `[3,4−i]` →11+i без сопряжения; record Complex immutable.
Начальный нейтральный элемент — математическое условие, не свойство одной
сигнатуры. C++ vector, Python dot сохраняют эти данные/билинейную сумму.
Array<T,N> C++20 проверяет одинаковый N отдельно при компиляции; Java List и
C++ vector проверяют длину при выполнении. Отсутствие value parameter Java
не выводится из стирания T.

**Python Protocol.** HasScore имеет read-only property score:int. Candidate
с frozen dataclass score:int не наследует протокол; checker принимает его
по структуре, runtime даёт True. BadCandidate(score:str) отвергается checker;
при прямом runtime после первого хорошего True возникает TypeError.
Объект без score дал бы AttributeError. Generic Arithmetic[T](Protocol)
принимает FloatArithmetic/ComplexArithmetic без nominal inheritance;
BadArithmetic.multiply→str rejected checker, runtime float+str→TypeError.
Wrong zero допустим checker и даёт12.0/1.0. Python3.14.7, Pyright1.1.412,
strict configuration локально в каждом inventory directory; нет модуля typed.
C#11/.NET7 comparison документирован, компилятор/CLR не запускались. Zig
в owned scope не добавлен и не заявлен проверенным.

**Erasure.** Исходный тип, JVM descriptor, Signature и класс фактического
содержимого раздельны. Box.get: descriptor `()Ljava/lang/Object;`, Signature
`()TT;`; Box<String>/Box<Integer> имеют общий runtime class, contents дают
String/Integer. Client BoxClient и SourceClient получают checkcast String.
Getter bridge TextSource.Object get() отмечен ACC_BRIDGE/ACC_SYNTHETIC и
делегирует String get(); в данном bridge checkcast отсутствует. Raw/unchecked
обход связи приводит к позднему CCE; SuppressWarnings скрывает диагностику,
но не исправляет содержимое. Полные runnable/javap sources идут ниже.

    def zero(self) -> T: ...
    def add(self, left: T, right: T) -> T: ...
    def multiply(self, left: T, right: T) -> T: ...

class FloatArithmetic:
    def zero(self) -> float:
        return 0.0
    def add(self, left: float, right: float) -> float:
        return left + right
    def multiply(self, left: float, right: float) -> float:
        return left * right

class ComplexArithmetic:
    def zero(self) -> complex:
        return 0j
    def add(self, left: complex, right: complex) -> complex:
        return left + right
    def multiply(self, left: complex, right: complex) -> complex:
        return left * right

    result = arithmetic.zero()

        term = arithmetic.multiply(left[i], right[i])
        result = arithmetic.add(result, term)
    return result
