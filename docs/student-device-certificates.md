# Подключение к учебным устройствам: Windows, macOS, Linux

Прототип инструкции для браузера студента. Преподаватель выдаёт точный HTTPS-адрес, **публичный корневой CA** и независимо подтверждённый SHA-256 сертификата. Сервер может работать в LAN по постоянному IP без DNS; этот IP должен быть указан в IP SAN серверного сертификата. `localhost` студента не является адресом VM. Для доступа к Moodle не требуется доступ к панели Proxmox.

Студент не получает приватные ключи, PFX/P12 или пароль к ключу. Перед импортом проверьте название, издателя, срок и Basic Constraints `CA=true`. Название само по себе не подтверждает подлинность. Импортируйте только согласованный корень: он позволяет доверять серверным сертификатам этого CA. На управляемом компьютере следуйте политике администратора.

| Платформа | Инструкция |
| --- | --- |
| Windows 10/11 | [Пошаговый импорт в CurrentUser Root, браузеры и удаление](student-windows-certificates.md) |
| macOS | Раздел ниже: Keychain Access для текущего пользователя |
| Linux | Раздел ниже: Firefox либо системное/NSS-хранилище |

Один CA устанавливается один раз для данной учётной записи/хранилища. Для другого CA требуется новая проверка; на другом компьютере доверие устанавливается отдельно.

## Проверка файла на macOS и Linux

Откройте терминал, укажите путь к выданному публичному сертификату в PEM:

```sh
cert="$HOME/Downloads/ca.crt"
openssl x509 -in "$cert" -noout -subject -issuer -dates -fingerprint -sha256
openssl x509 -in "$cert" -noout -text
```

Сверьте все 64 hex-символа SHA-256 с отпечатком, подтверждённым преподавателем отдельно. Проверьте `CA:TRUE` в Basic Constraints. Если файл в DER, добавьте `-inform DER` к обеим командам; формат уточните у преподавателя. Это отпечаток сертификата, а не хеш текстового PEM-файла. Если требуется PEM для импорта в Linux:

```sh
openssl x509 -inform DER -in "$HOME/Downloads/ca.cer" -out "$HOME/Downloads/ca.pem"
```

При несовпадении отпечатка не импортируйте сертификат. [OpenSSL x509](https://docs.openssl.org/3.5/man1/openssl-x509/).

## macOS

1. Откройте **Keychain Access / Связка ключей** через поиск Spotlight. Это отдельное приложение от Passwords / Пароли.
2. Выберите связку **login / вход** своей учётной записи. Через File → Import Items добавьте проверенный публичный CA либо перетащите файл в Keychain Access. Системная связка для всего компьютера требует отдельного администрирования.
3. Откройте добавленный сертификат, снова сверив его сведения и SHA-256. Раскройте **Trust / Доверие** и задайте доверие для **Secure Sockets Layer (SSL)**. Не требуется менять доверие для подписи программ или почты. Закройте окно; если macOS запросит авторизацию, используйте стандартное окно ОС.
4. Полностью закройте и откройте Safari/Chrome, затем проверьте точный выданный HTTPS-адрес и цепочку сертификата.
5. Firefox на macOS может автоматически учитывать пользовательские CA ОС. Проверьте параметр автоматического доверия сторонним корням; если профиль не учитывает корень, импортируйте проверенный CA в Authorities этого профиля по разделу ниже.

[Apple: добавление сертификата](https://support.apple.com/guide/keychain-access/kyca2431/mac), [Apple: изменение доверия](https://support.apple.com/guide/keychain-access/kyca11871/mac), [Mozilla: доверие CA операционной системы](https://support.mozilla.org/en-US/kb/setting-certificate-authorities-firefox).

Чтобы удалить доверие, найдите **точный** импортированный CA по отпечатку в выбранной связке, удалите только его и перезапустите браузер. Если сертификат установлен через профиль управления, обратитесь к администратору; не удаляйте другие корни. Ручной импорт в Firefox удаляется отдельно из того профиля.

## Linux: Firefox без изменения всей системы

Откройте Settings → Privacy & Security → Certificates → View Certificates → **Authorities** → Import. Выберите проверенный публичный CA и разрешите доверие для идентификации веб-сайтов. Названия пунктов зависят от версии Firefox. Перезапустите браузер и откройте точный HTTPS-адрес преподавателя. Установка действует для данного профиля.

Это не вкладка личных сертификатов, и не исключение для ошибочного сайта. Firefox на Linux не обязательно использует системные CA автоматически; импорт в Authorities работает независимо от настройки ОС. [Mozilla: способы установки CA](https://support.mozilla.org/en-US/kb/setting-certificate-authorities-firefox), [изменение доверия и удаление](https://wiki.mozilla.org/CA/Changing_Trust_Settings).

## Linux: системное доверие и Chromium

Если нужен доступ из разных приложений, после проверки CA администратор добавляет его в систему. Для **CachyOS/Arch** (публичный PEM или DER):

```sh
sudo install -m 644 "$HOME/Downloads/ca.crt" /etc/ca-certificates/trust-source/anchors/course-device-ca.crt
sudo update-ca-trust extract
```

Для **Debian/Ubuntu** нужен PEM с расширением `.crt`:

```sh
sudo install -m 644 "$HOME/Downloads/ca.crt" /usr/local/share/ca-certificates/course-device-ca.crt
sudo update-ca-certificates
```

Эти имена принадлежат данной инструкции: перед установкой проверьте, что существующий файл с таким именем отсутствует либо содержит тот же сертификат. Не заменяйте чужой CA. Для других дистрибутивов используйте их процедуру; настройка на CachyOS не доказывает проверку всех дистрибутивов. [Arch update-ca-trust](https://man.archlinux.org/man/update-ca-trust.8), [Debian update-ca-certificates](https://manpages.debian.org/testing/ca-certificates/update-ca-certificates.8.en.html).

Chromium в Linux также использует пользовательскую NSS-базу. Если системного импорта недостаточно, откройте менеджер сертификатов Chromium и импортируйте тот же проверенный CA для сайтов. При использовании `certutil` учитывайте актуальное расположение базы: с M146 это `$HOME/.local/share/pki/nssdb`, но существующая `$HOME/.pki/nssdb` имеет приоритет. NSS `certutil` отличается от одноимённой Windows-команды. [Официальная инструкция Chromium](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/cert_management.md).

После изменения доверия полностью перезапустите браузер. При завершении работы удалите только точный файл CA, который установили, и повторите штатную команду обновления системного доверия. Пользовательские импорты в NSS/Firefox удаляются отдельно по отпечатку. Не очищайте всё хранилище.

## Проверка подключения и помощь

Откройте выданный HTTPS-адрес: нет предупреждения о сертификате, имя/IP относится к нужному серверу, цепочка заканчивается выданным CA. Затем проверьте вход из Moodle. Тайм-аут требует проверки сети/IP/порта; ошибка имени — IP SAN; ошибка срока — часы и срок сертификатов; неизвестный издатель — CA, хранилище, профиль браузера и перезапуск. Если сервер не передаёт промежуточные сертификаты, это исправляет преподаватель. Не импортируйте leaf или промежуточный сертификат в Root.

Инструкция основана на официальных источниках; системная/NSS-настройка и Chromium проверены на CachyOS. На настоящих Windows/macOS эти шаги пока не проходили очную проверку, поэтому инструкция остаётся прототипом. Автоматизация **разработчика** проверяется отдельно для CachyOS; студент не запускает разработческий стенд и не переносит его приватные ключи.
