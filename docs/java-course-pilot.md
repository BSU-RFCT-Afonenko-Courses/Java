# Пилот курса Java: обобщения

Этот документ задаёт текущую работу и хранит её результаты. Устойчивые
правила находятся в [методике](authoring-methodology.md), общий вход —
в [рабочей документации](README.md).

## Цель и границы

Подготовить законченный комплект по обобщениям в пяти формах: связный
раздел теории, одну цельную лекцию, адресный справочник, одно введение
к лабораторной и лабораторную с самостоятельными заданиями. Минимальность
относится к охвату тем: полноценный рассказ не заменяется коротким макетом.

Сначала перестраивается рабочая документация и проходит отдельную
независимую рецензию. После её исправления и самостоятельного коммита
начинается работа над учебным комплектом. В конце готовый пилот показывается
локально пользователю. Следующая обязательная остановка — его рецензия
перед распространением решений на остальные темы.

Ветка — `codex/java-course-pilot`. Публикация и слияние в это задание
не входят. Остальные материалы курса сохраняют доступность; готовность
пилота не означает, что весь курс прошёл новую редактуру. Общий ориентир
в девять презентаций не требует подготовить девять презентаций сейчас.

## Техническая проверка

Технический исполнитель работает с завершёнными авторскими примерами.
Для каждого существенного результата сохраняются исходник, команда,
среда и наблюдение. Ожидаемая ошибка компиляции проверяется отдельно
от корректного примера; схема не заменяет фактический вывод `javap`.
Полные запускаемые файлы доступны по назначению, а отчёт о выполнении
находится здесь, вне учебного рассказа.

Штатная корневая сборка:

```sh
bash CI/render.sh
```

Она выполняет student → full → student. Отдельный проход возможен командой:

```sh
quarto render . --profile student --fail-if-warnings
```

Для преподавательского прохода используется `--profile full`. Результаты —
`_site-student/` и `_site-full/`. Корневая сборка охватывает пять проектов.
Готового профиля обобщений нет; точечный рендер может оставлять QRC-ссылки
отложенными и не доказывает связности комплекта. Объём проверки сокращают
только после исследования зависимостей с явной записью ограничения.

`delivery.instances.pilot` в `tasks/_quarto.yml` и запуск
`CI/check-projects.sh` относятся к поставке первых трёх лабораторных.
Они не проверяют лабораторную обобщений. Независимый маршрут этой поставки
описан в [документации PrairieLearn](prairielearn-labs.md).

После сборки локальный сайт можно открыть из каталога `_site-student/`
через статический HTTP-сервер. Проверяются главная, все пять форм пилота,
QRC-переходы и обе презентации. Рецензия читает полученный результат,
а не только исходную разметку.
