# Структура страниц и очистка документации двух курсов

По прямому уточнению пользователя от 7 ноября разрешены только `gpt-6.1-sol` и `gpt-6.1-terra`; роли и усилия задаёт обновлённая матрица. Учебный автор и независимый рецензент — разные Sol/high; ключевая архитектура и её независимая рецензия — разные Sol/max. Standard сохраняется.

Вы — N6, `gpt-6.1-sol/high`. Прочитайте [общее поручение](common.md). Владеете картой переносов, структурой источников, ссылками и служебной документацией обоих курсов. N1/N2 владеют телами условий до явной передачи готовой партии. N0 применяет корневые configs/pins и регенерирует установленную выдачу.

## Задачи

1. До перемещения составить точную карту старый → новый путь, коллизий имён, ресурсов и включений. Java:23 `theory/chapters/*.qmd` → `theory/`,25 `handbook/entries/*.qmd` → `handbook/`. Для SP применять равные правила по фактической структуре актуального PR11, не переносить старые локальные предположения.
2. Существующие вводные страницы использовать как нативный `part: документ.qmd`; убрать повторяющий первый пункт. В Java начальные случаи — `tasks/_quarto.yml` группы labs/bank/essays. Группы без вводных сохранить; новых11обзоров не создавать и первую предметную главу в обзор не превращать.
3. После передачи владения от N1/N2 переместить страницы, обновить все source links/includes/resources и передать N0 дельту конфигураций. Смысловые anchors сохранять, когда нет действительной необходимости менять их; проверить новые коллизии. Старые URL/редиректы не поддерживаются.
4. Провести очистку документации во всём обоих репозиториях, включая docs и корневые README/AGENTS/UPSTREAM. Классификация по назначению: действующая норма/руководство/учебный материал/исторический отчёт/план/одноразовое свидетельство. Число502 из прежнего отчёта не является разрешённым списком удаления.
5. До удаления перенести все живые требования, полномочия и действующие ссылки. Не удалять учебные Markdown/README комплектов по расширению файла. Исторические документы доступны в Git; новый archive не создаётся. Сохранять текущие спецификацию/план/задания, матрицу моделей, процедуру допуска и нужные методику/договоры до принятой рабочей замены.
6. Устаревшие executable helpers внутри docs передать техническому владельцу для проверки callers; удаление реально заменённого helper возможно после передачи нужных гарантий. Не превращать чистку docs в обход strict typing активного кода.
7. Запросить N0 полную регенерацию межпроектных каталогов и публикаций обоих курсов, проверку всех внутренних ссылок, скачиваний, ресурсов и переходов. Нельзя ограничиться ручной заменой путей в двух YAML.

## Приёмка и выход

Независимый Sol проверяет карту переносов, live-нормы, links и удаления. Изменение учебного содержания направляется N1/N2 и отдельному Sol-рецензенту. Выход: проверяемая структурная дельта, сокращённые актуальные входные docs, список удалений и их оснований, полный список требуемых проверок. Финальный PASS зависит от интеграционных refs и свежих результатов N0.
