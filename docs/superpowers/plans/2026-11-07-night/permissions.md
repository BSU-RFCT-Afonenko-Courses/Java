По прямому уточнению пользователя от 7 ноября разрешены только `gpt-6.1-sol` и `gpt-6.1-terra`; роли и усилия задаёт обновлённая матрица. Учебный автор и независимый рецензент — разные Sol/high; ключевая архитектура и её независимая рецензия — разные Sol/max. Standard сохраняется.

Нужны разрешения для конкретной программы и создаваемых рабочих копий. Полный доступ ко всему ноутбуку не требуется. Сейчас проверки исполнения и изменение настроек не выполнялись: пользователь отложил старт до следующего хода.

## Уже данное полномочие

- Создание отдельных Codex-чатов с субагентами для принятого плана; пользователь явно разрешил взаимные сообщения и передачи между ними.
- Упрощение и удаление неиспользуемого кода/API, обновление всех поддерживаемых consumers, редактура полного состава обоих курсов, перенос страниц и очистка документов после переноса живых требований.
- Обычные Git/зависимости/проверки/PR/релизы/публикация в рамках принятого регламента после соответствующей независимой приёмки. Недоступный сервер, Moodle, личные ключи и данные студентов не изменяются.

Разговорное полномочие не изменяет sandbox или GitHub scopes. Новые чаты отдельно проверяют фактически полученные права; унаследование не обещается.

## Нужные границы доступа при старте

| Доступ | Назначение и граница |
| --- | --- |
| Запись в `/home/tolya/Java/CI/.tools/night-20261107/` и Git metadata создаваемых копий | Изолированные checkout/ветки/коммиты, отчёты, инструменты и caches. Исходные старые пользовательские деревья не меняются |
| Сеть GitHub и соответствующие registry/CDN | Clone/fetch, зависимости, опубликованные runtime/toolchain, CI/PR и разрешённые push/release. Используются настоящие репозитории курса/расширений и их штатные manifests |
| Авторизованные Git/GitHub операции | Использовать существующие SSH-agent/GitHub-подключение, без извлечения или печати приватных ключей/токенов. Force-push чужих веток, удаление чужих PR и перезапись пользовательской работы не нужны |
| Локальный Docker daemon | Контейнерные проверки/сборки в единственном тяжёлом слоте; только ресурсы этой программы. Чужие контейнеры/volumes не останавливаются и не удаляются |
| Локальные loopback-сервисы и браузер | Временный preview и контрактные проверки только в выделенной рабочей области. Выход на старый сервер не требуется |
| Установка инструментов в рабочую область | Изолированные Python/Node/Deno/Java/Gradle/браузерные зависимости. Cache/venv располагаются здесь; системная установка и изменение `HOME` не являются стандартным путём |
| Инструменты управления чатами и GitHub | Создание семи чатов, wait/read/send между ними, необходимые PR/checks/release operations в согласованных репозиториях |

Предпочтителен ограниченный профиль записи в рабочую область с нужной сетью/локальным Docker и поддерживаемой автоматической проверкой разрешений. Не выбирать `never` как способ обойти отказы; отключение вопросов само по себе прав не добавляет. Автоматически разрешить все будущие неизвестные действия невозможно. Применить выбранные права нужно к новым чатам, а не только к текущему планировщику.

Точные Unix socket и registry hosts устанавливаются по фактической локальной конфигурации/штатным зависимостям при старте; не разрешать неизвестный удалённый Docker или прежний сервер по совпадению имени. Если профиль не допускает конкретный необходимый шаг, N0 запрашивает узкое системное разрешение с точной командой и причиной. После пользовательского окна недоступный пакет отмечается блокировкой, независимые задачи продолжаются; запреты не обходятся.

## Первая проверка после команды запуска

N0 сначала выполняет безопасные проверки доступа: создаёт свою рабочую копию и обычный коммит в ней; читает refs GitHub; проверяет работающий локальный Docker и loopback preview; получает штатные зависимости в выделенный cache. Это actual preflight, не проведённая проверка данного плана. Если требуется человеческая настройка, сообщить до первого массового пакета.

## Официальное основание

Песочница ограничивает доступ к файлам/сети, а политика approval отдельно определяет пересечение границ. [Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security). Auto-review применяется к подходящим запросам и сохраняет управляемые ограничения; она не означает безусловное разрешение каждой операции. [Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review).
