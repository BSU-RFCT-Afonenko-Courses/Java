# Типизация PrairieLearn Platform и Gateway

По прямому уточнению пользователя от 7 ноября разрешены только `gpt-6.1-sol` и `gpt-6.1-terra`; роли и усилия задаёт обновлённая матрица. Учебный автор и независимый рецензент — разные Sol/high; ключевая архитектура и её независимая рецензия — разные Sol/max. Standard сохраняется.

Вы — N4, `gpt-6.1-sol/high`. Прочитайте [общее поручение](common.md). Владеете каноническими PL exporter, Platform/runtime/checker/Bridge, действующим Gateway и реально относящимся собственным инфраструктурным кодом. Репозиторий Gateway установить по происхождению; Platform Bridge и VM-каталог не являются его заменой.

## Вход

PL закреплён Java на `087a60b00a6865dd4703d0fa6ef6378f85798f2a`. Исправление инициализации — Platform PR48 `b9a0f94ed1c45eb86d661617f0c296c4dd9c03fd`; общий CI не пройден. N0 выдаёт свежие refs и единолично запускает проверки/образы. Core public types принадлежат N3, установленные course copies — N0.

## Задачи

1. Установить полный собственный поддерживаемый состав и точки входа TS/JS/Python/Java/Shell/SQL-схем; vendor/imported исключить из ручной переработки, генерацию исправлять у производителя. Для JS выбрать проверяемые типы или TS по простоте, для Python — один строгий проверяющий инструмент с реальным покрытием.
2. Разобрать CI PR48. [Лог](https://github.com/Afonenko-Course-Tools/prairielearn-platform/actions/runs/42277175734/job/128096382516) содержит512tests/53skipped и единственную ошибку `test_plain_gradle.PlainGradleTests.test_ordinary_jar_run_and_test`: холодный изолированный `GRADLE_USER_HOME`, `gradle --offline --no-daemon … jar run test`, timeout35s. Это гипотеза стоимости инициализации, не установленная причина. Прочитать тест/окружение, заказать N0 адресное воспроизведение и времена фаз; исправлять подтверждённую причину, не повышать timeout вслепую.
3. Адаптировать Core public contracts. Начальные остатки: `application/native-answer.ts`, `native-delivery.ts`, `slots.ts`, `grading-policy.ts`, `completion.ts`, `source-selection.ts`. Исчерпывающе обработать виды ответов; сохранить смешанное ручное/автоматическое оценивание, приватность ключей, required/alternatives/max100 и различение инфраструктуры/ошибки решения.
4. Проверить действующий состав форм116/5/7 и допустимые имена/пути. Сохранённый Java `docs/release-transfer-20261105/local-checks/verify-java-full-export.py` ожидает старые126files-or-zip+2ZIP; определить, заменён ли этот one-off, и согласовать удаление с N6 либо исправить действующий consumer. Три реальные формы на прежнем стенде не объявлять заново принятыми этим исходным аудитом.
5. Улучшить сохранение результатов через существующие `check-course.py --id/--scenario`, маленькие партии и штатные отдельные отчёты. Synthetic прерывание должно оставить завершённые отчёты и точный неисполненный остаток. Новый оркестратор, DSL, manifest или receipt не создавать. Если требуется код, менять существующий checker минимально.
6. Удалить действительно неиспользуемые маршруты после проверки entrypoints/config/callers, обновить всех поддерживаемых consumers без compatibility layer. Приватность, безопасные paths, подписи/идентичность и валидность результата остаются предметными гарантиями.
7. Заказать N0 адресные регрессии, type/contract checks и относящуюся штатную CI. Исходные команды включают `quarto run tools/check-contracts.ts`, `bash tools/check-java.sh`, Node bridge tests и Python unittest; точный набор определяется свежим workflow и изменённой границей.

## Выход

Независимо проверенные коммиты, подтверждённая причина CI/исправление либо точный открытый диагноз, конечный typed-code inventory, проверяемые producer → consumer связи и сохранение штатных отчётов при прерывании. Источник, CI, опубликованный образ, установленный образ и полный course run имеют отдельные статусы. На сервер, старый стенд, Moodle, ключи и студенческие данные не воздействовать.
