# План реализации обновления Java и System Practice

По прямому уточнению пользователя от 7 ноября разрешены только `gpt-6.1-sol` и `gpt-6.1-terra`; роли и усилия задаёт обновлённая матрица. Учебный автор и независимый рецензент — разные Sol/high; ключевая архитектура и её независимая рецензия — разные Sol/max. Standard сохраняется.

> Исполнителям: выполнять задачи через `superpowers:subagent-driven-development` либо `superpowers:executing-plans` с выбранным владельцем. Прямое поручение пользователя задаёт работу отдельными чатами с субагентами; дополнительный выбор способа исполнения не нужен. Сейчас план подготовлен без запуска.

**Цель:** выполнить согласованный полный редакторский и технический проход обоих курсов в оставшемся окне до 7 ноября 2026 года, 10:29:13 Europe/Minsk.

**Архитектура:** семь отдельных чатов, непересекающееся владение кодом и текстами, один интегратор и единственный исполнитель тяжёлых локальных команд. Свежие изолированные рабочие копии сохраняют старые пользовательские каталоги. Поддерживаемые потребители переходят на упрощённые публичные API без слоя совместимости.

**Технологии:** Quarto/Pandoc, TypeScript/JavaScript, Python, Java/Gradle/JUnit, поддерживаемые Shell/Fish/PowerShell/Lua, GitHub Actions, существующие Platform/Gateway и artifacts.

**Спецификация:** [согласованные решения](../specs/2026-11-07-java-system-practice-night-design.md).

## Общие ограничения

- Последнее указание — только план; чаты и исполнение запускаются следующим ходом пользователя.
- Java и SP равноправны, объём — все 128 условий Java и все семь задач актуального SP, без выборочной замены полной работы.
- Предельное время — 7 ноября, 10:29:13 Europe/Minsk; отсчёт от первоначального сообщения владельца не сдвигается.
- Ровно один тяжёлый локальный процесс; локальные проверки типов и тестовые наборы по умолчанию также занимают этот слот.
- Пользователь прямо разрешил всем чатам и субагентам этой программы взаимные сообщения и передачи результатов. Разрешение переносится в каждое стартовое поручение.
- У файла/контракта в каждой фазе один владелец; владелец установленной копии, pins, корневых конфигураций и тяжёлых запусков — интегратор.
- Модельная матрица и полный собственный допуск обязательны. Глобальную конфигурацию моделей, Standard и личные авторизации не менять.
- Сохранять пользовательские деревья, незакоммиченные изменения и открытые PR. Старые URL/API можно удалить; учебные цели, оценивание, пользовательские данные и личные ключи сохраняются.
- Новые README, документация, задания и PR — по-русски; API, команды, пути, имена пакетов и URL буквально.
- Не создавать новый runner/сервис очередей/формат доказательств. Сначала использовать существующие selectors, отчёты и стандартные средства ОС/CI.
- Чтение старых START и календарей не запускает старую программу. Недоступный стенд и сервер не являются целями подключения.

## Риски для независимой проверки

1. Сокращение условия удаляет существенный способ ввода, состав файлов, ручной вопрос или требование самостоятельности — проверяет содержательный рецензент каждой партии.
2. Типы производителя расходятся с реальным потребителем либо скрывают непроверенный JSON — проверяются адресные контракты producer → consumer и статическая проверка всех активных входов.
3. После перемещения страницы ломаются включения, ресурсы, относительные ссылки или межкнижный каталог — проверяется свежая полная публикация обоих курсов и все внутренние адреса.
4. Обрыв проверки теряет завершённые результаты или частичные файлы принимаются за PASS — проверяется прерывание штатных маленьких партий и сохранность законченных штатных отчётов.
5. API-упрощение или объединение выдач переносит приватные bytes в student — проверяются student HTML/ZIP и отрицательные случаи путей/доступа на изменённых границах.

1. **Вход и доступы:** N0 сверяет bases, metadata, scopes и назначает владельцев; N1–N6 читают свои входы. Начальные блокировки записываются адресно.
2. **Параллельная работа:** редактура, инвентаризация типов, API-дизайн, чтение CI, карта docs и переносов. Каждый законченный пакет идёт в независимую рецензию.
