# Случайные альтернативы и первые три лабораторные Java — план выполнения

> Утверждён пользователем 12 октября 2026 года. Выполнение: инструменты — high, учебные материалы — ultra, независимые рецензенты — high/ultra; модель наследуется от текущего чата.

**Цель:** реализовать случайные альтернативы как одну позицию работы, выпустить согласованный комплект инструментов, затем подготовить первые три лабораторные Java и новый PR.

**Организация агентов**

| Агент | Усилие | Ответственность |
|---|---|---|
| Инструменты | `high` | Core, экспортёр, Platform, Gateway, инфраструктура, интеграционные тесты, выпуск |
| Учебные материалы | `ultra` | Условия Java, стартовые программы, решения, публичные и закрытые тесты, ошибочные реализации |
| Независимые рецензенты | `high` / `ultra` | Код и инфраструктура / содержание и проверка заданий |

Модель наследуется от текущего чата; усилие каждого исполнителя задаётся явно. Агентам передаются конкретные задачи и зафиксированные интерфейсы. Одновременное редактирование одного файла запрещено.

### Task 2: Закрепить единый новый контракт — агент `high`

   Принятый синтаксис:

   ```qmd
   ::: {.task-items stage="homework"}
   1. @exr-console-greeting
   1. [@exr-lunar-weight; @exr-gallon-conversion]{.task-alternatives #alt-numbers-conversion selection="random"}
   :::
   ```

   Все позиции нормализуются в одну модель:

   ```ts
   interface AssessmentSlot {
     id: string;
     selection: "fixed" | "random";
     candidates: string[];
     assignment: {
       stage?: "demonstration" | "classroom" | "homework";
       requirement: "required" | "optional";
       workMode: "individual" | "pair" | "group";
     };
   }
   ```

   Правила контракта:

   - Обычная ссылка — `fixed`, один кандидат, устойчивый ID из `exr-*`.
   - Группа — `random`, явный ID `alt-*`, минимум два различных кандидата, назначается ровно один.
   - Полный ключ позиции: `course/work/slot`; ключ вопроса: `course/exr-*`.
   - Один кандидат не может повторяться в разных позициях одной работы. Между работами повторное использование разрешено.
   - Обязательность и режим работы относятся ко всей позиции.
   - Баллы и попытки задаются для позиции; внутри группы максимальная цена вариантов одинакова.
   - Время группы — диапазон `min–max` её кандидатов. Диапазоны позиций суммируются; вводное время учитывается отдельно один раз.
   - До создания экземпляра работы назначенного варианта нет. После назначения повторные отправки сохраняют его.

   **Жёсткое ограничение:** одна актуальная схема для каждого интерфейса. Удалить старые обработчики, совместимые ветки, aliases и преобразования прежних поставок. Устаревшие схемы отклонять понятной ошибкой.

   Новые транспортные контракты: Body v2, native delivery v2, completion/results v2. Gateway получает единую актуальную конфигурацию именованных курсов, без прежнего standalone-режима.

### Task 4: Реализовать экспортёр — агент `high`

   Основные участки: `application/export.ts`, `export-course.ts`, `grading-policy.ts`, `completion.ts`, native validation и схемы.

   - Принимать только новый Body-контракт.

     ```json

     ```

   - Обычная позиция создаёт обычный native question block.
   - Запретить сочетание `id` и `alternatives`; не задавать выбор подмножества всей зоны.
   - Экспортировать и проверять **всех кандидатов**, включая неназначаемых конкретному студенту.

   Приёмка: native assessment назначает один вариант каждой группы; каталог содержит все вопросы; работают singleton, random и смешанные работы; проходят регрессии Java, fish и `EXDEV`.

### Task 5: Реализовать Platform и Gateway — агент `high`

   Platform: `bridge/server.mjs`, `native.sql`, `policy.mjs`, result schemas и операции синхронизации. Gateway: загрузка delivery, `grades.py`, `pl.py`, назначения, конфигурация и хранилище.

   - Bridge получает выбранный вопрос из штатных `instance_questions` конкретного экземпляра работы.
   - Проверяет состав native-группы, соответствие delivery, принадлежность кандидата и единственность выбора.
   - Учитывает, что native-группа существует также у обычной одиночной позиции.
   - Возвращает идентификатор экземпляра работы и ровно один результат каждой назначенной позиции.
   - Отсутствие экземпляра работы возвращается отдельным состоянием «не начато», без выдуманного выбора.
   - При существующем экземпляре пропавший, чужой или множественный выбор считается ошибкой.
   - Gateway независимо проверяет позиции, выбранные вопросы, попытку и версию назначения.
   - Позиция выполнена только при завершённой штатной оценке выбранного вопроса с полным результатом.
   - Не выбранные альтернативы не увеличивают знаменатель оценки и не считаются пропущенными.
   - Сохранить различие между фактической взвешенной оценкой лабораторной и признаком выполнения обязательных позиций.
   - Удалить поддержку прежних delivery/results/config.
   - Проверять неподдерживаемую поставку и старую БД **до** открытия хранилища на запись.
   - Новую БД создавать сразу в актуальной схеме. Автоматических миграций прежних данных не делать.

   Приёмка: неверный delivery/attempt/selected question отвергается; повторные отправки, переоценка и перезапуск сохраняют корректную привязку; partial и optional не закрывают обязательную позицию.

### Task 6: Подготовить Java для совместной приёмки — агент `ultra`

   Подготовку вести параллельно инструментам на изолированном кандидате PR12. Финальный PR Java пока не публиковать; кандидат нужен для проверки инструментов до их выпуска.

   | Числовые вычисления | `console-greeting`, `lunar-weight`, `lightning-distance`, `boolean-truth-table`, `interval-membership`, `short-circuit-and`, `gallon-conversion` |
   | Управляющие конструкции | `month-name`, `multiplication-table`, `count-console-spaces`, `toggle-console-case`, `number-extrema` |
   | Массивы | `array-average`, `reverse-array`, `subtract-array-average`, `sort-matrix-rows`, `move-row-zeros` |

   Для каждого проекта подготовить условие, компилируемый starter, авторское решение, полезные публичные примеры, закрытые JUnit-тесты, ошибочные реализации и ожидаемые результаты их проверки.

   Обязательные границы:

   - Учебное содержание — только PR12.
   - Java 25 без preview.
   - Условия фиксируют наблюдаемый контракт, сохраняя выбор алгоритма и организации программы.
   - Для матриц явно разрешить дополнительные входы **3×3, значения −3…3**, сохранив исходную матрицу обязательным примером.
   - Сортировку проверить на переставленных строках и равных суммах.
   - ASCII-преобразование регистра сохраняет остальные UTF-8 символы, включая кириллицу и emoji.
   - Эхо в задаче о молнии остаётся дополнительной неоцениваемой частью.
   - Не навязывать числовые CLI-аргументы задачам с заданными константами.
   - Требования к `&&`, двум `double` и использованию массива вынести в критерии преподавательской проверки. Автотесты не объявлять доказательством этих свойств исходника.
   - Не вводить неожиданные проверки произвольных размеров, `null`, рваных матриц или неоговорённых числовых диапазонов.
   - Обновить формулировки лабораторных и практик: вариант назначает PrairieLearn.
   - Сохранить 17 канонических `exr-*`; добавить три ID групп.
   - Оставить общие manual-defaults банка; автоматическую проверку подключить только к выбранным 17 заданиям.
