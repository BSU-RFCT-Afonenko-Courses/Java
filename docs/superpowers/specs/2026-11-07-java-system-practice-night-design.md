## Архитектурные границы

Используются существующие Quarto, Pandoc, экспортёр, checker, штатные artifacts и Native PrairieLearn. Публичный тип имеет одного владельца; потребители импортируют поддерживаемый API. JSON/YAML/HTTP/CLI проходят проверку на границе, затем передаются типизированными. Runtime-проверки приватности, путей, принадлежности и достоверности результата сохраняются.

Для TypeScript действует строгая проверка активных точек входа. Для собственного JavaScript выбираются проверяемые JSDoc-типы либо переход к TypeScript, если он упрощает результат. Для Python выбирается один подходящий строгий проверяющий инструмент; для Java — конкретные типы и диагностика небезопасных операций; для retained Lua — подходящие проверяемые аннотации. Shell/Fish проверяются доступными синтаксическими и статическими средствами и контрактными тестами. Точные механизмы фиксирует технический владелец после инвентаризации актуального кода. Намеренно ошибочные учебные примеры проверяются на ожидаемую диагностику, а демонстрационные raw types сохраняют учебный смысл.

Число удалённых `any` не является критерием готовности. Обязательны реальные производители и потребители API, сохранённое поведение, отсутствие маскирующих приведений/подавлений и конечный список поддерживаемых файлов. Ненужные совместимые ветви удаляются после проверки прямых и косвенных callers, конфигураций и генерируемых входов. Новая схема данных, AST-каркас, delivery manifest, оркестратор или общий кеш не вводятся без доказанной необходимости.

## Роли и приёмка

Роли и усилия задаёт `docs/agent-execution-proposal-20261029.md` с прямым уточнением пользователя от 7 ноября: только `gpt-6.1-sol` и `gpt-6.1-terra`. Старые назначения других моделей не применяются. Планирование Sol/ultra сохраняет свою отдельную область; исполнительный интегратор и технические владельцы — Sol/high, устойчивый ограниченный технический пакет — Sol/medium. Учебное авторство и независимая содержательная рецензия — разные Sol/high; ключевые межрепозиторные архитектурные решения проходят отдельный Sol/max-дизайн и Sol/max-рецензию. Terra/medium применяется к ограниченной служебной/визуальной работе, Terra/high — к ограниченной редакторской или содержательной партии с независимой Sol/high-проверкой. Maximum всем не назначается. Standard обязателен.

До роли, после возобновления и перед приёмкой каждый исполнитель подтверждает собственные первичные metadata и весь исходный интервал по `docs/model-admission.md`. Автор не принимает собственную работу. Весь код, включая стартеры, примеры, fixtures и тесты, пишет технический исполнитель. Содержательный рецензент проверяет каждую изменённую смысловую дельту; нового общего педагогического пилота нет.

Редактура сохраняет учебные цели, обязательные предметные объяснения, допустимые решения, ввод/вывод, API, файлы, пакеты, погрешности, самостоятельность, ручные вопросы, обязательность и балльные правила. SP сохраняет полноценные PowerShell/Fish и bundle/Workspace в действительном предметном объёме. Публичная выдача сохраняет границу student/private.

Существующие пользовательские деревья, PR, пользовательские файлы, история и данные студентов сохраняются. Решение об отказе от старых URL и API не является разрешением потерять эти данные. Полная эксплуатационная приёмка на недоступном стенде остаётся отдельной фазой.
