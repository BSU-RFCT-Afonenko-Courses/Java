# Стартовый промпт для продолжения на CachyOS

Этот промпт — общий вход в работу над банками Java и System Practice
на другом компьютере. Передайте новому чату текст следующего раздела.
Личные каталоги, локальные предпросмотры и журналы прежней машины не нужны.

## Текст для нового чата

Продолжи согласованный план публикации всего банка заданий Java
и System Practice, начиная с обязательных работ. Методика уже согласована;
повторного общего утверждения и педагогического пилота Java не требуется.
Принятые лекции 1, 2 и 5 сохраняют статус. Прежние редакционные задачи
не возобновляются автоматически.

До авторства или технической работы подтверди собственные первичные
метаданные запуска. Автор содержания и независимый рецензент работают
на `gpt-6-astra` / `ultra`, координатор и технический исполнитель —
на `gpt-6.1-sol` / `high`. Рецензент проверяет чужой текст.
Установи собственный ID по `session_meta.id` и, для подагента, `agent_path`;
проверь `model`, `effort`, `turn_id` в `turn_context` и согласованность
настроек режима совместной работы, если они присутствуют. ID родителя
и глобальные настройки не заменяют это свидетельство. Сохрани собственный
ID, начальный ход и результат проверки на текущей машине. После
возобновления и перед приёмкой проверяй весь интервал от исходного хода.
Отсутствие подтверждения или несовпадение останавливает соответствующую
роль. Специальная утилита прежнего компьютера для входа не требуется.

1. **Получи актуальные исходники обоих репозиториев.** Проверь удалённые
   адреса [Java](https://github.com/BSU-RFCT-Afonenko-Courses/Java)
   и [System Practice](https://github.com/BSU-RFCT-Afonenko-Courses/System-Practice).
   Получи свежие удалённые ссылки, включая ветки PR с методикой.
   Получи актуальные вершины
   [PR Java №18](https://github.com/BSU-RFCT-Afonenko-Courses/Java/pull/18)
   и [PR System Practice №4](https://github.com/BSU-RFCT-Afonenko-Courses/System-Practice/pull/4),
   исходная ветка обоих — `codex/task-publication-methodology-20261020`.
   Прочитай актуальную вершину каждого PR, даже если он ещё не слит;
   обновления одной ветки по умолчанию недостаточно. Зафиксируй URL PR
   и исходные коммиты. Для слитого PR проверь наличие принятых изменений
   в выбранной базе. Недоступную или неоднозначную базу уточни.
2. **Сохрани пользовательскую работу.** Проверь незакоммиченные изменения,
   ветки, рабочие деревья и открытые PR. Используй подходящее изолированное
   дерево либо создай его от проверенной вершины PR или базы с принятыми
   изменениями. Предпочти нативное управление рабочими деревьями, если оно
   доступно; иначе используй отдельное дерево Git. Пользовательские ветки
   не переключай; разрушительный сброс файлов и истории не выполняй.
3. **Прочитай действующие правила в каждом репозитории.** Открой его
   [AGENTS.md](../AGENTS.md), [вход в документацию](README.md),
   [дополнение методики](authoring-methodology.md#публикация-банка-заданий)
   и [порядок от 20 октября](course-revision-plan.md#публикация-банка-заданий-согласованный-порядок-от-20-октября-2026-года).
   Применяй требования к авторству и проверке. Старые сроки, абсолютные
   пути и локальные передачи прежних редакций не являются условиями входа.
4. **Применяй шесть принятых решений плана.** Задача System Practice —
   законченный самостоятельный результат; совместимые исторические карточки
   пробуют объединить с действующими, неиспользуемые и не соответствующие
   содержанию удаляют при переработке. Простые задачи Java используют только
   JDK и консоль; сложные, которым нужна система сборки, — Gradle вместо Maven.
   Комплекты минимальны; производные файлы Gradle генерирует сам.
   После первоначальной подготовки зависимостей локальные сборки и публичные
   проверки работают без загрузок. Подробная рубрика
   предназначена преподавателю, дополнительные действия студента кратко
   названы в условии. Курсы Java и System Practice в PrairieLearn раздельны,
   лабораторная — оценочная работа, задача — вопрос. Эти решения повторно
   не согласовывай. Уточняй оставшиеся попытки, баллы, веса и сочетание
   оценок перед зависимым действием; независимую работу продолжай.
   Совместимую версию Gradle проверь технически. Первоначальный запуск
   явно обеспечь установленным Gradle либо минимальным Wrapper, если нужен
   запуск без установленного Gradle; этот адресный выбор остаётся открытым.
5. **Выполняй этапы последовательно.** Применяй принятую методику,
   включая студенческое представление; организуй исходники, ID,
   зависимости и раздачу по принятым решениям; адаптируй задания и экспорт;
   проверь фактическое представление в PrairieLearn. Сохраняй весь банк в охвате,
   начиная с обязательных работ. Раздельно подтверждай исходники,
   скачиваемый комплект, экспорт, импорт на сервер и сдачу студентом,
   связывая результат с точным снимком.

CachyOS не подменяет будущую приёмку PowerShell 7 на Windows. Сохраняются
маршрут fish/Linux и обязательный GitHub по SSH в третьей лабораторной.
Gradle не требуется непрограммным задачам Java и задачам System Practice
с оболочкой или Git. Реальный обмен с GitHub и сдача в PrairieLearn требуют сети.

Изменения аккаунтов, ключей и действующих настроек, реальная публикация
в PrairieLearn, изменение Moodle, выпуск общих инструментов и слияние PR
требуют отдельного согласования. До него подготовь доступные локально
результаты и укажи, какая внешняя проверка остаётся открытой.
