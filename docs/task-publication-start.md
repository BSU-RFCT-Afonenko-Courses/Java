# Стартовый промпт для выполнения общего плана на CachyOS

Скопируйте следующий раздел целиком в новый чат. Он продолжает работу
над обоими курсами по репозиторным документам без материалов прежней машины.

## Текст для нового чата

Выполни [общий план публикации банков Java и System Practice](task-publication-plan.md)
на этом компьютере CachyOS. Разрешены локальные изменения исходников,
подготовка комплектов, проверки и новые реализационные PR. Действующую
PrairieLearn и Moodle, аккаунты, ключи и настройки доступа меняй только
по отдельному поручению; слияние PR и выпуск общих инструментов также
требуют отдельного разрешения.

Начни как координатор: `gpt-6.1-sol` / `high`. До своей работы подтверди
собственные первичные `session_meta` и `turn_context`: ID чата, модель,
усилие и начальный ход; ID родителя не подходит. Сохрани свидетельство
на текущей машине. После возобновления и перед приёмкой проверяй весь
интервал от исходного хода. При несовпадении останови эту роль; глобальную
конфигурацию не меняй. Для новых агентов используй `fork_turns="none"`
и явные `model`/`reasoning_effort` по нормативной таблице общего плана.
Не ограничивай ожидаемые усилия возможностями старого проверяющего скрипта.

Справочная копия ролей для старта приведена ниже. После получения исходников
сверь её с [единственным нормативным источником](task-publication-plan.md#роли-и-модельный-допуск).

| Роль | Модель | Усилие |
|---|---|---|
| Координатор | `gpt-6.1-sol` | `high` |
| Архитектор | `gpt-6.1-sol` | `xhigh` |
| Автор и методист | `gpt-6-astra` | `ultra` |
| Независимый содержательный рецензент | `gpt-6-astra` | `ultra` |
| Технический исполнитель | `gpt-6.1-sol` | `medium` |

1. Найди локальные репозитории
   [Java](https://github.com/BSU-RFCT-Afonenko-Courses/Java) и
   [System Practice](https://github.com/BSU-RFCT-Afonenko-Courses/System-Practice);
   если их нет, клонируй в свободные каталоги. Проверь адреса и получи свежие
   удалённые ссылки обоих репозиториев. Сохрани незакоммиченные изменения,
   пользовательские ветки, рабочие деревья и открытые PR.
2. Проверь текущее состояние
   [PR Java №18](https://github.com/BSU-RFCT-Afonenko-Courses/Java/pull/18) и
   [PR System Practice №4](https://github.com/BSU-RFCT-Afonenko-Courses/System-Practice/pull/4).
   Для открытого PR получи его свежую вершину; исходная ветка обоих —
   `codex/task-publication-methodology-20261020`. Для слитого PR получи
   свежую ветку по умолчанию и проверь наличие принятых документов.
   Закрытый без слияния PR либо неоднозначную базу уточни. Зафиксируй
   коммиты обоих курсов; одной свежей ветки по умолчанию при открытом PR
   недостаточно. Используй подходящее изолированное рабочее дерево или
   создай его нативным средством, если доступно, иначе через Git.
   Пользовательскую ветку не переключай; разрушительный сброс не выполняй.
3. В каждом репозитории прочитай его [AGENTS.md](../AGENTS.md),
   [вход в документацию](README.md) и
   [методику](authoring-methodology.md#публикация-банка-заданий), затем
   [общий план](task-publication-plan.md) из Java. Применяй его узкую политику
   ролей. Личные пути, сроки и передачи прежних редакций не являются
   условиями входа. Принятые лекции Java 1, 2 и 5 сохраняют статус;
   общего повторного утверждения методики и нового педагогического пилота нет.
4. Запусти нужные роли по плану, с собственным модельным допуском каждого
   агента. При четырёх местах работай волнами: координатор, архитектор,
   автор и технический исполнитель; после архитектурной передачи —
   координатор, автор, другой содержательный рецензент и технический
   исполнитель. Весь код, включая стартеры, эталоны и тесты, поручай
   техническому исполнителю; автору — содержание, архитектору — контракты
   без реализации. Назначай одного владельца файла на фазу; фиксируй снимок
   передачи и освобождение владения. Не позволяй автору принимать свой текст.
5. Исполняй шесть фаз общего плана, начиная с обязательных работ и сохраняя
   весь банк в охвате. Семь пользовательских решений уже приняты.
   Простые задачи Java используют только JDK и консоль; сложные —
   установленный Gradle вместо Maven, без Wrapper в комплекте.
   Исходники и выдача минимальны; производные файлы Gradle создаёт при работе.
   После подготовки зависимостей локальные сборки и публичные проверки
   выполняются без загрузок. Подробные критерии остаются преподавателю;
   необходимые дополнительные действия кратко указаны в условии.
6. Перед зависимыми настройками предложи меню только оставшихся попыток,
   баллов, весов и итогового оценивания, с ответом вида `8А 9Б`.
   Не выдумывай ответы; независимую работу продолжай. Раздельно подтверждай
   исходники, архив, экспорт, импорт и сдачу студентом на точных снимках.
   Выполни проверки рабочих окружений, минимальных комплектов, публичных
   и закрытых материалов, сайта и настоящего студенческого представления.
   Оформляй проверенные партии новыми реализационными PR.

CachyOS не подтверждает маршрут PowerShell 7/Windows. fish/Linux и реальный
GitHub по SSH имеют собственные проверки. Реальный обмен с GitHub и сдача
в PrairieLearn требуют сети. При отсутствии разрешённого внешнего доступа
зафиксируй открытые проверки, сохраняя достигнутые локальные результаты.
