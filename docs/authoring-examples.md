# Аннотированные образцы объяснения

Эти две учебные единицы поясняют [методику](authoring-methodology.md).
Первая взята из принятого пилота обобщённого программирования; вторая
показывает применение тех же принципов к ссылочным значениям. Аннотации
предназначены автору и рецензенту, а не для переноса в лекционный текст.

## От `ObjectBox` к `Box<T>`

В принятой [последовательности об общем контейнере](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/92069a7b540b96e9fde19e7531b5273c495da744/lectures/generics.qmd#L32-L170)
контейнер сначала хранит `Object`.
Клиент получает значение и приводит его к `String`. Пока в контейнер
положена строка, этот путь даёт ожидаемый результат. Замена аргумента
конструктора на `25` оставляет программу компилируемой, но приведение
в клиенте завершается `ClassCastException`.

Два следующих вызова — альтернативные варианты опыта:

```java
ObjectBox box = new ObjectBox("Java"); // чтение как String успешно
ObjectBox box = new ObjectBox(25);     // чтение как String даст ClassCastException
```

Заметки пилота предлагают до объяснения назвать строку, где обнаружится
ошибка, а при введении `T` — проследить три его появления. Они направляют
внимание и задают паузу для прогноза. Уточнение о типах исходной программы
готовит дальнейший переход к стиранию; вывод о представлении в JVM остаётся
на соответствующих экранах. Видимый рассказ уже содержит причину отказа,
поэтому заметки дополняют его, не закрывая пробел в объяснении.

Следующий шаг вводит `Box<T>`: один параметр типа связывает поле,
аргумент конструктора и результат `get`. В `Box<String>` попытка положить
`25` обнаруживается при компиляции, а чтение возвращает `String` без
приведения в исходнике клиента. Изменилось место обнаружения ошибки,
и читатель видит, какое отношение позволило её обнаружить.

Здесь сохранены конкретный контейнер, действие клиента и ошибочное значение.
Новое средство решает уже понятную задачу. Синтаксис `<T>` получает смысл
через связь входа и выхода. Объяснение завершается ограничением: обобщение
само по себе не запрещает `null`. Эта граница стоит рядом с результатом,
который студент мог бы ошибочно обобщить.

Дальнейшее рассмотрение стирания возвращается к тому же классу. Исходник
и `javap` различают обещание типов в программе и представление JVM;
компилятор вставляет `checkcast` в клиенте. Для мостового метода отдельно
показан вызов метода с конкретным возвращаемым типом. Один рисунок
«Java → байткод» не смог бы объяснить оба разных действия.

## От общего массива к параметру метода

Исходное состояние задаётся явно:

```java
int[] pages = {5, 7};
```

Метод требует непустой массив; в этом опыте условие выполнено.

```java
static void correctFirst(int[] data) {
    data[0] = 9;
}
```

В момент вызова `correctFirst(pages)` новый параметр получает копию
ссылочного значения. Обозначение `A` именует один объект, а не адрес памяти.

```text
кадр main                  кадр correctFirst
pages ─────────┐           data ────────┐
               └───────────┬────────────┘
                           v
                       A: [5, 7]
```

После `data[0] = 9` объект `A` содержит `[9, 7]`. Обе переменные по-прежнему
содержат ссылку на `A`, поэтому после возврата `pages[0]` равно `9`.

Теперь вызывается другой метод с тем же массивом `[9, 7]`:

```java
static void replace(int[] data) {
    data = new int[]{1, 2};
}
```

```text
кадр main                  кадр replace
pages ──> A: [9, 7]         data ──> B: [1, 2]
```

Присваивание заменило значение переменной `data`. Переменная `pages`
в другом кадре сохранила ссылку на `A`; после возврата `pages[0]` равно `9`.
Копирование значения аргумента объясняет оба результата одним правилом.

На экране нужны начальные данные, две переменные, общий объект, действие
и результат. В заметках преподавателю полезно предложить прогноз перед
`replace`, затем указать на левую часть присваивания: имя параметра или
компонент массива. Убирать один из этих двух результатов в заметки нельзя:
при самостоятельном чтении исчезло бы основание различия.

В сравнении с C++ опорой служит конкретное действие: присваивание параметру
типа `T&` меняет объект, связанный с этой ссылкой. Параметр Java `int[]`
является отдельной переменной со скопированным значением; рисунок показывает
место, где аналогия с параметром `T&` заканчивается.

Первичное основание — JLS 25 §15.12.4.5: значения аргументов присваиваются
новым переменным параметров. Кадры и локальные переменные описаны в JVMS 25
§2.6. Книга Шилдта, печ. с.190–192, помогает поставить два опыта и завершает
их пояснением о копировании самой ссылки. Оборот «как будто по ссылке»
на с.191 читается вместе с этим уточнением; правило в курсе формулируется
сразу через копирование значения.
