# Доступ к учебным устройствам с Windows

Эта инструкция — прототип для студентов с Windows 10/11. Перед подключением
преподаватель сообщает **точный HTTPS-адрес устройства**, выдаёт публичный
корневой сертификат CA (`ca.crt` или `ca.cer`) и отдельно подтверждает его
SHA-256. Здесь нет выпущенного сертификата или адреса будущего стенда: их выдадут
при развёртывании. CA локального демонстрационного стенда не является заранее
утверждённым CA будущей учебной сети.

Если устройство доступно по статическому IP виртуальной машины без DNS,
открывайте выданный адрес `https://<IP>:<порт>/…`. Серверный сертификат должен
содержать **именно этот IP как IP Address в Subject Alternative Name (SAN)**.
`localhost` на вашем компьютере обозначает ваш компьютер, а не сервер курса.
Само добавление CA не исправляет неправильный адрес или SAN.

## Получите и проверьте сертификат

Получите файл от преподавателя через согласованный канал. SHA-256 подтвердите
независимо от скачанного файла, например на занятии или в отдельном сообщении
преподавателя. Не берите корневой сертификат из предупреждения неизвестного сайта.

Нужен только **публичный корневой CA**. Студенту не нужны приватный ключ,
`*.key`, `*.pfx`/`*.p12` или пароль к ключу. Откройте сертификат: проверьте название,
издателя, срок действия и в «Подробно / Details» — «Основные ограничения / Basic
Constraints»: это должен быть центр сертификации (`CA=true`), а не сертификат
конкретного сайта. Название само по себе не подтверждает подлинность. Доверие
к этому корню разрешает браузеру доверять сертификатам, выданным этим CA.

Для проверки SHA-256 **сертификата** откройте обычный Windows PowerShell
(без «Запуск от имени администратора»), укажите путь к полученному файлу:

```powershell
$file = "$env:USERPROFILE\Downloads\ca.cer"
$cert = [System.Security.Cryptography.X509Certificates.X509Certificate2]::new($file)
$sha = [System.Security.Cryptography.SHA256]::Create()
try {
    $fingerprint = [BitConverter]::ToString($sha.ComputeHash($cert.RawData)).Replace('-', '')
} finally { $sha.Dispose() }
$cert | Format-List Subject, Issuer, NotBefore, NotAfter, Thumbprint, HasPrivateKey
$fingerprint
```

Сверьте все 64 шестнадцатеричных символа `$fingerprint` с SHA-256, который
подтвердил преподаватель; пробелы, двоеточия и регистр несущественны.
`HasPrivateKey` должен быть `False`. При несовпадении остановитесь и сообщите
преподавателю; не устанавливайте файл. `Thumbprint` в Windows обычно является
SHA-1 и **не заменяет эту проверку SHA-256**. Сохраните Thumbprint для точного
удаления сертификата позже.

Если преподаватель вместо отпечатка сертификата явно предоставил **SHA-256
файла**, сравните `(Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash`.
Это другая проверка: для одного сертификата PEM и DER имеют одинаковый отпечаток
сертификата, но разные хеши файлов. [Microsoft: Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash?view=powershell-7.5).

## Установите для своей учётной записи Windows

1. Нажмите **Win+R**, введите `certmgr.msc` и нажмите Enter. Откроется
   «Сертификаты — текущий пользователь / Certificates — Current User».
2. Откройте «Доверенные корневые центры сертификации / Trusted Root Certification
   Authorities» → «Сертификаты / Certificates».
3. В контекстном меню выберите «Все задачи / All Tasks» → «Импорт / Import».
   Укажите проверенный файл; при необходимости выберите отображение всех файлов.
4. Выберите «Поместить все сертификаты в следующее хранилище» и проверьте,
   что выбран именно раздел доверенных корневых CA **текущего пользователя**.
   Завершите мастер, подтвердив установку только проверенного корня.
5. Найдите установленный сертификат и сверьте его Thumbprint с сохранённым.

`certmgr.msc` открывает пользовательское хранилище, `certlm.msc` — компьютерное.
Для этой инструкции используется первое. Обычно права администратора не нужны;
на управляемом компьютере импорт может запрещать политика организации — тогда
обратитесь к преподавателю/администратору, не обходите запрет.
[Microsoft: области хранилищ сертификатов](https://learn.microsoft.com/en-us/windows-server/identity/ad-cs/inspect-certificates-manage-certificate-stores).

Вместо мастера, **после проверки выше**, можно выполнить один из вариантов
в обычном PowerShell:

```powershell
Import-Certificate -FilePath $file -CertStoreLocation 'Cert:\CurrentUser\Root'
```

или:

```powershell
certutil -user -addstore Root "$file"
```

`-user` обязателен для пользовательского варианта `certutil`. Не устанавливайте
сертификат в LocalMachine, Personal или Intermediate вместо Root.
[Microsoft: Import-Certificate](https://learn.microsoft.com/en-us/powershell/module/pki/import-certificate),
[Microsoft: certutil](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/certutil).

## Откройте сайт в браузере

Полностью закройте и снова откройте Edge/Chrome, затем перейдите по точному адресу
преподавателя. Локальные доверенные корни учитываются браузерами наряду с их
встроенными корнями: [Microsoft Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-security-cert-verification),
[Chrome Certificate Verifier](https://chromium.googlesource.com/chromium/src/+/main/net/data/ssl/chrome_root_store/faq.md).
Проверьте сведения о соединении: сертификат относится к нужному IP, цепочка
заканчивается выданным CA, предупреждения о сертификате нет. Не используйте
«Продолжить, несмотря на предупреждение» для входа в Moodle/Gateway.

В современном Firefox для Windows сначала проверьте «Настройки / Settings» →
«Приватность и защита / Privacy & Security». Найдите раздел сертификатов
(в новых версиях — «Защита соединения и программ / Connection and software
security» → «Дополнительные настройки / Advanced settings») и параметр
**Allow Firefox to automatically trust third-party root certificates you install**.
Включённый параметр позволяет учитывать CA из ОС; перезапустите Firefox.
[Mozilla: доверие корням ОС](https://support.mozilla.org/en-US/kb/automatically-trust-third-party-certificates).

Если CA всё ещё не учитывается, можно импортировать тот же проверенный публичный
файл в профиль Firefox: «Просмотр сертификатов / View Certificates» → «Центры
сертификации / Authorities» → «Импорт / Import», разрешив доверие для идентификации
веб-сайтов. Не используйте вкладку личных сертификатов. Такая установка относится
к данному профилю Firefox; её нужно отдельно удалить из Firefox при завершении
работы. Если настройки заблокированы политикой, обратитесь к администратору.
[Mozilla: ручное изменение доверия](https://wiki.mozilla.org/CA/Changing_Trust_Settings).

## Если соединение не работает

| Симптом | Что проверить |
|---|---|
| Сайт не открывается, тайм-аут | Правильные IP/порт, сеть/VPN и доступность VM; импорт CA не исправляет сетевое соединение. |
| Ошибка имени, например `ERR_CERT_COMMON_NAME_INVALID` | IP в адресной строке должен совпадать с IP SAN серверного сертификата; преподаватель исправляет адрес/сертификат. |
| Ошибка срока действия | Дата, время и часовой пояс Windows; срок действия CA и серверного сертификата. |
| Неизвестный издатель | Точный SHA-256 CA, выбранное пользовательское хранилище, перезапуск браузера; для Firefox — доверие ОС или импорт в профиль. |
| Не хватает промежуточного CA | Сервер должен передавать нужную цепочку; сообщите преподавателю. Не помещайте серверный или промежуточный сертификат в Root. |
| Импорт/настройки заблокированы | Политики учебного компьютера; запросите помощь администратора. |

Если несколько устройств используют **один и тот же CA**, установите корень один
раз для этой учётной записи Windows; адрес и SAN проверяйте у каждого устройства.
Для другого CA нужна отдельная проверка и установка. На другом компьютере или
в другой учётной записи Windows доверие настраивается отдельно.

## Удаление после завершения работы

Когда вы больше не используете данный учебный CA, откройте `certmgr.msc` →
Trusted Root Certification Authorities → Certificates. Найдите сертификат по
**точному сохранённому Thumbprint**, проверьте название и удалите только его.
Не удаляйте другие корни и не очищайте хранилище целиком.

Альтернатива в обычном PowerShell: замените значение на сохранённый Thumbprint
(SHA-1, 40 символов, без пробелов), сначала просмотрите точный объект и действие:

```powershell
$thumbprint = 'ВСТАВЬТЕ_СОХРАНЕННЫЙ_THUMBPRINT'
if ($thumbprint -notmatch '\A[0-9A-Fa-f]{40}\z') { throw 'Нужен точный Thumbprint' }
$path = "Cert:\CurrentUser\Root\$thumbprint"
Get-Item -LiteralPath $path | Format-List Subject, Issuer, Thumbprint
Remove-Item -LiteralPath $path -WhatIf
```

После проверки, если вы **решили удалить именно этот сертификат**:

```powershell
Remove-Item -LiteralPath $path -Confirm
```

Если корень установлен политикой или для всего компьютера, попросите
администратора удалить соответствующее доверие. Для ручного импорта в Firefox
удалите также точный CA из Authorities этого профиля. Перезапустите браузеры.

[Microsoft: работа с Cert: и удаление по Thumbprint](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/about/about_certificate_provider?view=powershell-7.5).
