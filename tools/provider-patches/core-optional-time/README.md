# Необязательная оценка времени в Core

> Историческая поправка пилота Core 6. Текущая установка использует опубликованный Core 7.1.0 из `providers.json`; эта поправка и rebuild.py в ней не участвуют. Ниже сохранена документация прежнего пилота для воспроизведения его исходного дерева; прежний `--install` относится только к историческому checkout курса, а не к текущей ветке.

Эта локальная поправка позволяет хранить банковскую задачу без оценки
времени. Она нужна для пилота курса Java: его условия и страницы не должны
содержать вымышленные тайминги. Установленный Core отклонял такие задачи
до отображения страницы с `CORE.METADATA_INVALID`, поле `time`.

Поправка основана на точном исходном commit
`9db360beec417b3798693026768262be2f7d3b18` репозитория
`Afonenko-Course-Tools/quarto-course`, закреплённом в курсе до адаптации.
Это локальное изменение исходников, а не новый опубликованный выпуск.
Точная база получена из Git; соседний commit или содержимое текущей
рабочей директории вместо неё не используются.

## Поведение

- Собственная `difficulty` банковской задачи остаётся обязательной.
- `time` можно не задавать. Если значение задано, оно должно быть
  положительным конечным целым числом минут, как и прежде.
- Отсутствие оценки не заменяется нулём, `null` или служебным числом.
- Если у хотя бы одного кандидата любой позиции работы нет оценки,
  сводка времени всей работы не выводится. Это относится и к кандидатам
  необязательных позиций: нельзя выдать неполный расчёт за полную оценку.
- Для работы со всеми заданными оценками сохраняется прежний расчёт:
  диапазоны альтернатив, суммы обязательных и всех позиций, добавление
  `theoryTime`. Поправка не меняет прежнее значение `theoryTime` по умолчанию.

Presentation уже выводит значок времени только при наличии значения.
Его реализация и Navigation не требуют изменений. Другие темы курса
продолжают использовать собственные заданные оценки.

## Состав

| Файл исходного пакета | Изменение |
| --- | --- |
| `course-core/native-document.lua` | Снять обязательность `time`, сохранить обязательность `difficulty` |
| `course-core/spec/core.cue` | Необязательное положительное целое поле в упражнении и декларации; условный перенос при построении деклараций |
| `course-core/domain/model.ts` | Необязательное поле в типах упражнения и декларации |
| `course-core/domain/release.ts` | Проверять значение времени только при его наличии |
| `course-core/entrypoints/preview.ts` | Не вычислять сводку при неполном наборе оценок |

Пути таблицы указаны относительно `_extensions` исходного репозитория.
Текстовый `optional-time.patch` также содержит адресную регрессионную
проверку. `manifest.json` фиксирует базу, контрольную сумму поправки
и ожидаемые Git commit/tree восстановленного исходника. Эти сведения
позволяют воспроизвести локальный commit без его публикации.

## Восстановление и установка

Нужны Python 3, Git и локальный репозиторий `quarto-course`, содержащий
точный базовый commit. Его рабочее дерево может находиться на другой
ревизии: сценарий использует закреплённую базу. Для установки нужен также
Quarto, доступный существующему `tools/sync-providers.py`.

Из корня репозитория курса выполните:

```sh
python3 tools/provider-patches/core-optional-time/rebuild.py \
  --source-repository /absolute/quarto-course \
  --work-dir /absolute/new-parent
```

Вместо путей примера укажите исходный репозиторий и новый отдельный
каталог. Сценарий читает исходный репозиторий, создаёт изолированный
`new-parent/quarto-course`, применяет поправку и проверяет ожидаемые
commit/tree. Исходный репозиторий не изменяется. Для повторной проверки
используйте другой новый каталог.

Чтобы одновременно установить восстановленный пакет в текущую ветку
курса, добавьте `--install`:

```sh
python3 tools/provider-patches/core-optional-time/rebuild.py \
  --source-repository /absolute/quarto-course \
  --work-dir /absolute/another-new-parent \
  --install
```

Установка вызывает существующий интерфейс
`tools/sync-providers.py --provider core`. Он устанавливает полные
пакеты Core, Presentation и Navigation в области, перечисленные
в `providers.json`, и записывает состав и контрольные суммы
в `installed-packages.json`. Исходники Presentation и Navigation
в восстановленном commit остаются прежними. Установленные `_extensions`
вручную не исправляются.

`providers.json` указывает локальный commit из манифеста. Обычная попытка
получить только этот SHA с удалённого сервера не заменяет восстановление:
публикация commit не требуется. Для новой рабочей копии курса сохранены
сама поправка, точная база и сценарий её применения.

## Запуск регрессионной проверки

Из корня восстановленного репозитория `new-parent/quarto-course`
выполните отдельную проверку:

```sh
CUE=/home/tolya/course-tools/local-tools/cue/cue quarto run tests/optional-time.ts
```

Замените путь в `CUE`, если исполняемый файл находится в другом каталоге.
Quarto запускает TypeScript-проверку через встроенный Deno; отдельный
запуск `deno` не нужен. Эта проверка не включена в `npm test`:
общий набор тестов и `tests/optional-time.ts` запускаются отдельно.

В пилоте именно эта команда выполнена из
`/tmp/java-pilot-providers/quarto-course` с Quarto 1.11.5 и CUE 0.17.1.
Получены семь результатов `PASS`, процесс завершился с кодом 0.
Другие переменные среды для этой проверки не задавались.

## Граница проверки

Адресные проверки должны подтвердить допуск отсутствующего `time`, отказ
для недопустимого заданного значения, сохранение обязательной
`difficulty`, построение деклараций из упражнений без времени и отсутствие
сводки при неполных оценках. Полностью оценённая работа должна сохранять
прежний результат.

Восстановление исходников и установка пакета сами по себе не подтверждают
успешную сборку курса. После них нужны штатный рендер банка и лабораторной,
проверка отсутствия таймингов в результате и обычные проверки пилота.
