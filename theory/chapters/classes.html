11.1 Поля и операции состояния

Класс вводит тип, задаёт состояние его экземпляров и операции над ним. Инкапсуляция объединяет представление данных с этими операциями и ограничивает доступ к внутреннему устройству. Закрытые поля позволяют сосредоточить изменение состояния в коде класса. Его конструкторы и методы определяют, какие значения допустимы и как их можно менять [51], [87].

Состояние бронирования определяется вместимостью capacity и числом занятых мест occupied. Свободные места вычисляются как их разность. Класс предоставляет чтение остатка и операцию бронирования:

final class Reservation {
    private final int capacity;
    private int occupied;

    Reservation(int capacity) {
        if (capacity <= 0) {
            throw new IllegalArgumentException("capacity must be positive");
        }
        this.capacity = capacity;
    }

    int available() {
        return capacity - occupied;
    }

    void reserve(int count) {
        if (count <= 0 || count > available()) {
            throw new IllegalArgumentException("invalid reservation size");
        }
        occupied += count;
    }
}
Reservation room = new Reservation(30);
room.reserve(8);
System.out.println(room.available()); // 22
// room.occupied = 100;               // поле private недоступно клиенту

Конструктор проверяет вместимость перед записью в поле. Начальное значение occupied равно 0: пока все места свободны. Метод reserve меняет поле только после проверки размера запроса. Если попытаться занять 25 мест после первых восьми, метод бросит исключение до изменения поля, и останутся 22 места. Класс поддерживает инвариант при каждой операции, а клиенту не требуется повторять его проверки.

Метод setOccupied(int value) с проверкой диапазона задавал бы новое абсолютное количество. При бронировании клиент передаёт размер запроса, а класс сам добавляет его к числу занятых мест. Вычисление available() из двух полей также устраняет дополнительную обязанность: при каждой записи в occupied пришлось бы обновлять отдельно хранимый остаток.

11.1.1 Сохранение инварианта

У бронирования инвариант 0 <= occupied <= capacity описывает допустимый объект между вызовами. Предусловие успешного бронирования 0 < count <= available() описывает допустимый запрос в текущем состоянии. После успеха occupied увеличен на count, а вместимость прежняя. После отклонённого запроса оба поля прежние.

Например, после reserve(8) у комнаты на 30 мест свободно 22. Все клиенты, получившие ссылку на эту комнату, читают общий счётчик и видят 22 свободных места. При отказе бронирование сохраняет весь остаток. Частичное выполнение заставило бы клиента выяснять, сколько мест уже занято этим запросом, прежде чем продолжить работу.

Reservation room = new Reservation(30);
Reservation same = room;
room.reserve(8);
try {
    same.reserve(25);
} catch (IllegalArgumentException ex) {
    System.out.println(room.available()); // 22
}

Обработчик catch читает остаток после отказа. Проверка запроса предшествует изменению. Поскольку число занятых мест после сложения не превышает положительную вместимость типа int, этот способ проверки также не допускает переполнения при occupied += count.

Внутри сложной операции несколько записей могут временно нарушать инвариант. До возврата клиенту или вызова кода, который пользуется состоянием, он должен быть восстановлен; исход при ошибке определяется договором операции. У reserve проверка предшествует единственной записи, поэтому и успех, и отказ оставляют допустимое состояние. private ограничивает места записи; порядок действий задаёт тело метода.

Это ограничение меняет объём рассуждения о программе. Если occupied доступно для записи всем клиентам, сохранение инварианта зависит от каждой такой записи. При закрытом поле и единственной операции reserve достаточно проверить создание объекта и переход, выполняемый этим методом, при оговорённых условиях последовательного использования. Новый клиент бронирования получает тот же договор, не добавляя ещё одно место самостоятельного изменения счётчика.

Скрытое представление даёт и свободу последующего изменения. В комнате можно хранить число свободных мест вместо числа занятых, если available и reserve сохраняют прежнее наблюдаемое поведение. В клиентском коде с прямым доступом к occupied такая замена потребовала бы правок. Поэтому набор открытых операций выбирается по смыслу бронирования: публикация отдельного средства записи для каждого поля снова сделала бы клиентов зависимыми от устройства состояния. [53]

11.1.2 Защищённое состояние книги

Название книги — строка, отличная от null и содержащая хотя бы один непробельный символ. Оно фиксируется при создании. Книга также хранит состояние выдачи: доступная книга может перейти в выданное состояние. Повторная выдача — отказ, после которого borrowed остаётся true. У этой модели книги закрытые поля: клиент изменяет состояние выдачи через операцию borrow, которая сохраняет инвариант.

public final class Book {
    private final String title;
    private boolean borrowed;

    public Book(String title) {
        if (title == null || title.isBlank()) {
            throw new IllegalArgumentException("Название должно содержать хотя бы один непробельный символ");
        }
        this.title = title;
    }

    public String title() { return title; }
    public boolean borrowed() { return borrowed; }

    public void borrow() {
        if (borrowed) {
            throw new IllegalStateException("Книга уже выдана");
        }
        borrowed = true;
    }
}

Две ссылки на книгу дают доступ к одному состоянию:

Book book = new Book("Java");
Book alias = book;
alias.borrow();
System.out.println(book.borrowed()); // true
System.out.println(alias == book);   // true
try {
    book.borrow();
} catch (IllegalStateException ex) {
    System.out.println("refused");
}
System.out.println(book.borrowed()); // true

Первое true — наблюдение состояния, второе — наблюдение тождества. private запрещает клиенту прямую запись поля, а проверка внутри borrow отвергает неверный переход до записи. throw прекращает обычное выполнение; catch здесь перехватывает отказ, чтобы затем прочитать состояние. Полный механизм разобран в Глава 21. Ошибку создания new Book(" ") конструктор обнаруживает до получения готовой книги.

11.2 Конструкторы и проверка исходного состояния

Конструктор имеет имя класса и не имеет возвращаемого типа, даже void. Он участвует в инициализации нового экземпляра и не вызывается как обычный метод. В объявлении void Reservation(int capacity) наличие возвращаемого типа делает Reservation обычным методом; такой метод вызывается у уже созданного объекта. [78]

Если в обычном классе не объявлено ни одного конструктора, компилятор предоставляет конструктор по умолчанию без параметров. Как только появился собственный конструктор, автоматического варианта без параметров нет. У Reservation объявлен только Reservation(int capacity), поэтому вызов new Reservation() отвергается: клиент должен задать вместимость.

Несколько допустимых способов создания выражаются перегрузкой и делегированием:

final class Box {
    private final int width;
    private final int height;

    Box(int width, int height) {
        if (width <= 0 || height <= 0) {
            throw new IllegalArgumentException("positive dimensions required");
        }
        this.width = width;
        this.height = height;
    }

    Box(int side) {
        this(side, side);
    }

    int area() {
        return Math.multiplyExact(width, height);
    }
}

new Box(3).area() возвращает 9, а new Box(3, 4).area() — 12. Оба пути проходят одну проверку. Присваивание this.width = width различает поле текущего экземпляра и одноимённый параметр. Если написать только width = width, будет присваивание параметра самому себе; final-поле останется неинициализированным, что обнаружит компилятор.

Положительные размеры могут дать произведение за пределами int; Math.multiplyExact проверяет переполнение при вычислении площади.

this(...) вызывает другой конструктор того же экземпляра. Дополнительный объект при делегировании не создаётся. Цикл таких вызовов отвергается при компиляции. super(...) обращается к конструктору непосредственного суперкласса; без явного вызова в обычном классе, кроме Object, подразумевается super().

Java 25 разрешает пролог перед явным this(...) или super(...), например проверку параметра. В раннем конструировании нельзя читать поля текущего экземпляра, вызывать его методы или передавать его ссылку. Допускается простое присваивание собственному полю без инициализатора при соблюдении правил раннего доступа. Пример проверки и фактический порядок даны в Глава 12.2. В Box(int side) пролог пуст: делегирование выполняется первым. Правила тела конструктора, JLS 25 §8.8.7.

11.3 Ссылка this на текущий экземпляр

Обычный метод вызывается для конкретного объекта. Внутри метода this обозначает ссылку на этот объект. В room.reserve(8) именно room задаёт получателя; выражение occupied += count изменяет его поле. Второй экземпляр Reservation имеет своё поле и не меняется.

Reservation first = new Reservation(30);
Reservation second = new Reservation(30);
first.reserve(8);
System.out.println(first.available());  // 22
System.out.println(second.available()); // 30

Проверка доступа private учитывает расположение обращающегося к полю кода. Метод класса Box может читать source.width у другого экземпляра Box. Это позволяет сравнивать экземпляры и создавать копии через фабрики. Для вложенных классов область доступа также включает предусмотренные языком отношения с окружающим объявлением.

Возврат this позволяет продолжить вызовы на том же экземпляре:

final class Counter {
    private int value;
    Counter increment() {
        value = Math.incrementExact(value);
        return this;
    }
    int value() { return value; }
}

Counter counter = new Counter();
Counter same = counter.increment().increment();
System.out.println(counter.value()); // 2
System.out.println(same == counter); // true

Каждый increment() меняет поле получателя и возвращает его ссылку. Поэтому оба вызова и последующее чтение относятся к одному счётчику.

11.4 Перегрузка и выбор объявления

Методы могут иметь одинаковое имя и разные списки типов параметров. Перегрузка позволяет назвать одно семейство действий общим именем. Один возвращаемый тип не различает перегрузки.

static String describe(int value) { return "int"; }
static String describe(String value) { return "String"; }

System.out.println(describe(3));      // int
System.out.println(describe("3"));    // String

Компилятор выбирает подходящее объявление по типам выражений аргументов и правилам применимости. Если подходящие перегрузки принимают String и Integer, вызов с null неоднозначен: null совместим с обоими типами, а ни один из них не является подтипом другого. Явное приведение describe((String) null) выбирает перегрузку со String; значение аргумента остаётся null.

В другой паре перегрузок есть отношение подтипов:

static String kind(Object value) { return "Object"; }
static String kind(String value) { return "String"; }

Object text = "Java";
System.out.println(kind(text));   // Object
System.out.println(kind("Java")); // String

Тип выражения text — Object, поэтому первый вызов выбирает kind(Object). Строковый объект, хранимый через эту ссылку, не меняет результат выбора перегрузки. Выбор реализации переопределённого метода при выполнении описан в Глава 12.

Перегрузки полезны, когда варианты семантически близки. Набор process(int), process(String), process(File) без общего понятного результата превращает имя в скрытый выбор разных операций. Иногда отдельные имена лучше объясняют намерение и уменьшают риск случайного выбора преобразования.

11.5 Статические члены класса

static-поле общее для экземпляров одного загруженного класса, а static-метод не имеет текущего экземпляра. Поэтому в статическом методе нельзя использовать this или читать нестатическое поле без указания объекта. [51]

final class Ticket {
    private static long nextId = 1;
    private final long id = nextId++;

    long id() { return id; }
}

Ticket a = new Ticket();
Ticket b = new Ticket();
System.out.println(a.id() + " " + b.id()); // 1 2

При последовательном создании двух билетов nextId проходит значения 1 → 2 → 3. Инициализатор каждого id сохраняет значение до увеличения, поэтому билеты получают 1 и 2. Увеличение nextId++ включает чтение и запись. Если выполнять его одновременно в нескольких потоках, два создания могут прочитать одно значение; для уникальности тогда потребуется согласовать доступ к счётчику.

Статический метод подходит для вычисления, которому достаточно аргументов, например Math.max(a, b). Если хранить a и b в полях и заполнять их сеттерами перед вызовом max(), результат будет зависеть от этой последовательности вызовов. Поле оправдано, когда значение относится к устойчивому состоянию экземпляра или класса. Временная входная величина обычно остаётся параметром метода. [52]

11.6 Ограничения присваивания с final

Для поля capacity слово final запрещает последующее присваивание. У ссылочного поля оно запрещает заменить ссылку; объект по этой ссылке может оставаться изменяемым.

final String[] names = {"Ann"};
names[0] = "Bob";         // допустимо
// names = new String[]{"Lin"}; // запрещено

Неизменяемость требует закрыть изменение полей, не выдавать изменяемое внутреннее состояние и принимать входные данные так, чтобы клиент не мог затем менять сохранённый объект. String неизменяема, поэтому несколько книг могут хранить одну ссылку на название без риска изменения текста через другой объект.

11.6.1 Закрытые поля и разделяемое изменяемое состояние

Объект хранит имена в массиве фиксированной длины. Клиент может получить доступ к изменяемым элементам через входную ссылку или результат метода.

final class OpenNames {
    private final String[] names;
    OpenNames(String[] names) { this.names = names; }
    String[] names() { return names; }
}
String[] input = {"Ann"};
OpenNames names = new OpenNames(input);
input[0] = null;
System.out.println(names.names()[0]); // null
names.names()[0] = "Bob";
System.out.println(input[0]); // Bob

И входная ссылка, и результат метода открывают тот же массив. private final ограничивает запись поля; через обе ссылки можно менять элементы массива. Если нужны только непустые имена и независимость от внешних записей, конструктор и метод чтения создают копии массива:

final class Names {
    private final String[] names;
    Names(String[] initial) {
        java.util.Objects.requireNonNull(initial, "initial");
        String[] copy = initial.clone();
        for (String name : copy) {
            if (name == null || name.isBlank()) {
                throw new IllegalArgumentException("nonblank name required");
            }
        }
        names = copy;
    }
    String[] names() { return names.clone(); }
}
String[] input = {"Ann"};
Names names = new Names(input);
input[0] = "Bob";
String[] read = names.names();
read[0] = "Lin";
System.out.println(names.names()[0]); // Ann

Копия при входе отделяет внутренний массив от input, копия при чтении — от read. Ссылки на строки могут совпадать, потому что сами строки неизменяемы. Для элементов типа изменяемого Book понадобилось бы отдельно решить, можно ли менять общую книгу: Глава 10.5.1. Операции коллекций для создания снимка списка гостей и его живого представления: Глава 18.13.1.

Финальный метод нельзя переопределять, финальный класс нельзя расширять. Состояние экземпляров финального класса может меняться: Reservation изменяет occupied по правилам reserve, а OpenNames позволяет клиенту менять элементы сохранённого массива.

11.7 Порядок инициализации

При создании объекта все его поля экземпляра сначала получают значения по умолчанию. Затем выполняется выбранный конструктор. Если он сразу вызывает конструктор суперкласса явно или неявно, порядок следующий: вызов суперкласса, инициализаторы полей и блоки инициализации текущего класса, эпилог конструктора. Эпилогом называют часть тела после вызова this(...) или super(...), а при неявном super() — всё записанное тело.

Инициализаторы полей и блоки инициализации экземпляра выполняются в порядке объявления. Блок записывается в теле класса между { и } без имени метода. Он позволяет выполнить несколько действий при создании каждого объекта. Блок с static относится к инициализации самого класса:

class Trace {
    static {
        System.out.println("класс");
    }
    private int value = initialize();
    {
        System.out.println("блок: " + value);
    }
    private int initialize() {
        System.out.println("поле");
        return 7;
    }
    Trace() {
        System.out.println("конструктор: " + value);
    }
}

new Trace();
new Trace();

Перед первым new Trace() класс инициализируется; его статический блок печатает класс. Для каждого нового объекта initialize() печатает поле и возвращает 7, это значение присваивается value. Блок экземпляра и тело конструктора уже читают 7:

класс
поле
блок: 7
конструктор: 7
поле
блок: 7
конструктор: 7

При делегировании через this(...) инициализаторы экземпляра выполняются один раз: после возвращения из конструктора суперкласса в конце цепочки. Возврат к делегировавшему конструктору продолжает его эпилог. Пролог Java 25 выполняется перед указанным в нём вызовом конструктора, поэтому допустимая ранняя запись поля может предшествовать super(...). Отказ любого этапа прерывает оставшуюся последовательность; выражение new при этом не возвращает клиенту ссылку на готовый объект. Порядок определён в JLS 25 §12.5.

Инициализация класса происходит перед первым активным использованием, например созданием экземпляра или вызовом объявленного в этом классе статического метода. Его статические инициализаторы выполняются один раз для данного загруженного класса; сама загрузка может произойти раньше. Подробные условия: JLS 25 §12.4.1.

11.8 Доступ к членам класса

Модификатор доступа определяет, из какого кода разрешено обратиться к полю, методу или конструктору:

Объявление Область доступа
private В пределах охватывающего верхнеуровневого объявления, включая его вложенные типы
Без модификатора В том же пакете
protected В том же пакете; также из подкласса другого пакета при дополнительных условиях
public Из кода, которому доступен содержащий тип, с учётом границ модулей

У верхнеуровневого класса допустимы public и доступ внутри пакета. Даже открытый метод недоступного типа может оказаться недоступен клиенту. При модульной организации доступ к публичному типу другого модуля также зависит от чтения модуля и экспорта пакета.

В другом пакете подкласс получает доступ к защищённому полю экземпляра через получателя своего типа или его подтипа. Произвольной ссылки на объект базового класса для этого недостаточно. Форма объявления и пример обращения через два типа ссылок: Модификаторы доступа. [94]

11.9 Инвариант стека

Стек извлекает элементы в порядке, обратном добавлению. У стека чисел массив data содержит элементы в позициях от 0 до size - 1; size хранит их количество. Инвариант 0 <= size <= data.length разрешает пустой и полностью заполненный стек. Ёмкость положительна. Попытка выйти за эти границы завершается IllegalStateException.

final class IntStack {
    private final int[] data;
    private int size;

    IntStack(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity");
        data = new int[capacity];
    }
    int size() { return size; }
    void push(int value) {
        if (size == data.length) throw new IllegalStateException("full");
        data[size] = value;
        size++;
    }
    int pop() {
        if (size == 0) throw new IllegalStateException("empty");
        size--;
        return data[size];
    }
}

При push успешная проверка подтверждает наличие свободной позиции data[size]. После записи увеличение size включает новый элемент в хранимую последовательность. При pop успешная проверка подтверждает наличие вершины; после уменьшения size её прежний индекс совпадает с новым размером.

IntStack stack = new IntStack(1);
stack.push(7);
try { stack.push(9); }
catch (IllegalStateException ex) { System.out.println("full refused"); }
System.out.println(stack.size()); // 1
System.out.println(stack.pop());  // 7
try { stack.pop(); }
catch (IllegalStateException ex) { System.out.println("empty refused"); }
System.out.println(stack.size()); // 0

После отказа push(9) размер равен 1, а извлечение возвращает прежнее 7. Отказ pop при пустом стеке сохраняет размер 0. Если перенести уменьшение размера перед проверкой пустоты, отклонённая операция оставит size == -1 и нарушит инвариант. Закрытое хранение массива и размера сосредоточивает проверяемые переходы в методах push и pop.
