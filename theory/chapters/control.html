6.1 Структура управления и рассуждение о состоянии

Алгоритм журнала меняет состояние по шагам: получает данные, проверяет их, вычисляет итог, печатает запись. Ветвление выражает несколько допустимых продолжений; цикл — повторение одного правила для последовательности данных. Структура управления делает эти пути явными в исходнике. Чтобы понять цикл, недостаточно прочитать тело: нужны начальное состояние, условие продолжения, изменение и состояние после выхода.

При суммировании массива страниц нужно обосновать три свойства цикла. Сначала обработанная часть пуста, а накопитель содержит её сумму — ноль. Каждая итерация расширяет обработанную часть ровно на один элемент. При выходе обработана вся требуемая последовательность. В этих формулировках важно отличить число выполненных шагов от значения накопителя: число шагов помогает обосновать завершение, накопитель содержит вычисленный результат.

Предусловие ограничивает допустимый вход, инвариант описывает сохраняемое отношение во время цикла, а условие выхода позволяет получить итоговый вывод. Для среднего предусловие непустоты нужно отдельно; сумма пустой последовательности равна нулю. Один и тот же цикл может быть правильным для одной операции и недостаточным для другой.

Структурированные конструкции помогают держать рассуждение локальным. После if видны пути, которые соединяются снова. После while ясно, какое условие стало ложным при обычном выходе. break добавляет ещё один путь выхода, и для него требуется отдельная причина правильности. Условие каждого перехода должно следовать из задачи.

6.2 Выбор действия через if

В Java условие if, while и обычного for должно иметь тип boolean либо допускать распаковку Boolean; числовые и строковые значения сами по себе не служат условиями [60], [121].

По условиям журнала среднее можно вычислять только при положительном количестве дней. Ветвление разделяет расчёт и сообщение о недопустимом количестве:

int pages = 5;
int days = 0;
if (days > 0) {
    System.out.println((double) pages / days);
} else {
    System.out.println("Количество дней должно быть положительным");
}

При days == 0 выполняется вторая ветвь, поэтому результат деления вообще не вычисляется. Если поменять значение на 2, выводится 2.5. Условие проверяется до выбора ветви; обе ветви входят в исходник и проверяются компилятором, но при запуске выполняется только выбранная.

Фигурные скобки обозначают блок действий. Формально после if может стоять одна инструкция без блока, но скобки уменьшают риск ошибки при добавлении действий. В записи без скобок отступы не определяют семантику; новая строка печати может оказаться вне условия, хотя визуально выглядит вложенной. Эта разница особенно заметна после Python, где отступы являются частью синтаксиса блока.

Цепочка if, else if и else проверяет условия по порядку. Для pages == 0, pages < 0 и положительного количества нужно точно определить условие каждой ветви. Если поставить pages >= 0 раньше pages == 0, ветвь для нуля станет недостижимой по смыслу проверки, хотя компилятор может принять текст. Типовая проверка не доказывает правильность порядка предметных условий.

6.3 Охранные проверки и нормальный путь

В main можно сначала проверить вход и завершить метод, если данные не допускают расчёт. return; завершает текущий метод без возвращаемого значения. После охранной проверки остаётся один обычный путь:

int pages = 5;
int days = 0;
if (pages < 0 || days <= 0) {
    System.out.println("Недопустимые данные чтения");
    return;
}
System.out.println((double) pages / days);

Вывод — Недопустимые данные чтения, деление не выполняется. Если изменить days на 2, проверка пропускает вход и печатается 2.5. Ветвление может либо соединить два пути ниже if, либо завершить один из них раньше; это позволяет читать основной расчёт без глубокой вложенности. Приведённые операторы образуют фрагмент тела main.

Замена отрицательных дней на 1 тоже позволила бы продолжить работу, но изменила бы данные и результат. Отказ и исправление — разные действия. Самостоятельный метод может передать отказ вызывающему коду через исключение, а успешное значение — через return с числом. Договор такого расчёта: Объявление метода.

6.4 Выбор по значению switch

switch вычисляет выражение-селектор и выбирает соответствующий случай. Для целого кода это равенство заданной константе; для String сравнивается содержимое строки. Несколько констант можно объединить запятой в одной метке case. Например, режим отчёта определяет его заголовок:

String mode = "brief";
String heading = switch (mode) {
    case "brief", "short" -> "Среднее";
    case "full" -> "Среднее количество страниц за день";
    default -> throw new IllegalArgumentException("Неизвестный режим");
};
System.out.println(heading); // Среднее

Здесь switch — выражение, значение которого записывается в heading. При "brief" и "short" получается одна и та же строка. При "full" получается длинный заголовок. Другое имя, отличное от null, вызывает исключение: присваивание и следующая печать тогда не выполняются. Правило со стрелкой заканчивается выбранным действием и не продолжает выполнение соседнего правила. Стрелка относится к синтаксису switch. [121]

Правила выражения определены в JLS 25, §15.28.

6.4.1 Результат выражения и yield

Если получение результата требует нескольких действий, после стрелки помещают блок. yield вычисляет своё выражение, передаёт результат окружающему switch-выражению и завершает его вычисление:

String mode = "full";
int limit = switch (mode) {
    case "brief" -> 10;
    case "full" -> {
        int base = 10;
        yield base * 3;
    }
    default -> 0;
};
System.out.println(limit); // 30
System.out.println("Выбор завершён");

После yield base * 3 значение 30 присваивается limit; затем выполняются обе печати. Метод продолжает работу. Удаление yield оставило бы блок "full" без результата и вызвало ошибку компиляции. Заменить его на return 30 тоже нельзя: выход к окружающему методу через границу switch-выражения запрещён. Для возврата уже выбранного значения из метода используют return switch (mode) { ... };, размещая return снаружи выражения.

6.4.2 Исчерпывающий выбор

Компилятор требует, чтобы switch-выражение было исчерпывающим: рассмотренные случаи должны покрывать возможные значения селектора по правилам языка. Перечисление строк "brief" и "full" не охватывает остальные возможные значения String. default охватывает остальные значения, отличные от null. Его результат может быть обычным значением, как 0 в расчёте limit, либо отказом, как исключение при выборе heading. Выбор определяет договор операции для неизвестного режима.

Для конечного набора констант перечисления enum можно перечислить все константы и обойтись без default. Тогда добавление новой константы потребует дополнить выбор при повторной компиляции. Требование исчерпываемости и наличие результата каждой нормально завершающейся ветви проверяются независимо: полного перечня случаев недостаточно, если один выбранный блок заканчивается без yield.

Так выбор результата становится одной проверяемой конструкцией. При присваиваниях внутри отдельных ветвей нужно проследить каждый путь до последующего использования переменной; Java обнаружит путь без обязательного присваивания, но предварительное значение вроде 0 может скрыть пропущенный случай. У выражения каждая нормально завершившаяся ветвь обязана выдать результат. При развитии enum отсутствие default потребует от автора вычисления задать обработку нового случая. Универсальная ветвь выражает другое решение: прежнее общее правило распространяется и на будущие варианты. Она полезна только тогда, когда это соответствует смыслу результата.

null у ссылочного селектора рассматривается отдельно. В приведённых примерах mode == null приводит к NullPointerException даже при наличии default. Для допустимого отсутствующего режима можно явно добавить case null -> ... или проверить отсутствие перед switch. Такая метка доступна начиная с Java 21. Формы выбора по типам и другие ссылочные селекторы перечислены в Ветви.

6.4.3 Выбор действий

Оператор switch выполняет действия выбранной ветви. В следующем методе эти действия — возвраты из самого метода:

static int limitFor(String mode) {
    switch (mode) {
        case "brief" -> { return 10; }
        case "full" -> { return 30; }
        default -> { return 0; }
    }
}

limitFor("full") возвращает 30. switch стоит отдельным оператором в теле метода; значение вызывающему коду передаёт return. Правила со стрелками допустимы и у оператора, и у выражения.

Обычный оператор выбора с селектором типа byte, short, char, int, Byte, Short, Character, Integer, String или типа перечисления enum, без шаблонов и case null, может не содержать default. Если подходящей метки нет, он завершится без действия. У расширенного оператора выбора — с шаблоном, case null или другим ссылочным типом селектора — требуется исчерпываемость, хотя сам оператор не вычисляет значение.

6.4.4 Метки с двоеточием

Двоеточие обозначает начало группы инструкций. После совпадения метки выполнение идёт дальше по тексту блока, включая инструкции за следующей меткой. В этом опыте break находится только после второй печати:

int code = 1;
switch (code) {
    case 1:
        System.out.print("A");
    case 2:
        System.out.print("B");
        break;
    default:
        System.out.print("C");
}
System.out.println();

Для code == 1 получается AB, для 2 — B, для 3 — C. При значении 1 метка case 2 не выполняет новую проверку: управление доходит до неё по порядку. break завершает оператор switch. Если поставить его после печати A, первый запуск напечатает только A.

У выражения switch также допустимы метки с двоеточием. В нём результат предоставляет yield:

int code = 1;
int limit = switch (code) {
    case 1:
    case 2:
        yield 10;
    default:
        yield 0;
};
System.out.println(limit); // 10

Метки 1 и 2 ведут к одному yield. Назначение switch — действие или значение — определяется местом конструкции в программе, а продолжение между случаями — формой меток. В одном блоке switch выбирают одну форму меток: двоеточия либо стрелки. Полные варианты и команды: Опыты с выбором и циклом.

6.5 Цикл с предварительной проверкой

while проверяет условие перед каждой итерацией. Если оно ложно вначале, тело не выполняется ни разу. Рассмотрим счёт оставшихся страниц.

int remaining = 5;
while (remaining > 0) {
    System.out.println(remaining);
    remaining--;
}
System.out.println("Done");

Вывод — 5, 4, 3, 2, 1, затем Done, каждое значение на своей строке. Изменение remaining приближает состояние к выходу. Если убрать уменьшение, условие останется истинным и цикл не завершится. Чтобы обосновать завершение, полезно назвать величину, которая монотонно приближается к границе, и убедиться, что она не переполняется и не меняется в противоположную сторону.

do ... while сначала выполняет тело, затем проверяет условие. Для подсчёта десятичных цифр неотрицательного числа это позволяет обработать ноль как запись из одной цифры:

int value = 0;
int digits = 0;
do {
    digits++;
    value /= 10;
} while (value != 0);
System.out.println(digits); // 1

При исходном 507 последовательность значений после делений — 50, 5, 0, поэтому результат равен 3. Обычный while (value != 0) с тем же телом пропустил бы исходный ноль и оставил digits == 0. У непустой десятичной записи нужна первая обработка независимо от величины числа. Для массива, который может быть пустым, доступ к первому элементу, напротив, должен следовать за проверкой длины. Полные опыты циклов: Опыты с выбором и циклом.

6.6 for и диапазон индексов

Обычный for собирает в одном месте инициализацию, условие продолжения и действие после итерации. Для массива из трёх значений используем полуоткрытый диапазон индексов [0, length).

int[] pages = {5, 7, 4};
long total = 0;
for (int i = 0; i < pages.length; i++) {
    total += pages[i];
}
System.out.println(total); // 16

Переменная i получает 0 один раз. Затем перед каждым проходом проверяется i < pages.length, выполняется тело и увеличивается i. При i == 3 условие ложно, поэтому недопустимый индекс 3 не используется. Замена < на <= нарушает границу и порождает ArrayIndexOutOfBoundsException.

Доказательство суммы можно сформулировать через инвариант: перед итерацией с индексом i переменная total содержит сумму элементов с индексами от 0 до i, не включая i. Сначала это пустая сумма 0; тело добавляет следующий элемент; после завершения i == length, поэтому просуммирован весь массив. Инвариант связывает инициализацию, изменение состояния и условие выхода для всех допустимых длин массива.

Условие завершения обосновывается величиной pages.length - i: она неотрицательна при проверке условия и убывает на единицу после каждого полного прохода. Индекс доходит до длины, после чего тело пропускается. Здесь i++ выполняется при i < pages.length, поэтому индекс не пересекает верхнюю границу int. В цикле for (int i = 0; i <= limit; i++) при limit == Integer.MAX_VALUE последний инкремент переполнит int; привычное рассуждение о росте счётчика перестанет обосновывать выход.

Для массива длины ноль тело не выполняется и результат остаётся 0. Среднее потребовало бы отдельного условия непустоты, потому что после суммы понадобится деление на количество элементов.

6.7 Расширенный for и изменение элементов

Когда индекс не нужен, расширенный for последовательно даёт значения элементов.

int[] pages = {5, 7, 4};
long total = 0;
for (int pageCount : pages) {
    total += pageCount;
}
System.out.println(total); // 16

Каждый независимый расчёт начинается с total = 0; иначе новая сумма прибавится к прежней. Переменная цикла получает копию значения очередного элемента. Поэтому pageCount = 0 изменяет эту локальную переменную и не записывает ноль в массив. Для замены компонентов нужен индекс и присваивание pages[i] = ....

Если элементы ссылочные, переменная получает ссылку. Через неё можно вызвать изменяющую операцию того же объекта, но присваивание переменной всё равно не заменяет компонент массива. Один принцип объясняет оба случая: копируется значение элемента, которое может быть числом или ссылкой. Полный разбор содержится в Глава 8.

6.8 Вложенный обход и положение проверки

Во вложенном переборе внешний цикл выбирает день, внутренний — один из двух сеансов чтения:

for (int day = 1; day <= 2; day++) {
    for (int session = 1; session <= 2; session++) {
        System.out.println(day + ":" + session);
    }
}

Вывод — 1:1, 1:2, 2:1, 2:2, по строке на пару. Для нового дня внутренний счётчик снова создаётся со значением 1. Если заменить внутреннюю границу на session <= 0, у каждого дня будет ноль внутренних итераций. Число шагов определяют оба диапазона; для этого перебора достаточно двух счётчиков. Хранение строк таблицы в массиве массивов: Массивы массивов.

break внутри внутреннего цикла завершит только его. Если поставить его сразу после первой печати, вывод станет 1:1, 2:1: внешний цикл продолжится. Чтобы остановить весь поиск из метода, можно вернуть найденный результат. Метка внешнего цикла позволяет выбрать иной переход, но её стоит вводить только при необходимости такого пути.

6.9 break, continue и return

break завершает ближайший подходящий цикл или switch, continue начинает следующую итерацию ближайшего цикла, а return завершает метод. В обычном for после continue выполняется часть изменения, затем проверяется условие; в while управление возвращается непосредственно к условию. [121]

int[] pages = {5, 7, 4};
int found = -1;
for (int i = 0; i < pages.length; i++) {
    if (pages[i] == 7) {
        found = i;
        break;
    }
}
System.out.println(found); // 1

break предотвращает дальнейший просмотр после первого совпадения. Если совпадений несколько, результат остаётся индексом первого. Если нет ни одного, сохраняется -1. При переходе к методу поиск можно закончить return i; тогда специальный результат -1 возвращается после цикла. Разница видна по области действия завершения.

Для пропуска отрицательных значений можно написать if (pageCount < 0) continue;, но это уже меняет правила обработки данных. В примере суммы отрицательные числа разрешены математически; в отчёте о страницах они могут означать ошибку. Выбор перехода должен соответствовать правилам обработки входа. Точные формы операторов находятся в Глава 4; выделение расчёта в метод объясняется в Декомпозиция и договор операции.

6.10 Поток ввода и граница обработанного состояния

С массивом длина известна до обхода. У потока следующий элемент ещё нужно прочитать, а конец обозначается отдельным результатом чтения. Поэтому цикл обработки входа имеет две связанные операции: получить данные и определить, можно ли их обработать. Признак EOF не является очередным текстовым символом. При чтении через Reader.read() результат имеет тип int, чтобы вместить и код единицы текста, и специальное отрицательное значение конца.

Представим счётчик обработанных единиц текста. До чтения счётчик равен нулю. После очередного полезного чтения он увеличивается; при EOF дальнейшего увеличения нет. Если приложение задаёт собственный терминатор, например точку, нужно отдельно решить, выводится ли она и входит ли в подсчёт. Это протокол приложения, который задаёт дополнительное условие поверх результата чтения.

6.10.1 Полный цикл чтения текста

Программа считает единицы UTF-16 до # или конца входа. Сам # в счётчик не входит. System.in предоставляет байты; InputStreamReader декодирует их как UTF-8 и предоставляет операции Reader. Поэтому граница между байтами и текстом задана до цикла. Файл CountUnits.java:

import java.io.IOException;
import java.io.InputStreamReader;
import java.io.Reader;
import java.nio.charset.StandardCharsets;

public class CountUnits {
    public static void main(String[] args) throws IOException {
        Reader input = new InputStreamReader(
            System.in, StandardCharsets.UTF_8);
        long count = 0;
        int unit;
        while ((unit = input.read()) != -1 && unit != '#') {
            count++;
        }
        System.out.println(count);
    }
}

При входе AЯ#tail выводится 2; при # или сразу EOF — 0. Если вход без терминатора содержит AЯ и перевод строки, перевод строки тоже входит в счётчик: тело учитывает каждую прочитанную единицу UTF-16 до терминатора. Эмодзи вне основной многоязычной плоскости занимает две единицы UTF-16; счётчик не является счётчиком видимых знаков.

read() возвращает число от 0 до 65535 либо -1. Поэтому результат хранится в int, а проверка EOF предшествует преобразованию в char. Присваивание внутри скобок получает очередной результат; сравнение с -1 управляет продолжением. Операция && проверяет терминатор только после успешного чтения. При # тело уже не выполняется, дальнейшие единицы входа цикл не обрабатывает. Декодер может заранее прочитать дополнительные байты из System.in; завершение цикла определяет границу обработки текста. [112]

В объявлении main запись throws IOException позволяет ошибке чтения завершить вызов исключением: локальное восстановление здесь не задано. Это не сигнал EOF. Стандартный поток этого примера предоставлен средой запуска. Передача отказа объясняется в Глава 21, владение ресурсами — в Глава 22. Команды компиляции и варианты подачи входа: Байты, текст и конец ввода.

При интерактивном вводе проверка тоже меняет сценарий работы. Неудачную попытку можно повторить только после получения нового входа. Повторять ту же проверку над неизменным неверным значением — бесконечный цикл, даже если тело содержит понятное сообщение. Состояние продвигается либо к следующему элементу, либо к исправленному вводу, либо к завершению.

Для числовых экстремумов начальное состояние зависит от договора непустоты. Ноль не является универсальным исходным максимумом: все полученные числа могут быть отрицательны. Первое допустимое значение служит начальным максимумом, который затем обновляется при чтении следующих чисел. Ввод, выбор начального состояния и обновление лучше рассматривать отдельно, чтобы не спрятать предметную ошибку в синтаксисе цикла. Точные приёмы чтения находятся в Глава 21; подготовка к своей лабораторной — в Управление обработкой данных.
