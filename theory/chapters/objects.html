10.1 Создание объекта и значение ссылки

Объект объединяет состояние конкретного экземпляра и действия над ним. Класс определяет тип таких объектов, их поля и методы [79].

Экземпляр Book хранит название и признак выдачи. Значение false поля borrowed означает доступную книгу, true — выданную:

class Book {
    String title;
    boolean borrowed;

    Book(String initialTitle) {
        title = initialTitle;
    }
}

Book(String initialTitle) — конструктор: он участвует в создании экземпляра и записывает переданное название в его поле title. Конструктор имеет имя класса, его объявление записывается без возвращаемого типа. Это объявление класса ещё не создаёт ни одной книги.

Book first = new Book("Java");
Book second = new Book("Algorithms");
System.out.println(first.title);  // Java
System.out.println(second.title); // Algorithms

Выражение new Book("Java") создаёт экземпляр, вызывает конструктор с аргументом "Java" и при успешном завершении даёт ссылку на созданный объект. Инициализатор записывает эту ссылку в локальную переменную first. Вторая операция new создаёт другой экземпляр; его ссылка сохраняется в second. У каждой книги собственное поле title.

Поля получают значения по умолчанию при создании объекта. Для ссылочного поля это null, для boolean — false. Целочисленные поля получают нуль, char — '\u0000', поля float и double — положительный нуль. Конструктор и инициализаторы полей могут затем записать другие значения. Вызов new Book("Java") проходит следующие состояния:

Момент title borrowed
Начальные значения полей null false
После выполнения тела конструктора ссылка на "Java" false

Конструктор записал значение только в title. Поэтому сразу после создания книга доступна. Запись в другую книгу меняет её собственное поле:

second.borrowed = true;
System.out.println(first.borrowed);  // false
System.out.println(second.borrowed); // true

Значения полей и последовательность создания определены в [13, Разд. 4.12.5], [16, Разд. 15.9.4].

10.1.1 Локальная переменная перед первым чтением

Объявление локальной переменной можно отделить от присваивания:

Book pending;
// System.out.println(pending.title); // ошибка компиляции
pending = new Book("Networks");
System.out.println(pending.title);    // Networks
System.out.println(pending.borrowed); // false

После Book pending; объявлена переменная, экземпляр Book этим действием не создан. До чтения pending компилятор требует определённого присваивания: анализ потока управления должен подтвердить получение значения на каждом пути к чтению. Это требование называется definite assignment. Если раскомментировать первую строку вывода, возникнет ошибка компиляции. После присваивания ссылка существует, а чтение поля borrowed даёт false, установленное при создании объекта.

Явная инициализация Book pending = null; тоже присваивает значение. Его чтение допустимо, но обращение pending.title завершится NullPointerException, поскольку объекта нет.

10.1.2 Ссылочные переменные и опыт C++

В C++ локальное объявление Book object; создаёт объект с автоматическим временем хранения, если класс допускает такую инициализацию. Java-объявление Book pending; создаёт ссылочную переменную. Она может получить ссылку на объект из результата new, возвращаемого значения метода или другой ссылочной переменной.

Копирование C++-указателя Book* создаёт ещё один путь к тому же объекту. Ссылочная переменная Java также может получить другую ссылку. У C++-ссылки Book& привязка к объекту задаётся при инициализации; присваивание через неё действует на связанный объект. В Python имя тоже может быть связано с общим объектом; объявленный тип Java дополнительно ограничивает допустимые значения переменной.

Через ссылку Java выполняются обращения к полям и методам. Язык не предоставляет арифметику адресов, разыменование оператором * или освобождение объекта оператором delete. На схеме ссылка изображается стрелкой к объекту: по ней можно проследить доступ к его состоянию. [94]

10.2 Присваивание ссылки и тождество объекта

Присваивание ссылочной переменной копирует ссылочное значение. В отдельном опыте создадим доступную книгу с названием Java и сохраним её ссылку ещё в одной переменной:

Book first = new Book("Java");
Book same = first;

first и same — отдельные переменные. В обеих хранится ссылка на объект A; операция new выполнена один раз. Поле borrowed принадлежит этому объекту. Запись через same и чтение через first обращаются к одному месту хранения:

same.borrowed = true;
System.out.println(first.borrowed); // true
System.out.println(first == same);  // true

Оператор == для ссылок даёт true, если обе ссылаются на один объект или обе равны null. Отдельная книга с теми же значениями полей сохраняет собственное тождество:

Book other = new Book("Java");
other.borrowed = true;
System.out.println(first == other); // false

У first и other одинаковые значения title и borrowed. Сравнение == установило наличие двух объектов. Для сравнения данных класса определяют правило равенства, например через метод equals.

10.2.1 Переназначение ссылочной переменной

Продолжим опыт с выданной книгой A, доступной через first и same:

same = new Book("Databases");
System.out.println(first.title);    // Java
System.out.println(first.borrowed); // true
System.out.println(first == same);  // false

Выражение справа создало новую книгу, а присваивание записало её ссылку в same. Значение first сохранилось:

Левая часть same.borrowed выбирала поле объекта, достигнутого по ссылке. Левая часть same выбирает саму переменную. Поэтому прежняя запись в поле была видна через first, а переназначение same оставило first связанной с прежней книгой. [79]

Совместный доступ существенен при защите состояния. Если библиотека возвращает клиенту ссылку на изменяемый внутренний объект, его доступные операции позволяют клиенту менять общее состояние. Закрытое поле ограничивает прямое обращение к нему; возврат хранящейся в нём ссылки может дать доступ к изменяемому объекту. Выбор общей ссылки или копии определяет, какие данные клиент сможет изменить. Управление допустимыми действиями класса разобрано в Глава 11.1.1.

10.2.2 Тождество экземпляра и обозначение книги

У библиотечного издания могут быть два физических экземпляра с одинаковым названием. Один выдан, второй доступен. Отдельный номер экземпляра позволяет выбрать книгу для выдачи или возврата; название относится к обоим экземплярам и такого выбора не обеспечивает.

Программа может дважды прочитать запись с одним номером и создать два Java-объекта. Они различны по ==, хотя описывают один библиотечный экземпляр. Изменение поля одного объекта автоматически не обновляет второй. При обновлении каталога номер помогает найти нужную сущность, а программа определяет, как согласовать хранимые представления её состояния.

Правило equals выбирается по назначению модели. Для точки или суммы денег обычно сравниваются компоненты значения; для записи о книге существенным может быть номер экземпляра. Наличие поля id само по себе не задаёт реализацию equals. Классы значений рассматриваются в Глава 14.

10.3 Передача значений аргументов

При вызове метода значения аргументов присваиваются новым переменным параметров. Параметр принадлежит этому вызову: присваивание ему меняет его собственное значение. Для аргумента типа int копируется число, для аргумента типа Book — ссылка на книгу. Это единое правило называется передачей по значению. [118, Разд. 15.12.4.5]

Два метода выполняют разные записи, получив ссылку на существующую книгу:

static void borrow(Book book) {
    book.borrowed = true;
}

static void replace(Book book) {
    book = new Book("Replacement");
}

Начнём с доступной книги A с названием Java:

Book original = new Book("Java");
borrow(original);
System.out.println(original.borrowed); // true
replace(original);
System.out.println(original.title);    // Java

В начале borrow(original) переменные original и book содержат одинаковые ссылки на A. Левая часть book.borrowed выбирает поле этой книги. Запись меняет false на true, и вызывающий код видит изменение через свою ссылку original.

В начале replace(original) новый параметр book тоже получает ссылку на A. Затем new Book("Replacement") создаёт книгу B, и присваивание с левой частью book записывает её ссылку только в параметр:

вызывающий код             вызов replace
original ──> A             book ──> B
             title = Java           title = Replacement
             borrowed = true        borrowed = false

По окончании вызова переменная параметра прекращает существование. Переменная original сохранила ссылку на A, поэтому чтение полей книги по-прежнему даёт Java и true. Если заменить всё тело replace единственным оператором book.title = "Replacement";, параметр сохранит ссылку на A. Запись изменит поле title этой книги, и новое название будет видно через original. Выбор места записи объясняет оба исхода при одном правиле передачи аргументов. [79, сс. 190–192]

У C++-параметра Book* book также копируется значение указателя: его переназначение оставляет указатель вызывающего кода прежним, а запись через book->borrowed меняет доступный объект. Параметр C++ Book*& book связывается с самой переменной указателя вызывающего кода и позволяет изменить её значение. Параметр Java Book book является отдельной переменной; способ передать её как C++-ссылку на переменную в языке отсутствует. Результат, которым клиент должен заменить свою ссылку, можно вернуть из метода.

10.3.1 Возвращаемая ссылка

Метод replacement создаёт доступную книгу и возвращает ссылку на неё:

static Book replacement() {
    Book book = new Book("Replacement");
    return book;
}

original = replacement();
System.out.println(original.title);    // Replacement
System.out.println(original.borrowed); // false

return book вычисляет значение локальной переменной. Возвращённая ссылка становится результатом вызова, а присваивание сохраняет её в original. Метод завершился; созданная книга доступна вызывающему коду. Вызов без сохранения результата, replacement();, оставил бы original прежней.

Возвращаемое ссылочное значение может обозначать и существующий объект. Например, static Book same(Book book) { return book; } возвращает полученную ссылку: same(original) == original даёт true. Создание нового экземпляра в replacement определяется операцией new в теле. Оператор return передаёт вычисленное значение и не копирует поля книги.

В C++ возврат указателя или ссылки на локальный объект с автоматическим временем хранения оставляет результат связанным с уже уничтоженным объектом. Возврат самого Book по значению создаёт объект результата; копирование, перемещение и их устранение подчиняются правилам C++. В Java локальной была переменная book, а созданный через new объект может использоваться после завершения метода по возвращённой ссылке.

10.4 Отсутствие объекта и null

null — специальное ссылочное значение, обозначающее отсутствие объекта. Его можно присвоить переменной любого ссылочного типа. Доступ к полю экземпляра или вызов метода экземпляра требует объекта; при null такое обращение завершается NullPointerException:

Book missing = null;
System.out.println(missing == null); // true
// missing.title = "Java";           // NullPointerException

Допустимость отсутствия зависит от смысла данных. У ещё не выданной книги читатель может быть не указан; обязательное название требуется уже при создании книги. Объявленный тип String допускает null. У массива ссылочных компонентов наличие самого массива также совместимо с null в отдельных компонентах. Требования к каждому из этих значений задаются отдельно.

10.4.1 Отсутствие объекта в контракте операции

Метод выдачи borrow(Book book) требует существующую книгу. Поиск findByCode(String code) может успешно завершиться без совпадения. Если договор поиска задаёт null как результат «книга не найдена», клиент проверяет его перед обращением к книге. Входное нарушение и результат поиска требуют разных действий клиента: исправить вызов или обработать отсутствие совпадения.

Методу чтения названия нужны и сама книга, и её название:

static String titleOf(Book book) {
    java.util.Objects.requireNonNull(book, "book");
    return java.util.Objects.requireNonNull(book.title, "title");
}

Objects.requireNonNull возвращает проверенное значение, если оно отличается от null, и бросает NullPointerException в противном случае. При titleOf(null) выполнение прекращается на первой проверке. При titleOf(new Book(null)) объект существует, и отказ возникает на второй. titleOf(new Book("Java")) возвращает Java.

Проверка входа позволяет отклонить неверное значение до сохранения в поле. Если записать null в обязательное название, ошибка может обнаружиться гораздо позже при другом действии над книгой. Закрытое поле и проверяющий конструктор в Глава 11.1.2 ограничивают места, где название может быть записано, и поддерживают его допустимость между обращениями клиента.

Результат «совпадение не найдено» отличается от неверного кода и отказа чтения каталога. Пустая книга с вымышленным названием ведёт себя как найденный объект и может попасть в дальнейшую обработку. Отдельное представление отсутствия позволяет сохранить это различие в программе. Тип Book сам по себе допускает и ссылку на книгу, и null, поэтому договор метода должен определить, какие результаты он возвращает. Ретроспективная критика такого неявного условия содержится в выступлении Тони Хоара Null References: The Billion Dollar Mistake. [30]

10.4.2 Допустимость отсутствия в системе типов

В Kotlin обязательность строки может быть выражена её типом:

fun titleLength(title: String): Int = title.length
fun possibleLength(title: String?): Int? = title?.length

titleLength("Java") даёт 4; параметр типа String требует строку. Тип String? допускает null, а ?. вычисляет длину только при наличии строки. Поэтому possibleLength(null) возвращает null; тип результата Int? допускает это значение. Прямое обращение title.length для String? требует предварительно установить, что значение отличается от null.

Оператор !! выполняет проверку во время работы: при null он бросает исключение. Для значений, пришедших из Java, действуют правила платформенных типов; проверка компилятора зависит от доступных сведений о допустимости null. В Java требование обязательного объекта задаётся контрактом операции и проверяется её реализацией. [140]

10.5 Копирование состояния объекта

Присваивание ссылки оставляет общий экземпляр. Для независимых полей книги метод copy создаёт второй объект и переносит значения полей:

static Book copy(Book source) {
    Book result = new Book(source.title);
    result.borrowed = source.borrowed;
    return result;
}

Вход source должен обозначать существующую книгу. В отдельном опыте исходная книга выдана, и копия получает тот же признак:

Book source = new Book("Java");
source.borrowed = true;
Book copied = copy(source);
copied.borrowed = false;
System.out.println(source == copied);   // false
System.out.println(source.borrowed);    // true
System.out.println(copied.borrowed);    // false

У двух объектов собственные поля borrowed, поэтому запись в копию сохраняет состояние источника. Поля title содержат скопированные ссылки на одну строку. String неизменяема: её текст нельзя переписать через одну из этих ссылок. Переназначение copied.title заменило бы только поле второй книги.

10.5.1 Совместное использование вложенного массива

Книга с метками хранит ссылку на массив строк:

class TaggedBook {
    String[] tags;
    TaggedBook(String[] tags) { this.tags = tags; }
}

В этом опыте передаваемые массивы существуют и содержат два элемента:

TaggedBook first = new TaggedBook(new String[]{"java", "oop"});
TaggedBook copy = new TaggedBook(first.tags);
copy.tags[0] = "changed";
System.out.println(first.tags[0]);           // changed
System.out.println(first == copy);          // false
System.out.println(first.tags == copy.tags); // true

Каждый new TaggedBook создал книгу со своим полем tags. Конструкторы сохранили в этих полях одну ссылку, поэтому copy.tags[0] выбирает компонент массива, доступного и через first.tags:

first ──> книга 1 ──tags──┐
                        ├──> ["changed", "oop"]
copy  ──> книга 2 ──tags──┘

Для независимых компонентов создаётся новый массив:

TaggedBook independent = new TaggedBook(first.tags.clone());
independent.tags[0] = "independent";
System.out.println(first.tags[0]);       // changed
System.out.println(independent.tags[0]); // independent
System.out.println(first.tags == independent.tags); // false

clone() массива копирует его компоненты в новый массив того же типа. Компоненты здесь содержат ссылки на неизменяемые строки; изменение компонента второго массива сохраняет первый. Для массива изменяемых книг новый массив содержал бы ссылки на прежние книги. Их поля по-прежнему можно было бы менять через обе структуры. Копирование массивов подробнее рассмотрено в Глава 8.5.

10.5.2 Граница независимого состояния

Поверхностная копия создаёт новый внешний объект и копирует значения его полей. Ссылочные поля сохраняют общие вложенные объекты. Глубокое копирование дополнительно создаёт независимые вложенные объекты в пределах выбранного графа. Реализация такого копирования должна учитывать общие узлы и циклы: повторное посещение одного узла требует связи с уже сделанной копией.

Границу копирования задаёт модель. Для независимого набора меток нужен свой массив. Две книги, связанные с одной записью об авторе, могут намеренно сохранять общего автора: исправление его данных тогда наблюдается через обе книги. Раздельные копии потребовали бы отдельного согласования этих исправлений. Метод Object.clone, когда его применение поддержано классом, копирует поля поверхностно; произвольный вложенный граф он рекурсивно не копирует. [110]

10.6 Достижимость и время жизни

Область действия имени определяет места программы, где это имя можно использовать. Время жизни объекта связано с возможностью дальнейшего доступа к нему. Метод может закончиться, сохранив созданный объект доступным через результат:

static Book create() {
    Book local = new Book("Java");
    return local;
}

Book kept = create();
Book alias = kept;
kept = null;
System.out.println(alias.title); // Java

Переменная local принадлежала завершившемуся вызову. Ссылка на ту же книгу была записана в kept, затем скопирована в alias. Присваивание kept = null убрало один путь доступа. Чтение alias.title выполняется по сохранившемуся пути. [85]

Объект достижим, если выполняющийся поток ещё может обратиться к нему при дальнейшем вычислении. Путь может проходить через используемые локальные ссылки, поля объектов, массивы и статические поля. Например, живой каталог содержит список книг, и ссылка в компоненте списка сохраняет доступ к книге после завершения метода её загрузки. Группа объектов, к которой больше нет пути из продолжающегося вычисления, может быть освобождена сборщиком мусора. Внутренний цикл A → B → A сохраняет связи внутри группы, но не создаёт внешнего пути к ней. [12, Разд. 12.6.1], [129, Разд. 2.5.3]

Если программа уже закончила работу с временными книгами, а долговечный каталог продолжает хранить их ссылки, они остаются достижимыми через каталог. Для освобождения такого состояния программа должна удалить ненужные связи. Присваивание null одной локальной переменной оставит ссылки каталога прежними.

Недостижимость допускает последующее освобождение памяти; момент сборки не определяется строкой присваивания null или концом блока. Область действия имени также не задаёт минимальную длительность хранения объекта: среда может установить, что значение больше не используется в дальнейшем вычислении, ещё до текстового конца области.

10.6.1 Память объекта и закрытие ресурса

Объект, представляющий открытый файл, связывает память Java с внешним ресурсом операционной системы. После close() объект ещё может быть достижим, хотя операция чтения из закрытого файла уже недоступна.

Интерфейс AutoCloseable задаёт операцию close. Конструкция try с ресурсами вызывает её при выходе из блока для каждого успешно инициализированного ресурса, значение которого отличается от null. Это правило действует и при выходе через return или исключение. Если ресурсов несколько, закрытие идёт в обратном порядке инициализации. Ошибки самого закрытия учитываются правилами исключений: Глава 22. [121]

У автоматического объекта C++ выход из области вызывает деструктор, который может закрывать принадлежащий объекту ресурс. Окончание области локальной переменной Java такого действия с объектом не выполняет; момент вызова close задаётся управлением потоком программы. Финализация Java устарела и подлежит удалению; она не задаёт своевременного закрытия. [110] Поэтому сохранение нужной ссылки отвечает за доступность объекта, а try с ресурсами — за вызов операции закрытия при выходе из блока.
