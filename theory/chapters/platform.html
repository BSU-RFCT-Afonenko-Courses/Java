3.1 Управляемая среда выполнения

Компилятор javac обычно создаёт файлы .class: двоичное описание классов, их полей и методов, включая инструкции JVM — байткод. Это инструкции абстрактной машины; их смысл одинаков для разных реализаций JVM. Реальная машина выполняет собственные инструкции, поэтому на ней нужна реализация, которая обеспечивает действия, предписанные байткодом.

C++:  исходники → компилятор и компоновщик → нативная программа → ОС и процессор
Java: исходники → javac → классы JVM → реализация JVM → ОС и процессор

При нативной сборке C++ компилятор переводит исходники, компоновщик соединяет определения, загрузчик ОС подготавливает процесс. Полученный файл содержит команды выбранного процессора и предназначен для выбранной системы. Для другой архитектуры исходники можно заново собрать под новую цель. Компиляторы могут применять промежуточный код и профильную оптимизацию. В Java файл класса — стандартная граница между производителем кода и выполняющей средой. Исходник может быть написан и на другом языке, если его компилятор соблюдает этот формат.

В The Java Language Environment 1996 года Гослинг и Макгилтон связывают такой выбор с распространением программ в неоднородной сетевой среде: разработчику не нужно заранее производить отдельный машинный код для каждого получателя. Там же переносимость связывается с заданными числовыми правилами. [25], [26]

Среду называют управляемой, потому что она участвует в загрузке и проверке кода, предоставлении памяти и выполнении операций. Например, Java проверяет индекс массива, а сборщик мусора позволяет не вызывать освобождение для каждого объекта. При выходе индекса за границы массива возникает исключение. Сохранённые ссылки удерживают объекты в памяти; открытый файл требует отдельного закрытия.

3.2 Состав платформы

Платформа Java объединяет правила выполнения классов и стандартные библиотечные средства. Реализация платформы выполняет классы и предоставляет библиотечные операции на конкретной системе.

Язык Java определяет допустимую запись и её смысл. JVM означает виртуальную машину, заданную спецификацией, либо конкретную реализацию этой машины — смысл зависит от контекста. Стандартная библиотека предоставляет String, ввод-вывод, коллекции и другие операции с собственными контрактами. Java SE объединяет спецификации языка, виртуальной машины и API.

JDK — комплект разработки со средой выполнения, библиотеками и инструментами: javac компилирует, java запускает, javap показывает устройство классов, jar работает с архивами, javadoc создаёт документацию API. Термин JRE обозначает среду выполнения; в старых материалах это также имя отдельного продукта. Команды учебных примеров используют JDK 25. Пользователь готового приложения может получить вместе с ним собственную среду выполнения: jpackage создаёт пакет приложения с образом среды, который включает нужные компоненты Java. Полный JDK с javac для запуска такого пакета не требуется. Состав и платформу образа выбирает автор поставки. [121]

int — тип языка, String.length() — библиотечная операция. Правило целочисленного деления нужно искать в спецификации языка, единицу длины строки — в API. Для понимания исполнения метода понадобится спецификация JVM.

3.3 Компиляция и запуск

Компактный исходный файл Hello.java содержит метод запуска:

void main() {
    IO.println("Hello");
}

main задаёт начальное действие программы; void означает отсутствие возвращаемого значения. IO.println выводит переданную строку и завершает строку вывода. Команда java Hello.java компилирует исходник для текущего запуска и печатает Hello.

Для компиляции и запуска выберем инструменты одного JDK 25. Проверить выбор можно командой java --version. При нескольких установках укажите путь к нужному инструменту, например /usr/lib/jvm/java-25-openjdk/bin/java Hello.java; аналогично выбираются javac и javap.

Компактный файл неявно объявляет класс. javac выбирает имя неявно объявленного класса из имени файла. Метод main в этом примере нестатический, поэтому среда создаёт объект класса и вызывает его метод. Для включения класса в именованный пакет требуется явное объявление класса. [118]

У журнала чтения две записи: за первый день прочитано пять страниц, за второй — семь. Программа выводит сумму и среднее. Сохраните её как Reading.java:

static int total(int[] pages) {
    int sum = pages[0] + pages[1];
    return sum;
}

void main() {
    int[] pages = {5, 7};
    int sum = total(pages);
    IO.println(sum);
    IO.println(sum / 2.0);
}

int[] — тип массива целых. Переменная этого типа хранит ссылку на массив или null. Здесь {5, 7} создаёт массив с двумя компонентами, индексы начинаются с нуля. pages.length равно двум. Метод total предполагает массив как минимум из двух компонентов и складывает первые два. Длина массива задаёт доступные индексы; операции над массивами произвольной длины: Глава 8.

main вызывает total, передав значение переменной pages, и сохраняет возвращённую сумму. Метод total объявлен static: отдельный объект для его вызова не нужен. Его параметр получает ссылку на массив, return отдаёт число вызывающему коду. Делитель 2.0 имеет тип double, поэтому деление сохраняет дробную часть результата в пределах точности double.

Чтобы получить сохранённый файл класса, из каталога с Reading.java выполните:

javac -encoding UTF-8 -g -d out Reading.java
java -cp out Reading

Результат компиляции — out/Reading.class; -cp out задаёт каталог поиска классов. Исходный файл остаётся снаружи out. Вывод:

12
6.0

-encoding UTF-8 задаёт кодировку исходника. -g сохраняет отладочные сведения: они понадобятся при чтении локальных переменных в javap. Для обычного выполнения этот параметр необязателен. [119], [120]

После замены 5 на 9 в исходнике два режима запуска используют разные данные. До повторного javac команда java -cp out Reading читает прежний класс и выводит 12, затем 6.0. Команда java -cp . Reading.java компилирует изменённый текст для текущего запуска и выводит 16, затем 8.0. Этот запуск исходника не обновляет сохранённый out/Reading.class: следующий java -cp out Reading снова выводит прежние числа.

Повторный javac записывает новый файл класса, после чего java -cp out Reading также выводит 16 и 8.0. В IDE действие сборки может происходить автоматически перед запуском. Полные исходники и команды для воспроизведения: Байткод учебного примера.

3.4 Модель выполнения байткода

Для следующего разбора исходный массив снова равен {5, 7}; файл класса получен повторной компиляцией этого варианта.

Файл класса содержит инструкции JVM, описания типов и методов, таблицу констант и атрибуты. Посмотрим метод total:

javap -classpath out -c -p -l Reading

Для приведённого тела total вывод javap содержит следующую последовательность инструкций. Числа слева задают смещения инструкций от начала байткода метода. Связь с номерами строк Java хранится отдельно. [136]

static int total(int[]);
  Code:
     0: aload_0
     1: iconst_0
     2: iaload
     3: aload_0
     4: iconst_1
     5: iaload
     6: iadd
     7: istore_1
     8: iload_1
     9: ireturn

Каждому вызову метода в модели JVM соответствует кадр, или фрейм. В нём есть локальные позиции для параметров и промежуточных значений и стек операндов для работы инструкций. У total позиция 0 содержит значение параметра pages — ссылку на массив; позиция 1 позже получит sum. Стек операндов нового фрейма пуст. Локальные позиции и стек операндов определяют модель выполнения инструкций JVM; конкретная JVM выбирает их физическое представление при реализации этой модели. [135]

Обозначим ссылку на наш массив буквой A, вершину стека будем писать справа:

Смещение и инструкция Действие Стек после действия
0: aload_0 Взять ссылку из локальной позиции 0 [A]
1: iconst_0 Положить индекс 0 [A, 0]
2: iaload Снять ссылку и индекс, прочитать компонент [5]
3: aload_0 Снова взять ту же ссылку [5, A]
4: iconst_1 Положить индекс 1 [5, A, 1]
5: iaload Прочитать второй компонент [5, 7]
6: iadd Снять два int, положить сумму [12]
7: istore_1 Снять сумму в локальную позицию 1 []
8: iload_1 Прочитать локальную сумму [12]
9: ireturn Завершить вызов с результатом 12 Фрейм завершён

Три первые инструкции соответствуют pages[0], три следующие — pages[1]; iadd соответствует +, запись и чтение позиции 1 — переменной sum. Позиция 0 содержит ссылку на массив. iaload использует её для чтения. Если бы ссылка была null или индекс выходил за границы, обычное возвращение суммы не состоялось бы.

3.5 Вызов метода и объект в куче

В модели JVM массив создаётся в куче (heap), общей области объектов. При вызове total(pages) значение ссылки из main передаётся в локальную позицию 0 нового фрейма. Объект остаётся тем же. Пока работает total, фрейм main ожидает его результата.

Стек вызовов потока                 Heap
┌ total ─────────────────────┐
│ local[0]: A ───────────────┼──────→ int[2] {5, 7}
│ local[1]: sum              │          ↑
│ operand stack: ...         │          │
├ main ──────────────────────┤          │
│ pages: A ──────────────────┼──────────┘
└────────────────────────────┘

Эта схема изображает состояние в ходе вызова; local[1] получает значение лишь после istore_1. Стек вызовов хранит фреймы, операндный стек принадлежит одному фрейму. После ireturn результат оказывается в распоряжении вызывающего метода, а фрейм total перестаёт существовать. Массив всё ещё доступен через pages в main, поэтому выход из total не освобождает его.

При повторном total(pages) создаётся новый фрейм. Если массив сохранил [5, 7], вычисление снова вернёт 12. Байткод метода сохраняется между вызовами: в модели JVM код и сведения о методах относятся к общей области методов. В ней хранятся определения для выполнения, тогда как фрейм содержит состояние отдельного вызова. Изменение аргумента меняет полученную фреймом ссылку, а исполняемое тело может оставаться прежним. [135]

В C++ int pages[2] может быть объектом с автоматическим временем жизни. В Java локальна переменная, содержащая ссылку; время жизни объекта определяется достижимостью, а освобождение памяти — работой среды. Даже несколько локальных переменных могут указывать на один объект.

Оптимизирующая JVM может встроить тело total в вызывающий код, удерживать значения в регистрах и удалить ненужное выделение объекта, если это сохраняет наблюдаемое поведение. Физическое представление кадра, число машинных инструкций и объём выделенной памяти определяются этими решениями реализации. [31], [95]

3.6 Загрузка, связывание и инициализация

До выполнения main среде нужно получить определение Reading. Загрузка находит двоичное представление класса и создаёт его представление внутри JVM. Связывание подготавливает его к участию в выполнении: проверка устанавливает соблюдение ограничений класса и байткода, подготовка создаёт статические поля и их начальные значения, разрешение символических ссылок находит определения классов, полей и методов. Разрешение допускается по мере необходимости. Инициализация выполняет предусмотренные языком инициализаторы класса.

Для начального класса Reading загрузка предшествует проверке и подготовке, а эти действия — его инициализации и вызову main. Разрешение символической ссылки реализация может отложить до использования соответствующего обращения. [134]

Вызов IO.println(sum) содержит символическую ссылку на библиотечный метод. Байткод сообщает, какая операция нужна, без сохранения адреса её машинного кода с компьютера автора. Среда связывает это описание с установленными определениями.

Проверка байткода отвергает применение iadd к двум объектным ссылкам: эта инструкция требует целых значений. Формулу над допустимыми числовыми типами проверка принимает независимо от её предметного смысла. Операции с файлами выполняются с правами процесса приложения.

Если не найден начальный класс, main не начинается. Отсутствующая зависимость может понадобиться позже. Несовместимая версия формата вызывает UnsupportedClassVersionError; старый вызов удалённого метода может привести к NoSuchMethodError. Для выполнения нужны определения зависимостей, соответствующие обращениям в файлах классов.

3.7 Исполнение в HotSpot

Полученный байткод ещё нужно исполнить. Интерпретатор читает инструкции и выполняет соответствующие действия. JIT-компилятор переводит код в машинные инструкции во время работы процесса. Спецификация JVM разрешает разные стратегии; наличие конкретного JIT не является её требованием.

HotSpot — реализация JVM в используемом OpenJDK. В ней применяется многоуровневое выполнение: интерпретация и менее затратная компиляция помогают начать работу и собрать сведения о вызовах, циклах и фактически происходящих действиях. Более глубокая оптимизация может использовать этот профиль выполнения. Машинный код занимает место в кэше кода, а получение профиля и компиляция расходуют время процессора. Полученный код может обслуживать несколько вызовов: завершение одного вызова не требует его повторной компиляции. [95]

Представим сервер, который много раз считает сумму двухдневных записей. total вызывается часто и имеет маленькое тело: встраивание может убрать затраты на отдельный вызов и сделать возможными последующие оптимизации. Если цикл обрабатывает разные записи, среда наблюдает реальную нагрузку, которой javac при создании переносимого класса мог ещё не знать.

Сведения профиля помогают компилятору выбрать оптимизацию:

Наблюдение Возможное использование
Частые вызовы или повторения цикла Выделить участки, где оптимизация может окупиться
Частота ветвей Учесть обычный путь выполнения
Типы получателей вызовов Специализировать код для наблюдавшихся случаев с проверкой предположений

Для total существенно уже изменение характера нагрузки: один вызов в короткой команде и многократное использование в сервисе дают разные возможности окупить компиляцию. По диагностике выбранного запуска можно определить, скомпилирован ли конкретный метод отдельно или встроен в вызывающий код. Журнал компиляции показывает действия JIT, а исследование полученного машинного кода уточняет, какие операции сохранены после оптимизации.

Прогрев — изменение состояния процесса в начале нагрузки: загружаются классы, выполняются инициализаторы, накапливается профиль, появляется скомпилированный код. Длительность прогрева устанавливают для выбранной нагрузки: редко используемый участок может остаться интерпретируемым, а новые входы потребовать иной оптимизации. Если специализация опирается на проверяемое предположение, например единственный тип получателя, код проверяет его. При нарушении HotSpot может восстановить состояние выполнения для интерпретатора и продолжить с соответствующей точки. Такая деоптимизация сохраняет поведение программы; последующая компиляция может учесть новые наблюдения. [40]

javap читает инструкции JVM из файла класса, полученного после javac. Машинные инструкции JIT-компилятор формирует отдельно при выполнении программы. Встроенный total может физически не иметь отдельного вызова: его машинные инструкции становятся частью вызывающего кода.

3.8 Стоимость выполнения

Когда программа больше не может достичь массива через используемые ссылки, его память становится кандидатом на повторное использование. Сборщик мусора (GC) определяет живые объекты и освобождает память недостижимых. Момент освобождения определяется работой сборщика. Она расходует процессорное время и память; некоторые её этапы могут приостанавливать выполнение приложения. Разные сборщики выбирают разные сочетания пропускной способности, задержек и расхода памяти. [99]

Два расчёта одинаковой суммы могут создавать разное количество временных данных. Если программа на каждом шаге создаёт новую копию большого массива, она обрабатывает больше данных и выделяет память для новой копии. Если она хранит все прошлые массивы в коллекции, они остаются достижимыми: GC не может освободить их память.

У команды java -cp out Reading можно измерить интервал от запуска процесса до завершения. Он включает подготовку JVM, загрузку классов, создание массива, вычисление и печать 12 и 6.0. Ускорение сложения уменьшает лишь часть этого интервала. Если запустить команду десять раз, каждый раз возникает новый процесс; при десяти вызовах total в одном процессе загруженный класс используется повторно.

Для работающего сервиса возьмём модельный журнал: после прогрева за 10 секунд завершены 1000 запросов на сложение пар чисел. Пропускная способность на этом интервале равна 1000 / 10 = 100 запросам в секунду. Теперь выберем один запрос: сервис принял его в 2,000 с, отправил ответ в 2,150 с. Его задержка составила 0,150 с, то есть 150 мс; сюда вошли ожидание обработки и получение ответа. Частное 10 с / 1000 = 10 мс не даёт задержку этого запроса: одновременно в системе могут обрабатываться или ожидать другие запросы.

По задержкам отдельных запросов строят распределение. Например, перцентиль 99% отмечает границу, в которую укладывается примерно 99% наблюдаемых задержек; оставшиеся могут быть больше. Приостановка приложения во время GC способна задержать сразу несколько запросов. Одно число завершений за большой интервал такого эпизода не показывает. JMH на уровне вызовов метода также разделяет измерение скорости повторений и выборку длительностей; граница запроса целого сервиса может охватывать несколько методов и очередь. [146]

Затраты ресурсов дополняют эти наблюдения. JIT использует процессорное время для получения машинного кода и память для его хранения; программа может выиграть время последующих вычислений ценой этой работы. Создание нового массива для каждого запроса увеличивает объём выделений, удержание всех прошлых массивов — объём живых данных. Поэтому два варианта с одинаковыми 100 запросами в секунду могут различаться по занятости процессора, потреблению памяти и задержкам. Для сравнения Java- и C++-реализации нужна одинаковая операция над одинаковыми входами и такая же граница измерения: время короткой команды не сопоставимо со временем одного вызова в уже работающем процессе.

3.9 Переносимость числовых операций

В Java int всегда представляет знаковые 32-битные целые, long — 64-битные. Типы операндов определяют арифметическую операцию.

int pages = 5;
int days = 2;
double first = pages / days;
double second = (double) pages / days;
System.out.println(first);  // 2.0
System.out.println(second); // 2.5

Первый расчёт выполняет целое деление и лишь затем преобразует 2 в double. Второй преобразует левый операнд до деления; правый также расширяется, поэтому получается 2.5. Обе последовательности преобразований заданы языком и сохраняются на совместимых JVM.

int count = 50_000;
long first = count * count;
long second = (long) count * count;
System.out.println(first);  // -1794967296
System.out.println(second); // 2500000000

В первом случае произведение двух int вычислено в 32 битах и переполнилось; расширение переносит уже полученное отрицательное значение. Во втором само умножение 64-битное. Для C++ обычное переполнение знакового целого не имеет такого определённого результата; Python int увеличивает представление по мере необходимости. [12], [154], [160]

double представляет конечное множество значений с ограниченной двоичной точностью. Округление операндов и результатов влияет на сравнение: 0.1 + 0.2 == 0.3 даёт false из-за двоичного округления. Современная Java использует строгую плавающую семантику для всех вычислений; это правило действует с Java 17. У библиотечных трансцендентных функций остаются собственные требования к точности. Подробные диапазоны, преобразования, деление и особые значения доступны в Глава 4 и Глава 5. [129]

3.10 Имена классов и зависимости

Компактный файл подходит для небольшой программы в безымянном пакете. Чтобы включить класс в именованный пакет, объявим его явно. Это отдельный вариант Hello.java, заменяющий начальный компактный файл:

package course;

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

package course включает класс в пакет, полное имя теперь course.Hello. Традиционная форма точки входа явно задаёт доступность public, отсутствие объекта-получателя static и параметр String[] args для строк командной строки. При запуске без аргументов этот массив пуст. Здесь для печати использован System.out.println: через стандартный поток out вызывается метод println. Имя публичного класса Hello совпадает с именем исходного файла.

Из каталога с Hello.java получим файл класса в отдельном каталоге и запустим:

javac -d out Hello.java
java -cp out course.Hello

Вывод — Hello. Опция -d out задаёт корень результата компиляции: получается out/course/Hello.class. Опция -cp out задаёт корень поиска: загрузчик находит внутри него course/Hello.class. Если указать -cp out/course, он будет искать эту структуру ещё раз от неверного корня.

При запуске класса указывается имя, без .class. import java.util.Arrays; позволяет записать короткое имя Arrays в исходнике; импорт не устанавливает библиотеку. Определения внешней библиотеки нужны и при компиляции, и при выполнении. Зависимость, найденная IDE, может отсутствовать в ручной команде. Подробные формы classpath и запуск архива: Глава 25.

3.11 Двоичная совместимость

Классы приложения и библиотеки могут компилироваться и обновляться отдельно. Вызов библиотечного метода в классе клиента содержит символическую ссылку: имя класса или интерфейса, имя метода, типы параметров и результата. При разрешении этой ссылки JVM ищет соответствующее определение среди загруженных классов.

Изменение библиотеки двоично совместимо, если прежние классы, которые связывались без ошибки, продолжают связываться с новой версией. Замена тела метода может сохранить его доступное объявление и разрешение прежних обращений. Удаление метода способно оставить старую ссылку без подходящего определения и привести к NoSuchMethodError. При связывании клиент использует символическое обращение, сохранённое в его файле класса. Выбор метода по исходному тексту выполнялся при компиляции клиента; при запуске старого класса JVM разрешает сохранённую ссылку по новым определениям. [24]

Совместимость исходного кода означает возможность снова скомпилировать прежний исходник с обновлёнными объявлениями. При такой компиляции имена и перегрузки разрешаются заново, поэтому её результат может отличаться от сохранения старого класса. Совместимость поведения относится к договору операции: возвращаемым значениям, эффектам и ошибкам. Если метод с прежним объявлением начинает возвращать длительность в миллисекундах вместо секунд, связывание может пройти успешно, но использующий результат расчёт изменится.

3.12 Конфигурация среды разработки

Интегрированная среда разработки (IDE) объединяет редактор, сборку, запуск и отладку. Исходники и зависимости образуют проект, для которого выбираются инструменты и параметры. Компилятор получает исходные файлы и доступные объявления библиотек; запускаемая JVM получает классы, пути их поиска и условия нового процесса.

Конфигурация запуска сохраняет имя начального класса, используемую среду, аргументы, рабочий каталог и другие параметры. Например, в IntelliJ IDEA JDK выбирается для проекта, а конфигурация Application позволяет отдельно задать среду выполнения и classpath. Рабочий каталог служит началом относительных путей к файлам. Поэтому один и тот же класс, запущенный с разными рабочими каталогами, может читать разные данные по одному относительному имени. [143], [144]

Внешняя командная оболочка выбирает программы javac и java по своим правилам поиска, например по PATH. Настройка JDK проекта задаёт выбор в IDE; установка нескольких JDK допускает другой выбор в оболочке. Версии реально вызванных инструментов показывают команды:

javac --version
java --version

3.13 Целевая версия платформы

Выпуск Java SE задаёт правила языка, стандартный API и поддерживаемое устройство файлов классов. Версия установленного компилятора и целевая версия программы могут различаться: новый javac поддерживает также ограниченный набор прежних выпусков. Целевая версия определяет, какие конструкции и библиотечные объявления доступны исходнику и для какой среды создаётся файл класса.

Опция javac --release 25 согласованно выбирает язык, API платформы и формат результата для Java SE 25. Если выбрана более ранняя поддерживаемая цель, компилятор проверяет программу по её правилам и доступным библиотечным объявлениям. Проверка API отвергает обращение к методу, которого в выбранном выпуске ещё нет. Внешние зависимости имеют собственные требования к среде; их версии также должны поддерживать целевую платформу. [120]

Форма исходника и способ запуска задают другие свойства. Компактная единица компиляции Java 25 не требует явного внешнего объявления класса; обычная единица содержит явные объявления и может входить в именованный пакет. Обе формы можно заранее скомпилировать и затем запустить класс. При прямом запуске .java команда java сама выполняет компиляцию исходника перед исполнением. Доступность его конструкций определяется выбранной версией инструментов. Формы команд: java.

3.14 Дополнение: исследование выполнения

Наблюдение загрузки или компиляции показывает события выбранного процесса. Профилирование ищет участки, которые занимают время или создают данные. Бенчмарк сравнивает выбранную метрику на определённой нагрузке. Журнал компиляции фиксирует решения JIT; измерения времени позволяют оценить их влияние на выбранную нагрузку.

Для микробенчмарков JVM существует JMH. Его примеры показывают две ловушки: неиспользуемый результат может позволить оптимизатору удалить вычисление; многократное повторение операции в самодельном цикле может дать оптимизацию всего цикла, отличную от стоимости отдельного вызова. В микробенчмарке задают вход и способ использования результата, разделяют прогрев и измерение и повторяют опыт в независимых процессах. [147], [148]

Модель JVM различает область сведений о методах и классах, пул констант, отдельные стеки потоков и средства вызова нативного кода. long и double занимают две локальные позиции в модели байткода. Физическое размещение значений выбирает реализация JVM. Настройка кучи, выбор сборщика, параметры компиляции и измерение пауз имеют смысл после постановки цели: например, сократить задержку ответа при известной нагрузке, сохранив доступную память.
