18.1 Общие интерфейсы коллекций

Коллекция хранит элементы вместе с отношениями между ними. У списка это позиции и порядок, у множества — принадлежность, у очереди — выбор элемента для следующей обработки. Карта связывает ключ со значением. Обращения s1, s2, s1 можно сохранить как три позиции журнала, два посещённых кода или два соответствия код → частота. По одному множеству кодов число обращений восстановить нельзя; карта частот также теряет порядок отдельных обращений.

Интерфейс определяет доступные операции и их смысл. Класс реализации определяет способ хранения и алгоритмы этих операций. Тип List<String> позволяет передать список между независимо написанными загрузчиком и отчётом: они согласуют порядок, повторения и тип элементов, пользуясь одним API. Совместимость таких библиотек и небольшой набор основных понятий были целями создания Collections Framework. Прежние Vector и Hashtable приспособили к общим интерфейсам. [59]

18.1.1 Группа элементов и порядок обхода

Collection<E> предоставляет размер, проверку наличия, добавление, удаление и обход элементов. Параметр E связывает тип добавляемого элемента с типом результата чтения итератором. Iterable<E> определяет получение итератора методом iterator(); Collection расширяет этот интерфейс.

Интерфейс Дополнительный договор
List<E> Последовательность вхождений с индексами от нуля; допускаются повторения
Set<E> По одному представителю каждого равного значения
Queue<E> Голова — элемент для следующего извлечения; дисциплина определяется реализацией
Deque<E> Чтение, вставка и удаление на обоих концах
SequencedCollection<E> Заданный порядок обхода, доступ к концам и обратное представление
SequencedSet<E> Уникальность множества вместе с заданным порядком обхода

Начиная с Java 21 List расширяет SequencedCollection, а Deque одновременно расширяет Queue и SequencedCollection. Порядок обхода задаёт первое, второе и последующие вхождения. Он может определяться позициями, временем вставки или сравнением значений. Интерфейс SequencedCollection предоставляет getFirst, getLast, reversed и необязательные операции изменения на концах; индексного get(i) у него нет.

На этой схеме все узлы — интерфейсы; треугольник указывает на расширяемый тип. SortedSet связывает порядок со сравнением элементов. NavigableSet добавляет поиск соседей: меньшего, большего и ближайших с допуском равенства; операции диапазонов он наследует от SortedSet. SortedSet явно объявляет и Set, и SequencedSet среди своих непосредственных родителей. [57]

Прежний общий тип Collection не выражал наличие порядка, хотя им обладали и списки, и некоторые множества. Приём параметра типа List исключал LinkedHashSet и SortedSet; приём Collection требовал описывать порядок отдельным условием. Семейство Sequenced* внесло эту общую возможность в систему типов. [58]

SequencedCollection<String> codes =
    new LinkedHashSet<>(List.of("s2", "s1", "s2"));
System.out.println(codes.getFirst()); // s2
System.out.println(codes.getLast());  // s1

Обычное добавление в LinkedHashSet сохраняет порядок первого появления. У TreeSet концы определяются сравнением: для тех же кодов первым был бы s1, последним — s2. Обе структуры подходят параметру SequencedCollection<String>. Требование конкретного порядка, например регистрации, остаётся частью договора вызывающего метода.

Map<K,V> содержит соответствия, в каждом из которых ключу типа K сопоставлено значение типа V. Метод get(key) ищет значение по ключу, put(key, value) сохраняет обе части. Через представление клиент обращается к данным основной структуры. Обычные стрелки обозначают получение представления. Map.Entry<K,V> представляет пару и даёт методы getKey() и getValue(). У values() могут повторяться значения разных ключей; ключи и пары представлены множествами. [43], [143]

18.1.3 Необязательные операции

Некоторые интерфейсные операции объявлены необязательными. Реализация вправе отвергнуть такую операцию через UnsupportedOperationException. Например, List объявляет add и set, а объект от List.of запрещает обе. Список от Arrays.asList разрешает замену элемента, сохраняя фиксированный размер. Один статический тип описывает эти разные договоры изменения.

Разработчики объясняли выбор небольшого API сочетаниями ограничений: изменяемые контейнеры, фиксированный размер, только добавление или только удаление через представление. Для отражения всех сочетаний потребовалась бы разветвлённая иерархия, а ограничения на значения элементов всё равно проверялись бы при выполнении. [43]

В C++ const std::vector<T> ограничивает изменение через данный доступ. В Python изменяемому list соответствует отдельный тип последовательности tuple с запрещённым изменением состава. В Java List может обозначать изменяемый список, снимок или представление; поддержка set устанавливается по способу получения объекта и его документации.

18.2 Реализации и абстрактные основы

Классы ArrayList и LinkedList реализуют один договор List через разные структуры. Для отчёта, использующего чтение по позиции, сохраняются тип результата и смысл индекса:

List<String> codes = new ArrayList<>();
codes.add("s1");
String first = codes.get(0); // s1

Замена конструктора на new LinkedList<>() сохраняет эти свойства, но обращение по индексу потребует переходов между узлами. LinkedList реализует также Deque; клиент может выбрать договор списка или дека.

У абстрактного базового класса часть методов уже реализована через меньший набор опорных операций. От него наследуют конкретные классы. AbstractList предоставляет итератор через индексированные операции; для собственного списка с запрещённым изменением достаточно реализовать get(int) и size(). AbstractSequentialList строит индексированные операции через итератор списка; его основа — listIterator(int) и size(). [44], [46]

Сплошная линия с треугольником обозначает наследование класса, пунктирная — реализацию интерфейса; треугольник указывает на общий тип. Унаследованные интерфейсы также доступны подклассу. Например, LinkedList получает договор List через цепочку базовых классов и дополнительно предоставляет Deque. [109]

18.2.2 Основы множеств и отображений

AbstractSet предоставляет общую реализацию равенства и хеша множества, AbstractMap — ряд операций через множество пар. Для собственного типа наследование этих основ удобно готовыми методами; непосредственно реализовать интерфейс также допустимо. HashSet наследует AbstractSet и использует внутреннюю HashMap для хранения данных. [45], [47], [49]

18.3 Последовательный обход

Алгоритму вывода кодов достаточно получать следующие строки. Параметр типа Iterable<String> выражает именно эту возможность:

static void printCodes(Iterable<String> codes) {
    Iterator<String> it = codes.iterator();
    while (it.hasNext()) {
        String code = it.next();
        System.out.println(code);
    }
}

Iterable предоставляет источник элементов, а Iterator — отдельное состояние обхода. hasNext() проверяет наличие следующего элемента; next() возвращает его и продвигает обход. У исчерпанного итератора hasNext() даёт false, а next() — NoSuchElementException. Эти действия позволяют писать общий алгоритм без знания индексов, узлов или внутренней таблицы. [39], [50]

var input = List.of("s1", "s2", "s1");
printCodes(new ArrayList<>(input));
printCodes(new LinkedList<>(input));
printCodes(new LinkedHashSet<>(input));

Первые два вызова печатают s1, s2, s1; третий — s1, s2. Каждая строка выводится отдельно. Конструктор множества уже устранил повтор, а общий алгоритм лишь прочитал сохранённые элементы. При пустом входе тело цикла не выполняется. Порядок HashSet не задан; последовательный обход ArrayList и LinkedList посещает позиции списка по порядку. [111]

18.3.1 Независимые состояния обхода

У списка [s1, s2, s3] создаются два итератора. Состав списка во время опыта сохраняется:

var codes = new ArrayList<>(List.of("s1", "s2", "s3"));
Iterator<String> first = codes.iterator();
Iterator<String> second = codes.iterator();
System.out.println(first.next());  // s1
System.out.println(first.next());  // s2
System.out.println(second.next()); // s1
                     список codes: [s1, s2, s3]
после iterator():    first:  | s1, s2, s3    second: | s1, s2, s3
после first.next():  first: s1 | s2, s3      second: | s1, s2, s3
после first.next():  first: s1, s2 | s3      second: | s1, s2, s3
после second.next(): first: s1, s2 | s3      second: s1 | s2, s3

Черта — логическая граница выданного префикса и оставшихся элементов. Сами строки остаются в одном списке. first продвинулся дважды, second — один раз. Повторная проверка hasNext() не выдаёт элемент и сохраняет эту границу. Присваивание second = first вместо второго вызова iterator() создало бы две ссылки на один объект обхода. Такая пара переменных разделяла бы его положение.

У ArrayList каждый вызов iterator() создаёт отдельное состояние. Поэтому во вложенном цикле внутренний итератор проходит список заново, сохраняя положение внешнего. Iterable задаёт получение итератора; возможность повторного прохода определяется договором источника.

18.3.2 Расширенный цикл for

for (String code : codes) {
    System.out.println(code);
}

Для Iterable<String> этот цикл получает собственный итератор и выполняет проверки hasNext() с чтением через next(). Явная форма:

for (Iterator<String> it = codes.iterator(); it.hasNext(); ) {
    String code = it.next();
    System.out.println(code);
}

Положение скрытого итератора сохраняется между выполнениями тела. Локальная переменная code получает очередную ссылку; присваивание ей другой строки не заменяет элемент коллекции. Эта форма for применима также к массивам, где язык задаёт обход по индексам. Массив не реализует Iterable, поэтому сам массив нельзя передать в printCodes. [60]

Карта участвует в том же алгоритме через представление ключей:

var counts = new LinkedHashMap<String, Integer>();
counts.put("s1", 2);
counts.put("s2", 1);
printCodes(counts.keySet()); // s1, затем s2

У обычной LinkedHashMap ключи обходятся в порядке первого добавления. Для чтения обеих частей пары используется entrySet(), для одних значений — values(). Связь представлений с исходной картой: Представления коллекций.

18.4 Протоколы обхода в C++ и C#

В C++ итератор обозначает позицию, а граница диапазона задаёт его конец. Для std::vector<std::string>:

std::vector<std::string> codes{"s1", "s2", "s3"};
for (auto it = codes.begin(); it != codes.end(); ++it) {
    std::cout << *it << '\n';
}

Проверка it != codes.end() устанавливает наличие элемента; *it читает его, ++it переходит к следующему. За последним элементом итератор сравнивается с end(), который не разыменовывают. У пустого контейнера begin() == end().

Шаблон C++20 выражает общий алгоритм через операции типа итератора:

template<std::input_iterator I, std::sentinel_for<I> S>
void printCodes(I it, S end) {
    for (; it != end; ++it) {
        std::cout << *it << '\n';
    }
}

input_iterator требует чтения и продвижения, sentinel_for<I> — совместимой границы; значение *it здесь должно поддерживать вывод в std::cout. Один шаблон можно вызвать с диапазоном vector<string> или list<string>. Общий базовый класс их итераторов не требуется: компилятор проверяет применимость операций и ограничений шаблона. [91]

В C# на платформе .NET 10 интерфейс IEnumerable<T> обозначает источник элементов типа T. Его GetEnumerator() возвращает IEnumerator<T> — перечислитель с состоянием обхода. string является именем строкового типа C#, а List<string> — списком строк.

IEnumerable<string> codes = new List<string> { "s1", "s2", "s3" };
using (IEnumerator<string> it = codes.GetEnumerator()) {
    while (it.MoveNext()) {
        Console.WriteLine(it.Current);
    }
}

Начальное положение предшествует первому элементу. MoveNext() переходит к следующему и возвращает true при успехе. После этого свойство Current предоставляет элемент; чтение свойства само не продвигает перечислитель. После MoveNext() == false обход завершён, Current не определён. using обеспечивает вызов Dispose() при выходе из блока; перечислители источников с ресурсами могут освобождать их в этом методе. [33], [34], [35]

В Java источник и итератор реализуют соответствующие интерфейсы. В C++ шаблон задаёт требования к операциям типа итератора. C# разделяет источник и состояние интерфейсами, а продвижение объединяет с проверкой. Цикл foreach (string code in codes) выполняет этот обход и завершает использование перечислителя. Во всех трёх фрагментах выводятся s1, s2, s3 по одной строке.

18.4.1 Категории возможностей итераторов C++

18.4.2 Итератор списка и разделение обхода

ListIterator<E> расширяет Iterator<E>: добавляет движение назад, индексы соседних позиций, замену и вставку. Его курсор находится между элементами; у списка из трёх вхождений четыре положения курсора. Метод listIterator(index) устанавливает его перед вхождением index, а при index == size() — за последним.

var codes = List.of("s1", "s2", "s3");
ListIterator<String> it = codes.listIterator(codes.size());
while (it.hasPrevious()) System.out.println(it.previous());
// s3, s2, s1 — по одному коду в строке

previous() возвращает предыдущий элемент и перемещает курсор назад. При чередовании next() и previous() курсор проходит через одно вхождение в противоположных направлениях и возвращает его повторно. Вызов set заменяет последний элемент, выданный next или previous; add вставляет перед элементом, который был бы выдан следующим next. Изменяющие операции необязательны. set требует предшествующего next/previous, после которого не выполнялись remove или add; remove допускается один раз после каждого next или previous, если после этого чтения не выполнялся add. [53]

Spliterator<T> поддерживает другой способ обхода: tryAdvance(action) получает один элемент и применяет к нему действие, возвращая признак успеха. forEachRemaining(action) обрабатывает все оставшиеся элементы. Метод trySplit() отделяет часть оставшихся элементов в новый Spliterator или возвращает null, если часть не была отделена. У упорядоченного источника успешное разбиение отделяет строгий префикс.

var codes = new ArrayList<>(List.of("s1", "s2", "s3", "s4"));
Spliterator<String> rest = codes.spliterator();
Spliterator<String> prefix = rest.trySplit();
if (prefix != null) prefix.forEachRemaining(System.out::println);
rest.forEachRemaining(System.out::println);
// s1, s2, s3, s4 — по одному коду в строке

Ссылка на метод System.out::println задаёт действие печати строки. Сначала обработана отделённая начальная часть, затем остаток; при отказе разбиения все элементы обрабатывает rest. Источник во время опыта не изменяется. Разделение позволяет параллельному алгоритму распределять части между исполнителями; сам trySplit дополнительные потоки не создаёт.

Характеристики Spliterator сообщают, например, наличие порядка (ORDERED), известного размера (SIZED) или различных элементов (DISTINCT). У ArrayList есть порядок позиций и известный размер; повторения допустимы. Разбиение и характеристики используются при организации потоковых вычислений: Глава 20. [56]

18.5 Массив и расширяемый список

У массива фиксирована длина. При неизвестном числе имён программа должна отдельно хранить число занятых позиций и при заполнении массива переносить ссылки в больший массив. ArrayList выполняет эту работу внутри объекта списка. Сам объект списка сохраняется при замене его внутреннего массива.

List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Lin");
names.add("Ada");
System.out.println(names);        // [Ada, Lin, Ada]
System.out.println(names.get(1)); // Lin

List<String> нужен клиенту, который читает строки и обращается к ним через get. Компилятор проверяет строковый аргумент add и строковый результат get; попытка names.add(25) отвергается. new ArrayList<>() выбирает хранилище. Повторное имя занимает самостоятельную позицию: размер равен трём, хотя различных строк две.

Замена и вставка по одному индексу меняют разные части состояния:

names.set(1, "Max"); // [Ada, Max, Ada], размер 3
names.add(1, "Lin"); // [Ada, Lin, Max, Ada], размер 4

set заменяет ссылку в существующей позиции. add(index, value) освобождает позицию для новой ссылки, сдвигая хвост. Для get, set и remove(index) допустимо 0 <= index < size(); для вставки допустимо также index == size(). Чтение из пустого списка по индексу 0 даёт IndexOutOfBoundsException. Удаление по значению убирает первое равное вхождение и возвращает признак изменения. У List<Integer> выбор перегрузки существенен:

var numbers = new ArrayList<>(List.of(10, 20, 10));
numbers.remove(1);                    // позиция 1: удалено 20
numbers.remove(Integer.valueOf(10)); // первое значение 10
System.out.println(numbers);         // [10]

new ArrayList<String>(100) создаёт пустой список с начальной вместимостью 100; его size() равен нулю. В C++ std::vector<T>(100) создаёт сто элементов, а reserve(100) резервирует хранилище без такого изменения размера. [73], [137]

18.6 Стоимость доступа и изменения

У ArrayList ссылка в позиции i находится индексированием внутреннего массива. get и set имеют стоимость \(O(1)\). Вставка в позицию i списка размером \(n\) сдвигает \(n-i\) ссылок; удаление сдвигает оставшийся хвост. Копируются ссылки, поэтому сами объекты элементов сохраняются.

Добавление в свободный конец требует одной записи. Когда места нет, создаётся больший массив и переносятся прежние ссылки. Отдельное расширение стоит \(O(n)\); серия из \(n\) добавлений имеет суммарную стоимость \(O(n)\). Поэтому стоимость добавления называют амортизированно постоянной. Начальный резерв может сократить число расширений, но не создаёт элементы. [137]

LinkedList хранит узлы, в каждом из которых находятся ссылка на элемент и связи с соседними узлами. get(i) проходит от ближайшего конца к позиции. После нахождения узла удаление меняет соседние связи за \(O(1)\), однако remove(i) включает и поиск позиции. Например, полный просмотр через get(0), get(1), …, get(n-1) многократно начинает проход заново и суммарно требует \(O(n^2)\) переходов. Один итератор проходит все узлы за \(O(n)\).

Операция ArrayList LinkedList
Чтение по индексу \(O(1)\) \(O(n)\) в худшем случае
Добавление в конец Амортизированно \(O(1)\) \(O(1)\)
Удаление по среднему индексу Сдвиг хвоста: \(O(n)\) Поиск узла: \(O(n)\)
Удаление через уже установленный итератор Сдвиг хвоста Изменение соседних связей: \(O(1)\)
Последовательный обход итератором \(O(n)\) \(O(n)\)

Выбор для частых удалений зависит от способа нахождения удаляемых элементов. У LinkedList отдельные узлы требуют памяти и переходов по ссылкам; ArrayList хранит ссылки в одном массиве. Асимптотическая оценка описывает рост объёма работы при увеличении входа. Для измерения времени дополнительно нужны конкретные размеры, последовательность операций, прогрев и границы измеряемого участка. [40], [76]

18.6.1 Одна вставка в двух хранилищах

Оба списка получают исходную последовательность [s1, s3]. Вставка s2 перед вторым элементом должна дать [s1, s2, s3]. Для ArrayList сначала зарезервированы три позиции:

var array = new ArrayList<String>(3);
array.add("s1");
array.add("s3");
array.add(1, "s2");
System.out.println(array); // [s1, s2, s3]

До вставки позиция 2 массива M свободна. В том же массиве сдвиг переносит ссылку на s3 из позиции 1 в позицию 2; затем в позицию 1 записывается ссылка на s2. Строковые объекты сохраняются. При поэлементном сдвиге вправо перенос начинают с конца, чтобы запись в соседнюю позицию не уничтожила ещё нужную ссылку. После удаления элемента по индексу оставшийся хвост сдвигается влево, а последняя освободившаяся ячейка перестаёт удерживать ссылку на элемент. В OpenJDK jdk-25-ga эти действия выполняют индексный add, System.arraycopy и fastRemove. [37]

При исходном резерве 2 перед той же вставкой требуется рост:

var tight = new ArrayList<String>(2);
tight.add("s1");
tight.add("s3");
tight.add(1, "s2");
System.out.println(tight); // [s1, s2, s3]
Состояние Объект списка Внутренний массив Состав
До вставки T M, длина 2 [s1, s3]
После вставки Тот же T Новый N, длина не меньше 3 [s1, s2, s3]

Список меняет ссылку на хранилище, поскольку длина существующего массива постоянна. Перенос прежних ссылок обеспечивает сохранность элементов; сдвиг освобождает выбранную позицию. Конкретный коэффициент роста API ArrayList оставляет реализации.

Для LinkedList получение позиции и вставка выражены отдельными вызовами:

var linked = new LinkedList<>(List.of("s1", "s3"));
var position = linked.listIterator(1);
position.add("s2");
System.out.println(linked); // [s1, s2, s3]

В двух состояниях N1 и N3 обозначают прежние узлы. listIterator(1) находит границу перед N3. add создаёт N2 со ссылкой на s2, связывает его с обоими соседями и меняет встречные связи соседей. Курсор оказывается после вставленного элемента, перед N3. Число переключений связей не зависит от длины списка; путь до позиции зависит от её индекса.

Вызов linked.add(1, "s2") объединяет эти две работы. При удалении уже найденного N2 соседи N1 и N3 связываются друг с другом. Вызов remove(1) также включает поиск удаляемого узла. [38], [40], [76]

18.7 Изменение при обходе

Удаление пустых имён требует сохранять положение после изменения списка:

var names = new ArrayList<>(List.of("Ada", "", "Lin", ""));
var it = names.iterator();
while (it.hasNext()) {
    String name = it.next();
    if (name.isEmpty()) it.remove();
}
System.out.println(names); // [Ada, Lin]

После каждого next итератор помнит последний выданный элемент. Его remove удаляет этот элемент и согласует собственное положение с новым состоянием списка. Обе пустые строки удаляются, включая последнюю. Удаление до первого next или повторное удаление без следующего next нарушает порядок вызовов и даёт IllegalStateException. next после исчерпания даёт NoSuchElementException. Само удаление должно поддерживаться итератором; у неизменяемого списка оно отвергается. [39], [111]

Структурное изменение ArrayList через сам список во время работы его итератора нарушает условия обхода. Fail-fast проверка может обнаружить расхождение и выдать ConcurrentModificationException, в том числе в одном потоке. Обнаружение выполняется по возможности; определять завершение алгоритма по возникновению этого исключения нельзя. В правильном удаляющем обходе изменения выполняет итератор. Вызов names.removeIf(String::isEmpty) удаляет элементы по условию, заданному ссылкой на метод String::isEmpty: Ссылки на методы.

18.7.1 Замена и структурное изменение Java 25

У ArrayList и LinkedList замена элемента через set не относится к структурным изменениям. Позиции сохраняются, и дальнейшее чтение ещё не пройденной позиции получает новую ссылку:

var codes = new ArrayList<>(List.of("s1", "s2"));
var it = codes.iterator();
System.out.println(it.next()); // s1
codes.set(1, "s9");
System.out.println(it.next()); // s9

Тот же опыт с new LinkedList<>(List.of("s1", "s2")) даёт s1, затем s9. Добавление и удаление меняют число позиций. У ArrayList структурным считается также явное изменение размера внутреннего массива. В отдельном опыте добавление выполнено через список:

var codes = new ArrayList<>(List.of("s1", "s2"));
var it = codes.iterator();
codes.add("s3");
it.next(); // В OpenJDK 25: ConcurrentModificationException

Явный next достигает проверки нарушения; прежний итератор больше не продолжает корректный обход. Аналогичный опыт с LinkedList имеет тот же наблюдаемый результат. Контракты этих классов задают fail-fast диагностику с обнаружением по возможности. Политика другой реализации должна быть задана её собственным договором. Общий Iterator не гарантирует ни устойчивость, ни конкретное исключение после стороннего изменения. Изменение внутри действия forEachRemaining также требует отдельной политики реализации; для удаления используется показанный цикл с next/remove. [39], [40], [137]

18.7.2 Изменение контейнеров C++20 и .NET 10

В C++ инвалидирование означает, что сохранённая позиция перестала соответствовать требованиям допустимого итератора или ссылки. Операции std::vector связывают действительность позиций с перемещением хранилища и сдвигом элементов:

Операция над vector Действительность прежних позиций
Вставка без перераспределения Итераторы, ссылки и указатели до точки вставки сохраняются; начиная с неё и прежний end недействительны
Вставка с перераспределением Все прежние итераторы, ссылки и указатели, включая прежний end, недействительны
erase Итераторы и ссылки начиная с точки удаления недействительны
reserve(n), n > capacity() Перераспределение, все прежние позиции недействительны
reserve(n), n <= capacity() Перераспределения нет, прежние позиции сохраняются

В опыте с std::vector<std::string> вызов reserve(4) обеспечивает достаточно места для добавления третьего элемента. Размер остаётся 2. Итератор первого элемента находится до места вставки:

std::vector<std::string> codes{"s1", "s2"};
codes.reserve(4);
auto first = codes.begin();
codes.push_back("s3");
std::cout << *first << '\n'; // s1
std::cout << codes.size() << '\n'; // 3
codes.reserve(codes.capacity() + 1);
first = codes.begin();
std::cout << *first << '\n'; // s1

Второй reserve требует большего хранилища и делает прежний first недействительным. Присваивание нового begin() восстанавливает допустимую позицию до следующего чтения. Договор reserve не фиксирует точную ёмкость после роста. Нужны заголовки <vector>, <string>, <iostream>. [85], [86]

У std::list вставка сохраняет итераторы и ссылки; удаление затрагивает только относящиеся к удалённым элементам. Уже найденный сосед остаётся доступным:

std::list<std::string> codes{"s1", "s3"};
auto first = codes.begin();
auto third = std::next(first);
codes.insert(third, "s2");
std::cout << *first << ' ' << *third << '\n'; // s1 s3
third = codes.erase(third);
std::cout << std::boolalpha << (third == codes.end()) << '\n'; // true
std::cout << *first << '\n'; // s1

erase возвращает позицию после удалённого элемента. Удалённый s3 был последним, поэтому получен end. Прежнее значение third больше не используется. Нужны <list>, <iterator>, <string>, <iostream>. Разыменование инвалидированного итератора вызывает неопределённое поведение: стандарт C++ не устанавливает требований к такому выполнению программы. Обязательное исключение не предусмотрено. [84]

В .NET 10 перечислитель List<T>.Enumerator становится недействительным при добавлении, удалении и замене элемента. C# использует индексатор для последнего действия:

var codes = new List<string> { "s1", "s2" };
var it = codes.GetEnumerator();
it.MoveNext();
Console.WriteLine(it.Current); // s1
codes[1] = "s9";
it.MoveNext(); // InvalidOperationException

Нужны пространства имён System и System.Collections.Generic. Вызов MoveNext после изменения выдаёт InvalidOperationException. Замена элемента отличается от изменения поля общего объекта по ссылке: индексатор записывает новую ссылку в список. У Java ArrayList.set замена неструктурна; у данного перечислителя .NET замена делает дальнейшее продвижение недопустимым. [36]

18.8 Способ поиска и операции элемента

Одинаковый вопрос «есть ли это значение?» допускает разные механизмы. Последовательный алгоритм может получить элементы через Iterable и сравнить каждый с запросом. Хеш-таблица использует предварительное размещение по хешу. Дерево сравнивает запрос с узлом и выбирает ветвь.

Механизм Действие до совпадения Условие совпадения
Линейный поиск Получить очередной элемент Равенство значения

TreeSet / TreeMap Выбрать ветвь по знаку сравнения Ноль выбранного сравнения

В HashMap конкретные формула индекса и устройство ячейки принадлежат реализации. Устройство ячейки и отбор кандидатов в OpenJDK jdk-25-ga: Ячейка, хеш узла и равный ключ. Линейный алгоритм с ранней остановкой: Линейный поиск по значению. Направления поиска и отличие нулевого сравнения от equals: Уникальность в упорядоченных множествах.

Последовательному поиску достаточно текущих элементов и операции равенства. Хеш-структуре нужны устойчивые данные равенства и хеша, дереву — устойчивые данные порядка. Внешнее правило равенства для ASCII-кодов в C++ и .NET: Внешнее правило равенства в C++ и C#.

18.9 Уникальность и порядок обхода

Множество хранит по одному представителю каждого различимого значения. У HashSet совпадение определяется согласованными equals и hashCode. Хеш сужает область поиска; совпадение хеша допускает несколько неравных элементов, которые различает проверка равенства.

Set<String> names = new LinkedHashSet<>();
System.out.println(names.add("Ada")); // true
System.out.println(names.add("Lin")); // true
System.out.println(names.add("Ada")); // false
System.out.println(names);            // [Ada, Lin]

add возвращает, изменился ли состав. Повторный Ada сохраняет размер и место прежнего элемента. LinkedHashSet совмещает поиск по хешу с порядком вставки. У HashSet порядок обхода не задан. Для получения строк в порядке сравнения применяют TreeSet или сортируют отдельный список.

TreeSet направляет поиск результатом compareTo либо Comparator.compare. Ноль сравнения означает найденный элемент, поэтому сравнение строк только по длине объединит "Ada" и "Lin". Сортировка списка тем же компаратором сохранит обе строки. Для соблюдения общего договора Set ноль сравнения должен совпадать с equals в обе стороны. Разбор этого условия: Уникальность в упорядоченных множествах. [42]

Состояние ключа участвует в размещении. Если изменить сведения равенства и хеша после добавления, хеш-таблица сохранит прежнее размещение и начнёт искать по новым сведениям. У дерева изменение поля порядка аналогично рассогласует узел с направлением поиска. Устойчивый строковый код или неизменяемый класс идентификатора сохраняет необходимые условия. Полная трасса повреждённого поиска: Изменяемые ключи.

При хорошем распределении хешей базовые операции HashSet и HashMap имеют ожидаемую постоянную стоимость. У TreeSet и TreeMap поиск, добавление и удаление требуют \(O(\log n)\) сравнений. Список ищет по значению линейно. Стоимость самого хеша и сравнения входит в фактическую работу; например, сравнение длинных строк требует чтения их символов.

18.9.1 Операции над составами

Объединение содержит элементы обоих множеств, пересечение — только общие. Изменение самостоятельной копии сохраняет входы:

Set<Integer> first = Set.of(1, 2);
Set<Integer> second = Set.of(2, 3);
var union = new HashSet<>(first);
union.addAll(second);
var intersection = new HashSet<>(first);
intersection.retainAll(second);
System.out.println(union.equals(Set.of(1, 2, 3))); // true
System.out.println(intersection.equals(Set.of(2))); // true

addAll и retainAll меняют получателя и возвращают признак изменения. Если второй вход пуст, пересечение пусто, а объединение равно первому. При одинаковых входах оба результата равны их составу. Явный обход с add и contains даёт другой способ реализовать те же операции. Сигнатуры и условия поддержки изменения: Групповые операции множеств.

18.10 Ключ и значение

Map<K,V> хранит соответствия: каждому ключу сопоставлено одно значение. Разные ключи могут иметь равные значения. В карте баллов код участника играет роль ключа, а балл — значения:

Map<String, Integer> scores = new LinkedHashMap<>();
System.out.println(scores.put("s1", 90)); // null
System.out.println(scores.put("s2", 70)); // null
System.out.println(scores.put("s1", 95)); // 90
System.out.println(scores.get("s1"));     // 95
System.out.println(scores.size());        // 2

Первые два вызова создают соответствия. Третий находит ключ s1, заменяет 90 на 95 и возвращает прежнее значение; размер сохраняется. Если задача запрещает повтор кода во входе, приложение должно выявить его отдельно. При обновлении сведений такая замена является требуемым результатом.

18.10.1 Отсутствие и null

HashMap и LinkedHashMap допускают null-значения. Поэтому результат get нужно читать с учётом двух состояний:

scores.put("s3", null);
System.out.println(scores.get("s3"));                 // null
System.out.println(scores.get("missing"));            // null
System.out.println(scores.containsKey("s3"));         // true
System.out.println(scores.containsKey("missing"));    // false
System.out.println(scores.getOrDefault("s3", 0));      // null
System.out.println(scores.getOrDefault("missing", 0)); // 0

getOrDefault использует запасное значение при отсутствии соответствия. Хранящееся null сохраняется как результат, поэтому его распаковка в int завершилась бы NullPointerException. У карты счётчиков можно выбрать договор: присутствующее значение отличается от null и содержит положительное число. Тогда следующий шаг определён для каждого полученного кода:

var counts = new HashMap<String, Integer>();
for (String id : List.of("s1", "s2", "s1")) {
    counts.put(id, counts.getOrDefault(id, 0) + 1);
}
System.out.println(counts.get("s1")); // 2
System.out.println(counts.get("s2")); // 1

Сначала getOrDefault читает прежнюю частоту или ноль; затем put записывает увеличенное число. В counts.merge(id, 1, Integer::sum) ссылка на метод Integer::sum задаёт сложение прежней частоты с единицей. Обычная HashMap не обеспечивает атомарность такого обновления при совместном изменении несколькими потоками. [143]

18.11 Каталог и порядок отчёта

Запись grade.Student(String id, String name, int score) хранит код, имя и балл 0–100; методы id(), name(), score() читают компоненты. Строки после strip() должны быть непустыми и не содержать ;, CR или LF. Неверные значения дают IllegalArgumentException, null — NullPointerException. Полное объявление: Запись участника учебного журнала.

В следующем входе коды различны. Индекс сохраняет ссылки на участников для повторных обращений по коду:

var input = List.of(new Student("s1", "Ada", 90),
                    new Student("s2", "Lin", 70));
Map<String, Student> byId = new LinkedHashMap<>();
for (Student student : input) byId.put(student.id(), student);
System.out.println(byId.get("s1").score()); // 90
byId.put("s1", new Student("s1", "Ada", 95));
System.out.println(byId.size());           // 2
System.out.println(input.get(0).score());  // 90

Карта получила новую версию s1; первая позиция входного списка сохраняет ссылку на прежний объект. Student неизменяем, поэтому исправление балла представлено созданием записи. Для единого текущего каталога нужен один владелец изменений: он либо обновляет все индексы согласованно, либо хранит основную карту и строит списки для каждого отчёта из её текущих значений. Снимок списка нужен для отчёта по состоянию на определённый момент.

Один поиск по коду можно выполнить линейным обходом списка. При многократных запросах индекс сокращает повторные просмотры ценой дополнительных ссылок и обязанности поддерживать соответствие данных. Для вывода по убыванию балла с возрастанием кода при ничьей сортируют отдельный List<Student>. Порядок вставки ключей LinkedHashMap остаётся порядком регистрации кодов.

Python by_id[id] = student тоже заменяет значение существующего ключа. В C++ byId[id] = student выполняет присваивание, а try_emplace сообщает, существовал ли ключ. Политику обновления или отказа при повторе задаёт программа. [172], [181]

18.11.1 Построение и сохранение ведомости

При редком запросе обход может сразу вернуть нужную запись. Источник, его элементы и код запроса отличны от null:

static Student findStudent(Iterable<Student> students, String code) {
    for (Student student : students) {
        if (student.id().equals(code)) return student;
    }
    return null;
}

Первое совпадение завершает поиск. Отсутствие даёт null; у пустого источника не выполняется ни одного сравнения. Для частых запросов текущие сведения сохраняются в карте. Устойчивый StudentId определён в Соглашение equals; его равенство учитывает только строковый код. Новая загрузка получает три записи:

var input = List.of(new Student("s3", "Ann", 90),
    new Student("s2", "Lin", 70), new Student("s1", "Ada", 90));
var current = new LinkedHashMap<StudentId, Student>();
for (Student student : input) {
    var id = new StudentId(student.id());
    if (current.putIfAbsent(id, student) != null)
        throw new IllegalArgumentException("Повтор кода: " + student.id());
}
System.out.println(current.get(new StudentId("s1")).score()); // 90

putIfAbsent возвращает прежнее значение и сохраняет его, если ключ уже связан со значением, отличным от null. В этом каталоге значения отличны от null, поэтому любой повтор кода обнаруживается. Если карта допускает сохранённое null, метод считает такой ключ кандидатом для записи нового значения; эта политика отличается от проверки containsKey. При ошибке загрузки частично построенная локальная карта не передаётся клиенту. Последующее изменение уже принятого каталога использует обычный put.

Карта сохраняет порядок регистрации кодов s3, s2, s1. Ведомость использует другой порядок: балл по убыванию, код по возрастанию при равных баллах. ReportOrder — реализация Comparator<Student> с этим правилом:

final class ReportOrder implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        int byScore = Integer.compare(b.score(), a.score());
        return byScore != 0 ? byScore : a.id().compareTo(b.id());
    }
}
var draft = new ArrayList<>(current.values());
draft.sort(new ReportOrder());
var report = List.copyOf(draft);
for (Student row : report) System.out.println(row.id());
// s1
// s3
// s2
current.put(new StudentId("s1"), new Student("s1", "Ada", 95));
current.put(new StudentId("s4"), new Student("s4", "Max", 80));
System.out.println(current.get(new StudentId("s1")).score()); // 95
System.out.println(report.get(0).score()); // 90
System.out.println(current.size());       // 4
System.out.println(report.size());        // 3

Сортировка переставила ссылки только в draft. report сохранил их порядок и состав. Замена значения карты направила ключ s1 к новой записи; прежняя запись в отчёте осталась неизменной. Строки и целое число в компонентах Student обеспечивают устойчивость сведений. Обычный put в этой LinkedHashMap сохраняет место существующего ключа; новый ключ s4 добавляется после прежних. Для нового отчёта повторно получают текущие значения, сортируют отдельный список и фиксируют его состав. [51], [52], [143]

18.12 Представления коллекций

Представление предоставляет доступ к данным другой структуры. keySet, values и entrySet карты показывают соответственно ключи, значения и пары. У values могут повторяться равные значения: два ключа с баллом 90 дают два вхождения 90. Для обхода пар ключ и значение доступны одновременно:

var scores = new LinkedHashMap<String, Integer>();
scores.put("s1", 95);
scores.put("s2", 70);
for (var entry : scores.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}
// s1: 95
// s2: 70
var keys = scores.keySet();
keys.remove("s2");
System.out.println(scores.containsKey("s2")); // false
scores.put("s3", 80);
System.out.println(keys.contains("s3"));     // true

Удаление через изменяемое представление удалило запись карты. Последующая вставка в карту стала видна прежнему keys. Добавление одного ключа через keySet.add не поддерживается: для новой записи требуется значение. Замена значения существующего ключа обычной LinkedHashMap сохраняет его место; отдельный конструктор позволяет выбрать порядок доступа.

18.12.1 Связь представления с владельцем

Стрелки означают обращение к общей основе. После scores.put("s3", 80) прежнее представление видит новый ключ. keys.remove("s2") удаляет соответствие из карты, поэтому оно исчезает также из её values и entrySet. Представления не выделяют самостоятельный набор соответствий.

Поддерживаемые изменения задаёт карта. У изменяемой LinkedHashMap представления поддерживают удаление, но запрещают add и addAll. Во время обхода entrySet поддерживаемый entry.setValue(value) заменяет значение текущего соответствия. Связь полученного объекта Map.Entry с картой гарантирована на время этого обхода; для длительного хранения нужен самостоятельный снимок пары. У карты, запрещающей изменение, запрещены и эти пути записи. [143]

18.12.2 Диапазон и обратный порядок

subList(from, to) представляет полуоткрытый диапазон списка [from, to). Индекс 0 представления соответствует from основы:

var names = new ArrayList<>(List.of("Ada", "Lin", "Max"));
var middle = names.subList(1, 3);
middle.set(0, "Ann");
System.out.println(names);  // [Ada, Ann, Max]
middle.remove(1);
System.out.println(names);  // [Ada, Ann]

Изменение через middle согласовано с основой. Если структурно изменить основу вне этого представления, его дальнейшая семантика становится неопределённой договором subList; для независимого диапазона нужен new ArrayList<>(names.subList(from, to)).

Начиная с Java 21 List наследует SequencedCollection: доступны getFirst, getLast и reversed(). Обратный список тоже является представлением. Для изменяемой основы [Ada, Lin] выражение names.reversed().set(0, "Max") заменит её последний элемент и даст [Ada, Max]. Чтение крайнего элемента пустого списка даёт NoSuchElementException. [142]

18.12.3 Изменение обратного представления

У обратного представления ArrayList первый элемент соответствует последнему элементу основы:

var codes = new ArrayList<>(List.of("s1", "s2"));
var reverse = codes.reversed();
reverse.addFirst("s3");
System.out.println(codes);   // [s1, s2, s3]
System.out.println(reverse); // [s3, s2, s1]
codes.set(0, "s9");
System.out.println(reverse); // [s3, s2, s9]
Обратное представление Соответствующее место основы
Первый элемент Последний элемент
Последний элемент Первый элемент
get(i) при размере n get(n - 1 - i)
addFirst(e) Добавление в конец
removeLast() Удаление первого элемента

Разрешённые изменения через reversed проходят в основу. Общие SequencedCollection, SequencedSet и SequencedMap задают обратный порядок; поддержка изменений зависит от реализации. Видимость изменений самой основы общий договор reversed также оставляет реализации. ArrayList и его обратное представление обращаются к текущему составу одного списка. Независимый список в обратном порядке можно получить копированием new ArrayList<>(codes.reversed()).

У SequencedMap методы firstEntry и lastEntry возвращают снимок крайнего соответствия; pollFirstEntry и pollLastEntry дополнительно удаляют его. Эти записи запрещают setValue. Они отличаются от записи, полученной во время обхода изменяемого entrySet, которая допускает поддерживаемую замену значения карты. [54], [55], [142]

18.13 Копирование состава и состояние элементов

List.of, Set.of, Map.of создают контейнеры с запрещёнными изменениями и отвергают null. Список допускает повторения; Set.of отвергает повторные элементы, Map.of — повторные ключи через IllegalArgumentException. Set.copyOf может получить коллекцию с повторами и сохранить одного представителя каждого равного значения. Порядок обхода фабричных множеств и карт не задан.

Arrays.asList(array) имеет фиксированный размер и опирается на массив: set меняет и список, и соответствующий компонент массива; add и удаление элементов не поддерживаются.

18.13.1 Общая ссылка, представление, копия и снимок

Книга course.examples.objects.Book хранит название и признак выдачи. Book("Java") создаёт доступную книгу, borrow() отмечает выдачу, borrowed() читает этот признак. Повторная выдача даёт IllegalStateException без изменения состояния. Объявление: Защищённое состояние книги.

Book book = new Book("Java");
var source = new ArrayList<>(List.of(book));
List<Book> alias = source;
var view = Collections.unmodifiableList(source);
var copy = new ArrayList<>(source);
var snapshot = List.copyOf(source);

alias содержит ту же ссылку, что source. view обращается к составу source, запрещая изменение через себя. copy и snapshot сохраняют последовательность ссылок на момент создания; дальнейшее добавление в источник на них не влияет:

source.add(new Book("Types"));
System.out.println(source.size() + " " + alias.size() + " "
    + view.size() + " " + copy.size() + " " + snapshot.size());
// 2 2 2 1 1
source, alias ──> список S: [ ──> книга Java, ──> книга Types ]
view ───────────> представление S
copy ───────────> список C: [ ──> та же книга Java ]
snapshot ───────> снимок:   [ ──> та же книга Java ]

copy.add изменит только копию. У view и snapshot запрещены добавление, удаление, замена через set, сортировка и replaceAll. В прежнем живом представлении видны разрешённые изменения самого источника. Изменение книги проходит по общим ссылкам:

book.borrow();
System.out.println(source.get(0).borrowed() + " " + view.get(0).borrowed()
    + " " + copy.get(0).borrowed() + " " + snapshot.get(0).borrowed());
// true true true true
System.out.println(snapshot.get(0) == book); // true

Во всех списках первая ссылка ведёт к одной книге. Снимок сохраняет число и порядок ссылок; состояние объекта Book меняется через его собственный метод. Для независимого состояния потребовались бы новые объекты элементов и правило копирования их внутренних связей. У записи Student компоненты String/String/int устойчивы, поэтому снимок списка таких записей сохраняет также представленные ими сведения.

Получение списка Видит последующее изменение состава источника Разрешает собственные изменения Общие элементы
alias = source Да, это тот же список Да, меняется источник Да
unmodifiableList(source) Да Нет Да
new ArrayList<>(source) Нет Да Да
List.copyOf(source) Нет Нет Да

List.copyOf может повторно использовать подходящий неизменяемый список; тождество возвращённого объекта не является требованием снимка. Источник и его элементы должны отличаться от null. Обёртка unmodifiableList допускает null-элементы, если они допустимы в основе. Контракты: List.copyOf и Collections.unmodifiableList.

Выбор между представлением и снимком определяет, какое состояние получит клиент при последующих чтениях. Если панель должна показывать текущий состав каталога при каждом чтении, живое представление сохраняет связь с владельцем данных и не требует отдельного копирования состава при выдаче. Но результат двух чтений может различаться вследствие действий владельца. Для воспроизводимого отчёта нужен состав на выбранный момент: снимок отделяет его от будущих добавлений и удалений ценой копирования ссылок в общем случае. Если сведения в элементах изменяемы, потребуется зафиксировать и их, как показал опыт с Book. Запрет add и remove у получателя отвечает только на вопрос о доступных ему действиях; устойчивость наблюдаемого состояния требует отдельного решения о связи с источником.

Защита внутреннего состава нужна и на входе. Если конструктор сохранит сам список клиента, последующий clientList.clear() изменит состояние владельца. Копирующий конструктор new ArrayList<>(clientList) создаёт самостоятельный состав; книги по его ссылкам по-прежнему общие. [73], [83]

У персистентных структур операция создаёт новую версию с сохранением прежней; версии могут разделять неизменяемые части хранения. Через живое представление доступна одна изменяемая основа. Общий интерфейс Java List не задаёт операций построения персистентных версий. Формы фабрик: Конструирование и свойства.

18.13.2 Владение составом и состоянием элементов

У конструктора и метода доступа разные границы владения. Копирование входного списка сохраняет состав владельца после clientList.clear(). Возвращаемая изменяемая копия позволяет клиенту менять собственный состав; неизменяемый снимок запрещает эти изменения. Живая оболочка Collections.unmodifiableList сохраняет связь с основой, поэтому изменение через другую ссылку видно и через оболочку. [48]

Если отчёт должен сохранить признак выдачи книги, ему нужны собственные устойчивые сведения. Запись BookState хранит название и значение флага на момент чтения:

record BookState(String title, boolean borrowed) {}
Book book = new Book("Java");
var saved = new BookState(book.title(), book.borrowed());
book.borrow();
System.out.println(book.borrowed());  // true
System.out.println(saved.borrowed()); // false

Снимок содержит String и boolean, поэтому последующее изменение исходного Book не меняет сохранённые сведения. Для более сложного элемента выбирают все данные, от которых зависит устойчивость сохраняемых сведений. Согласованность нескольких полей проверяют на сохранённой копии. Источник при этом должен оставаться стабильным во время копирования или передаваться по явно заданному протоколу синхронизации.

Передача владения без копирования требует явного обязательства клиента больше не изменять переданный объект. Тип List не выражает такое обязательство. Защитная копия закрывает путь изменения через прежнюю ссылку на состав; глубина копирования определяет, какие пути через общие элементы остаются. [83]

18.14 Дисциплина очереди

Queue выделяет голову — элемент, который должен обрабатываться следующим. FIFO выдаёт элементы по порядку поступления. У Deque доступны оба конца, поэтому FIFO получается добавлением в хвост и извлечением из головы:

Deque<String> queue = new ArrayDeque<>();
queue.addLast("Ada");
queue.addLast("Lin");
System.out.println(queue.pollFirst()); // Ada
System.out.println(queue.pollFirst()); // Lin
System.out.println(queue.pollFirst()); // null

pollFirst сообщает пустоту через null; removeFirst в этом состоянии даёт NoSuchElementException. peekFirst читает голову без удаления. ArrayDeque запрещает null-элементы, поэтому специальный результат однозначно обозначает пустоту. offer отличается от add способом сообщить об ограничении вместимости: false или IllegalStateException. Ограничение самого элемента, например запрет null, может дать исключение в обеих формах. ArrayDeque расширяет хранилище по необходимости. [140]

Стек LIFO получается при добавлении и извлечении с одного конца: push соответствует addFirst, pop — removeFirst. После push("Ada"), push("Lin") первым выйдет Lin. Такое хранение нужно вложенным незавершённым действиям, например открывающим скобкам. Для стека доступны операции Deque; старый класс Stack сохраняется в API для совместимости.

PriorityQueue определяет голову естественным порядком или компаратором: среди 30, 10 и 20 первым извлекается 10. Повторения сохраняются; при равных приоритетах выбор следующего представителя произволен. Очередь поддерживает минимум, не устанавливая отсортированный порядок всех элементов для итератора. Для последовательности по приоритету повторяют poll, который удаляет голову, или сначала копируют очередь, если исходный состав нужно сохранить. offer и poll имеют стоимость \(O(\log n)\), peek — \(O(1)\); поиск и удаление произвольного значения линейны. null запрещён. [41]

18.15 Равенство контейнеров

List.equals сравнивает размер и равенство элементов на соответствующих позициях. ArrayList и LinkedList с последовательностью [Ada, Lin] могут быть равны, несмотря на различное хранение. Перестановка в [Lin, Ada] изменяет значение списка. Для множества существенен состав, для карты — одинаковые соответствия ключей и значений.

List<String> a = new ArrayList<>(List.of("Ada", "Lin"));
List<String> b = new LinkedList<>(List.of("Ada", "Lin"));
System.out.println(a.equals(b)); // true
System.out.println(Set.of("Ada", "Lin").equals(Set.of("Lin", "Ada")));
// true

Queue и Deque не задают общего равенства последовательностей. Два разных ArrayDeque с одними элементами различаются через equals. Если задача сравнивает именно порядок наблюдаемых элементов, можно получить два списка и применить List.equals.

При проверке результата Set.equals допускает любой порядок обхода множества, а List.equals проверяет и позиции, и повторения. Результат toString предназначен для представления данных и не задаёт требуемого отношения равенства. Полные исходники опытов, импорты и команды: Полные опыты.
