4.1 Тип как модель данных

Тип определяет множество допустимых значений и операции над ними. Переменная имеет тип и хранит одно значение; выражение тоже имеет тип, по которому компилятор проверяет его использование [12], [72].

Представим журнал чтения. За два дня прочитано пять страниц; программа должна показать объём работы, среднее за день и подпись к записи. Все три результата относятся к одному событию, но над ними допустимы разные операции. Страницы можно складывать, среднее может иметь дробную часть, подпись можно соединять с другим текстом. Число 5 и строка "5" похожи на экране, однако выражения 5 + 1 и "5" + 1 дают 6 и "51". Компилятор определяет по типам операндов, какое действие означает знак +; одного вида напечатанных знаков для этого недостаточно.

int pages = 5;
String label = "5";
System.out.println(pages + 1); // 6
System.out.println(label + 1); // 51
// System.out.println(label - 1); // ошибка компиляции

Для String определена операция +, соединяющая текст; операция - к строкам неприменима. Разбор текста числа — отдельная операция: Integer.parseInt(label) возвращает int, если запись допустима. Подробный контракт разбора находится в Разбор целого числа: Integer.parseInt.

Предметный смысл — что означают данные: страницы, дни, метры или подпись. Тип — какие значения и операции доступны программе. Представление — как эти значения кодируются и обрабатываются. Тип int помогает исключить строковую подпись из умножения, но не отличает страницы от дней и допускает отрицательное количество страниц. Поэтому удачный выбор типа дополняют именами, единицами измерения и проверками предпосылок. Пользовательский класс может закрепить часть этих ограничений в конструкторе и допустимых операциях.

Java проверяет типы переменных и выражений до выполнения. Компилятор отвергнет присваивание pages = "five" из-за несовместимости типов. Присваивание pages = -5 допустимо: отрицательное число входит в диапазон int. В журнале чтения ограничение pages >= 0 выражает правило задачи, которого нет у общего целочисленного типа.

4.2 Тип выражения и значение операции

При расчёте среднего тип выражения деления определяется до присваивания результата переменной double average.

int pages = 5;
int days = 2;
double average = pages / days;
System.out.println(average); // 2.0

Компилятор сначала определяет тип pages / days: оба операнда имеют тип int, поэтому получается int. Во время выполнения вычисляется 2, затем присваивание преобразует его в 2.0. Потерянная дробная часть не восстанавливается. Чтобы получить 2.5, нужно изменить хотя бы один операнд до деления: (double) pages / days.

Сначала определяются типы подвыражений и допустимые преобразования, затем значения вычисляются по выбранным правилам. Тип переменной слева определяет, какие преобразования допустимы при присваивании результата правой части. При умножении двух int произведение также вычисляется как int; присваивание в long расширяет полученный результат, включая результат переполнения.

4.3 Примитивные типы

Примитивные типы встроены в язык. Диапазоны числовых примитивов заданы языком, поэтому переход между системами не меняет диапазон int. При этом объём памяти, который занимает переменная int или содержащий её объект, зависит от реализации JVM.

Тип Значения и назначение
byte Знаковое целое, 8 бит: от −128 до 127
short Знаковое целое, 16 бит: от −32768 до 32767
int Знаковое целое, 32 бита: от −2³¹ до 2³¹−1
long Знаковое целое, 64 бита: от −2⁶³ до 2⁶³−1
char Беззнаковое целое, 16 бит; единица UTF-16
float Числа формата IEEE 754 binary32
double Числа формата IEEE 754 binary64
boolean Только true и false

Точность чисел с плавающей точкой определяется числом двоичных разрядов значащей части. Расстояние между соседними представимыми значениями меняется с величиной числа. [12]

Для многих расчётов разумной отправной точкой служит double; для счётчика элементов — int; для большого количества или произведения — long, если его диапазон достаточен. Арифметика byte и short часто проходит через int. [80]

boolean нельзя подменить целым числом. Запись if (count) запрещена, нужно if (count != 0). Она явно называет условие, которое в C++ могло бы выражаться преобразованием числа в логическое значение, а в Python — правилами истинности объекта. char хранит одну единицу UTF-16. Кодовая точка вне основной многоязычной плоскости занимает две такие единицы. Например, у строки "AЯ🙂" три кодовые точки. Первые две занимают по одной единице UTF-16, последняя — пару. Поэтому "AЯ🙂".length() возвращает 4, а чтение одного char может дать только часть представления кодовой точки.

String text = "AЯ🙂";
System.out.println(text.length());             // 4
System.out.println((int) text.charAt(0));       // 65
System.out.println((int) text.charAt(1));       // 1071
System.out.println((int) text.charAt(2));       // 55357
System.out.println((int) text.charAt(3));       // 56898

Приведение к int позволяет напечатать числовое значение единицы UTF-16. Последние два числа вместе кодируют 🙂; отдельное число из этой пары не является кодовой точкой 🙂. Это влияет на индексы, длину и посимвольное чтение. Единица длины и индекса задана в String API. Представление текста: Глава 9.

4.4 Ограниченное представление чисел

В математике множество целых не имеет верхней границы. В программе журнал чтения может использовать int: ограниченный диапазон достаточен для количества страниц одной книги. Однако тип, вмещающий каждое входное значение, может оказаться слишком узким для промежуточного результата. Для таблицы сравнения каждой записи с каждой уже приходится умножать два допустимых счётчика.

int records = 50_000;
long wrong = records * records;
long correct = (long) records * records;
System.out.println(wrong);   // -1794967296
System.out.println(correct); // 2500000000

У произведения двух int тоже тип int. Математическое число 2 500 000 000 не помещается, а обычное умножение Java сохраняет младшие 32 бита результата; их знаковая интерпретация здесь отрицательна. Присваивание в long точно расширяет уже полученное неверное для нашей задачи число. Во втором варианте один операнд преобразован заранее, поэтому само умножение проходит в long. Переход к большему типу нужно сделать перед операцией, которой не хватает диапазона. [125]

Поведение примитивов должно оставаться одинаковым при переносе между платформами. В документе разработчиков Java 1996 года фиксированные размеры базовых типов и поведение арифметики прямо связываются с переносимостью. [25]

Если задача требует обнаружения переполнения с помощью исключения, библиотека предоставляет Math.multiplyExact. Если диапазона long недостаточно, для целочисленного расчёта есть BigInteger. Он представляет большие целые с изменяющимся объёмом данных; арифметика имеет другой API и расход ресурсов. Python int также имеет диапазон, ограниченный доступными ресурсами, поэтому одно и то же большое целочисленное произведение нельзя оценивать через правила Java int. [34]

4.4.1 Дробный результат и двоичное приближение

Тип double представляет дробные значения с ограниченной двоичной точностью. Конечное двоичное представление имеет ту же проблему, что конечная десятичная запись числа 1/3: некоторые дроби приходится приближать. Для binary64 точно представимо 0.5, но не 0.1. Поэтому результат сложения двух приближений может отличаться от приближения ожидаемого десятичного результата.

double total = 0.1 + 0.2;
System.out.println(total);        // 0.30000000000000004
System.out.println(total == 0.3); // false

При печати различаются результаты сложения двоичных приближений 0.1 и 0.2 и округления десятичного 0.3. Для измерений выбирают точность и правило сравнения с учётом масштаба и ошибки исходных данных. Для точного учёта десятичных денежных величин выбирают, например, целые минимальные единицы либо BigDecimal с явным правилом округления.

У плавающих типов есть также бесконечности и NaN. 1.0 / 0.0 даёт положительную бесконечность, 0.0 / 0.0 — NaN, а целочисленное деление на ноль вызывает ArithmeticException. NaN не равен даже себе; его проверяют через Double.isNaN. При требовании конечного среднего проверяют конечность входа и результата. Правила арифметических операций: Глава 5.

4.5 Литерал, константа и имя

Литерал прямо записывает значение: 42, 42L, 2.5, 2.5F, 'A', true. Строковый литерал "A" обозначает объект String, поэтому не совпадает по типу с 'A'. Суффикс важен: 42L задаёт long, 2.5F задаёт float, а 2.5 без суффикса имеет тип double.

long count = 3_000_000_000L;
float ratio = 0.5F;
char initial = 'J';
String name = "Java";

Подчёркивание между цифрами служит читаемости и не входит в числовое значение. В десятичном целом без L компилятор проверяет допустимость литерала типа int. Число 3_000_000_000 без суффикса будет отвергнуто и при присваивании переменной long: значение литерала превышает диапазон int.

Имя переменной объясняет предметный смысл. count, days и pages могут иметь одинаковый тип, но допускают разные действия в задаче. Тип не кодирует автоматически единицу измерения: умножение метров на секунды всё ещё может быть допустимым численным выражением.

4.6 Одномерный массив

String и массив относятся к ссылочным типам. В String title = "Java"; переменная содержит ссылку на строковый объект. Если скопировать её в savedTitle, а затем присвоить title = "Java course", через savedTitle по-прежнему доступен текст Java. Изменилась переменная, прежняя строка сохранилась. Компоненты массива изменяемы.

int[] pages = {5, 7};
System.out.println(pages.length); // 2
System.out.println(pages[0]);     // 5
pages[0] = 9;
System.out.println(pages[0]);     // 9
pages = new int[]{1, 2};
System.out.println(pages[0]);     // 1

int[] — тип массива целых; переменная этого типа хранит ссылку на массив или null. Инициализатор {5, 7} создаёт объект с двумя компонентами. pages[0] = 9 заменяет число внутри этого объекта; pages = new int[]{1, 2} создаёт другой массив и меняет ссылку переменной. Квадратные скобки выбирают компонент по индексу. Первый индекс равен 0, последний — length - 1. Поле length читается без скобок и не меняется после создания массива.

int[] zeros = new int[2];
String[] notes = new String[2];
int[] empty = new int[0];
System.out.println(zeros[0]);   // 0
System.out.println(notes[0]);   // null
System.out.println(empty.length); // 0
// System.out.println(empty[0]); // ArrayIndexOutOfBoundsException

new int[2] создаёт массив с двумя числовыми нулями; new String[2] создаёт массив с двумя ссылочными значениями null. Строковые объекты можно создать отдельно и записать ссылки на них в компоненты. Пустой массив существует и имеет длину 0, но компонента с индексом 0 у него нет. Обращение к такому индексу вызывает исключение при выполнении; само индексное выражение проходит проверку компилятора. Операции обхода и копирования: Глава 8. [119]

4.7 Инициализация и область видимости

Локальная переменная должна получить значение до чтения. Поля объектов и элементы массивов имеют начальные значения по правилам языка: числовой ноль, false или null. [45]

int pages;
// System.out.println(pages); // значение ещё не присвоено
boolean known = true;
if (known) {
    pages = 5;
} else {
    pages = 0;
}
System.out.println(pages); // 5

Компилятор анализирует пути выполнения по формальным правилам определённого присваивания и принимает чтение после ветвей, когда значение присвоено на каждом пути. Если убрать ветвь else, он не принимает последующее чтение: при ложном условии присваивание отсутствует.

Область видимости определяет, где имя обозначает данную переменную в исходнике. Для локальной переменной блока она начинается с объявления и продолжается до конца блока, включая вложенные блоки. Начальное значение вычисляется при выполнении объявления; последующий вход в тот же блок снова выполняет его инициализатор.

int total = 0;
for (int day = 0; day < 2; day++) {
    int added = 5;
    total += added;
    added = 0;
}
System.out.println(total); // 10
// System.out.println(added); // имя недоступно за блоком
// System.out.println(day);   // имя недоступно за циклом

На каждой итерации added сначала получает 5. Присваивание 0 в конце первой итерации не меняет значение, с которого начинается вторая. total объявлена снаружи и сохраняет накопленную сумму. Имя внешней локальной переменной доступно внутри цикла; объявить там ещё одну локальную total нельзя. В C++ вложенный блок допускает локальное объявление, скрывающее внешнюю переменную; Java отвергает такую повторную декларацию в пределах области видимости локальной переменной того же метода.

Завершение области видимости имени само по себе не освобождает объект. Если ссылка на созданный в блоке массив сохранена во внешней переменной, массив остаётся доступным после выхода. Переменные и объекты: Глава 10. Полные опыты со значениями и локальными переменными: Опыты с копированием, областью видимости и UTF-16.

4.8 Расширение и сужение числовых значений

При расширяющем преобразовании значение переходит к разрешённому более широкому числовому типу. Из int в long оно переходит точно. Из int в float переход разрешён, но точность может потеряться: широкий диапазон не равен способности представить каждое целое. [121]

int exact = 16_777_217;
float rounded = exact;
System.out.println((int) rounded); // 16777216

Рядом с этим числом точности float уже недостаточно, чтобы различать соседние целые. Программа компилируется, поскольку язык допускает такое преобразование. Если задаче нужен точный счётчик, его представление должно сохранять все целые значения допустимого диапазона.

Сужение обычно записывается явно. Приведение (byte) 130 оставляет младшие восемь бит и даёт -126. Чтобы отвергнуть значение за пределами диапазона byte, перед приведением проверяют условие -128 <= value && value <= 127. Приведение (int) 2.9 даёт 2: дробная часть отбрасывается в направлении нуля. Преобразование плавающего значения в int даёт 0 для NaN; слишком большое или слишком малое значение ограничивается соответствующей границей int.

Для присваивания целой константы действует исключение: byte small = 100; допустимо, потому что константное значение помещается в диапазон. Но int n = 100; byte small = n; требует приведения. Для сужения при присваивании компилятору требуется константное выражение с подходящим значением. Обычная изменяемая переменная n этому условию не удовлетворяет, даже если сейчас содержит 100.

4.9 Присваивание примитивных и ссылочных значений

Примитивная переменная хранит примитивное значение. У двух переменных после присваивания одинаковые числа, но последующее изменение одной не меняет другую. Ссылочная переменная хранит другое значение — ссылку. Копирование ссылки может сохранить доступ к одному общему изменяемому объекту.

int pages = 5;
int saved = pages;
pages = 9;
System.out.println(saved); // 5

int[] journal = {5, 7};
int[] view = journal;
view[0] = 9;
System.out.println(journal[0]); // 9

В первой части присваивание saved = pages копирует число 5. Во второй присваивание view = journal копирует ссылку на массив. Две ссылки ведут к одному объекту, и замена его первого компонента видна через обе. Если затем выполнить view = new int[]{1, 2};, изменится только значение view: journal сохранит доступ к прежнему массиву. Для независимого массива нужно отдельно создать его и перенести значения компонентов. Операции копирования и их глубина: Глава 8.

После изменения компонента общий объект выглядит так:

journal ──┐
          ├──> A: [9, 7]
view ─────┘

После view = new int[]{1, 2} переменные содержат разные ссылки:

journal ──> A: [9, 7]
view    ──> B: [1, 2]

Примитивное значение может быть полем объекта или компонентом массива, ссылка — локальной переменной или полем. Во всех этих случаях присваивание копирует значение переменной. [12]

4.9.1 Копирование в C++

У слова «ссылка» в двух языках разная роль. В C++ объявление int& alias = n создаёт другое имя для уже выбранного n. Присваивание alias = 9 меняет n; связь alias с выбранной переменной сохраняется на всё время жизни ссылки. Java-переменная int[] сама хранит значение, которое можно заменить ссылкой на другой массив. По действию копирования она ближе к переменной C++ с указателем, однако Java не предоставляет через неё арифметику адресов или ручное освобождение памяти. [134]

Для сравнения копирования контейнера используем std::array, у которого есть обычное присваивание; встроенные массивы C++ таким присваиванием не копируются.

#include <array>
std::array<int, 2> pages{5, 7};
auto copy = pages;       // отдельное значение контейнера
auto* view = &pages;     // указатель на прежний контейнер
copy[0] = 9;            // pages[0] по-прежнему 5
(*view)[0] = 11;        // pages[0] теперь 11

В Java int[] copy = pages копирует ссылку на прежний массив. Для создания отдельного массива с копиями чисел нужна операция pages.clone(). [131]

4.9.2 Дополнение: объектность и копирование в CLR

В CTS — общей системе типов .NET, поддерживаемой CLR, — различают value types и reference types. В C# int является именем System.Int32; собственную структуру тоже можно определить как value type. При обычном присваивании её значение копируется. Java предоставляет такую семантику копирования для примитивов, но экземпляры пользовательских классов остаются объектами, доступными по ссылкам. [129], [133]

Например, структура с двумя числовыми полями «прочитано» и «дней» в C# может копироваться как единое значение. Однако если её поле содержит ссылку на изменяемый список, копирование структуры копирует и эту ссылку: список остаётся общим. Структура может храниться в локальной переменной, поле объекта или элементе массива; присваивание в каждом случае копирует значения её полей.

4.9.3 Связывание имён и копирование в Python

Python показывает ещё один вариант: числовые данные являются объектами, но числа неизменяемы. В saved = pages; pages += 1 имя pages получает другой результат, а число, доступное через saved, не меняется. У списка присваивание другому имени и изменение элемента оставляют общий объект. [33]

4.10 Статический тип и его вывод

Аннотация Python pages: int = 5 описывает ожидаемые значения имени; обновление pages = 7 сохраняет это ожидание. Присваивание pages = "seven" допустимо при обычном выполнении Python, но отдельный статический анализатор Pyright в режиме strict сообщает несовместимость присваивания (reportAssignmentType). Если после него вычислить pages + 1, Python получает TypeError: операция сложения строки с числом запрещена. [33]

Тип принадлежит объекту; повторное связывание имени не меняет тип прежнего объекта. В Java int pages = 5; закрепляет тип переменной, поэтому несовместимое присваивание отвергает уже javac. Python-аннотации и средства модуля typing позволяют добавить статическую проверку к этой модели связывания имён; обычный интерпретатор не проверяет соответствие значений аннотациям. Полные файлы, выбранные версии инструментов и команды: Python-аннотация и отдельный анализатор.

Статический тип выражения определяет доступные операции при компиляции. В записи Object label = "five"; переменная имеет тип Object, а объект является строкой. Поэтому label.length() запрещён: этот метод не объявлен типом Object. Переменная label хранит ссылку на исходную строку. Связь объявленного типа, класса объекта и доступных методов: Глава 10.

В var pages = 5; компилятор выводит int из инициализатора и затем применяет те же проверки, что при явном объявлении. pages = 7 допустимо, а pages = "seven" отвергается: выведенный тип переменной остаётся int. Цель такого выведения — убрать повторение очевидного типа, сохранив статическую проверку; разработчики JEP 286 также связывают его с возможностью разбивать сложные выражения на ясные промежуточные шаги. [9]

Инициализатор null не задаёт компилятору подходящий тип для var: var text = null; запрещено. Чтобы разрешить последующее строковое значение, нужно явно объявить String text = null;. Отсутствие объекта и допустимые действия: Ссылочные значения и отсутствие.

4.11 Ссылочные значения и отсутствие

4.11.1 Состояния строковой переменной

Переменная ссылочного типа хранит ссылку на объект или null. Сравним существующий пустой текст, явно отсутствующую подпись и переменную, которой ещё не присвоили значение:

String comment = null;
String empty = "";
System.out.println(comment == null); // true
System.out.println(empty.length());  // 0
// System.out.println(comment.length()); // NullPointerException при выполнении
String pending;
// System.out.println(pending); // ошибка javac: значение не определённо присвоено

null — уже присвоенное значение, его разрешено сравнить. Оно не обозначает строковый объект, поэтому вызывать через него экземплярный метод нельзя. Длина существующей пустой строки равна 0. У pending нет значения, разрешённого для чтения: ошибку обнаруживает компилятор. Поле или компонент массива получает начальное значение по умолчанию; локальной переменной значение присваивает программа. JLS 25, §16.

Если отсутствующая подпись допустима, выберем действие до обращения к строке. if выполняет блок при истинном условии; else выбирается в другом случае:

String comment = null;
if (comment == null) {
    System.out.println("Комментарий не указан");
} else {
    System.out.println("Длина: " + comment.length());
}

При null выводится Комментарий не указан; при "" — Длина: 0; при "Java" — Длина: 4. Если журнал объединяет отсутствие с пустым комментарием, программа заменяет null на "" на границе ввода. Для int отсутствующей ссылки нет: int pages = null отвергается компилятором. Переменная числовой оболочки допускает null.

4.11.2 Примитив и его оболочка

Примитив int и класс Integer задают разные способы представления числа. Примитив непосредственно обозначает числовое значение; переменная Integer содержит ссылку на объект-оболочку или null. Оболочка связывает числовое значение со средствами, которые ожидают объект. Например, переменная типа Object может получить оболочку Integer, но не хранит примитив int как собственное объектное значение. Оболочки также позволяют хранить числовые значения в обобщённых коллекциях. Автоматическая упаковка и распаковка позволяют переходить между ними в предусмотренных контекстах. [23]

Ранняя Java уже разделяла эти два представления: описание её разработчиков сохраняет знакомый по C/C++ набор примитивов и указывает возможность заключать их в библиотечные объекты. В современной Java автоматические переходы сокращают запись, но различие значений не исчезает. У int нет экземплярных методов; у оболочки они есть, а переменная ссылочного типа допускает отсутствие объекта. [26]

Integer boxed = 5;
int primitive = boxed;
System.out.println(primitive + 1); // 6
Integer missing = null;
// int value = missing; // NullPointerException

При присваивании int primitive = boxed распаковка получает числовое значение из оболочки. Для null обращение к оболочке завершается NullPointerException. Если отсутствие допустимо по договору операции, программа проверяет его до распаковки или сохраняет как отдельный результат.

Две переменные оболочек при == обычно сравниваются как ссылки. Из-за кэширования небольших значений сравнение в одном опыте может дать истину, а в другом — ложь, хотя сравниваемые числа равны. Поэтому проверка числового равенства не должна зависеть от способа получения объекта. Используют equals с понятным правилом отсутствия либо явно работают с примитивами.

Присваивание Long n = 5; запрещено: контекст присваивания не допускает расширение примитива с последующей упаковкой в Long. В Long n = 5L; литерал имеет тип long и сразу упаковывается в Long.

4.11.3 Переменные final

final запрещает повторное присваивание переменной. Для числа это фиксирует число, для ссылки — её значение. Компоненты массива остаются отдельными переменными:

final int[] pages = {5, 7};
pages[0] = 9;
System.out.println(pages[0]); // 9
// pages = new int[]{1}; // ошибка javac: повторное присваивание final

Запись в компонент разрешена, замена ссылки запрещена. final относится к переменной pages; компоненты массива имеют собственные значения и допускают присваивание. У String неизменяемость текстового значения задана правилами класса.

4.12 Статический анализ отсутствия

Аннотация — пометка программы, которую может читать компилятор или другой инструмент. Аннотация @Nullable из библиотеки Checker Framework сообщает подключённому Nullness Checker, что параметр может получить отсутствующую ссылку. Импорт задаёт, какая именно аннотация имеется в виду; одноимённые аннотации разных библиотек требуют поддержки выбранного анализатора.

Метод length — операция класса: static позволяет вызвать её без создания экземпляра, параметр text получает переданное значение, return отдаёт число типа int. Параметр @Nullable String text допускает null, а вызов text.length() требует ссылки на строковый объект. Файл NullnessDemo.java:

import org.checkerframework.checker.nullness.qual.Nullable;

public class NullnessDemo {
    static int length(@Nullable String text) {
        return text.length();
    }
    public static void main(String[] args) {
        System.out.println(length(null));
    }
}

При наличии JAR с аннотацией обычный javac -proc:none принимает файл. При запуске возникает NullPointerException. Запуск Nullness Checker на том же исходнике отвергает обращение с диагностикой dereference.of.nullable: аннотация допускает null, а text.length() требует существующий объект. Для этого метода выберем правило «для отсутствующей строки метод возвращает 0» и заменим тело:

if (text == null) {
    return 0;
}
return text.length();

Анализатор принимает исправленный метод, и length(null) даёт 0. После возврата из первой ветви опасный путь исключён; на оставшемся пути строка существует. Для API, которое запрещает отсутствие, подошёл бы отказ вместо 0. Точные команды и зависимости для демонстрации: Java: аннотация отсутствия и анализатор. [144]. JSpecify предоставляет другую систему аннотаций; её тоже должен понимать выбранный анализатор, и совпадение названия Nullable не делает системы взаимозаменяемыми.

4.12.1 Дополнение: модели отсутствия в других языках

В C# nullable-анализ также отделён от выполнения: при включённом контексте проверки допустимости null обращение к возможному null даёт предупреждение компилятора, а оставленный в программе опасный путь всё ещё способен вызвать исключение. В JavaScript переменная после let text; содержит значение undefined; чтение того же имени до объявления в его блоке запрещено из-за временной мёртвой зоны (temporal dead zone). В Zig optional-тип ?i32 с null явно допускает отсутствие числа; undefined означает неопределённое содержимое и не служит проверяемым признаком отсутствия.

C# nullable reference types, ECMAScript: чтение binding, Zig: undefined.
