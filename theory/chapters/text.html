9.1 Значение строки и изменение переменной

Название отчёта хранится в переменной ссылочного типа String:

String title = "Java";
String saved = title;
title = title + " course";
System.out.println(title); // Java course
System.out.println(saved); // Java

Обе переменные сначала содержат ссылку на строку Java. Конкатенация получает новое строковое значение, и присваивание меняет ссылку в title. Объект, на который по-прежнему ссылается saved, не меняется:

до присваивания           после присваивания
title ─┬→ "Java"          title ───→ "Java course"
saved ─┘                  saved ───→ "Java"

Строковое значение сохраняется на всё время жизни объекта. Переменная без final может получать новые ссылки, сохраняя доступ к очередному строковому результату.

Строковые методы также возвращают результат, когда выполняют преобразование.

String name = "  Java  ";
name.strip();
System.out.println("[" + name + "]"); // [  Java  ]
name = name.strip();
System.out.println("[" + name + "]"); // [Java]

Первый вызов не меняет name: возвращённое значение проигнорировано. Второе присваивание сохраняет результат без крайних пробельных символов. Если крайних пробельных символов нет, текст результата совпадает с исходным; тождественность результата и получателя контрактом strip() не задана.

Вызов concat("") возвращает прежнюю ссылку:

String title = "Java";
System.out.println(title.concat("") == title); // true

Свойства возвращаемой ссылки определяет контракт конкретного метода. [64], [115]

Неизменяемость упрощает совместное использование: после передачи строки методу её содержимое сохраняется. Присваивание другой ссылки параметру изменяет только переменную текущего вызова. Правило передачи аргументов: Глава 7.

9.2 Равенство ссылок и текста

Две разные строки могут содержать одинаковый текст. == сравнивает ссылочные значения, а equals для String сравнивает последовательность единиц UTF-16.

String literal = "Java";
String separate = new String("Java");
System.out.println(literal == separate);      // false
System.out.println(literal.equals(separate)); // true

new создаёт отдельный объект, поэтому == даёт false при одинаковом содержимом строк. Для литералов и некоторых константных строковых выражений действует интернирование, поэтому "Ja" + "va" == "Java" истинно. Сравнение содержимого через equals даёт один результат для одинакового текста независимо от способа создания объектов.

Вызов text.equals("Java") требует ссылки text, отличной от null. Для проверки на заданную строку удобен вызов "Java".equals(text), который при null даёт false; для двух допускающих отсутствие значений есть Objects.equals. Отсутствие и пустой текст различаются: null означает отсутствие объекта, "" — строку длины ноль. isEmpty() проверяет нулевую длину. Если пробельное содержимое также считается пустым по требованиям, isBlank() проверяет пустую строку или строку из пробельных кодовых точек.

Регистр, нормализация и языковой порядок сравнения задают отдельные отношения между строками. Общие свойства равенства объектов: Глава 17.

9.3 Индексы UTF-16 и кодовые точки

Unicode задаёт кодовые точки, а UTF-16 кодирует их одной или двумя 16-битными единицами. char хранит одну такую единицу. Кодовые точки основной многоязычной плоскости, кроме диапазона суррогатов, занимают один char; для дополнительных плоскостей нужна суррогатная пара.

String text = "A\uD83D\uDE00B"; // A😀B
System.out.println(text.length()); // 4
System.out.println(text.codePointCount(0, text.length())); // 3
System.out.println(text.codePointAt(1)); // 128512

Сопоставим индексы и значения кодовых единиц:

индекс:    0       1       2       3
UTF-16: [0041]  [D83D]  [DE00]  [0042]
точки:  U+0041  └─ U+1F600 ──┘  U+0042

Буквы A и B занимают по одной единице, 😀 — суррогатную пару. Поэтому длина 4 не означает четыре воспринимаемых символа. charAt(1) отдаёт первую половину пары; самостоятельно эта единица не является кодовой точкой всего знака. [108], [115]

При обходе по кодовым точкам индекс увеличивают на число единиц текущей точки:

for (int offset = 0; offset < text.length(); ) {
    int codePoint = text.codePointAt(offset);
    System.out.println(codePoint);
    offset += Character.charCount(codePoint);
}

Вывод — 65, 128512, 66; позиции меняются как 0 → 1 → 3 → 4. Индекс по-прежнему измерен в единицах UTF-16, но шаг составляет один или два. Цикл offset++ прочитал бы половины пары отдельно. Вызов substring(1, 2) оставит одну половину пары. Для получения одной кодовой точки от позиции 1 конец вычисляется так:

int end = text.offsetByCodePoints(1, 1); // 3
System.out.println(text.substring(1, end)); // 😀

String допускает и непарные суррогатные единицы. При обходе codePointAt возвращает значение такой единицы, а codePointCount считает её отдельно. Поэтому подсчёт кодовых точек сам по себе не проверяет корректность последовательности UTF-16.

Буква с комбинируемым ударением или последовательность эмодзи может включать несколько кодовых точек и восприниматься как один знак. Для курсора, обрезки пользовательского текста и подсчёта видимых знаков нужен анализ границ текстовых элементов. Единица длины входит в договор операции: байты, единицы UTF-16, кодовые точки или воспринимаемые текстовые элементы.

9.4 Модель UTF-16

Unicode начинался с 16-битной модели; расширение набора кодовых точек потребовало в UTF-16 суррогатных пар. Поэтому один char хранит одну кодовую единицу, а для части кодовых точек требуется пара. [137]

Java сохраняет UTF-16 как модель длины и индексации String. Реализация может менять внутреннее представление, соблюдая контракт length(), charAt() и остальных операций. [115]

9.5 Подстроки

Метод substring(begin, end) выбирает диапазон [begin, end): начало включено, конец исключён. Для "Java" границы выглядят так:

границы: 0   1   2   3   4
         | J | a | v | a |
             └───────┘
               [1, 3)

"Java".substring(1, 3) даёт "av". Допустимы 0 <= begin && begin <= end && end <= length(). При равных границах получается пустая строка; выход за диапазон вызывает IndexOutOfBoundsException. Длина результата в единицах UTF-16 равна end - begin. Одноаргументный substring(begin) выбирает остаток строки, поэтому "Java".substring(4) тоже даёт "". [115]

Поиск indexOf возвращает индекс первого совпадения или -1. Отрицательный результат нужно проверять, прежде чем использовать его как границу подстроки.

String record = "pages=16";
int separator = record.indexOf('=');
if (separator >= 0) {
    System.out.println(record.substring(separator + 1)); // 16
}

9.6 Замена и разбиение текста

Метод replace ищет буквальное содержимое. Метод replaceAll читает первый аргумент как регулярное выражение — описание множества подходящих фрагментов. Поэтому одинаковая строка "." задаёт разные действия:

System.out.println("a.b".replace(".", "-"));    // a-b
System.out.println("a.b".replaceAll(".", "-")); // ---

В шаблоне точка соответствует одному символу, кроме распознаваемых шаблоном разделителей строк при стандартных флагах. В данном вводе ей соответствует каждая из трёх позиций. Буквальная замена находит единственную точку между a и b. [114]

Аналогично split принимает регулярное выражение. Для разделения по точке нужно экранирование, например split("\\."). Кроме того, split(regex) по умолчанию отбрасывает хвостовые пустые элементы; "a,,".split(",", -1) сохраняет три поля. Если данные содержат пустые столбцы, потеря этих полей меняет смысл записи. Справочник Глава 7 даёт сигнатуры и границы отдельных операций.

Строка замены в replaceAll тоже имеет синтаксис: $1 обращается к первой захваченной группе. Если искомый текст и замена поступили как буквальные данные, их можно передать replace. При работе через Pattern экранируются обе части по правилам каждого аргумента:

String literal = ".";
String replacement = "$1";
var pattern = java.util.regex.Pattern.compile(
    java.util.regex.Pattern.quote(literal));
String result = pattern.matcher("a.b").replaceAll(
    java.util.regex.Matcher.quoteReplacement(replacement));
System.out.println(result); // a$1b

Pattern.quote сохраняет точку как искомый текст. quoteReplacement сохраняет $1 как два знака результата. Полное совпадение строки, поиск следующего фрагмента и состояние Matcher: Регулярные выражения: полное совпадение и поиск. [110], [114]

9.7 Вставка текста

Длина length() и индекс charAt измеряют единицы UTF-16; в ограниченном алфавите задания каждая буква занимает одну единицу. Файл с текстом хранит байты, и кодировка UTF-8 может отвести той же букве несколько байтов.

Вставка в строку не меняет исходный объект. Метод insertAt имеет следующий договор: параметры text и fragment должны обозначать существующие строки, позиция допускается от 0 до text.length() включительно. substring(begin, end) получает диапазон с включённым началом и исключённым концом; substring(begin) — остаток строки. Знак + соединяет строковые значения.

static String insertAt(String text, int position, String fragment) {
    if (position < 0 || position > text.length()) {
        throw new IndexOutOfBoundsException("position: " + position);
    }
    return text.substring(0, position) + fragment + text.substring(position);
}

// В main:
String title = "Java";
System.out.println(insertAt(title, 2, "-")); // Ja-va
System.out.println(title);                 // Java
System.out.println(insertAt(title, 0, "-")); // -Java
System.out.println(insertAt(title, 4, "-")); // Java-

В позиции 2 взяты Ja и va; между ними добавлен фрагмент. Позиция 0 даёт пустую левую часть, позиция 4 — пустую правую. Для пустой исходной строки допустима единственная позиция 0; пустой фрагмент сохраняет текстовое значение. Позиция 5 для Java отвергается до получения результата. Через null нельзя прочитать длину; этот метод не определяет вставку отсутствующего текста. Предпосылка «существующая строка» является частью договора метода, а допустимость позиции проверяет его тело.

9.8 Границы слова

Обработка слов зависит от правила, определяющего их границы. Для алфавита латинских и русских букв Java2\tкод! содержит слова Java и код: цифра, табуляция и ! — разделители. Обработка должна находить границы в исходной строке прежде, чем менять её длину. Разбиение по одному пробелу оставило бы цифру внутри слова и не увидело табуляцию. Регулярное \b использует собственное определение границы; заданный алфавит выражается проверкой символа или шаблоном диапазонов букв. Формы поиска по шаблону: Границы слова в заданном алфавите.

9.8.1 Построение результата по исходным границам

Метод markWords заключает каждое слово в квадратные скобки, сохраняя разделители. Вспомогательный метод isWordLetter распознаёт латинские и русские буквы, включая Ё и ё.

Оба метода объявлены в одном классе. Параметр text должен обозначать существующую строку; слово состоит только из букв указанного алфавита.

static boolean isWordLetter(char c) {
    return c >= 'A' && c <= 'Z' || c >= 'a' && c <= 'z'
        || c >= 'А' && c <= 'Я' || c >= 'а' && c <= 'я'
        || c == 'Ё' || c == 'ё';
}

static String markWords(String text) {
    StringBuilder result = new StringBuilder();
    int cursor = 0;
    while (cursor < text.length()) {
        if (!isWordLetter(text.charAt(cursor))) {
            result.append(text.charAt(cursor));
            cursor++;
        } else {
            int start = cursor;
            while (cursor < text.length()
                    && isWordLetter(text.charAt(cursor))) {
                cursor++;
            }
            result.append('[');
            result.append(text, start, cursor);
            result.append(']');
        }
    }
    return result.toString();
}

Для "Java2\tкод!" результат — "[Java]2\t[код]!", для "123!" — "123!", для "" — "". В этих записях \t обозначает одну табуляцию. StringBuilder — изменяемый накопитель: append добавляет к нему фрагмент, а toString получает готовое строковое значение. Вызов append(text, start, cursor) переносит исходный диапазон [start, cursor).

Перед каждой итерацией префикс до cursor уже обработан. Ветка разделителя переносит ровно одну единицу; ветка слова сначала находит его конец и только потом дописывает результат. Вставленные скобки не меняют индексов text и не участвуют в повторном поиске. Это свойство сохраняется и для преобразования, которое меняет длину каждого слова. Если менять саму обрабатываемую строку на каждом шаге, придётся заново согласовывать исходные и новые координаты.

9.9 Дополнение: нормализация и регистр

Одинаково выглядящий текст может иметь разные последовательности кодовых точек.

String first = "\u00E9";   // é, одна кодовая точка
String second = "e\u0301"; // e и комбинируемое ударение
System.out.println(first.equals(second)); // false

equals точно сравнивает содержимое и не выполняет нормализацию. Если приложение считает канонически эквивалентные формы одинаковыми, можно явно привести обе к выбранной форме.

String normalized = java.text.Normalizer.normalize(
    second, java.text.Normalizer.Form.NFC);
System.out.println(first.equals(normalized)); // true

Форма нормализации определяет, какие последовательности считаются эквивалентными. Формы нормализации с совместимостью устраняют дополнительные различия, которые могут быть значимы для приложения. Формат идентификатора или внешнего протокола должен задавать допустимую форму нормализации. [112]

Преобразование регистра тоже зависит от языка. Вызовы toLowerCase() и toUpperCase() без аргумента используют текущую локаль. Для независимых от языка технических обозначений часто явно выбирают Locale.ROOT; для пользовательского текста выбирают согласованную локаль. Такие преобразования не всегда сохраняют длину. equalsIgnoreCase не является полной языковой сортировкой; порядок слов по правилам языка требует других средств, например Collator.

9.9.1 Каноническая форма и правило поиска

Каноническая нормализация объединяет способы записи одной буквы: "ё" и "е\u0308" приводятся NFC к одинаковому значению. Буквы "е" и "ё" после NFC остаются различными: диакритический знак сохраняется. То же относится к "и" и "й".

Поиск, который должен объединять разные буквы или игнорировать регистр, задаёт дополнительное отношение эквивалентности. Например, для технического названия с правилом «краевые пробелы и регистр несущественны» ключом служит name.strip().toLowerCase(java.util.Locale.ROOT). Исходное название остаётся доступным для показа, ключ — для сравнения. Одинаковое преобразование применяется к искомому значению и к каждому кандидату.

Границы слов определяются выбранным алфавитом. Совпадение ключей целых слов и совпадение подстроки дают разные результаты: поиск слова "код" не включает слово "кодекс". Если преобразование меняет длину, позиции совпадения в ключе не могут непосредственно служить индексами исходного текста. Для сохранения разделителей сначала выделяются диапазоны в исходном тексте, затем сравниваются значения извлечённых слов.

9.10 Текст числа и числовое значение

Разбор переводит текстовую запись числа в числовое значение по правилам выбранного формата. Метод Integer.parseInt получает десятичную запись целого в допустимом диапазоне и возвращает int.

String input = "16";
int pages = Integer.parseInt(input);
System.out.println(pages + 1); // 17
System.out.println(input + 1); // 161

Число не сохраняет оформление: Integer.parseInt("0016") даёт 16, и последующее преобразование обратно в строку не восстанавливает ведущие нули. Для номера документа они могут быть значимыми, поэтому не всякая последовательность цифр должна храниться числом.

parseInt(" 16 ") не убирает пробелы автоматически, а parseInt("16.5") не выбирает округление дроби. Оба случая дают NumberFormatException. Если формат задачи допускает внешние пробелы, их можно убрать до разбора; если допускает дробь, нужно другое правило и тип.

Для локализованного числа вроде "16,5" недостаточно заменить один символ во всех возможных строках: в языке ввода могут существовать разделители групп и другие соглашения. Форматирование и разбор пользовательских чисел выбирают с учётом локали. Машинный формат, напротив, обычно задаёт фиксированное правило, которое не меняется с настройками компьютера.

9.11 Построение текста через StringBuilder

Повторная конкатенация накопленного результата в цикле логически создаёт последовательность новых строковых значений. На больших данных это может многократно переносить уже собранный текст. Для последовательного построения используется изменяемый StringBuilder. [42], [116]

int[] pages = {5, 7, 4};
StringBuilder builder = new StringBuilder();
for (int i = 0; i < pages.length; i++) {
    if (i > 0) builder.append(", ");
    builder.append(pages[i]);
}
String result = builder.toString();
System.out.println(result); // 5, 7, 4

append меняет накопитель. toString получает строковый результат, который сохраняется после последующих изменений накопителя:

builder.append(", 9");
System.out.println(builder); // 5, 7, 4, 9
System.out.println(result);  // 5, 7, 4

Здесь изменение ограничено этапом построения: один метод собирает текст в своём накопителе, затем передаёт наружу String. Получатель может хранить эту строку и передавать ссылку на неё дальше: её содержимое остаётся прежним у всех получателей. Неизменяемость сокращает число возможных состояний общего объекта; при последовательном наращивании большого текста та же модель требует получать новые значения. Пара StringBuilder–String разделяет эти задачи: изменяемое рабочее состояние и стабильный результат. [53]

Если сам накопитель передать нескольким участникам, изменение снова станет общим: одной замены класса недостаточно для сохранности данных. Ёмкость и длина накопителя различаются: длина измеряет содержимое, ёмкость — запас для роста. Предварительная ёмкость может снизить число перераспределений при накоплении текста в цикле; слишком большой запас занимает память, которая может не понадобиться для результата.

9.12 Строка и байты внешнего текста

Файл или сетевое сообщение содержит байты. Для получения строки нужна кодировка; при обратном преобразовании она снова должна быть выбрана явно.

byte[] bytes = "Я".getBytes(java.nio.charset.StandardCharsets.UTF_8);
System.out.println(bytes.length); // 2
String restored = new String(bytes,
    java.nio.charset.StandardCharsets.UTF_8);
System.out.println(restored); // Я

Два байта UTF-8 представляют одну кодовую точку, которая в этой строке занимает одну единицу UTF-16. Чтение тех же байтов по другой кодировке может дать другой текст: декодер сопоставляет байтам значения по правилам выбранной кодировки.

Политика кодирования и декодирования определяет реакцию на недопустимые последовательности: замену или отказ. Кодер и декодер позволяют задать эту политику явно: Глава 23.

9.13 Границы текстового алгоритма

У строковой операции входной диапазон и диапазон результата могут различаться. В markWords индекс cursor продвигается только по text; накопитель принимает дополнительные скобки и имеет собственную длину. Для исходной строки "я, код" второе слово начинается с индекса 3, а в результате "[я], [код]" — с индекса 6. В исходной строке второй индекс указывает уже на границу после слова.

Алфавит устанавливает допустимую единицу обработки. У латинских и русских букв без составных сочетаний индекс char совпадает с номером буквы при нумерации от нуля. У A😀B для третьей кодовой точки нужен индекс UTF-16 3. При чтении байтов дополнительно задаётся кодировка; нормализация уже полученного текста не восстанавливает байты, потерянные при неверном декодировании.
