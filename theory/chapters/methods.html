7.1 Декомпозиция и договор операции

Метод объединяет действия, выполняющие одну операцию. В журнале одна операция получает данные, другая вычисляет среднее, третья формирует текст. Их разделение позволяет изменить источник ввода, сохранив расчёт, либо изменить подпись, не меняя числовые правила. Имя и параметры метода должны объяснять именно эту самостоятельную операцию.

Для average(pages, days) договор включает больше, чем возвращаемый double. Количество страниц неотрицательно, дней больше нуля, результат выражается в страницах за день. Сигнатура гарантирует числовые типы, но не кодирует все эти ограничения. Проверка в теле отвергает недопустимый вход, а примеры допустимых и недопустимых данных позволяют проверить реализацию договора.

Если метод читает консоль, сам выбирает вход и сразу печатает результат, проверить расчёт для другого набора сложнее. Параметры передают известные данные, возвращаемое значение позволяет сравнить результат или использовать его дальше. [61]

При возвращении результата вызывающий код может проверить average(5, 2) сравнением с 2.5, затем использовать это же число в отчёте. Ввод и вывод за пределами метода сохраняют для каждого такого вызова явно заданные данные.

7.2 Объявление метода

Метод average класса Reading объединяет проверку входа и вычисление среднего. Вызывающий код получает результат и самостоятельно выбирает действие с ним:

static double average(int pages, int days) {
    if (pages < 0 || days <= 0) {
        throw new IllegalArgumentException("Недопустимые данные о чтении");
    }
    return (double) pages / days;
}

double описывает возвращаемый результат, average — имя, int pages и int days — формальные параметры. Тело метода задаёт действия для каждого вызова. Модификатор static означает операцию класса: ей не нужен отдельный объект Reading. Метод average использует свои параметры и возвращает число. Состояние объектов и методы экземпляра: Глава 11.

double first = average(5, 2);
double second = average(7, 2);
System.out.println(first + " " + second); // 2.5 3.5

Каждый вызов создаёт собственные переменные параметров: в первом pages получает 5, во втором — 7. Если вызвать average(5, 0), метод завершается исключением до деления и обычное значение вызова не получается.

7.3 Параметр, аргумент и результат

Параметр — переменная в объявлении метода. Аргумент — выражение, указанное в вызове; его значение передаётся параметру. Результат — значение выражения вызова, если метод завершается нормальным return с результатом.

int totalPages = 5;
int activeDays = 2;
double result = average(totalPages + 2, activeDays);
System.out.println(result); // 3.5

Сначала вычисляется totalPages + 2, получается 7; затем читается activeDays, получается 2. Значения инициализируют pages и days. Метод возвращает 3.5, которое присваивается result. Вычисление аргумента не меняет исходный totalPages: сумма вычислена отдельно.

Аргументы вычисляются слева направо. Если первый аргумент порождает исключение, второй не вычисляется и тело метода не начинается. Поэтому вызов с побочными действиями в нескольких аргументах требует внимательного чтения. Удобнее сначала получить данные отдельными выражениями, а затем вызвать расчёт: это облегчает и проверку значений, и локализацию отказа.

Метод с результатом должен обеспечивать подходящий результат на каждом пути нормального завершения. Недостаточно написать return только внутри одного условного случая. Метод с void не производит значения для присваивания, но может выполнять действия: печатать, менять объект или отправлять данные. Простой return; в таком методе завершает его досрочно.

В модели JVM каждый вызов получает отдельный кадр со своими локальными переменными, включая параметры. Ссылка в параметре может вести к тому же массиву, что и ссылка в кадре вызывающего метода. Запись через любую из этих ссылок меняет общий массив. Локальные переменные кадра: Модель выполнения байткода.

7.4 Копирование примитивного значения

Увеличение числа страниц в вызывающем коде требует изменения его переменной. Присваивание параметру действует только внутри вызова:

static void addPage(int pages) {
    pages++;
}

// В main:
int pages = 5;
addPage(pages);
System.out.println(pages); // 5

При вызове параметр получает 5. Увеличение меняет параметр на 6, но локальная переменная pages в main остаётся другой переменной со значением 5. После завершения вызова параметр прекращает существование.

Следующее значение метод может вернуть вызывающему коду.

static int nextPageCount(int pages) {
    return Math.addExact(pages, 1);
}

pages = nextPageCount(pages);
System.out.println(pages); // 6

Теперь метод возвращает новое число, а вызывающий код явно присваивает его своей переменной. Параметр C++ типа int& может непосредственно обозначать переменную вызывающего кода. В Java такой формы параметра нет; перенос решения требует выбрать результат или объектное состояние.

7.5 Копирование ссылки и общий объект

Переменная int[] хранит ссылку на объект массива. При вызове метода значение этой ссылки присваивается новой переменной параметра. Массив при этом не копируется: две переменные дают доступ к одному объекту. Запись в компонент изменяет общий массив; присваивание параметру меняет ссылку только в переменной этого вызова.

Методу correctFirst требуется существующий непустой массив. Его объявление:

static void correctFirst(int[] data) {
    data[0] = 9;
}

Вызов с массивом [5, 7]:

int[] pages = {5, 7};
correctFirst(pages);
System.out.println(pages[0]); // 9

В начале вызова переменная pages вызывающего метода и параметр data находятся в разных кадрах. Обозначение A на схеме именует общий объект массива:

кадр main                  кадр correctFirst
pages ─────────┐           data ────────┐
               └───────────┬────────────┘
                           v
                       A: [5, 7]

Запись data[0] = 9 проходит по ссылке к объекту A и меняет его первый компонент. Ссылочные значения обеих переменных сохраняются. После возврата параметр data завершает существование, но pages продолжает вести к массиву [9, 7]. Поэтому чтение pages[0] даёт 9.

Второй метод получает тот же массив после исправления:

static void replace(int[] data) {
    data = new int[]{1, 2};
}

// В main после correctFirst:
replace(pages);
System.out.println(pages[0]);     // 9
System.out.println(pages.length); // 2

При входе data снова получает ссылку на A. Затем создаётся массив B, а присваивание записывает новую ссылку в переменную параметра:

кадр main                  кадр replace
pages ──> A: [9, 7]         data ──> B: [1, 2]

Переменная pages в другом кадре не участвует в этом присваивании. После возврата она сохраняет ссылку на A; массив B ей не возвращён. [62], [116]

Параметр C++ int*& связывается с переменной-указателем вызывающего кода и позволяет заменить хранящийся в ней указатель. В Java data является самостоятельной переменной со скопированным ссылочным значением. Замена ссылки в вызывающем коде выражается возвратом новой ссылки и присваиванием результата его переменной. Python-функция с изменяемым списком даёт похожую пару наблюдений: изменение общего списка видно снаружи, а новое связывание локального параметра не заменяет внешнее имя. [141]

Параметр можно объявить final int[] data. Тогда присваивание data = new int[]{1, 2} запрещено при компиляции, а data[0] = 9 разрешено: место записи находится внутри массива. final фиксирует значение параметра, через которое массив доступен.

7.6 Побочные эффекты и условия метода

Метод correctFirst принимает существующий массив хотя бы с одним компонентом. Вызов с null завершится NullPointerException при обращении к компоненту, а с пустым массивом — ArrayIndexOutOfBoundsException. Договор операции указывает, какие из этих случаев допустимы и какое поведение требуется для каждого допустимого входа.

correctFirst имеет побочный эффект: меняет состояние общего массива. Вычисляющий метод average возвращает результат без изменения массива или полей. Когда вызывающему коду нужна сохранность исходных данных, это различие входит в договор операции. Побочный эффект может быть именно желаемым действием, например исправлением записи в журнале; тогда место изменения должно быть понятно пользователю метода.

Отделение расчёта от вывода позволяет использовать результат в разных контекстах. Если average печатает сообщение при каждом вызове, построение отчёта или автоматическая проверка вынуждены учитывать этот вывод. Возвращаемое число оставляет выбор представления вызывающему коду.

7.7 Перегрузка и выбор при компиляции

Перегрузка позволяет дать одно имя методам с разными списками типов параметров. Для методов без параметров типа сигнатуру составляют имя и типы параметров; возвращаемый тип не позволяет создать отдельную перегрузку.

static String kind(int value) { return "int"; }
static String kind(long value) { return "long"; }

System.out.println(kind(5));  // int
System.out.println(kind(5L)); // long

Выбор зависит от типов аргументов, известных компилятору. Если оставить только kind(long), вызов с 5 допустим за счёт расширения int в long. Но kind(byte) не принимает переменную int без явного сужения, даже если текущее значение равно 5: правила вызова не равны всем правилам присваивания констант. [122], [125]

Нельзя добавить второй kind(int) только с другим результатом, например int вместо String: возвращаемый тип не входит в сигнатуру метода. При разрешении перегрузки компилятор учитывает преобразования аргументов, обобщения и переменное число аргументов.

7.8 Возвращаемая ссылка и независимый результат

Правило копирования значения действует и при возврате. Первый метод отдаёт уже существующий массив, второй создаёт новый результат из первых двух компонентов; для второго требуется не менее двух компонентов:

static int[] same(int[] values) {
    return values;
}
static int[] firstTwo(int[] values) {
    return new int[]{values[0], values[1]};
}

// В main:
int[] source = {5, 7};
same(source)[0] = 9;
System.out.println(source[0]); // 9
int[] result = firstTwo(source);
result[0] = 100;
System.out.println(source[0]); // 9
System.out.println(result[0]); // 100

same(source) и source дают ссылку на один объект. firstTwo создаёт новый массив и копирует два числа, поэтому последующая запись меняет только результат. Тип результата в обоих случаях int[]; отличие задаёт тело операции. Для firstTwo(null) возникает NullPointerException, для входа длины меньше двух — ошибка границы до успешного возврата.

Метод clone создаёт новый массив и копирует значения всех компонентов. Для ссылочных компонентов сохраняются ссылки на прежние объекты. Возвращая внутренний массив напрямую, класс предоставляет вызывающему коду возможность менять его компоненты. Глубина копирования: Копирование массива.

7.9 Массив для переменного числа аргументов

Последний параметр можно объявить с переменным числом аргументов.

static long sum(int... values) {
    long result = 0;
    for (int value : values) {
        result += value;
    }
    return result;
}

System.out.println(sum());       // 0
System.out.println(sum(5, 7));   // 12
System.out.println(sum(new int[]{5, 7})); // 12

В теле values имеет тип int[]. Для отдельных аргументов вызов формирует массив; существующий массив можно передать непосредственно. Параметр получает копию ссылки, через которую метод может читать и изменять компоненты общего массива. Метод sum требует ссылку, отличную от null: в вызове sum((int[]) null) попытка обхода завершится NullPointerException.

Формы объявлений и ограничения: Глава 5. Полные программы с вызовами: Полные примеры.

7.10 Простой рекурсивный вызов

Метод может вызывать себя. Для неотрицательного числа сеансов определим обратный отсчёт; значение 0 завершает работу:

static void countDown(int sessions) {
    if (sessions == 0) {
        return;
    }
    System.out.println(sessions);
    countDown(sessions - 1);
}

// В main:
countDown(3);

Вывод — 3, 2, 1. Первый вызов получает 3, печатает его и создаёт вызов с параметром 2; затем возникают вызовы с 1 и 0. Последний возвращается без печати. После него завершается вызов с 1, затем с 2, затем с 3; их параметры не были одной общей переменной. Если начать с 0, вывода нет. Для неотрицательного входа каждый следующий вызов уменьшает положительное значение на единицу до достижения нуля. Отрицательное число нарушает предусловие операции; это доказательство продвижения к нулю на него не распространяется.

Продвижение к базовому случаю обосновывает конечность алгоритма. Каждый рекурсивный вызов требует собственного кадра; доступная глубина ограничена ресурсами. Java не гарантирует устранение хвостовых вызовов. Цикл позволяет выполнить большой отсчёт без роста числа вложенных вызовов.

7.11 Разделение расчёта и изменения данных

Предположим, к каждому дневному результату нужно добавить поправку. Операция может изменить переданный массив либо вернуть новый. Это два разных договора, даже если после вызова на экране видны одинаковые числа. Когда исходный журнал нужно сохранить, самостоятельный результат делает требование явным.

static int[] withBonus(int[] pages, int bonus) {
    int[] result = new int[pages.length];
    for (int i = 0; i < pages.length; i++) {
        result[i] = Math.addExact(pages[i], bonus);
    }
    return result;
}

Входная ссылка должна отличаться от null. Для {5, 7} и поправки 1 возвращается {6, 8}, исходный массив остаётся {5, 7}. Метод читает существующие компоненты и записывает новые. Если сумма для одного из элементов не помещается в int, обычный результат не возвращается, а исходные данные сохранены. Недописанный новый массив не передан вызывающему коду. Если тот же алгоритм писал бы непосредственно в исходный массив, отказ на позднем компоненте мог оставить часть массива уже изменённой. Локальный массив результата обеспечивает сохранность исходных данных как при успешном вычислении, так и при отказе.

Такое разделение имеет цену: одновременно существуют исходный массив и новый массив той же длины. При большом журнале дополнительная память может быть существенна. Если массив принадлежит одному вычислению и прежние числа больше никому не нужны, изменение на месте позволяет обойтись без второго массива. Тогда договор должен определить состояние после неудачи. Например, отдельный проход может сначала проверить все суммы и лишь затем изменить компоненты. Он требует повторного чтения и сохраняет смысл только при условии, что между проверкой и записью вход никто не меняет.
