15.1 Контейнер с типом Object

Поле типа Object может хранить ссылку на строку, упакованное число или другой объект. Такой контейнер принимает и возвращает Object:

final class ObjectBox {
    private final Object value;
    ObjectBox(Object value) { this.value = value; }
    Object get() { return value; }
}

Клиент, которому нужна длина строки, восстанавливает строковый тип приведением:

ObjectBox box = new ObjectBox("Java");
String text = (String) box.get();
System.out.println(text.length()); // 4

Тип выражения box.get() определяется объявлением метода. Компилятор видит Object, хотя конструктору была передана строка. Приведение проверяет совместимость возвращённой ссылки со String при выполнении. Успешная проверка сохраняет ссылку на ту же строку.

Заменим только аргумент конструктора:

ObjectBox box = new ObjectBox(25);
String text = (String) box.get(); // ClassCastException

Конструктор по-прежнему принимает значение: 25 упаковывается в Integer, который совместим с Object. При чтении проверка приведения обнаруживает Integer вместо строки. Объявление ObjectBox допускает обе записи и не связывает тип содержимого с типом, нужным клиенту. [75]

15.2 Параметр типа

Обобщённое объявление содержит параметры типов: имена, которые связывают типы полей, параметров и результатов методов. При использовании объявления выбираются аргументы типов. В Java параметры типов объявляют классы, интерфейсы, методы и конструкторы [17], [74].

Связь содержимого и результата выражается одним параметром T:

final class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
}

Поле принимает значение параметра конструктора, а get() возвращает значение поля. Все три позиции обозначены одним T. Поэтому при использовании Box<String> конструктор принимает String, а результат get() имеет статический тип String:

Box<String> title = new Box<>("Java");
String text = title.get();

Box<Integer> edition = new Box<>(25);
int number = edition.get();

Box — обобщённый класс, Box<String> — параметризованный тип. Второй вызов использует ссылочный аргумент Integer: литерал 25 упаковывается при передаче, результат распаковывается при присваивании переменной int. Аргументом обобщённого типа может быть ссылочный тип; запись Box<int> запрещена. [18], [24], [56], [76]

Запись <>, называемая diamond, поручает компилятору вывести аргументы создаваемого класса. При выводе компилятор учитывает аргументы конструктора и целевой тип выражения. Следующее создание коробки отвергается при компиляции:

Box<String> title = new Box<>(25); // ошибка компиляции

Слева требуется Box<String>, справа конструктор должен принять Integer. Нельзя выбрать аргумент типа, удовлетворяющий обоим требованиям. У ObjectBox несогласованность обнаруживало приведение клиента; у Box<String> проверка конструктора останавливает её до создания коробки.

Параметризация описывает семейство применений одного определения — параметрический полиморфизм. Она сочетается с полиморфизмом подтипов: Box<Number> принимает Integer и Double, потому что оба типа совместимы с Number. Результат get() через такую ссылку имеет тип Number, даже когда в коробке хранится экземпляр одного из его подклассов.

15.2.1 Общий объект в контейнере

Параметр T не меняет правила передачи значения. Конструктор копирует ссылку. Книга и коробка остаются разными объектами, а содержимое коробки и переменная клиента могут указывать на одну книгу:

final class Book { boolean borrowed; }

Book book = new Book();
Box<Book> stored = new Box<>(book);
book.borrowed = true;
System.out.println(stored.get().borrowed); // true
System.out.println(stored.get() == book);  // true
book ──────────────────────────> Book { borrowed = true }
stored ──> Box { value ─────────> тот же Book }

final относится к полю value: его ссылку после конструирования заменить нельзя. Поле borrowed принадлежит книге и остаётся изменяемым. Тип результата Book разрешает клиенту обратиться к нему после get().

Конструктор также принимает null, поскольку это допустимое значение ссылочного типа:

Box<String> missing = new Box<>(null);
System.out.println(missing.get() == null); // true
// missing.get().length();                // NullPointerException

Требование содержимого, отличного от null, можно обеспечить вызовом Objects.requireNonNull(value) при записи значения в поле. У приведённого Box такой проверки нет. В Box<Integer> сохранённый null также допустим, но его распаковка в int завершается NullPointerException.

15.2.2 Параметризация необязательного результата

Для поиска, который может закончиться без совпадения, подходит Optional<String>. Его аргумент задаёт тип найденного значения. Отсутствие совпадения выражается существующим пустым контейнером:

java.util.Optional<String> found = java.util.Optional.of("Java");
java.util.Optional<String> missing = java.util.Optional.empty();
System.out.println(found.orElse("not found"));   // Java
System.out.println(missing.orElse("not found")); // not found

orElse возвращает вложенную строку либо указанный результат пустого случая. of требует значения, отличного от null; ofNullable(null) создаёт пустой контейнер. Вызов get() у пустого контейнера бросает NoSuchElementException. У самой переменной ссылочного типа может быть значение null, однако договор метода, возвращающего Optional, предписывает возвращать существующий контейнер. [123]

Пустой Optional обозначает отсутствие значения. Если результат должен различать отсутствие, неоднозначность и отказ, эти исходы получают собственные представления: Глава 14.6.1.

15.2.3 Независимые параметры типов

Два параметра позволяют выбирать типы частей независимо. Запись record объявляет класс с компонентами, конструктором и методами чтения:

record Entry<K, V>(K key, V value) {}

Entry<String, Integer> result = new Entry<>("passed", 12);
String key = result.key();
int value = result.value();

K связывает аргумент ключа с результатом key(), V — аргумент значения с результатом value(). Допустим и Entry<String, String>: независимость разрешает выбрать совпадающие типы. Если обе части всегда должны иметь один согласованный тип, их обозначают одним параметром. [77]

Зависимость между двумя параметрами можно выразить границей: class Related<A, B extends A>. В Related<Number, Integer> аргумент Integer подходит к границе Number. Обратная пара Related<Integer, Number> отвергается. Для параметра после extends разрешён как класс или интерфейс, так и другой параметр типа.

15.3 Обобщённый метод

Собственный параметр метода записывается перед возвращаемым типом:

static <U> U identity(U value) {
    return value;
}

Вызов String word = identity("Java") связывает U со строковым типом. При Book book = new Book() вызов Book same = identity(book) возвращает ту же ссылку на книгу: same == book истинно. Выбор U относится к вызову метода. У Box.get() собственных параметров типа нет: используемый T объявлен классом и определяется типом ссылки на коробку. [22], [57]

Статическая фабрика связывает принимаемое значение с создаваемой коробкой:

final class Boxes {
    static <T> Box<T> of(T value) {
        return new Box<>(value);
    }
}

Box<String> title = Boxes.of("Java");
Box<Number> amount = Boxes.<Number>of(25);
Number value = amount.get();
System.out.println(value.getClass().getSimpleName()); // Integer

В первом вызове аргумент типа выводится. Во втором он записан явно перед именем метода: <Number>. Выражение amount.get() имеет статический тип Number и возвращает ссылку на упакованный Integer. Вызов getClass() относится к хранимому объекту: по его классу нельзя установить, был ли аргументом коробки Number, Integer или Object.

В статическом члене Box<T> параметр класса использовать запрещено: static T value недопустим. Статическое поле принадлежало бы общему классу Box, и у него не было бы аргумента отдельной параметризации. Статический метод вправе объявить свой параметр, как Boxes.of. Параметры могут иметь и конструкторы; их параметры действуют в пределах конструктора независимо от параметров создаваемого класса.

15.3.1 Вывод аргументов типа

При выводе компилятор ищет аргументы типов, удовлетворяющие всем требованиям. Они определяются границами объявления, типами аргументов вызова и, где применимо, целевым типом результата:

Box<String> first = new Box<>(null); // Box<String>
var second = new Box<>(null);        // Box<Object>
var third = new Box<String>(null);   // Box<String>
Box<String> fourth = Boxes.of("Java");

У first левая часть требует Box<String>. У second тип переменной выводится из инициализатора: контекст со String отсутствует, значение null подходит любому ссылочному типу, и получается Box<Object>. У third аргумент задан прямо. Во всех трёх коробках хранится null, поэтому различие статических типов следует именно из объявлений.

После вывода тип переменной сохраняется:

third = new Box<>("Java"); // допустимо для Box<String>
// third = new Box<>(25);  // несовместимый аргумент конструктора

Использование одного T для нескольких параметров метода требует общего согласованного типа. Фактические классы аргументов могут различаться: и Integer, и Double подходят явно выбранному Number. Более точный разбор влияния границы на результат: Глава 16.4.

15.3.2 Перестановка элементов

Параметр метода может связывать только вход и локальные значения:

static <T> void swap(T[] values, int i, int j) {
    T saved = values[i];
    values[i] = values[j];
    values[j] = saved;
}

String[] names = {"Ada", "Lin"};
swap(names, 0, 1);
System.out.println(names[0]); // Lin

Метод сохраняет ссылку первого элемента до перезаписи позиции и затем возвращает её в другую позицию. Сами элементы не сравниваются, поэтому дополнительной границы у T нет. void означает отсутствие возвращаемого значения; метод остаётся обобщённым.

Массив должен существовать, оба индекса должны быть допустимы. При совпадении индексов содержимое сохраняется. Все записываемые значения прочитаны из того же массива, поэтому подходят его фактическому типу компонента. Границы индексов параметр T не выражает.

15.4 Границы параметра типа

Без явной границы параметр имеет верхнюю границу Object. Компилятор проверяет операции по ней: value.toString() допустим, вызов value.doubleValue() требует числовой границы. Граница ограничивает выбор аргумента и одновременно даёт телу доступ к нужным членам:

static <T extends Number> double twice(T value) {
    return 2.0 * value.doubleValue();
}

При twice(3) число упаковывается в Integer; doubleValue() даёт 3.0, умножение — 6.0. Ссылка должна отличаться от null. Аргументом типа может служить сам Number или его подтип. Строковый аргумент отвергается до выполнения. [78]

В этой сигнатуре T встречается только у входа: результат всегда double. Для того же вычисления достаточно параметра Number value. Именованный параметр становится необходимым, когда его тип должен связывать несколько позиций, например аргумент и возвращаемое значение.

Number предоставляет числовые преобразования. Он не объявляет сложение с результатом того же вида числа, а произвольный T extends Number не распаковывается в один заранее определённый примитивный тип. Выражение value + value поэтому запрещено. Преобразование большого целого в double может потерять точность; замена арифметики вызовами doubleValue() меняет смысл числового вычисления. [141]

15.4.1 Сравнение значений

Интерфейс Comparable<T> задаёт int compareTo(T other). Знак результата определяет отношение получателя к аргументу: отрицательный — меньше, ноль — эквивалентен в выбранном порядке, положительный — больше. Результат не ограничен числами -1, 0, 1:

System.out.println("Ada".compareTo("Lin"));   // -11
System.out.println("Java".compareTo("Java")); // 0
System.out.println("Lin".compareTo("Ada") > 0); // true

String сравнивает единицы UTF-16 до первого различия. У A значение 65, у L — 76: разность равна -11. При совпавшем начале раньше идёт более короткая строка. Правила упорядочения слов конкретного языка задаются отдельно. Правило сравнения строк: String.compareTo и знак порядка.

Для выбора большего объекта требуется доступ к этому методу:

static <T extends Comparable<T>> T larger(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}

String left = new String("Java");
String right = new String("Java");
System.out.println(larger("Ada", "Lin")); // Lin
System.out.println(larger(left, right) == left); // true

Граница разрешает сравнение двух T, а результат метода сохраняет T. При равенстве выбирается левый объект: проверка == подтверждает сохранение именно его ссылки. Оба аргумента должны отличаться от null. Сравнение должно задавать согласованный порядок, включая транзитивность; одного наличия метода с результатом int для корректного поиска недостаточно. [36]

Если наследник сравнивается методом базового класса, подходит граница Comparable<? super T>: Глава 16.4. Полный договор порядка: Глава 15. Для нескольких требований служит пересечение границ, например <T extends Number & Comparable<T>>. Класс ставится первым, последующие границы должны быть интерфейсами.

15.5 Операции списка

List<E> — интерфейс последовательности с доступом по индексу. ArrayList<E> — изменяемая реализация. Оба типа находятся в java.util:

List<Integer> values = new ArrayList<>();
values.add(1);
values.add(2);
System.out.println(values.size()); // 2
System.out.println(values.get(0)); // 1
System.out.println(values);        // [1, 2]

add дописывает элемент, size() возвращает их количество, isEmpty() проверяет пустоту. Для get(i) требуется 0 <= i < size(). При размере 2 индекс 2 уже за пределами списка. У массива размер читают из поля length.

List.of(1, 2) создаёт готовый список, состав которого нельзя изменить; передача null этой фабрике вызывает отказ. Пустой List.of() имеет размер 0. Возможность выполнить add или set определяется реализацией списка и рассматривается вместе с типом добавляемого элемента. [112]

Устройство коллекций: Глава 18.1. Массив и расширяемый список: Глава 18.5. Формы операций: Основные операции.

15.6 Поиск максимума

Для непустого списка начальным кандидатом служит его первый элемент. Ноль не является универсальным кандидатом: он может превосходить все отрицательные числа, а для строки числовой ноль вообще не подходит. Следующий элемент заменяет кандидата только при строгом увеличении:

static <T extends Comparable<T>> T maximum(List<T> values) {
    if (values.isEmpty()) {
        throw new IllegalArgumentException("Empty list");
    }
    T best = values.get(0);
    for (int i = 1; i < values.size(); i++) {
        T value = values.get(i);
        if (value.compareTo(best) > 0) {
            best = value;
        }
    }
    return best;
}

System.out.println(maximum(List.of(4, 9, 2))); // 9

Перед каждой итерацией best указывает на первый из максимальных элементов уже просмотренной части списка. Изначально эта часть содержит один элемент. Если очередной value больше кандидата, он становится новым максимумом; иначе прежний кандидат сохраняется. После просмотра всего списка это свойство даёт результат всего поиска. Строгое > 0 сохраняет первый из равных максимумов.

[4] 4
[4, 9] 9
[4, 9, 2] 9

Метод возвращает ссылку на элемент списка и не меняет его состав. Предполагаются список и элементы, отличные от null, и согласованный порядок. Пустота проверяется отдельно, потому что у пустого списка нет первого элемента. При одном элементе цикл не выполняется.

Операций сравнения ровно n - 1 для непустого списка размера n. Время обхода зависит также от get(i): у ArrayList чтение по индексу занимает постоянное время, у связного списка повторный поиск позиции может привести к квадратичному времени обхода. Общий тип List<T> описывает операции и их результаты; для оценки стоимости нужна реализация.

Граница Comparable<T> подходит Integer и String. Сохранение типа наследника с унаследованным сравнением разобрано в Глава 16.4.

15.7 Контракт арифметических операций

Сумма попарных произведений двух векторов равной длины имеет вид

\[ \operatorname{dot}(a,b)=\sum_{i=0}^{n-1}a_i b_i. \]

Для действительных входов [1, 2] и [3, 4] результат равен 11. Для комплексных чисел используется билинейная сумма без сопряжения. Эрмитово скалярное произведение дополнительно сопрягает одну из сторон, поэтому требует другой операции и другого договора вычисления.

Тип элементов должен сохраняться при накоплении. Объект арифметики предоставляет начальное значение, сложение и умножение с согласованным типом:

interface Arithmetic<T> {
    T zero();
    T add(T left, T right);
    T multiply(T left, T right);
}

T выражает замкнутость операций по типу. Математический договор требует нейтрального начального значения для сложения и соответствующего смысла add и multiply. В данном вычислении списки, элементы, объект арифметики и результаты операций должны быть отличны от null; операции сохраняют входные элементы. Эти условия позволяют передавать промежуточный результат в следующее действие, сохраняя входы.

static <T> T dot(List<T> left, List<T> right, Arithmetic<T> arithmetic) {
    if (left.size() != right.size()) {
        throw new IllegalArgumentException("Different vector lengths");
    }
    T result = arithmetic.zero();
    for (int i = 0; i < left.size(); i++) {
        T term = arithmetic.multiply(left.get(i), right.get(i));
        result = arithmetic.add(result, term);
    }
    return result;
}

Равенство длин проверяется до обращения к арифметике. При разных длинах последний элемент длинного вектора не имеет пары. После i шагов накоплен результат первых i произведений в заданном порядке. У пустых векторов произведений нет, возвращается zero().

Реализация для Double использует распаковку и операции double:

final class DoubleArithmetic implements Arithmetic<Double> {
    public Double zero() { return 0.0; }
    public Double add(Double a, Double b) { return a + b; }
    public Double multiply(Double a, Double b) { return a * b; }
}

double value = dot(List.of(1.0, 2.0), List.of(3.0, 4.0),
                   new DoubleArithmetic());
System.out.println(value); // 11.0

Накопление проходит 0.0 → 3.0 → 11.0. Эти значения представимы точно. В общем случае операции double округляются, а перестановка или перегруппировка слагаемых может изменить результат. Этот цикл задаёт накопление слева направо; он не использует предположение об ассоциативности машинного сложения.

Другой объект арифметики сохраняет сигнатуры, но задаёт иное начальное значение:

final class WrongZeroArithmetic implements Arithmetic<Double> {
    public Double zero() { return 1.0; }
    public Double add(Double a, Double b) { return a + b; }
    public Double multiply(Double a, Double b) { return a * b; }
}

System.out.println(dot(List.of(1.0, 2.0), List.of(3.0, 4.0),
                       new WrongZeroArithmetic())); // 12.0

Последовательность 1.0 → 4.0 → 12.0 содержит лишнюю единицу. Компилятор проверил совместимость аргументов и результатов Double. Нейтральность начального значения из этих типов не следует: она нарушена реализацией zero(). Для пустых входов тот же объект сразу вернёт 1.0.

Комплексный тип хранит действительную и мнимую части; арифметика создаёт новые значения по обычным формулам:

record Complex(double re, double im) {}

final class ComplexArithmetic implements Arithmetic<Complex> {
    public Complex zero() { return new Complex(0.0, 0.0); }
    public Complex add(Complex a, Complex b) {
        return new Complex(a.re() + b.re(), a.im() + b.im());
    }
    public Complex multiply(Complex a, Complex b) {
        return new Complex(a.re() * b.re() - a.im() * b.im(),
                           a.re() * b.im() + a.im() * b.re());
    }
}

Complex value = dot(
    List.of(new Complex(1, 1), new Complex(2, 0)),
    List.of(new Complex(3, 0), new Complex(4, -1)),
    new ComplexArithmetic());
System.out.println(value); // Complex[re=11.0, im=1.0]

Произведения равны 3+3i и 8−2i, сумма — 11+i. Один и тот же dot использует объявленные операции при каждом шаге. Компоненты комплексного числа объявлены в записи Complex, а формулы операций находятся в ComplexArithmetic.

15.8 Модели обобщённого вычисления

В Java тело dot проверяется по объявлению Arithmetic<T>; объект, реализующий этот интерфейс, предоставляет нужные операции. Можно устроить обобщение иначе: потребовать допустимость выражений над выбранным типом, связать операции со статическими членами интерфейса или находить операции у фактических объектов при выполнении. Во всех вариантах сумма произведений вычисляется над теми же данными, без комплексного сопряжения.

15.8.1 Шаблоны C++

Параметр шаблона C++ входит в зависимые выражения общего определения. Зависимые операции шаблона проверяются с учётом подставляемого типа; тело обобщённого метода Java опирается на объявленные границы. Поэтому шаблон может использовать + и *, если эти выражения допустимы для конкретного аргумента. Концепты позволяют явно описать проверяемые требования к подстановке. [30]

template<class T>
concept DotElement = std::semiregular<T> && requires(const T a, const T b) {
    T{};
    { a + b } -> std::same_as<T>;
    { a * b } -> std::same_as<T>;
};
template<DotElement T>
T dot(const std::vector<T>& left, const std::vector<T>& right) {
    if (left.size() != right.size()) {
        throw std::invalid_argument("Different vector lengths");
    }
    T result{};
    for (std::size_t i = 0; i < left.size(); ++i) {
        result = result + left[i] * right[i];
    }
    return result;
}

std::semiregular<T> добавляет требования к созданию, копированию и присваиванию значений, которые использует тело функции. Выражения проверяются для константных операндов, потому что функция читает векторы через const-ссылки; результат каждой операции должен иметь тип T, чтобы его можно было передать следующей операции. В этом варианте требуется также, чтобы T{} обозначал нейтральный элемент сложения. Сам requires проверяет допустимость выражения, но не его математическое значение. Для примеров с double и std::complex<double> выбранная начальная величина подходит.

Вызовы имеют одну форму:

auto real = dot(std::vector<double>{1.0, 2.0},
                std::vector<double>{3.0, 4.0});

using C = std::complex<double>;
auto complex = dot(std::vector<C>{{1.0, 1.0}, {2.0, 0.0}},
                   std::vector<C>{{3.0, 0.0}, {4.0, -1.0}});

Этот вариант использует C++20. Вычисление с действительными числами даёт 11, с комплексными — (11,1), то есть \(11+i\). Java вызывает add и multiply у переданного Arithmetic; C++ записывает a+b и a*b и проверяет зависимые выражения с учётом подстановки. Полные примеры и команды: C++20: требования к выражениям и длине.

Размер можно выразить отдельным параметром, аргумент которого является значением. Следующий короткий вариант также рассчитан на C++20 и уже определённый DotElement:

template<DotElement T, std::size_t N>
T dot(const std::array<T, N>& left, const std::array<T, N>& right) {
    T result{};
    for (std::size_t i = 0; i < N; ++i) {
        result = result + left[i] * right[i];
    }
    return result;
}

У std::array<double, 2> аргумент double — тип, а 2 — значение. Два массива длины 2 дают 11; вызов с длинами 2 и 3 не позволяет вывести единый N и отвергается при компиляции. У показанного ранее C++ vector размеры, как и в Java List<T>, проверялись при выполнении. У std::array длина входит в тип и участвует в выводе аргумента N. У vector и List<T> размер является свойством объекта, доступным при выполнении; Java-параметр T задаёт тип элемента. [31]

15.8.2 Обобщения C#

CLR, среда выполнения .NET, сохраняет аргументы обобщённых типов. List<int> и List<string> являются различными построенными типами; аргументами могут служить ссылочные типы и типы значений. Например, typeof(List<int>) == typeof(List<string>) даёт false: typeof получает описание типа времени выполнения. Среда может использовать общий машинный код для нескольких подстановок ссылочных типов, сохраняя сведения о каждом построенном типе. [35]

Начиная с C# 11 и .NET 7 нужные операции можно выразить через интерфейсы со статическими абстрактными членами. Для нашего алгоритма достаточно требований сложения, умножения и наличия нейтрального элемента:

static T Dot<T>(IReadOnlyList<T> left, IReadOnlyList<T> right)
    where T : IAdditionOperators<T, T, T>,
              IMultiplyOperators<T, T, T>,
              IAdditiveIdentity<T, T>
{
    if (left.Count != right.Count)
        throw new ArgumentException("Different vector lengths");

    T result = T.AdditiveIdentity;
    for (int i = 0; i < left.Count; i++)
        result += left[i] * right[i];
    return result;
}

IReadOnlyList<T> предоставляет чтение по индексу и число элементов Count. Ограничения where T перечисляют интерфейсы пространства имён System.Numerics: они разрешают +, * и обращение к статическому T.AdditiveIdentity при проверке тела метода. Для комплексных чисел достаточно этих операций; отношение «больше» алгоритм не использует. [34]

Вызовы с double и System.Numerics.Complex сохраняют прежние данные:

var real = Dot(new double[] { 1, 2 }, new double[] { 3, 4 });
var complex = Dot(new Complex[] { new(1, 1), new(2, 0) },
                  new Complex[] { new(3, 0), new(4, -1) });

В C# var выводит локальный тип из инициализатора: у real это double, у complex — Complex. Вызовы дают 11 и комплексное значение с действительной частью 11 и мнимой частью 1.

15.8.3 Динамический полиморфизм Python

Функция Python использует начальное значение 0, операторы + и *:

def dot(left, right):
    if len(left) != len(right):
        raise ValueError("Different vector lengths")
    result = 0
    for a, b in zip(left, right):
        result = result + a * b
    return result

print(dot([1.0, 2.0], [3.0, 4.0]))          # 11.0
print(dot([1 + 1j, 2 + 0j], [3 + 0j, 4 - 1j]))  # (11+1j)

При каждом выполнении a * b Python использует операции фактических объектов. У float получается действительное произведение, у complex — комплексное; прибавление к начальному целому нулю подходит обоим случаям. Функция работает с двумя типами без объявления параметра типа или отдельного класса арифметики. Для двух пустых последовательностей она возвращает целое 0: ни одно произведение ещё не определило другой вид результата.

zip перебирает пары и останавливается на более коротком входе. Предварительная проверка длины нужна, чтобы в сумму вошли все элементы обоих векторов. Сумма попарных произведений вычисляется без комплексного сопряжения.

При строковом элементе числовая операция становится недопустимой:

dot(["3"], [4.0])  # TypeError при умножении строки на float

Обычный интерпретатор обнаруживает несовместимость при выполнении умножения. Аннотации задают анализатору допустимые типы аргументов и результата функции:

from collections.abc import Sequence

Number = float | complex

def dot(left: Sequence[Number], right: Sequence[Number]) -> Number:
    if len(left) != len(right):
        raise ValueError("Different vector lengths")
    result: Number = 0
    for a, b in zip(left, right):
        result = result + a * b
    return result

Здесь Sequence описывает доступ к длине и элементам, а float | complex — допустимые числовые типы. Правила статической типизации Python допускают int там, где ожидается float, поэтому начальный 0 тоже подходит. Такая сигнатура допускает смешение действительных и комплексных значений; тип ответа описан тем же набором. Для вызова с действительными аргументами анализатор также получает результат float | complex. Связь результата с конкретным типом аргументов задаётся параметром типа. [45]

Анализатор типов, например Pyright, теперь может отвергнуть вызов dot(["3"], [4.0]). Если запустить его обычным Python, аннотации не выполнят эту проверку: программа снова дойдёт до неподходящей операции и получит TypeError. Форма float | complex доступна с Python 3.10. [37] Команды и отдельные файлы обычного и аннотированного вариантов: Python: запуск и проверка аннотаций.

15.8.3.1 Структурный контракт операций

Если способ вычисления нужно выбирать отдельно от самих чисел, полезен уже знакомый объект операций. Например, при изучении алгоритма можно подсчитывать выполненные умножения: объект делает обычное умножение float и увеличивает свой счётчик. Цикл и числовые входы остаются прежними. Объект операций предоставляет начальное значение, сложение и умножение. Protocol описывает для анализатора структуру такого объекта и связь типов его методов:

from collections.abc import Sequence
from typing import Protocol

class Arithmetic[T](Protocol):
    def zero(self) -> T: ...
    def add(self, a: T, b: T) -> T: ...
    def multiply(self, a: T, b: T) -> T: ...

def dot[T](left: Sequence[T], right: Sequence[T],
           arithmetic: Arithmetic[T]) -> T:
    if len(left) != len(right):
        raise ValueError("Different vector lengths")
    result = arithmetic.zero()
    for a, b in zip(left, right):
        result = arithmetic.add(result, arithmetic.multiply(a, b))
    return result

Protocol задаёт требуемые методы для статической проверки. Объявление параметра T в квадратных скобках доступно с Python 3.12. Вызов теперь связывает тип элементов, результатов операций и ответа; для пустого входа начальное значение тоже поставляет выбранная арифметика.

class FloatArithmetic:
    def __init__(self) -> None:
        self.multiplications = 0

    def zero(self) -> float: return 0.0
    def add(self, a: float, b: float) -> float: return a + b
    def multiply(self, a: float, b: float) -> float:
        self.multiplications += 1
        return a * b

arithmetic = FloatArithmetic()
print(dot([1.0, 2.0], [3.0, 4.0], arithmetic))  # 11.0
print(arithmetic.multiplications)              # 2

Для двух пар элементов метод multiply вызван дважды. Счётчик принадлежит переданному объекту, поэтому клиент может прочитать его после dot. Числовые элементы остались обычными float, а объект, выполняющий операции, сохранил свой счётчик.

FloatArithmetic не наследует Arithmetic: анализатор принимает его по структуре трёх методов. Для той же роли Java требовала явное implements Arithmetic<Double>. Если zero() объявить возвращающим str, объект уже не подходит к Arithmetic[float]; отдельный отрицательный пример доступен по Переданные операции и Protocol. Интерпретатор по-прежнему выполняет доступные операции без автоматической проверки аннотаций. [40]

C++ requires проверяет выражения; Java ? extends и ? super описывают отношение неизвестного аргумента типа к другим типам. В первой функции Python операции выбираются при выполнении; аннотации позволяют отдельно проверить допустимость числовых входов. В варианте с переданными операциями Protocol описывает структуру объекта без требования наследования. Обычный интерпретатор вызывает операции фактических объектов; несовместимая операция обнаруживается при выполнении.

Равенство длин остаётся условием выполнения во всех показанных версиях с динамическими последовательностями. Только вариант C++ с std::array<T, N> включил длину в тип. Во всех четырёх языках начальное значение должно быть нейтральным элементом сложения; начальная единица добавила бы к сумме лишнее слагаемое.

Выбор способа предоставления операций влияет и на развитие вычисления. В показанном варианте C++ операции выбираются по числовому типу, а Java получает их отдельным аргументом. Объект Arithmetic<T> можно заменить, сохранив класс чисел и тело dot: например, задать другую согласованную арифметику для того же представления или вести учёт вызовов. В Python такой учёт уже находится в объекте FloatArithmetic. Цена отдельного объекта — дополнительный участник договора: вызывающий код должен выбрать его и обеспечить смысловую согласованность операций. Если у типа один естественный набор операций, непосредственная запись через операторы делает вызов короче. Передать объект операций можно и в C++; сопоставление показывает разные способы организации одного алгоритма.

15.9 Согласование источников и операций

В сигнатуре суммы произведений один T связывает два источника и принимающий их значения объект арифметики:

static <T> T dot(List<T> left, List<T> right, Arithmetic<T> ops)
left.get(i): T ──┐
                ├──> multiply(T, T): T ──> add(T, T): T
right.get(i): T ─┘                          ↑
                                      result: T

При T = Complex произведение имеет тип Complex и подходит следующему сложению. Замена обоих списков на List<?> оставляет тип элементов каждого списка неизвестным и не задаёт связи между ними. Чтение тогда предоставляет только Object, который нельзя передать в multiply(T, T). [21]

Источник можно описать гибче, сохранив связь с арифметикой: List<? extends T>. Из такого списка читается значение, пригодное как T. Для объекта Arithmetic<T> параметр остаётся точным: он и принимает, и возвращает T. Смысл верхней границы и правила записи разобраны в Глава 16.2.

Совместимость типов не включает длину векторов: два List<Double> могут содержать разное число элементов. Проверка длины обеспечивает наличие каждой пары. Нейтральность zero() задаётся смыслом арифметики: реализация с началом 1.0 удовлетворяет сигнатуре, но добавляет единицу.
