14.1 Обычный класс для представления значения

Пусть точка имеет две целочисленные координаты. При сравнении сначала надо установить, что второй аргумент является точкой. В методе equals эту проверку выполняет образец типа (type pattern) other instanceof PointClass p: если other обозначает экземпляр PointClass, проверка успешна, а переменная p содержит ссылку на этот же объект с типом PointClass. Для другого класса и для null проверка даёт false. [14]

Выражение справа от && выполняется только при успешной левой проверке. Именно там компилятор разрешает использовать p, поскольку уже известно, что образец совпал. Так можно прочитать координаты второго объекта без отдельного приведения. Координаты устанавливаются конструктором и затем доступны для чтения:

final class PointClass {
    private final int x;
    private final int y;

    PointClass(int x, int y) {
        this.x = x;
        this.y = y;
    }

    int x() { return x; }
    int y() { return y; }

    @Override public boolean equals(Object other) {
        return other instanceof PointClass p && x == p.x && y == p.y;
    }

    @Override public int hashCode() {
        return java.util.Objects.hash(x, y);
    }

    @Override public String toString() {
        return "PointClass[x=" + x + ", y=" + y + "]";
    }
}

Вызовы new PointClass(2, 3).equals("2, 3") и new PointClass(2, 3).equals(null) возвращают false: после несовпадения образца правая часть && не выполняется. Переменную p нельзя использовать в месте, где успешность совпадения не установлена; область её допустимого использования зависит от ветвей выполнения.

Два самостоятельных экземпляра с координатами (2, 3) не тождественны по ==, но равны по реализованному equals. Равным значениям должен соответствовать одинаковый хеш; обратное не обязательно. Эти правила нужны, чтобы значение могло быть ключом хешированной коллекции. Обычный Object.equals сравнивает тождество объектов; сравнение координат задаёт показанное переопределение. Равенство и порядок: Глава 17. [108]

В C++20 сравнение членов можно получить объявлением bool operator==(const PointClass&) const = default;; неявный копирующий конструктор такой точки копирует значения её целочисленных членов. В Java equals также может сравнивать координаты, но присваивание переменной копирует ссылку. Декоратор Python @dataclass также создаёт методы для данных. По умолчанию его поля изменяемы; frozen=True запрещает обычное присваивание полям. У записи Java компонентные поля всегда final. [140], [148], [149]

14.2 Компоненты и стандартные члены записи

Запись (record) — класс, состояние которого задано компонентами в заголовке объявления. Каждый компонент имеет имя и тип; из этого описания язык предоставляет конструктор, методы чтения и стандартные операции равенства, хеширования и строкового представления [75].

record Point(int x, int y) {}

Point a = new Point(2, 3);
Point b = new Point(2, 3);
System.out.println(a.x());      // 2
System.out.println(a.equals(b)); // true
System.out.println(a == b);      // false
System.out.println(a);           // Point[x=2, y=3]

В заголовке перечислены компоненты. Для каждого создаётся закрытое final-поле и открытый метод чтения с тем же именем. Канонический конструктор принимает компоненты в порядке объявления. Если методы equals, hashCode и toString не объявлены явно, язык предоставляет их реализации на основе компонентов. Равенство требует одного и того же типа записи и равных соответствующих значений; классы Point и ScreenPoint с одинаковыми числами не становятся равными автоматически. [75]

Запись неявно финальна и непосредственно расширяет java.lang.Record. Она не может выбрать другой суперкласс, но может реализовать интерфейсы. Дополнительные поля экземпляра запрещены: состояние экземпляра описано компонентами. Допустимы методы, статические поля и вложенные объявления. Например, int sum() { return x + y; } вычисляет сумму координат, сохраняя состав компонентов. Вложенная запись неявно static; локальную запись можно объявить внутри метода. Она не захватывает локальные переменные окружающего метода: нужные данные передают её конструктору.

14.2.1 Представление записи и её API

Обычный класс может скрывать представление: клиент читает available(), не зная, хранится ли число свободных мест отдельно или вычисляется из двух полей. У записи представление связано с её API. Заголовок Point объявляет два компонента, которые участвуют в создании, чтении, равенстве и представлении объекта. Изменение состава хранимых данных затрагивает этот API.

Добавление третьего компонента меняет форму канонического конструктора, добавляет метод чтения и изменяет состав данных для равенства и хеша. Клиент зависит от этого состава. В JEP 395 записи предложены как прозрачные носители данных; ограничение представления позволяет выводить стандартный API из заголовка. Одна из целей предложения — сохранить номинальную типизацию. Имя Point отличает координату от другой пары целых чисел, даже когда их компоненты имеют одинаковые типы. [1]

Записи доступны с Java 16. Point остаётся ссылочным типом:

Point first = new Point(2, 3);
Point same = first;
System.out.println(same == first); // true

Присваивание не создаёт новую точку. Для другого значения создают новый объект, например new Point(first.x() + 1, first.y()). [135]

14.2.2 Запись как реализация интерфейса

Интерфейс Counted предоставляет чтение количества. Изменяемая обёртка CountingSender увеличивает свой счётчик после нормального завершения отправки; её устройство описано в Глава 13.6. Ту же операцию может реализовать запись со снимком числа:

interface Counted { int count(); }
record DispatchStats(int count) implements Counted {}

Метод чтения count(), полученный из компонента, уже удовлетворяет интерфейсу. После двух отправок и снятия снимка выполняется ещё одна:

CountingSender sender = new CountingSender(new RecordingSender());
sender.send("A");
sender.send("B");
DispatchStats saved = new DispatchStats(sender.count());
sender.send("C");
System.out.println(sender.count()); // 3
System.out.println(saved.count());  // 2

В запись скопировано число 2. Поле счётчика отправителя и компонент снимка принадлежат разным объектам. Клиент, которому нужна только операция count(), может принять любой из них через Counted. Объявленный тип Counted не определяет, изменится ли результат между вызовами: это свойство конкретного участника и его операций.

14.2.3 Равенство компонентов

Стандартный equals сначала требует тот же тип записи. Для ссылочных компонентов он учитывает null: два отсутствующих значения равны, ровно одно отсутствующее — нет; два существующих объекта сравниваются их equals. Поэтому два Point с координатами (2, 3) равны, а Point и другая запись ScreenPoint(int x, int y) остаются разными типами значений.

Для примитивных компонентов действует сравнение, соответствующее compare класса-обёртки. У int оно совпадает с обычным сравнением чисел. У double два NaN в компонентах считаются равными, а +0.0 и -0.0 — различными. Эти правила согласованы со стандартным hashCode записи. Равные записи имеют равный хеш; разные значения могут иметь одинаковый хеш.

toString() включает имя записи и имена компонентов. Представление Point[x=2, y=3] удобно при выводе состояния. Долговременный формат файла задаётся отдельно: точная пунктуация toString и численное значение хеша не являются устойчивым протоколом обмена. [93]

14.3 Проверка и нормализация в каноническом конструкторе

Для интервала начальная граница не должна превышать конечную. Компактный канонический конструктор проверяет параметры без повторения их списка и присваивания каждого поля:

record Interval(int start, int end) {
    Interval {
        if (start > end) {
            throw new IllegalArgumentException("Начало превышает конец");
        }
    }

    boolean contains(int value) {
        return start <= value && value <= end;
    }
}

new Interval(2, 5).contains(4) возвращает true, а new Interval(5, 2) завершается исключением до получения готового значения. После нормального окончания тела компактного конструктора параметры автоматически присваиваются соответствующим полям. В теле можно нормализовать параметр, а прямое присваивание компонентному полю там запрещено.

record BookCode(String value) {
    BookCode {
        value = java.util.Objects.requireNonNull(value).strip();
        if (value.isEmpty()) {
            throw new IllegalArgumentException("Пустой код");
        }
    }
}
System.out.println(new BookCode("  A-17  ").value()); // A-17

В поле попадёт нормализованный параметр. В обычной форме канонического конструктора явно повторяются типы, порядок и имена компонентов; тело должно присвоить каждое компонентное поле. Компактная форма оставляет эти присваивания языку. Дополнительный конструктор с другим списком аргументов в конечном счёте делегирует каноническому. Например, в тело Interval можно добавить:

Interval(int point) {
    this(point, point);
}

new Interval(2) создаёт интервал [2, 2]; проверка порядка границ выполняется в том же каноническом конструкторе. Канонический конструктор не может объявлять throws, быть обобщённым или делегировать другому конструктору. Его доступность должна быть не меньше доступности самой записи. Точные формы: Записи.

14.3.1 Запись участника учебного журнала

В учебном журнале участник имеет код, имя и целый балл от 0 до 100. Строковый формат использует ; как разделитель и одну физическую строку на участника. Поэтому после удаления краевых пробельных символов код и имя должны оставаться непустыми и не содержать ;, CR или LF. Тип grade.Student закрепляет эти ограничения при создании:

package grade;

import java.util.Objects;

public record Student(String id, String name, int score) {
    public Student {
        Objects.requireNonNull(id);
        Objects.requireNonNull(name);
        id = id.strip();
        name = name.strip();
        if (id.isEmpty() || name.isEmpty()
                || hasSeparator(id) || hasSeparator(name)) {
            throw new IllegalArgumentException("неверный код или имя");
        }
        if (score < 0 || score > 100) {
            throw new IllegalArgumentException("балл вне диапазона 0..100");
        }
    }

    private static boolean hasSeparator(String value) {
        return value.indexOf(';') >= 0 || value.indexOf('\n') >= 0
            || value.indexOf('\r') >= 0;
    }
}

new Student(" s1 ", " Ada ", 90) хранит s1, Ada, 90. strip() удаляет краевые пробельные символы; пустые код/имя, ;, CR/LF внутри нормализованного поля и балл вне 0..100 отвергаются. null отвергается проверкой requireNonNull с NullPointerException. Компактный конструктор проверяет одну запись. Два участника с тем же кодом и разными баллами могут быть разными значениями записи; уникальность кодов всего каталога проверяет загрузчик. При сравнении кодов регистр значим.

Участники с одинаковыми id, name и score равны. При изменении балла создаётся новое значение:

Student original = new Student(" s1 ", " Ada ", 90);
Student corrected = new Student(original.id(), original.name(), 80);
System.out.println(original.score());          // 90
System.out.println(original.equals(corrected)); // false

Объявление public record Student находится в пакете grade. Другой пакет обращается к нему по имени grade.Student или импортирует это имя. Класс Student, объявленный в другом пакете или внутри другого класса, представляет самостоятельный тип.

14.4 Поверхностная неизменяемость записи

Компонент ссылочного типа хранит ссылку. Его final-поле сохраняет эту ссылку, а доступный по ней объект может иметь изменяемое состояние:

record Vector(int[] values) {}
int[] input = {1, 2};
Vector vector = new Vector(input);
input[0] = 7;
System.out.println(vector.values()[0]); // 7
vector.values()[1] = 9;
System.out.println(input[1]); // 9
System.out.println(vector.values() == input); // true

Vector a = new Vector(new int[]{1, 2});
Vector b = new Vector(new int[]{1, 2});
System.out.println(a.equals(b)); // false

Первая запись хранит общий массив. В последних двух записях массивы разные: обычное равенство массива сравнивает тождество, поэтому одинаковых чисел недостаточно для равенства записей. Для математического вектора равенство обычно задаётся по координатам. Такая модель требует согласовать сравнение, хеширование и доступ к массиву.

У grade.Student компоненты — неизменяемые строки и примитивное число; его состояние устойчиво после создания. У записи с изменяемым компонентом свойства зависят от этого компонента. Например, если equals и hashCode компонента учитывают изменяемое содержимое, изменение этого содержимого может изменить равенство и хеш всей записи. У массива собственные equals и hashCode основаны на идентичности; изменение его элементов не превращает его в другой объект.

14.4.1 Защитные копии и равенство массива

Запись Scores представляет последовательность целых баллов. Копия в конструкторе разрывает связь с входным массивом; копия в методе чтения защищает внутренний массив от записи через возвращённую ссылку:

record Scores(int[] values) {
    Scores {
        values = java.util.Objects.requireNonNull(values).clone();
    }

    public int[] values() { return values.clone(); }

    @Override public boolean equals(Object other) {
        return other instanceof Scores that
            && java.util.Arrays.equals(values, that.values);
    }

    @Override public int hashCode() {
        return java.util.Arrays.hashCode(values);
    }

    @Override public String toString() {
        return "Scores[values=" + java.util.Arrays.toString(values) + "]";
    }
}

Arrays.equals сравнивает длины и соответствующие числа, Arrays.hashCode вычисляет хеш по этим же элементам. Метод equals обращается к закрытому полю другого экземпляра Scores; внутри самого класса такой доступ разрешён. Образец other instanceof Scores that связывает that с проверяемым объектом только при успешной проверке типа. Для null и другого типа проверка ложна; правая часть && пропускается. Arrays.toString строит строку по элементам массива.

int[] input = {80};
Scores saved = new Scores(input);
input[0] = 90;
int[] output = saved.values();
output[0] = 100;
System.out.println(saved.values()[0]); // 80
Scores copy = new Scores(saved.values());
System.out.println(saved.equals(copy)); // true
System.out.println(saved);              // Scores[values=[80]]
System.out.println(copy);               // Scores[values=[80]]
System.out.println(saved.toString().equals(copy.toString())); // true

После первой копии входной и внутренний массивы различаются. Второе копирование создаёт массив output. Оба внешних присваивания изменили эти отдельные массивы; внутреннее число осталось 80.

Для записей действует требование восстановления: создание новой записи из результатов всех методов чтения должно давать равное значение. Одна лишь защита копиями при стандартном equals нарушила бы его: каждая новая запись получила бы отдельный массив. Явное поэлементное равенство Scores сохраняет это требование и согласовано с хешированием.

Строковое представление тоже согласовано с равенством: у двух равных Scores оно одинаково. Их внутренние массивы различаются, поэтому стандартное строковое представление массива могло бы различаться у равных значений записи. Явный toString() использует те же числа, что и сравнение. Показанный человекочитаемый вид удобен для наблюдения; устойчивый формат файла или обмена определяется отдельно.

Копия массива ссылок копирует ссылки на элементы; защита самих изменяемых элементов требует дополнительного решения. Контракт Record, API Java 25.

14.5 Именованные константы перечисления

enum LoanStatus {
    AVAILABLE, BORROWED, LOST
}

LoanStatus state = LoanStatus.BORROWED;
System.out.println(state == LoanStatus.BORROWED); // true

Константы перечисления — заранее определённые экземпляры одного типа. Нельзя написать new LoanStatus(), а значение "BORROWED" типа String не является значением перечисления. Такой тип предотвращает случайные произвольные коды вроде 17 или строковую опечатку в состоянии. Однако обычная переменная LoanStatus всё ещё может содержать null; перечисление не отменяет общие правила ссылок.

Перечисление может иметь поля, методы и конструктор, используемый при создании констант:

enum Priority {
    LOW(1), NORMAL(5), HIGH(10);

    private final int weight;
    Priority(int weight) { this.weight = weight; }
    int weight() { return weight; }
}
System.out.println(Priority.HIGH.weight()); // 10

Не следует сохранять ordinal() как устойчивый внешний код: он отражает положение в текущем списке констант и меняется при перестановке или вставке. Для хранения в файле или обмена назначается отдельное стабильное значение. valueOf использует точное имя константы и при отсутствии совпадения бросает IllegalArgumentException; пользовательский формат может потребовать собственный метод разбора. 14.6 Запечатанная семья вариантов данных

У результата поиска может быть найденная запись или объяснение отсутствия. Варианты содержат разные данные, поэтому один enum без дополнительной модели не описывает их полностью.

sealed interface SearchResult permits Found, Missing {}
record Found(String title) implements SearchResult {}
record Missing(String reason) implements SearchResult {}

Теперь непосредственные реализации SearchResult ограничены указанными типами. Записи уже неявно финальны. Обычный непосредственный класс-реализация должен явно выбрать final, sealed или non-sealed. Непосредственный подинтерфейс выбирает sealed или non-sealed: интерфейс не может быть final. non-sealed разрешает дальнейшее свободное расширение своей ветви. Разрешённые подтипы должны находиться в том же именованном модуле, а в неназванном модуле — в том же пакете.

static String describe(SearchResult result) {
    return switch (result) {
        case Found found -> "Found: " + found.title();
        case Missing missing -> "Missing: " + missing.reason();
    };
}

В case Found found используется знакомый образец типа: ветвь подходит объекту Found, а found даёт типизированную ссылку на него в правой части этой ветви. Аналогично missing доступна в ветви Missing. Компонент читается обычным вызовом title() или reason().

Для двух указанных вариантов switch исчерпывающий; компилятор проверяет покрытие возможных подтипов. Здесь предполагается аргумент, отличный от null: без case null переключение по null бросит NullPointerException. Если добавить третий разрешённый вариант и заново компилировать метод, потребуется учесть новый случай. Если же выбрать non-sealed-ветвь, список всех дальнейших конкретных классов уже не закрыт. [93]

14.6.1 Дополнительный опыт: расширение вариантов результата поиска

Сначала каталог искал по уникальному коду. Позднее клиенту понадобился поиск по названию, которое может совпасть у нескольких книг. Возвращение null для обоих случаев — «ничего нет» и «найдено несколько» — лишило бы клиента основания для следующего действия. При нескольких совпадениях клиент должен запросить уточнение, позволяющее выбрать одну книгу.

Следующая версия заменяет объявление семьи результатов:

sealed interface SearchResult permits Found, Missing, Ambiguous {}
record Found(String title) implements SearchResult {
    Found { java.util.Objects.requireNonNull(title, "title"); }
}
record Missing(String reason) implements SearchResult {
    Missing { java.util.Objects.requireNonNull(reason, "reason"); }
}
record Ambiguous(int count) implements SearchResult {
    Ambiguous {
        if (count < 2) throw new IllegalArgumentException("Нужно хотя бы два совпадения");
    }
}

Вариант Ambiguous хранит количество, потому что клиенту важно объяснить неоднозначность. Его конструктор отвергает случай с одним совпадением, который не является неоднозначным. У результата SearchResult, отличного от null, конкретный тип определяет, какой случай представлен; у отсутствующей ссылки такой информации нет.

static String describe(SearchResult result) {
    return switch (result) {
        case Found found -> "Found: " + found.title();
        case Missing missing -> "Missing: " + missing.reason();
        case Ambiguous many -> "Matches: " + many.count();
    };
}
System.out.println(describe(new Ambiguous(3))); // Matches: 3

Если оставить прежний switch из двух ветвей и повторно компилировать его с новой семьёй, компилятор сообщит о неполном покрытии. При наличии универсального default новый вариант попадёт в эту ветвь, и повторная компиляция не потребует отдельного случая. Условия title != null, reason != null и count >= 2 обеспечиваются конструкторами; switch проверяет покрытие типов. Передача null в показанный метод заканчивается NullPointerException. [2]

Запись соединяет компоненты одного случая, а запечатанная семья перечисляет альтернативные случаи. Например, найденная книга содержит данные находки, а неоднозначность содержит другие данные. Такое использование наследования служит описанию вариантов; общего унаследованного хранилища для них не нужно. Открытый интерфейс Sender из Глава 13 задаёт отправку текста и допускает новые независимые реализации. Выбор между открытой ролью и ограниченной семьёй зависит от того, что должен знать клиент: одну операцию участника или все варианты результата.

14.7 Выбор формы данных по операциям

У Sender и SearchResult различаются ожидаемые изменения. Новый способ отправки реализует существующую операцию send, поэтому клиенту достаточно знать её договор. Открытая роль допускает реализацию, которую автор клиента никогда не видел. У результата поиска клиент, напротив, принимает решение по каждому известному исходу. Запечатанная семья позволяет проверить полноту такого решения при компиляции.

За полноту платят согласованием изменений. Новый вид результата Ambiguous заставляет пересмотреть исчерпывающие разборы семьи. Зато новое действие над уже известными исходами — например, построение отчёта — можно выразить отдельным полным switch, сохранив классы вариантов. У открытой роли ситуация иная: новая реализация прежних операций обычно не требует правки клиентов, а добавление обязательной операции затрагивает реализующие классы. Выбор границы зависит от того, кто будет добавлять варианты и кто должен отвечать за полноту операций над ними.

Форма данных также определяет, какие свойства состояния входят в договор с клиентом. enum фиксирует именованный набор экземпляров. Запись делает состав компонентов частью публичного договора, включая их чтение и равенство; добавление компонента меняет этот договор. Обычный класс позволяет менять скрытое представление за прежними операциями, но автор сам определяет эти операции и правила равенства.

Запись Loan(String bookCode, String readerCode) может хранить сведения об одной выдаче. Класс службы хранит текущие выдачи и выполняет операции выдачи и возврата. У службы меняется состояние, а записи фиксируют данные, которые участвуют в отдельных действиях и отчётах.

Присваивание переменных этих типов копирует ссылки. Для хранения данных с сохранением связи между типом добавленного значения и типом результата чтения используется параметр типа: Глава 15.

14.8 Описание типа во время выполнения

Объект new Student(...) хранит данные одного участника. Выражение Student.class получает объект типа Class, описывающий сам тип Student. Из него программа может узнать имена и типы компонентов, не читая запись участника из файла. Такое исследование структуры программы во время выполнения называется рефлексией.

Тип Class<?> описывает объект метаданных. Class имеет аргумент типа для описываемого типа; ? здесь означает «конкретный аргумент сейчас неизвестен». Чтение имён и типов компонентов доступно и при неизвестном аргументе. Угловые скобки задают аргумент типа. Параметры типов и wildcard: Глава 15 и Глава 16.2.

У Student объявлены компоненты String id, String name и int score. Чтение данных экземпляра и чтение метаданных дают разные результаты:

Student student = new Student(" s1 ", " Ada ", 90);
Class<?> type = Student.class;
System.out.println(student.id());
System.out.println(type.isRecord());
for (var component : type.getRecordComponents()) {
    System.out.println(component.getName() + ":"
            + component.getType().getSimpleName());
}

Полный вывод:

s1
true
id:String
name:String
score:int

student.id() читает компонент экземпляра. isRecord() проверяет, является ли класс записью, getRecordComponents() даёт массив описаний в порядке заголовка записи; getName() и getType() читают имя и тип компонента. var выводит тип переменной component из типа элемента этого массива. Объект int.class описывает тип последнего компонента, поэтому печатается int. Объект Class здесь представляет примитивный тип. Сам балл 90 остаётся значением int; получение описания типа выполняется без упаковки этого числа в Integer. У обычного класса isRecord() будет false, а getRecordComponents() — null, поэтому такой обход допустим, когда известно, что тип — запись. При создании участника с другим кодом student.id() вернёт этот код, а метаданные компонентов останутся прежними. Состав метаданных определяется объявлением типа и одинаков для всех его экземпляров.
