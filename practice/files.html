Аргументы и вход

Число аргументов

В задачах копирования передают пути входа и выхода. У gradeapp другая команда: путь входа и порог, ровно два аргумента. Готовая часть точки входа проверяет число аргументов, порог 0–100 и синтаксис пути до чтения. Шаблон обращения к массиву:

if (args.length != 2) {
    System.err.println("нужны два аргумента");
    return;
}

Это тело main(String[] args). Нельзя читать args[1] до проверки длины. Ошибка компиляции препятствует запуску; недопустимые аргументы и отказ чтения обрабатываются во время выполнения: Компиляция, вход и состояние программы.

Рабочий каталог

var source = java.nio.file.Path.of("samples", "students.txt");
System.out.println(source.toAbsolutePath());

Фрагмент помещается в main. Абсолютный адрес зависит от рабочего каталога процесса; Path.of не открывает файл, toAbsolutePath не доказывает его существования. API: Путь.

Попросить предсказать, что изменится при запуске из соседнего каталога. Сопоставить строку пути и напечатанный абсолютный адрес. Проверку существования файла оставить самой операции открытия. Предложить повторить запуск с абсолютными путями к входу и выходу.

Подготовка входа

Для копирования подготовьте UTF-8 с кириллицей, ASCII-пробелом и переводом строки; сохраните вход для сравнения. Входной и выходной файлы выбирайте разными. Правило одинакового файла и состояние выхода после отказа определяет условие Упражнение 27.1.

При копировании вход открывается до выхода. Если вход отсутствует, прежний выход должен сохраниться; если запись отказала, часть выхода уже может измениться. Порядок открытия и закрытия определяет эти исходы.

Для gradeapp уже есть samples/students.txt, blank.txt, duplicate.txt. Пустой файл можно создать отдельно. Выходного пути у этой команды нет.

Предложить обозначить момент первого изменения выходного файла. Сопоставить отсутствие входа и отказ уже начавшейся записи: до какого действия удалось дойти в каждом случае?

Чтение и конец входа

Байты и конец

InputStream.read() возвращает int: 0–255 для байта или -1 для конца входа. Для 0xFF получается 255. Конец входа даёт -1; IOException сообщает об отказе чтения. Байтовое копирование заменяет ASCII-пробел 0x20 и сохраняет прочие байты.

Строки и конец

BufferedReader.readLine() возвращает текст без разделителя. Пустая строка обозначается "", конец входа — null. Files.newBufferedReader(path, UTF_8) задаёт декодирование. Номер физической строки увеличивается и для пропущенной пробельной строки; пустая строка обрабатывается как часть входа.

Кодировка и сохранение текста

Кириллическая буква кодируется несколькими байтами UTF-8. Приведение одного байта к char её не декодирует. Чтение строк удаляет разделители; печать через println может заменить их. Символьное чтение через Reader.read() сохраняет сами символы-разделители. В заданиях нужны соответственно байтовые потоки и Reader/Writer с UTF-8. Способ обхода выбираете самостоятельно: Чтение и запись.

Закрытие и реакция

Явное закрытие при отказе

var input = java.nio.file.Files.newInputStream(source);
try {
    System.out.println(input.read());
} finally {
    input.close();
}

Это тело метода static void first(java.nio.file.Path source) throws java.io.IOException. При байтах 0x00,0xFF печатается 0; при пустом входе −1. Если чтение откажет, finally всё равно вызывает close. Если откажет также close, в этой форме ошибка закрытия вытеснит ошибку чтения.

Прочитать опыт по трём путям: байт получен, конец входа, IOException. Для каждого указать момент finally. Затем добавить отказ close и спросить, какое исключение увидит клиент этой простой формы. Перейти к двум ресурсам: защита уже открытого первого должна охватывать открытие второго.

Несколько ресурсов

Защита первого начинается до открытия второго. Два вызова close подряд в одном finally не обеспечивают второй вызов после отказа первого. Вложенные try/finally обеспечивают попытку закрыть каждый успешно открытый ресурс. Сохранение обеих ошибок требует дополнительного кода. Подробный пример: Ручное закрытие двух ресурсов.

Конструкция try с ресурсами

Конструкция try с ресурсами открывает слева направо и закрывает справа налево. Ошибка тела остаётся основным исключением, отказ close присоединяется к списку suppressed; cause сохраняет причину обёртывания исключения. Полный CauseCloseDemo с выводом: Первичная и подавленная ошибки.

Политика обработки отказа

Ресурс в опыте сообщает проверяемый отказ чтения. Внешний обработчик показывает сообщение после закрытия ресурса. Полный файл ResourcePolicyDemo.java:

public class ResourcePolicyDemo {
    static final class Resource implements AutoCloseable {
        void read() throws java.io.IOException {
            throw new java.io.IOException("read failed");
        }
        @Override public void close() {
            System.out.println("closed");
        }
    }
    public static void main(String[] args) {
        try (var resource = new Resource()) {
            resource.read();
            System.out.println("use result");
        } catch (java.io.IOException failure) {
            System.err.println("operation failed: " + failure.getMessage());
        }
    }
}

До запуска предложить выписать ожидаемые stdout и stderr по отдельности. Отметить пропуск use result после read failed. Попросить определить, какой блок отвечает за освобождение, какой — за сообщение. Полный пример восстанавливается как один ResourcePolicyDemo.java; дополнительных библиотек и настоящего файла ему не требуется.

Результат обработки отказа

Stdout: closed; stderr: operation failed: read failed; процесс завершается обычно. use result не печатается. Закрытие происходит до catch. Внешний обработчик печатает сообщение об отказе; основная операция ресурса завершается исключением. Stdout и stderr наблюдаются отдельно: терминал может объединять их отображение в разном порядке.

catch и close не откатывают изменения. Частично записанный выход копирования возможен по условию; gradeapp проверяет весь вход до stdout, но не может забрать уже переданные байты при отказе stdout.

Каталог участников

Журнал поставок (Глава 24) объединяет повторы и сохраняет ошибки строк. gradeapp принимает каталог участников: нормализованные коды должны быть уникальны, неверная строка отменяет отчёт. Из полностью допустимого каталога отбираются участники с баллом не ниже порога.

При пороге 80 строки s3;Ann;90, s10;Ada;90 дают сначала s10;Ada;90, затем s3;Ann;90: равные баллы упорядочены по строковому коду.

Сопоставить цели: сумма поставок по повторяющемуся ключу и выбор участников с уникальными кодами. Попросить показать, почему прежнее продолжение после неверной строки нарушило бы договор gradeapp. Затем перейти к заготовке.

Сборка заготовки

Упражнение 27.14 использует готовые модель, исключение, сборку и проверку аргументов команды. Из корня скачанного student проверьте sh ./build.sh --version, затем sh ./build.sh -DskipTests package. Версия Java должна быть 25; точные команды и состав: Maven Wrapper.

Тела с TODO в парсере, загрузчике, Reports и Main.run(Path,int) компилируются и выбрасывают UnsupportedOperationException. Предоставленная проверка команды уже возвращает код 2 при неверном числе аргументов. После реализации sh ./build.sh test package выполняет открытые примеры.

Сначала проверить версию Java, затем выполнить сборку с пропуском исполнения тестов. Попросить объяснить, почему компилируемый TODO ещё не выполняет договор. В дальнейшей работе открытые примеры проверяют поведение, а студент добавляет граничные входы из условия. Сохраняются опубликованные методы заготовки; организация вспомогательных методов остаётся свободной.
