Теория: Сохранение инварианта.

Представление состояния

У Reservation из теории вместимость положительна, а число занятых мест находится между нулём и вместимостью. Это инвариант объекта — условие, которое выполняется после создания и каждого завершённого действия. Поля и конструктор класса:

final class Reservation {
    private final int capacity;
    private int occupied;
    Reservation(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException();
        this.capacity = capacity;
    }
    int available() { return capacity - occupied; }

Конструктор устанавливает допустимое состояние. Свободные места вычисляются из двух полей, поэтому отдельный счётчик свободных мест согласовывать не нужно.

Покажите, какое значение occupied получает до тела конструктора. Предложите добавить поле свободных мест и перечислить места, где пришлось бы менять сразу два счётчика. Свяжите это с выбором минимального состояния.

Изменение с сохранением инварианта

Завершение того же класса:

    void reserve(int count) {
        if (count <= 0 || count > available()) {
            throw new IllegalArgumentException();
        }
        occupied += count;
    }
}

При вместимости 30 вызов reserve(8) оставляет 22 свободных места. Последующий reserve(25) отвергается до записи и сохраняет эти 22 места. Инвариант зависит от порядка проверки и изменения.

Попросите восстановить поля модели и объяснить остаток после первого запроса. Сопоставьте знакомый класс C++ с закрытыми полями и методами: какая часть его кода отвечает за недопустимый запрос? Попросите назвать начальное число занятых мест и место его установления.

Предложите переставить проверку после присваивания и проследить состояние после исключения. Обратите внимание, что перехват исключения клиентом сам по себе не отменяет выполненные записи.

Состояние стека

Стек возвращает символы в порядке, обратном добавлению. При ёмкости 2 заполненный стек хранит A под B. Попытка добавить C сохраняет эти символы и их порядок. Условия Упражнение 21.3 задают наблюдаемый отказ:

Действия Результат
Поместить A, B A под B
Попытаться поместить C строка Стек переполнен, состояние прежнее
Извлечь дважды B, затем A
Извлечь ещё раз строка Стек пуст и результат '\0'

Положительная ёмкость — предпосылка создания в этой задаче. Нулевой символ зарезервирован для отказа. Представление вершины и вспомогательные методы студент выбирает самостоятельно.

Попросите сформулировать инвариант для выбранного студентом представления вершины. Допустимы число элементов и индекс последнего элемента при согласованных границах. Сравните отказ стека с исключением Reservation: сохранение состояния общее, наблюдаемый результат задан каждым договором.

Локальная перестановка ссылок

У объекта Test одно поле a. Метод получает две ссылки:

final class Test {
    int a;
    Test(int value) { a = value; }
}
static void localSwap(Test left, Test right) {
    Test saved = left;
    left = right;
    right = saved;
}

Ссылки переставлены в параметрах left и right; поля a переданных объектов остаются прежними.

Нарисуйте два объекта с полями 3 и 8 и по две ссылки на каждый: переменную клиента и параметр. Переставляйте только стрелки параметров. Попросите указать строку, которая могла бы изменить поле: в этом методе её нет.

Наблюдение после возврата

Клиент создаёт объекты со значениями 3 и 8:

Test left = new Test(3);
Test right = new Test(8);
Test alias = left;
localSwap(left, right);
System.out.println(left.a + " " + right.a); // 3 8
System.out.println(alias == left);          // true

После возврата ссылки клиента и поля объектов прежние. Для обмена содержимым в Упражнение 21.2 наблюдение другое: поля должны стать 8 и 3, причём alias увидит изменённое поле первого объекта.

Попросите объяснить ответ через получателя присваивания. Затем объедините обе стрелки на одном объекте и предложите назвать ожидаемое состояние после swap(x, x).

Переменное число аргументов

Параметр int... values принимает переменное число целых аргументов:

static void inspect(int... values) {
    System.out.println(values.length);
}
inspect();       // 0
inspect(4, 7);   // 2

Внутри метода параметр имеет тип int[]. Пустой список аргументов создаёт массив длины ноль: обход выполняет ноль шагов. У вычисления по массиву должен быть определён результат и для такого случая. Форма параметра: Глава 5.

Предложите заменить inspect(4, 7) на inspect(new int[]{4, 7}) и объяснить, что видит тело метода. Сопоставьте пустой массив с null и попросите найти в условии суммы, какой из этих входов допустим.

Объект и алгоритм отбора

Книга в задаче хранит авторов и год издания; автомобиль — модель, год выпуска и цену. Два конструктора дают два способа создать запись с заданными свойствами. toString() возвращает текстовое представление одной записи. Метод отбора получает массив записей и критерий.

Отбор читает свойства записей и сохраняет исходный массив и объекты. По тем же данным можно выполнить второй запрос. Несколько ссылок на один объект в исходном массиве означают несколько вхождений, каждое участвует в отборе.

Варианты: Упражнение 21.4, Упражнение 21.5.

Предложите один автомобиль поместить в массив дважды. Спросите, сколько вхождений выдаёт фильтр, если он подходит. Затем отделите эту задачу от удаления повторов: фильтр сохраняет каждое подходящее вхождение.

Строгая граница отбора

При текущем годе 2026 и пороге возраста 5 автомобиль 2021 года имеет возраст ровно 5 и не подходит условию «больше 5». Автомобиль 2020 года подходит. Год сравнения поступает параметром, поэтому тот же набор данных воспроизводим.

Автор книги совпадает с одним полным именем в списке авторов. Подстрока "Иван" не совпадает с именем "Иван Петров". Строковые критерии учитывают регистр. Отсутствие совпадений даёт пустую подборку.

Попросите составить три случая вокруг одной границы: меньше, равно, больше. Затем предложите неизвестного автора и два совпадения в разных местах массива. Так проверяются отдельно критерий, пустой результат и сохранение порядка.

Представление результата

Для каждого решения покажите обычный случай и существенную границу. У изменяющей операции наблюдайте состояние после возврата или отказа; у отбора — результат и сохранность исходных данных.

Точные API, допустимые входы и выбор одной предметной модели заданы в Глава 7. Обязательные приёмы обсуждаются по исходному коду и демонстрации.

Предложите студенту выбрать одно утверждение о своей программе и показать наблюдение, которое его проверяет. Для стека одного сообщения об отказе недостаточно: последующие извлечения раскрывают сохранённое состояние.
