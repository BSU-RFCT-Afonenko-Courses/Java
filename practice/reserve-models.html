Значение дроби и её представление

Для задач о дробях нужны классы и массивы.

Для Упражнение 22.9 1/2, 2/4 и -1/-2 обозначают одно значение. Нормализация сокращает дробь и переносит знак в числитель; 0/5 приводится к 0/1.

Равенство и хеш должны использовать согласованное представление. Нулевой знаменатель и деление на нулевую дробь вызывают ArithmeticException. Промежуточные результаты по условию помещаются в long.

Автоматически созданный equals у record сравнивает компоненты. Правила нормализации дроби задаются в коде класса. Глава 14; Глава 17.

Предложите представить одно значение тремя парами целых. Спросите, какая нормализация даст одно представление для equals и hashCode. Для нуля отдельно проверьте знаменатель 1.

Значения элементов после преобразования

В Упражнение 21.8 дробь на чётном индексе складывается со следующей. Для массива значений

[1/2, 1/3, 1/4, 1/4, 2/5] → [5/6, 1/3, 1/2, 1/4, 2/5]

меняются элементы 0 и 2. У последнего элемента нет пары, поэтому индекс 4 сохраняет значение; нечётные элементы тоже остаются прежними.

Если операция возвращает новую дробь, нужно заменить элемент массива; один вызов без сохранения ответа его не изменит. Если несколько позиций ссылаются на одну дробь, изменение этого объекта видно в каждой из них. Условие сохраняет значения нечётных элементов, поэтому выбор мутации или нового объекта должен учитывать эти связи.

Поместите одну дробь в две позиции массива и проследите мутацию. Попросите сопоставить наблюдаемое изменение с условием о сохранении нечётных элементов.

Логический порядок и физические позиции

Для символьной очереди нужны классы и массивы; обобщённые очереди требуют также параметров типов.

В Упражнение 22.7 при ёмкости 4 пусть head = 3, число элементов 3, а позиции содержат:

Индекс 0 1 2 3
Элемент B C свободно A

Порядок клиента — A, B, C. Для номера элемента k физическая позиция равна (head + k) % capacity. Увеличение ёмкости должно сохранить этот порядок.

Начните чтение таблицы с head. Попросите назвать последовательность физических индексов 3, 0, 1 и соответствующие выдаваемые символы A, B, C.

Копирование физических позиций

В исходном массиве head = 3, логический порядок — A, B, C. Arrays.copyOf создаёт массив большей длины и копирует компоненты по их прежним индексам:

String[] old = { "B", "C", null, "A" };
String[] grown = java.util.Arrays.copyOf(old, 8);
System.out.println(java.util.Arrays.toString(grown));
// [B, C, null, A, null, null, null, null]

При прежнем head = 3 следующий индекс по новой ёмкости равен (3 + 1) % 8 = 4: там находится null, хотя следующим нужен B. Нужно перенести оставшиеся логические элементы и согласовать новые индексы так, чтобы извлечение по-прежнему давало A, B, C.

Для Упражнение 23.6 сначала определите своё размещение. Правила индексации и роста должны соответствовать выбранному линейному или кольцевому размещению элементов. Arrays.copyOf для ссылочных компонентов; Глава 11.

Сравните получившийся массив с логической последовательностью A, B, C. Копирование сохранило физические позиции; сохранение FIFO после роста требует согласовать новый порядок и индексы.

Отбор записей и связи графа

В реестре записи отбираются по критерию. Если нужен порядок строк, String.compareTo сравнивает их лексикографически по UTF-16: String.compareTo и знак порядка. Алфавитный порядок конкретного языка задаётся другими правилами сравнения.

У графа есть вершины и связи между ними. Пусть вершины — A, B, C, а единственное неориентированное ребро — A—B. Списки смежности:

A: [B]    B: [A]    C: []

Одна связь представлена с двух сторон. Вершина C существует и при пустом списке соседей. Для ориентированной дуги A→B запись находится только в списке исходящих связей A.

Предложите удалить ребро A—B и предсказать число вершин. Затем попросите объяснить, почему два пустых списка соседей не превращают A и C в одну вершину. Сопоставьте ответ с выбранным способом идентификации вершин.

Хранение вершин и соседей

Для Упражнение 24.10 нужны операции коллекций: List хранит последовательность, Set — множество без повторов, Map связывает ключ с соответствующим значением.

Если хранить только найденные рёбра, сведения об изолированной C будут потеряны. Модель должна сохранять и вершины без соседей. Совпадение списков смежности также не определяет равенство вершин: после удаления A—B все три списка пусты, а вершин по-прежнему три.

При выборе хранения учитывают идентификаторы вершин и допустимость повторных связей. Операции коллекций: Глава 16; Глава 17.

Попросите показать, где в предложенной модели сохраняется C. Затем верните ребро A—B и проследите добавление и удаление обеих записей.

Текущее состояние расписания

Для задачи о расписании нужны коллекции и интерфейсы.

В Упражнение 28.2 занятие связывает дату и время с предметом, преподавателем, группой и аудиторией. Обозначим преподавателей T1, T2, группы G1, G2, предметы S1, S2.

Занятие Дата и время Предмет Преподаватель Группа Аудитория
L1 19.10, 09:00 S1 T1 G1 101
L2 19.10, 10:00 S2 T2 G1 102
L3 20.10, 09:00 S1 T1 G2 101
L4 20.10, 10:00 S2 T2 G2 102

Для T1 результат выборки — L1, L3, количество — 2. Для G1 результат — L1, L2, количество — 2.

Попросите сначала найти строки T1 и G1 глазами. Перед следующим экраном предложите отменить L1 и предсказать обе новые выборки и их размеры.

Изменение выборки

В расписании из четырёх занятий отменено L1.

Запрос До отмены После отмены
Занятия T1 L1, L3 L3
Количество занятий T1 2 1
Занятия G1 L1, L2 L2
Количество занятий G1 2 1

Подсчёт и отображение должны читать одно текущее состояние. Сохранённое без обновления число 2 противоречило бы оставшейся выборке. Перенос L3 в другую аудиторию меняет место занятия, сохраняя его принадлежность преподавателю и группе.

Сопоставьте прогноз с таблицей. Предложите назвать данные, по которым можно вычислить количество повторно, и объяснить, какое обновление понадобится, если количество хранится отдельно.

Удаление связанной сущности

После отмены L1 преподаватель T1 всё ещё связан с L3. При попытке удалить T1 возможны разные заранее выбранные политики:

Политика Результат попытки
Отказ, пока есть связанные занятия T1 и L3 сохраняются
Удаление вместе со связанными занятиями Удаляются T1 и L3

Если дата объявлена выходным, занятия этой даты исключаются из действующего расписания. Для школы дополнительно проверяется число уроков за день, для автошколы — наличие автомобиля у практического занятия. Предел уроков и модель автомобилей определяются в решении.

Предложите выбрать одну из политик удаления и описать наблюдаемое состояние после действия. Затем отдельно добавьте выходной на 20.10 и попросите перечислить оставшиеся занятия. Напомните исходное состояние этого опыта: L1 уже отменено; попытка удаления T1 рассматривается как отдельная ветвь.

Частоты слов и префиксный код

Для задачи о кодировании слов нужен предварительный разбор алгоритма Хаффмена.

Пусть текст — red red red blue blue green. Частоты слов: red — 3, blue — 2, green — 1. Код заменяет каждое слово последовательностью битов.

Префиксный код не содержит кода слова, который был бы началом кода другого слова. Например, red → 1, blue → 01, green → 00:

red red red blue blue green
 1   1   1   01   01    00  → 111010100

При чтении слева направо очередной полный код однозначно определяет слово. Получено 3 × 1 + 2 × 2 + 1 × 2 = 9 битов.

Предложите восстановить слова из видимых битов, закрыв строку исходного текста. Затем сравните с назначением кодов 0 и 01 двум разным словам: чтение 0 ещё не определяло бы, завершился ли код.

Построение дерева Хаффмена

Каждому слову соответствует лист с весом, равным частоте. Алгоритм повторно объединяет два узла с наименьшими весами в новый узел с их суммой:

green:1 + blue:2 → узел:3
узел:3  + red:3  → корень:6

После пометки двух ветвей каждого узла битами 0 и 1 путь от корня к листу даёт код слова. Слова находятся в листьях, поэтому один код не продолжается внутри другого. Такое объединение минимизирует сумму произведений частот на длины кодов. [2]

PriorityQueue позволяет извлекать узел с наименьшим весом и добавлять объединённый узел. При равных весах требуется выбранное правило порядка; обычный обход очереди не задаёт последовательность извлечения. [3]

Попросите восстановить на дереве коды предыдущего экрана: ветвь к red получила 1, ветвь к объединённому узлу — 0. Обратите внимание на равенство весов 3 после первого объединения: правило должно применяться и к узлам.

Границы кодирования

В Упражнение 28.3 единицы кодирования — слова с сохранением регистра. Для реализации нужны классы, коллекции и PriorityQueue.

Вход Наблюдаемый результат
Пустой текст Пустая таблица и пустая последовательность битов
red red red Единственный код red → 0, результат 000
red blue green Все частоты равны; выбранный порядок даёт воспроизводимое дерево

При одном различном слове дерево состоит из листа без рёбер; код 0 задаётся отдельным правилом задачи. При равных частотах возможны разные оптимальные деревья. Выбранные коды должны однозначно восстанавливать слова и давать минимальную суммарную длину.

Попросите объяснить, почему получение кода только из рёбер дало бы для единственного листа пустую строку. Для равных частот сравните два порядка объединения: конкретные коды могут меняться при сохранении оптимальности.
