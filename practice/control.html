Теория: Полный цикл чтения текста.

Чтение и состояние цикла

Источник текста

Reader input = new InputStreamReader(
    System.in, StandardCharsets.UTF_8);

System.in даёт байты, обёртка декодирует их как UTF-8 в единицы UTF-16. Отказ чтения передаётся наружу через throws IOException в main. Полный исходник и команды: Запуск текстовых примеров.

Проследить движение данных от байтов System.in к единицам UTF-16, которые возвращает Reader. Выбор UTF-8 относится к декодированию входных байтов. Объявление throws IOException позволяет передать отказ чтения вызывающей среде. Если нужна полная форма файла, открыть указанную справку.

Одно чтение

int unit = input.read();
if (unit != -1) {
    System.out.println(unit);
}

Почему int, хотя читаем текст? EOF обозначен -1, за диапазоном char. Преобразование в char до проверки потеряло бы этот признак.

Назвать возможные результаты чтения: значение единицы UTF-16 либо -1. Попросить сравнить -1 с диапазоном char. Сначала проверяется признак конца, затем значение может использоваться как текстовая единица. Печать unit в данном фрагменте выводит число: это следствие выбранной перегрузки println(int).

Условие продолжения

long count = 0;
int unit;
while ((unit = input.read()) != -1 && unit != '#') {
    count++;
}
System.out.println(count);

Для входа AЯ#tail какие единицы попадут в тело? Когда условие будет проверено последний раз?

До перехода к таблице предложить проследить AЯ#tail: отмечать каждое чтение, проверку и вход в тело. Отдельно спросить, увеличит ли счётчик # и запросит ли цикл ещё одну единицу после него. Перед показом таблицы записать предполагаемую последовательность действий. Для немедленного EOF должно быть объяснено отсутствие входов в тело.

Состояние после чтения

Результат чтения Условие цикла Счётчик после шага
A Истина 1
Я Истина 2
# Ложь 2

tail не обрабатывается. При немедленном EOF тело не выполняется. При переводе строки без терминатора счётчик увеличивается.

Сверить предположение с таблицей. Терминатор уже извлечён из источника, но условие не допускает его в тело. Остаток tail цикл не обрабатывает; декодер мог заранее получить его байты, но нового вызова read() после терминатора нет. Обсудить отличие пустого ввода от строки, содержащей перевод строки: во втором случае прочитана текстовая единица. EOF обозначает состояние источника, отдельного символа EOF в данных нет.

Завершение ввода и отбор данных

EOF и терминатор определяют завершение чтения. Предметное условие определяет, какие прочитанные данные изменяют результат.

Если считать только определённые единицы, новое условие находится внутри прежнего цикла. Проверка окончания от этого не исчезает.

Предложить изменить предмет подсчёта на букву A. Условие завершения сохраняет назначение, а увеличение счётчика становится условным. Попросить объяснить, почему неподходящая буква должна позволять читать дальше. Затем вернуть обсуждение к условию лабораторной: там выбраны обычный пробел и точка как терминатор.

Непустой набор и начальное состояние

Начальное значение максимума

int[] pages = {-8, -3, -11};
int largest = pages[0];
for (int i = 1; i < pages.length; i++) {
    if (pages[i] > largest) largest = pages[i];
}
System.out.println(largest); // -3

Инвариант обхода: перед проверкой условия largest — максимум элементов с индексами от 0 до i - 1. Массив здесь заведомо непустой; у потока нужно получить первый элемент.

Восстановить три состояния максимума: -8, -3, -3. Затем заменить начальное значение на ноль и показать, почему ни один элемент не исправляет ошибку. Формулировка инварианта связывает сохранённое значение с просмотренным префиксом. Значение из первого элемента сразу принадлежит непустому обрабатываемому набору.

Получение числового значения

java.util.Scanner input = new java.util.Scanner(System.in);
int count = input.nextInt();
if (count <= 0) {
    System.out.println("Нет набора для обработки");
    return;
}
int first = input.nextInt();

Фрагмент находится в main, вход состоит из корректных целых. return прекращает метод до чтения первого значения пустого набора.

Проследить вход 0: после чтения количества выполняются сообщение и выход, чтения элемента нет. Для входа 1 -5 первым элементом становится -5. Фрагмент предполагает корректные токены. Сопоставить эту предпосылку с опубликованным условием нахождения экстремумов.

Данные для проверки инициализации

Набор 2 5 9 не обнаружит неверный исходный максимум 0. Набор 2 -5 -9 обнаружит его.

Набор из одного числа проверяет, не пропущено ли первое значение. Случай n = 0 проверяет переход до попытки чтения элемента.

Уточнить, что первое число в каждой записи — количество последующих элементов. Сравнить два запуска ошибочной программы с исходным максимумом ноль. Затем попросить предложить аналогичный различающий набор для ошибочного минимума ноль: нужны только положительные элементы. Для единственного элемента оба экстремума должны совпасть.

Попросить назвать условие завершения каждой задачи. В текстовой задаче это точка или EOF; в числовой — обработка объявленного количества. Условия входят в постановку задачи, поэтому механический перенос одного цикла в другую задачу меняет смысл входа. Открыть карточки для точного формата вывода.

Попросить студента связать переменную результата с уже обработанной частью входа. Если объяснение ограничивается итоговым числом, вернуться к состоянию после первого элемента. Для проверки терминатора подходят пустой префикс и непустой хвост после точки; хвост не должен влиять на ответ.
