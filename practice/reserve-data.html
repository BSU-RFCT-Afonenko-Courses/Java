Подготовка данных

Этапы обработки данных

Чтение, преобразование и запись образуют отдельные этапы. Для каждого этапа определите вход, результат и возможный отказ.

Ошибка числа в строке файла не должна незаметно превращаться в ноль, если условие этого не разрешает.

Политика частичного результата

Программа может прочитать несколько корректных строк и встретить ошибочную.

Договор задачи определяет, останавливается ли вся обработка, пропускается ли строка и что происходит с выходным файлом. Назовите эти условия до записи алгоритма.

Состояние преобразования текста

Удаление комментариев Java зависит от того, находится ли текст внутри строки или символьного литерала. Последовательность // внутри строки не начинает комментарий.

Разбор должен учитывать состояние литералов и комментариев: Упражнение 27.13.

Два момента вызова

IntFunction<IntPredicate> задаёт IntPredicate apply(int value); полученный IntPredicate задаёт boolean test(int value). Предскажите оба ответа:

IntFunction<IntPredicate> atLeast = limit -> n -> n >= limit;
IntPredicate enough = atLeast.apply(5);
System.out.println(enough.test(4));
System.out.println(enough.test(5));

Первый вызов выбирает порог; второй проверяет число. Для Упражнение 25.16 разберите такую же последовательность аргументов без смешения создания и применения: Возвращаемое правило и состояние замыкания.

Сначала остановиться после atLeast.apply(5): получена функция с выбранным порогом, проверка числа ещё не выполнена. Предсказать enough.test(4) и enough.test(5). Затем попросить назвать два момента вызова в выбранной самостоятельной задаче с возвращаемой функцией и записать тип каждого результата.

Сохранённый порог

Вывод — false, затем true. apply(5) выполнился один раз и вернул правило с порогом 5. Два последующих test применили его к 4 и 5.

Сверить прогноз и попросить назвать тип каждого промежуточного результата. В выбранной задаче о возвращаемой функции сначала обозначить данные каждого вызова, затем записать лямбду.

Воспроизводимые файловые данные

Предскажите число строк и номера строк, равных alpha:

Path input = Files.createTempFile("practice-", ".txt");
try {
    Files.writeString(input, "alpha\nbeta\nalpha", StandardCharsets.UTF_8);
    System.out.println(Files.readAllLines(input, StandardCharsets.UTF_8).size());
} finally {
    Files.deleteIfExists(input);
}

Пронумеровать физические строки до перехода к ответу. Уточнить, есть ли после последнего alpha перевод строки и нужен ли он для чтения.

Строки и освобождение файла

Файл содержит три строки; последняя не имеет завершающего перевода. Печатается 3. Для alpha номера совпадений — 1 и 3: Упражнение 27.11.

Files.writeString и Files.readAllLines закрывают свои ресурсы. finally выполняет попытку удалить временный файл, в том числе после отказа чтения; удаление тоже может выбросить IOException.

Сверить прогноз. Добавить пустую строку между alpha и beta и пересчитать номера совпадений: 1 и 4. Сопоставить этот опыт с Files.lines, где поток закрывает использующий его код. Самостоятельный файловый опыт: Самостоятельные опыты.

Размеры и состояние результата

Упражнение 27.3 связывает позиции двухмерных данных. По условию матрица квадратная. Возьмите несимметричный вход, чтобы обмен строк и столбцов был виден. Допустимый вход содержит одинаковое число строк и чисел в каждой строке. Чтение чисел, проверка формы и запись — разные этапы.

Карточка задаёт допустимую непустую квадратную матрицу int; прямоугольный и повреждённый вход находятся вне её договора. Вход читают целиком до открытия выхода. Отсутствующий вход сохраняет прежний результат; самокопирование отклоняется. Ошибка записи может оставить частичный выход, атомарность не требуется. Политика публикации: Публикация файлового результата.

Сравнение байтов и длины

Для Упражнение 27.6 одинаковый префикс ещё не означает равенства. После него один поток может закончиться, а другой дать очередной байт. Сравните пары равных файлов, разных байтов и разных длин.

Значение -1 означает конец входа, а IOException — отказ чтения. Два ресурса и исключения закрытия: Порядок открытия и закрытия; буферное чтение: Байтовый поток и конец входа.

Проект сохранения

Упражнение 28.1 соединяет предметную модель, поиск и сохранение.

Согласуйте отдельный срок. На опубликованных трёх самолётах получите суммарную вместимость, грузоподъёмность, порядок по дальности и отбор по расходу [1500, 2400]. Затем покажите сохранение, повторную загрузку и обновление через коннектор. Объясните выбранные поля static и transient после загрузки. Дополнительный поиск без совпадений помогает проверить поведение пустого результата.
