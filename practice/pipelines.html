Целевой тип лямбды

Predicate<Integer> задаёт метод boolean test(Integer value). Предскажите два ответа условия n > 0:

Predicate<Integer> positive = n -> n > 0;
System.out.println(positive.test(-2));
System.out.println(positive.test(3));

Тело выполняется при каждом test с новым аргументом.

Сначала рассмотреть присваивание лямбды переменной: получен ли уже результат проверки числа? Затем указать аргумент каждого вызова test и получить прогноз двух результатов.

Попросить заменить Predicate на IntPredicate и назвать изменение метода вызова: он остаётся test, но параметр примитивный. Затем для сдвига числа на заданную величину попросить назвать два входа и результат.

Собственная форма действия

Предыдущее условие даёт false для -2 и true для 3. Для сдвига числа форма другая: два int → один int.

@FunctionalInterface
interface IntAdjustment {
    int adjust(int value, int offset);
}

Реализация метода adjust и его вызов:

IntAdjustment shift = (value, offset) -> value + offset;
System.out.println(shift.adjust(4, -1)); // 3

Сигнатура содержит два входа. В выбранной задаче о делимости либо дискриминанте потребуется другая форма абстрактного метода.

Восстановить интерфейс по вызову adjust: два int поступают, один int выходит. Для самостоятельной работы попросить назвать входы и результат выбранной задачи.

Промежуточная и терминальная операции

Предскажите вывод и укажите вызов, запускающий обработку:

var stream = Stream.of(1, 2, 3).map(n -> n * 2);
System.out.println("built");
stream.forEachOrdered(n -> System.out.println("take " + n));
System.out.println("done");

Получить прогноз до перехода. Попросить назвать данные, которые потребитель получит из map, и место начала прохода.

Порядок терминальной печати

built
take 2
take 4
take 6
done

map задаёт ленивое преобразование; forEachOrdered запускает проход и печатает результаты в порядке встречи элементов.

Сверить прогноз. Убрать мысленно forEachOrdered целиком и назвать оставшийся вывод: built и done. Связать обязательную печать с терминальным потребителем.

Источник и результат фильтрации

var source = new ArrayList<>(List.of(-2, 3, 0, 3));
var selected = source.stream().filter(n -> n > 0).toList();
System.out.println(selected); // [3, 3]
System.out.println(source);   // [-2, 3, 0, 3]

Отбор сохраняет обе тройки. Структура источника остаётся прежней; полученный список запрещает изменения через свои методы.

Спросить, где удалился -2: он отсутствует в результате, а в source остался. Связать это с задачей удаления чётных: если договор требует записи в прежний массив, нужно отдельно выполнить эту запись.

Создание и вызов действия

Function<Integer, String> задаёт метод String apply(Integer value). Клиент передаёт число, реализация возвращает подпись:

Function<Integer, String> label = n -> "n=" + n;
System.out.println(label.apply(3)); // n=3

Переменная хранит действие Integer → String. При вызове apply(3) появляется строка. Для иной формы сначала выбирают абстрактный метод, затем записывают совместимую лямбду.

Формы: Глава 18.

Предложить спрогнозировать второй apply с -2 и отметить отсутствие накопленного состояния. Переход к массиву сохраняет эту же функцию для каждого элемента.

Тип массива результата

Integer[] source = {1, 2, 3};
String[] result = Arrays.stream(source)
    .map(n -> "n=" + n)
    .toArray(String[]::new);
System.out.println(Arrays.toString(result)); // [n=1, n=2, n=3]

Конструкторная ссылка задаёт тип нового массива. Для пустого источника получится пустой String[]. Сигнатура: Источники и операции.

Попросить восстановить тип потока до и после map. В задаче фильтрации строк тип элемента сохранится, но результат всё равно должен быть новым массивом. Показать, где этот выбор закрепляет toArray.

Устойчивая сортировка списка

var words = List.of("bb", "a", "cc").stream()
    .sorted((left, right) ->
        Integer.compare(left.length(), right.length()))
    .toList();
System.out.println(words); // [a, bb, cc]

bb и cc имеют равные ключи. Упорядоченный поток сохраняет их взаимный порядок при сортировке. Лямбда-компаратор задаёт отношение по длине.

Поменять исходные bb и cc местами и попросить новый результат. Перенести правило на геометрически равноудалённые точки: дополнительный ключ по координате изменил бы требуемую устойчивость.

Отбор и сортировка

Упражнение 25.2 требует длину строго больше порога и новый массив с прежним порядком подходящих строк.

Упражнение 25.3 задаёт целые координаты [-10000, 10000]. Квадрат расстояния точно помещается в int. Для равных геометрических расстояний сохраняется исходный порядок.

Предложить пару (1:10), (2:0) и спросить, какой признак определит порядок. Затем пару (3:4), (0:5): они равноудалены.

Границы результата отбора

Строка с длиной ровно пороговой не проходит строгий фильтр. Пустой отбор даёт новый пустой массив; исходный массив сохраняется. Длина измеряется char через String.length().

Повторные точки сохраняются. Компаратор обязан возвращать равенство для равных расстояний; допустимый диапазон исключает переполнение целого квадрата расстояния.

Попросить три входа: строка на границе, только неподходящие строки, две одинаковые подходящие строки. Затем восстановить, какие именно свойства проверяет каждый вход.

Передача поведения

Упражнение 25.5 получает условие и две функции, затем возвращает Function<T, R>.

Predicate<? super T> получает аргумент T. Function<? super T, ? extends R> принимает тот же аргумент и выдаёт результат, подходящий для R. Созданной функции аргумент передадут позже.

Нарисовать путь T к предикату и выбранной ветви, затем путь результата к R. Раскрыть смысл границ ? super T и ? extends R; класс и наличие static остаются выбором автора программы.

Отложенная ветвь на готовом условии

Supplier<String> fallback = () -> {
    System.out.println("fallback");
    return "none";
};
boolean missing = false;
String result = missing ? fallback.get() : "ready";
System.out.println(result); // ready

При missing = true выводятся fallback и none. Создание поставщика само не вычисляет запасную строку.

Восстановить обе трассы и точку get. В самостоятельной задаче выбор тоже нужно отложить: её предикат и аргумент появятся при apply возвращённого действия.

Выбранная ветвь функции

Для ternaryOperator создание новой функции не вызывает условие и переданные функции. Каждый apply проверяет условие один раз и вызывает выбранную ветвь один раз на том же аргументе. Повторный apply выполняет выбор заново.

Проверьте обе ветви и невыбранную функцию, которая выбросила бы исключение. Отказ условия либо выбранной ветви передаётся клиенту без замены.

Попросить указать, где разместить наблюдение вызовов: в condition и двух функциях. Сначала проверить отсутствие вызовов при создании, затем точную последовательность для прямого apply. Это договор собственной функции, а оптимизации Stream к нему не относятся.

Подсчёт по группам длин

var counts = List.of("a", "bb", "c").stream()
    .collect(Collectors.groupingBy(
        String::length, Collectors.counting()));
System.out.println(counts.get(1)); // 2
System.out.println(counts.getOrDefault(3, 0L)); // 0

Ключ выбирает группу, counting() считает её элементы. Порядок ключей карты не задан. Запрос отсутствующего ключа получает ноль.

Восстановить группы длины 1 и 2 вручную. Для задачи частот студент должен выбрать иной ключ и форму источника; если отчёт следует списку запросов, порядок задаёт этот список.

Источник кодовых единиц

System.out.println("a a".chars().boxed().toList());
// [97, 32, 97]
System.out.println("\uD83D\uDE00".chars().boxed().toList());
// [55357, 56832]

chars() выдаёт int-значения кодовых единиц UTF-16. Суррогатная пара содержит две единицы; пробел учитывается. boxed() позволяет использовать обобщённые операции Stream.

Сначала назвать частоту 97, затем спросить о количестве ключей второй строки. Подчеркнуть, что условие считает кодовые единицы; переход к codePoints изменил бы предметную задачу.
