Запуск программы

Запускаемый класс

Исходник src/course/reading/Reading.java и порядок подготовки каталога: Глава 25. Команды выполняются с JDK 25 из каталога, содержащего src.

javac --release 25 -encoding UTF-8 -d out src/course/reading/Reading.java
java -cp out course.reading.Reading

После изменения исходника какой из двух шагов обновляет выполняемый код? Почему корнем поиска остаётся out?

javac создаёт класс; полное имя задаёт путь к нему относительно корня. После изменения исходника повторная компиляция обновляет выполняемый класс.

Проследить путь от имени course.reading.Reading к файлу out/course/reading/Reading.class. Предложить мысленно заменить classpath на out/course и получить ошибочный путь поиска. Затем связать две команды с двумя разными файлами: редактирование .java само по себе не меняет .class. Если студент запускает через IDE, попросить найти действие сборки перед запуском.

Получение числового значения

Вход, заданный при запуске

После компиляции java -cp out CountArgument 12 передаёт строку "12". Полный файл и команда компиляции: Аргумент запуска и его числовое значение. Внутри main параметр args — массив строк:

String token = args[0];
System.out.println(token + 1);              // 121
System.out.println(Integer.parseInt(token) + 1); // 13

Почему одинаковые видимые цифры дали разные результаты? Строковое соединение и числовое сложение выбираются по типам.

Попросить назвать типы обоих операндов каждого +. Строка "12" сохраняет представление ввода; parseInt создаёт числовое значение для арифметики. Отдельно уточнить, что написанное после имени класса попадает в args, а введённое позже в консоли читается из другого источника.

Наличие аргумента

Тело main класса CountArgument:

if (args.length == 0) {
    System.out.println("Укажите количество страниц");
    return;
}
String token = args[0];
System.out.println(token + 1);
System.out.println(Integer.parseInt(token) + 1);

Без аргументов выводится Укажите количество страниц; с 12 — строки 121 и 13, как в предыдущем опыте. Проверка количества делает индекс допустимым. Правильность числовой записи здесь предполагается; abc вызовет NumberFormatException.

Проследить запуск без слов после имени класса: длина равна нулю, печатается сообщение, return завершает метод. Затем пройти запуск с 12. Сопоставить доступность компонента массива и корректность его содержимого: проверка длины устанавливает только первое. Для лабораторной перечень ошибочных входов берётся из её условия.

Числа стандартного ввода

Для трёх заранее корректных целых достаточно чтения токенов:

var input = new java.util.Scanner(System.in);
int first = input.nextInt();
int second = input.nextInt();
int third = input.nextInt();

Пробелы и переводы строки разделяют числа. Имена переменных в своей задаче выберите по смыслу данных. Полная форма и десятичный ввод: Целое число: Scanner.

Показать один и тот же набор как 4 5 6 и как три строки: последовательность токенов одинакова. Попросить объяснить, сколько успешных чтений предполагает фрагмент. Перед обращением к справочнику сформулировать конкретный вопрос: чтение целых или чтение десятичного числа с точкой.

Тип промежуточного выражения

Деление и преобразование

int pages = 7;
int days = 2;
double first = pages / days;
double second = (double) pages / days;

Какой тип у правой части каждого присваивания?

В первом int / int даёт 3, затем 3.0. Во втором деление даёт 3.5. Преобразование операнда должно предшествовать делению.

Разобрать присваивание справа налево по смысловым этапам: сначала вычислено выражение, затем его значение помещено в переменную. В первом случае в double попадает уже целое 3. Во втором преобразование меняет тип левого операнда деления. Попросить указать место преобразования в выражении; один только тип получателя не объясняет различие.

Различающие входные данные

С данными 8 и 2 обе версии дают 4.0. Этот запуск не различает реализации.

С данными 7 и 2 потеря дробной части становится видимой.

Сопоставить оба набора с одной ошибочной реализацией. Делимость без остатка маскирует потерю дробной части. Предложить выбрать собственную пару с ненулевым остатком и получить ожидаемое среднее до запуска.

Большой промежуточный результат

int records = 50_000;
long first = records * records;
long second = (long) records * records;

Первое умножение уже завершилось в int: результат -1794967296. Второе вычисляет 2500000000 в long.

Если в формуле несколько умножений, проследите тип каждого промежуточного выражения, начиная слева. Числовое повышение перед операцией

Сначала вычислить математическое произведение и сопоставить его с верхней границей int. Затем показать, какое значение расширяет первое присваивание. Для цепочки из нескольких множителей попросить обвести первую операцию: позднее приведение не восстанавливает потерянные биты. В задаче изображения студент самостоятельно определяет диапазон произведения размеров и глубины цвета.

Выбор единицы

double seconds = 90.0;
double minutes = seconds / 60.0;

Получилось 1.5 минуты. Тип определяет вычисление, а коэффициент и подпись — смысл результата. Правильный тип не исправит перепутанное преобразование единиц.

В собственной задаче сначала определите единицу входа и выхода.

Восстановить размерность выражения: секунды делятся на число секунд в минуте. Если заменить деление умножением, тип double останется допустимым, но смысл результата нарушится. Предложить проверить формулу на одной минуте. Связать это наблюдение с байтами и мебибайтами в условии лабораторной.

Условие как договор о данных

Логический результат

int pages = 7;
boolean hasPages = pages > 0;

В Java условие требует логического значения: if (pages) не подходит. В записи границы важно различить «больше» и «не меньше».

Для объединённого требования сначала выделите отдельные сравнения.

Сопоставить значения pages = 0 и pages = 1. Получаются два значения boolean, которые можно сохранить, вывести или использовать как условие. Попросить записать отдельно два ограничения составного требования, затем назвать подходящую логическую операцию. Число и признак наличия страниц играют разные роли.

Порядок проверок

int pages = 7;
int days = 0;
boolean positive = days != 0 && pages / days > 0;
System.out.println(positive); // false

При ложной левой части && не вычисляет правую. Замена на & требует выполнить деление и вызывает ArithmeticException.

Эта трасса разобрана в теории: Логические операции и короткое замыкание. Полный опыт с порядком вычисления: Опыты с вычислением выражений.

Пройти выражение слева направо при days = 0: получить ложь и остановить трассу до деления. Затем мысленно заменить && на & и показать точку отказа. Предложить случай с ненулевым делителем, чтобы увидеть, когда правая часть всё-таки вычисляется. Короткое замыкание влияет на допустимые действия программы.

Границы промежутка

Для полуинтервала (-2, 4] проверим -3, -2, 1, 4, 5. Ответы по порядку: false, false, true, true, false.

Внутренняя точка показывает обычный случай. Равенство концам различает строгие и нестрогие сравнения; внешние точки проверяют оба направления.

Изменение левой границы на замкнутую меняет только ответ для -2.

Отметить включённые точки на числовой прямой и объяснить каждый показанный ответ. Сопоставить изменение левой границы с заменой одного сравнения. В лабораторной все четыре вида промежутка должны следовать собственному математическому условию.

Самостоятельное применение

Связь с лабораторной работой

В Глава 3 запуск с аргументом используется для приветствия, числовая модель — для размера изображения, логические границы — для интервалов.

Определите преобразования и промежуточные типы по данным и требуемому результату каждой задачи.

Попросить для каждой задачи назвать источник данных и вид результата. Приветствие использует строку аргумента, расчёт изображения — числовые значения, промежутки — логические ответы. Обсудить, какие части разобранных примеров помогают начать работу.

Представление решения

Покажите исходник, команды запуска и несколько содержательных входов. Объясните один расчёт по промежуточным типам и один результат на границе.

Для изображения найдите пример, на котором счёт в int уже недостаточен. Для приветствия проверьте отсутствие аргумента. Для интервала — оба конца.

Выбрать один предложенный студентом вход и проверить, какую ошибку он способен обнаружить. Если несколько запусков показывают одно свойство, предложить добавить случай с другой причиной возможного отказа. В объяснении расчёта должны появиться тип промежуточного выражения и единица результата; в объяснении границы — строгость сравнения.
