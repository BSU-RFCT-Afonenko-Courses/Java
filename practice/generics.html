Предложить вспомнить один вызов из теории, в котором значение возвращается с тем же типом, с которым его передали. Вопрос о нужной операции возвращать к конкретной строке каждого разбираемого примера.

Чтение сохранённой строки

final class ObjectBox {
    private final Object value;
    ObjectBox(Object value) { this.value = value; }
    Object get() { return value; }
}

ObjectBox title = new ObjectBox("Java");
String text = (String) title.get();
System.out.println(text.length()); // 4

Почему клиент восстанавливает String приведением? В объявлении get указан только Object. При замене содержимого на 25 приведение всё ещё скомпилируется, но при чтении возникнет ClassCastException.

Клиенту заранее известно, что здесь нужна строка. Как связать это требование с созданием коробки и типом результата get()?

Повторить опыт из Контейнер с типом Object. Попросить указать объявление, по которому компилятор определяет тип title.get(). Обсудить, почему успешная запись строки сама не меняет это объявление.

Один параметр в трёх местах

final class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
}

Box<String> title = new Box<>("Java");
String text = title.get();

Одно имя T связывает принимаемое значение, поле и результат чтения. При Box<String> все три места согласованы со String, поэтому Box<String> title = new Box<>(25) отвергается уже при компиляции.

Для чисел выбираем Box<Integer> и сохраняем то же тело класса. get() использует T, объявленный у Box; собственного параметра у этого метода нет. Разбор: Параметр типа.

Попросить проследить путь строки от аргумента конструктора к результату. Если заменить T на Object только в результате get, клиент снова потеряет строковый тип.

Проверка общего тела

Вставим в Box<T> ещё один метод:

int length() { return value.length(); } // ошибка компиляции

Почему создание Box<String> не делает этот метод допустимым? Тело класса должно работать для каждого разрешённого аргумента типа. У T здесь есть только граница Object, которая не предоставляет length().

Разберите две проверки: какие операции разрешены автору Box<T> и какое значение разрешено клиенту Box<String>?

Объявление связывает типы. При помещении в коробку объект не копируется. Если коробка хранит изменяемую книгу, обе ссылки по-прежнему ведут к этой книге: Общий объект в контейнере.

Разместить ошибочный метод в отдельной копии коробки. До компиляции сравнить два разрешённых применения, Box и Box. Доступ к конкретной строковой операции вернуть клиенту после get().

Обмен элементов

Теперь нужно поменять местами два элемента массива. Какие действия над самими значениями нужны при переходе от строк к целым числам?

static <T> void swap(T[] values, int i, int j) {
    T saved = values[i];
    values[i] = values[j];
    values[j] = saved;
}

Сохраняем одну ссылку и переставляем две ссылки. Сравнивать или складывать значения не требуется, поэтому у T нет дополнительной границы. Тело подходит и String[], и Integer[].

Параметр объявлен самим методом: он связывает массив с временным значением при каждом вызове. Массив существует, индексы допустимы. Разбор: Перестановка элементов.

Проследить обмен на names = {“Ada”, “Lin”}, затем на {4, 9}. Попросить объяснить, зачем saved сохраняется до первой записи в массив. Ни один шаг не создаёт копию объекта элемента.

Выбор большего

Для выбора большего уже нужно узнать порядок. Что позволит общему коду сравнить два T, если оператор > для произвольных объектов не определён?

static <T extends Comparable<T>> T larger(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}

System.out.println("Ada".compareTo("Lin")); // -11
System.out.println(larger("Ada", "Lin")); // Lin

Граница предоставляет метод compareTo. Его результат — int: знак сообщает порядок, поэтому его можно сравнить с нулём. Здесь -11 < 0, выбирается правый аргумент; при равенстве сохраняется левый.

Аргументы отличны от null, сравнение задаёт согласованный порядок. Разбор: Сравнение значений.

Спросить, почему проверка == -1 не подходит для результата сравнения. Вернуть обсуждение к выбору одного из исходных объектов.

Кандидат на максимум

Как использовать выбор большего для списка [4, 9, 2]? После сравнения 4 и 9 нужно сохранить 9 для сравнения с 2. Назовём сохранённого кандидата best.

T best = values.get(0);

Начинаем с первого элемента: он уже имеет нужный тип и принадлежит данным. Числовой ноль не подходит строкам и может оказаться больше всех отрицательных чисел. Для пустого списка первый кандидат отсутствует.

Следующий value сравниваем с best; это прежний выбор из двух:

if (value.compareTo(best) > 0) best = value;

Если значения равны, кандидат остаётся прежним. После шага он максимален среди всех уже просмотренных элементов.

Попросить назвать best после сравнения с 9, затем с 2. Сопоставить шаг с best = larger(best, value): ветвь равенства оставляет тот же объект. После каждого шага попросить назвать уже просмотренные элементы и указать среди них максимальный.

Повторение шага

Первый элемент уже стал кандидатом. Поэтому обход начинается с индекса 1:

static <T extends Comparable<T>> T maximum(List<T> values) {
    if (values.isEmpty()) throw new IllegalArgumentException("Empty list");
    T best = values.get(0);
    for (int i = 1; i < values.size(); i++) {
        T value = values.get(i);
        if (value.compareTo(best) > 0) best = value;
    }
    return best;
}

get(i) читает элемент, size() ограничивает обход. Когда просмотрен весь список, свойство best даёт искомый максимум. Строгое > 0 сохраняет первый из равных максимумов.

Список и элементы отличны от null, порядок согласован. Разбор: Поиск максимума.

Для n элементов выполняется n - 1 сравнений. Оценка общего времени зависит также от стоимости get(i) и самого compareTo.

До чтения цикла предложить назвать первый ещё не просмотренный индекс. Проверить рассуждение на одном элементе: цикл не нужен, кандидат уже является ответом. Отказ пустого списка относится к этому методу.

Диапазон самостоятельного поиска

В массиве {4, 9, 2, 7} диапазон [1, 3) содержит 9 и 2: индекс 1 включён, индекс 3 исключён. Диапазон [2, 3) содержит ровно один элемент 2.

Какие позиции следует просмотреть для [2, 4)? В нём максимум 7, хотя максимум всего массива — 9.

В самостоятельном задании диапазон заранее допустим и непуст: программная проверка этих предпосылок не требуется. У массива размер доступен через length, у списка — через size().

Условие допускает обе изученные границы Comparable<T> и Comparable<? super T>, а при нескольких максимумах — любой из них.

Сумма попарных произведений

Вернёмся к dot из теории. Для [1, 2] и [3, 4] нужно получить 1·3 + 2·4 = 11. Для [1+i, 2] и [3, 4−i] — (1+i)·3 + 2·(4−i) = 11+i.

Какие действия нужны одному циклу для обоих случаев?

  • Получить начальный ноль суммы.
  • Умножить элементы с одним индексом.
  • Прибавить произведение к накопленному результату.

У произвольного T нет операторов + и *. Передадим объект, который умеет выполнять эти действия над выбранным типом. Здесь сумма вычисляется без комплексного сопряжения.

Разбор: Контракт арифметических операций.

Попросить назвать три действия по формуле до перехода к интерфейсу. Уточнить, что Number предоставляет преобразования чисел, а нужные здесь сложение и умножение с результатом T требуют собственного контракта.

Контракт операций

interface Arithmetic<T> {
    T zero();
    T add(T left, T right);
    T multiply(T left, T right);
}

Одно T связывает операнды и результат: произведение можно прибавить к сумме, а новую сумму — использовать на следующем шаге.

DoubleArithmetic реализует эти действия над Double: zero() возвращает 0.0, методы add и multiply используют + и *. ComplexArithmetic возвращает Complex и вычисляет его действительную и мнимую части.

В этом опыте списки, элементы, объект арифметики и результаты операций отличны от null; операции не изменяют переданные элементы.

Попросить проследить тип результата multiply до аргумента add. При необходимости открыть реализацию арифметики в теории: знание конкретных числовых операций находится именно в этих классах.

Построение общего цикла

Почему начинать нужно с zero()? У суммы ещё нет слагаемых; добавление первого произведения должно дать это произведение. Для пустых векторов останется тот же ноль.

T result = arithmetic.zero();
for (int i = 0; i < left.size(); i++) {
    T term = arithmetic.multiply(left.get(i), right.get(i));
    result = arithmetic.add(result, term);
}

Это тело dot после проверки равенства длин. При разных длинах некоторому элементу не хватает пары. Длины проверяет программа; параметр T связывает типы элементов, промежуточных значений и результата.

Для действительных входов [1, 2] и [3, 4] сумма меняется 0 → 3 → 11. Как пройдёт тот же цикл с комплексной арифметикой?

Предложить найти в теле каждую операцию объявленного контракта. Для Double операции выполняются с обычным округлением double; значения 0.0, 3.0 и 11.0 в этом опыте представимы точно.

Смена арифметики

В первом вызове T связывает элементы и арифметику для Double:

double real = dot(List.of(1.0, 2.0), List.of(3.0, 4.0),
                  new DoubleArithmetic()); // 11.0

Второй вызов использует record Complex(double re, double im) из теории:

Complex value = dot(
    List.of(new Complex(1, 1), new Complex(2, 0)),
    List.of(new Complex(3, 0), new Complex(4, -1)),
    new ComplexArithmetic()); // части результата: 11.0 и 1.0

Произведения равны 3+3i и 8−2i; накопленная сумма меняется 0 → 3+3i → 11+i. Изменились данные и объект с операциями. Цикл по-прежнему умножает пару элементов и прибавляет результат.

Начальный элемент вычисления

Пусть другой объект арифметики возвращает 1.0 из zero(), сохраняя обычные сложение и умножение. Все сигнатуры по-прежнему используют Double. Какой результат даст прежний цикл?

Для [1, 2] и [3, 4] получится 1 → 4 → 12. Для двух пустых списков получится 1. Оба результата имеют нужный тип. Начальное значение нарушает смысл суммы: оно должно оставлять первое слагаемое неизменным.

Правило для подсчёта

Обобщённый метод подсчёта получает правило выбора элементов. Например, одно правило выбирает нечётные целые числа, другое — строки длиннее трёх символов.

Что должен узнать общий алгоритм о каждом элементе? Достаточно ответа, удовлетворяет ли он свойству. Выбор свойства передадим отдельному объекту, как в dot передавали конкретную арифметику.

Определение нечётности и обращение к длине строки принадлежат разным правилам. Обход и подсчёт должны работать с любым переданным правилом по его общему контракту.

Действия пользователя контейнера

Теперь значения нужно хранить между вызовами. Пользователь помещает A, затем B, после чего просит извлечь один элемент. Тип содержимого определяет тип аргумента и результата, а выбор контейнера — порядок.

Контейнер Помещение Извлечение Первым вернётся
Очередь void put(T value) T get() A: первый помещённый
Стек void push(T value) T pop() B: последний помещённый

Для строк T = String, для целых чисел — T = Integer. Извлечение возвращает значение и удаляет его из контейнера.

Как изменится доступное место после извлечения? Что должна означать попытка добавить значение, если место уже занято целиком?

Связать тип аргумента и результата с разобранным ранее примером коробки. Очередь сохраняет порядок FIFO, стек — LIFO.

Вместимость и отказ

Пусть вместимость равна двум. После добавления A и B свободного места нет. Попытка добавить C должна сообщить отказ и сохранить прежние значения в прежнем порядке.

Теперь извлечём один элемент и снова добавим C:

Контейнер Извлечено Порядок следующих извлечений
Очередь A B, затем C
Стек B C, затем A

Успешное извлечение освобождает место. У пустого контейнера нет значения для извлечения — нужен второй вид отказа.

Массив для выбранного типа

В этой работе хранилищем служит переданный конструктору массив. Поле T[] допустимо. Создание new T[n] запрещено: параметр T не предоставляет фактический тип компонента для нового массива.

Какой массив позволит контейнеру Number хранить и целые, и дробные числа?

Number[] safe = new Number[2];
Number[] narrow = new Integer[2];
safe[0] = 2.5;
// narrow[0] = 2.5; // ArrayStoreException

Number[] принимает Double, а фактический Integer[] отвергает его при записи. Поэтому условие требует совпадения типа компонента массива с аргументом типа контейнера; проверять это программно не требуется.

Причины: Ограничения выполняемого представления. Форма хранилища: Массив как хранилище.

Тип переменной narrow разрешает запись Number; отказ создаёт проверка типа компонента самого массива Integer[]. Условия также оговаривают положительную вместимость и дальнейшее использование массива только контейнером.

Тип списка и доступные действия

Массив Integer[] разрешено рассматривать как Number[], но запись Double завершилась отказом. Какая запись запрещается заранее у списка?

List<Integer> integers = new ArrayList<>(List.of(1, 2));
// List<Number> numbers = integers; // ошибка компиляции
List<? extends Number> source = integers;
Number first = source.get(0);
// source.add(2.5);                // ошибка компиляции

Через List<Number> можно было бы записать Double в список целых. ? extends Number сохраняет безопасное чтение. Неизвестный аргумент не позволяет выбрать для добавления значение, отличное от null.

Что изменит source.clear()? Удаление допускается по типам; в данном ArrayList оно очистит тот же объект, видимый через integers.

Нужны импорты java.util.List и java.util.ArrayList. Повторить рассуждение об инвариантности из Инвариантность параметризованных типов; показать различие между допустимостью присваивания и проверкой массивной записи. Уточнить: неизвестность аргумента не означает неизменяемость списка.

Сообщение об отказе

Как сообщить вызывающему коду, что значение не удалось получить? Вспомним take: успешный вызов возвращает 7, другой путь создаёт отказ.

static class EmptyException extends Exception {
    EmptyException(String message) { super(message); }
}
static int take(boolean empty) throws EmptyException {
    if (empty) throw new EmptyException("empty");
    return 7;
}

throw выполняется в ветви отказа. throws в объявлении сообщает клиенту, что такой выход возможен, и требует обработать или передать проверяемое исключение. Само объявление отказа не создаёт.

Проверяемый отказ операции: Проверяемый отказ операции.

Класс исключения и take — члены EarlyCheckedDemo. Предложить пройти ветви с false и true, назвав для каждой результат действия. Контейнер применит то же средство к своему состоянию.

Реакция вызывающего кода

static int forward(boolean empty) throws EmptyException {
    return take(empty);
}

try {
    System.out.println(forward(true));
    System.out.println("после успешного вызова");
} catch (EmptyException failure) {
    System.out.println(failure.getMessage()); // empty
}
System.out.println("дальше");

forward передаёт отказ клиенту, catch выбирает реакцию. В этом вызове печать после успеха пропускается; после обработчика выводится «дальше».

В контейнерной задаче клиент после отказа должен увидеть прежнее состояние. Исключение само ничего не откатывает: порядок действий внутри операции должен обеспечить это требование.

Метод forward расположен в EarlyCheckedDemo, try/catch — внутри main. Определить, где компилятор потребует throws, если убрать обработчик.

Самостоятельная работа

Примените разобранные связи типов и правила состояния к новым условиям:

  • Максимум диапазона: выделить область поиска и сохранить тип результата.
  • Подсчёт по свойству: отделить общее действие от правила для конкретного типа элементов.
  • Очередь либо стек: связать тип содержимого, порядок извлечения и состояние при успешных действиях и отказах.

Полный состав и представление результата — в лабораторной работе. В пределах условий выберите устройство программы самостоятельно. Перед реализацией сформулируйте ожидаемый результат своих примеров.

Формы объявлений: методы и классы.

Предпосылки из условий не превращать в дополнительные проверки входа. Уточнить, что оба метода обязательны, а из двух контейнеров выбирается один.
