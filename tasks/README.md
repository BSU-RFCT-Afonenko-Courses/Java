# Исследовательские рефераты по Core Java

Книга `tasks/`, прежде `essay/`, содержит 60 тем в 12 разделах и открытый демонстрационный комплект Unicode. Условия исследований, контрольные, решения, ID и проверочные проекты сохранены. Теория находится в `theory/`, справочные приложения — в `handbook/`; слайды лекций и практики ссылаются на эти материалы.

## Работа с книгой

Нужны Quarto 1.11.5, CUE 0.17.1; для проектов — JDK 25 или новее и совместимый Gradle (для JDK 25 — [9.1 или новее](https://docs.gradle.org/current/userguide/compatibility.html#java_runtime)). Расширения включены в репозиторий. Запускайте команды из корня Java-курса:

```sh
quarto render --profile full --fail-if-warnings
quarto render --profile student --fail-if-warnings
quarto preview --profile student --no-browser --port 4200
```

Корневая сборка согласует пять частей и межкнижные ссылки, проверяет учебную модель и создаёт стартовые ZIP-архивы. Сайты находятся в `_site-full/` и `_site-student/`, рефераты — под `tasks/`. Публикуйте студенческий сайт. Отдельный рендер каталога не разрешает ссылки на остальные книги.

## Авторский формат

В разделе находятся вводный `index.qmd` и общая подготовка `_prerequisites.qmd`. В теме — `index.qmd`, включаемый `_control.qmd` и проекты. Оглавление задаёт `_quarto.yml`; указатели по семестрам и сложности строятся из метаданных глав. Уровни `introductory`, `intermediate` и `advanced` соответствуют У1, У2 и У3.

Банк явно включён в каталогах 60 канонических тем, где `_metadata.yml` задаёт `exercise-bank: true`. Каждая `exr-*` задача содержит собственные difficulty и time в минутах. Сложность страницы нужна указателям; она не наследуется задачей. Начальные оценки времени являются авторскими оценками по содержанию и сложности, а не измерениями.

Открытое исследование использует `statement-visibility="open"`, три контрольные задачи — `restricted`. Core скрывает restricted условия, связанные решения и ссылки назначений в student; отдельная профильная обёртка контроля не применяется. Grading notes и ключи отделены от условия. Полный профиль предназначен для преподавательской проверки, студенческий — для публикации. Публичный Git отдельно раскрывает исходники курса.

Одна QMD описывает одну работу `assessment.kind: test`; список `.task-items` назначает три контрольные задачи в исходном порядке. Defaults назначений — required/individual, stage можно не указывать. Общие параметры PrairieLearn применяются только к явно подключившим `assessment.prairielearn` работам. Native assessment и фактическое число оцениваемых попыток проверяются отдельно в PL.

Открытая демонстрация Unicode не включает банк. Её `exm-*` прогнозы и самопроверка, `sol-*` объяснения и стартеры сохраняют обычную семантику Quarto и публичность. Не следует преобразовывать эти пары в банковские решения. Для новых банковских решений применяется одинаковый suffix в том же QMD или анонимная `.solution` внутри задачи.

Core проверяет модель и проекцию аудитории; Presentation оформляет оставшиеся блоки; QRC связывает адреса без копирования условий. Общая подготовка включается внутри соответствующей задачи. [Рекомендации оформления](../docs/current-authoring.md) закрепляют версии и границы публикации.

## Исполняемые комплекты

- `failures-boundaries/charset-decoding/`: три задания по обработке UTF-8, стартовые проекты, авторские решения и автоматические проверки; контроль и архивы доступны в `full`.
- `text-arrays/unicode-demonstration/`: открытая демонстрация с тремя практическими заданиями и стартовыми архивами; она не входит в контрольные PrairieLearn.
- `prairielearn-pilot/`: одна самостоятельная Java 25 задача для сдачи исходника в PrairieLearn. Starter не использует Gradle или внешние зависимости: `javac --release 25 UnicodeSlice.java Examples.java`, затем `java Examples`; условие и файлы выдаются в назначенной работе PL.

Остальные темы содержат описания и условия контроля; каталоги проектов пока служат местами будущей реализации. Проверка авторского контракта не превращает их в готовые исполняемые задания.

В двух существующих Gradle-комплектах `student/` содержит самостоятельный Gradle-проект, `reference/` — авторское решение, `tests/` — дополнительные проверки. Из каталога соответствующего проекта:

```sh
gradle -p student test
gradle -p student -Preference -Pgrading test
```

Первая команда проверяет стартовый проект, вторая — авторское решение полным набором тестов. Версия Java и зависимости зафиксированы в проектах. Часть проверок стартового кода до выполнения задания закономерно не проходит.

`{{< project-download exr-id >}}` создаёт ZIP из каталога, явно указанного в `project-download.resources`. Папки `reference/`, `tests/` и результаты сборки не входят в стартовый архив. ZIP формируется при сборке; условия остаются в QMD.

[Основной README](../README.md) описывает сборку и проверки, [карта переноса](../docs/original-author-migration.md) — новые пути.
