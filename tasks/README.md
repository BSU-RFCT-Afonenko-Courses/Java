# Задания по Java

`tasks/` — одна книга Quarto. Раздел `essays` содержит исследовательские
рефераты; `assessments` — самостоятельные контрольные работы,
`demonstrations` — учебные демонстрации, `exercises` — линейные лабораторные задания.

| Файл или каталог | Назначение |
| --- | --- |
| `index.qmd` | Введение в книгу заданий |
| `essays.qmd` | Общие требования к рефератам и их защите |
| `essays/*.qmd` | 12 тематических документов, по пять постановок реферата |
| `exercises/*.qmd` | Тематические документы лабораторных работ |
| `assessments/*.qmd` | Одна контрольная работа на документ; условия, назначения и критерии |
| `demonstrations/unicode.qmd` | Открытый учебный пример |
| `projects/<kind>/<theme>/<task>/` | Полные деревья проектов с заготовками, решениями и проверками |

## Авторский формат

Общий семестр и ключевые слова задаются в метаданных тематического документа.
У каждой банковской задачи собственные `difficulty` и `time` в минутах.
Общая подготовка находится в начале темы; постановки ссылаются на неё по ID.
Индивидуальные предварительные знания остаются рядом с условием.

Банк включён в `essays/_metadata.yml`, `exercises/_metadata.yml` и `assessments/_metadata.yml`.
Рефераты открыты; контрольные условия restricted. Одна контрольная работа
имеет собственный `assessment.kind` и список `.task-items`. Ответы, решения
и `.grading-notes` редактируются рядом с соответствующей задачей.
Учебная демонстрация остаётся вне банка и использует обычные `exr`, `exm`, `sol`.

Оглавление книги перечисляет темы; оглавление тематической страницы —
постановки рефератов. Повторяющихся ручных `listing` нет. Автоматический
указатель по семестру и сложности относится к согласованной доработке инструментов.

## Назначение реферата

Студент выбирает конкретную постановку внутри темы; ей соответствует
контрольный комплект. Исходники описывают содержание, критерии и эту связь.
Записи студентов, подтверждения и персональный доступ принадлежат учебному
потоку на платформе и не включаются в разметку курса.

Для доработки платформы рассматриваются оба режима: выбор становится заявкой
и подтверждается преподавателем либо сразу закрепляется за студентом.
В студенческом списке должны оставаться лабораторные работы и назначенная
контрольная по реферату. Единый результат «Защита реферата» в ведомости
нужно проектировать отдельно от видимости контрольных комплектов.

## Представления и сборка

```sh
quarto render --profile student --fail-if-warnings
quarto render --profile full --fail-if-warnings
```

Команды выполняются из корня курса. Student включает лабораторные работы,
рефераты и учебную демонстрацию; full дополнительно включает контрольные работы как приложения.
Преподавательские страницы не входят в student оглавление, поиск или каталог QRC.
Дерево `projects/` исключено из прямого копирования в обоих профилях.

## Проекты

Проекты рефератов находятся в `projects/essays/<theme>/<task>/`, обычных
заданий — в `projects/exercises/<theme>/<task>/`. В обеих ветках сохраняются
тематические каталоги. Например, `essays/numbers.qmd` соответствует
`projects/essays/numbers/`, а `exercises/numbers.qmd` — `projects/exercises/numbers/`.

- `projects/exercises/numbers/integer-arithmetic/`: первая лабораторная по сумме
  и среднему двух int. Условие и скачиваемая заготовка доступны в обоих профилях.
- `projects/essays/failures-boundaries/charset-decoding/`: три задания по UTF-8 со стартовыми Gradle-проектами,
  авторскими решениями и проверками. Ссылки на стартеры остаются только в full.
- `projects/exercises/text-arrays/unicode-demonstration/`: три локальных проекта учебной демонстрации.
  Публичная страница содержит условия и разборы, без ссылок на архивы проектов.
- `projects/exercises/text-arrays/java25-pilot/unicode-slice/`: самостоятельный проект Java 25
  для контрольной `assessments/java25-pilot.qmd` и редактора PrairieLearn.
  Проверки — стандартный JUnit; стартовый проект можно скачать в full.

В Gradle-комплектах из корня соответствующего проекта:

```sh
gradle -p student test
gradle -p student -Preference -Pgrading test
```

## Проверка изменяемого API

В заданиях на реализацию открытые и закрытые JUnit-тесты находят классы и
методы через public reflection. Отсутствие метода, неверные параметры,
модификаторы или тип результата дают предметное сообщение JUnit, сохраняя
компиляцию самого набора тестов. InvocationTargetException разворачивается,
чтобы проверять реальное исключение студенческого кода.

Синтаксические ошибки самой реализации остаются сообщениями javac с файлом
и строкой. В штатном Java grader они возвращаются как `gradable: false`
с диагностикой. Ошибка компиляции авторских тестов требует исправления
проверяющего комплекта. Тесты задания на разработку тестов сохраняют обычные
вызовы стабильного API, предоставленного преподавателем.

Пилот использует структуру `tests/junit` и образ `prairielearn/grader-java`
из дополнительной конфигурации курса; собственная программа подсчёта
проверок удалена. JUnit-примеры выполняются локально через Gradle.

Полный преподавательский архив с решениями и закрытыми тестами, архив только
условий демонстрации и экспорт полного курса PrairieLearn требуют согласованной
доработки инструментов. Нынешний Download выдаёт только разрешённые стартеры.
Наличие платформенных параметров у остальных контрольных задач не означает
готовности их проверяющих проектов.

[Руководство инструментов](https://afonenko-course-tools.github.io/quarto-template-course/guide/index.html)
и [основной README](../README.md) описывают общие правила и зависимости.
