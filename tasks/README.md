# Задания по Java

Канонические условия хранятся в `bank/`, состав лабораторных — в `labs/`,
исследовательские темы — в `essays/`. Страницы лабораторных и другие формы
выдачи используют один текст задания из банка. Введение к каждой
лабораторной находится в `../practice/` и доступно студенту с сайта.

Студенческий вход — [задания курса](index.qmd), подборки —
[лабораторные работы](labs/index.qmd). Десять основных работ задают
обязательный состав и выбор между альтернативами; три дополнительные
подборки предназначены для добровольной работы.

Авторские правила находятся в [рабочей документации](../docs/README.md).
Порядок редактуры и связи с другими формами курса задаёт
[план](../docs/course-revision-plan.md).

## Проекты и проверка

В `projects/` находятся стартовые проекты, публичные примеры, авторские
решения и закрытые проверки. Материалы для студентов отделены от материалов
преподавателя. Автоматическая проверка оценивает наблюдаемое поведение;
наличие обязательных приёмов в исходном коде и объяснение решения проверяет
преподаватель.

В настроенном экземпляре PrairieLearn `pilot` используются первые три
лабораторные и восемь обязательных заданий без случайного выбора:

- числовые вычисления — приветствие, размер изображения, принадлежность интервалу;
- управление обработкой данных — подсчёт пробелов, экстремумы последовательности;
- массивы — обратный вывод, вычитание среднего строки, устойчивая перестановка строк.

Дополнительные карточки банка доступны независимо от этого отбора.
Скачиваемые стартовые проекты используются и в заданиях с ручной проверкой.
Подготовка среды, правила экспорта и проверки описаны
в [документации лабораторных](../docs/prairielearn-labs.md).

Команды сборки и запуска приведены в README стартового проекта.
Требуемый результат, обязательные API и существенные ограничения определяет
каноническое условие конкретной задачи. При редактировании условия проверяйте,
какие новые требования оно предъявляет студенту и соответствуют ли ему
используемые проверки.

Для фиксированного API обязательны отдельная компиляция решения,
независимая рефлексивная предпроверка, компиляция зависимых модульных тестов
и проверка поведения — в этом порядке. Ошибка компиляции, несоответствие
API и неверный результат получают разные сообщения. При проверке свободного
консольного решения нельзя вводить новый API, требовать повторного вызова `main`
в одной JVM или запрещать `System.exit`. Для поведенческих проверок используется JUnit
с поддержкой отдельной JVM; подробности приведены в документации лабораторных.
