# Задания по Java

Канонические условия хранятся в `bank/`, состав лабораторных — в `labs/`,
исследовательские темы — в `essays/`. Страницы лабораторных и другие
потребители используют один текст задания из банка. Введение к каждой
лабораторной находится в `../practice/` и доступно студенту с сайта.

Авторскую работу начинайте с [рабочей документации](../docs/README.md).
Действующий [план полной переработки](../docs/course-revision-plan.md)
охватывает десять основных и три добровольные работы, связанные введения,
банк и исследования. Принятый пилот обобщений сохраняет статус;
[документ пилота](../docs/java-course-pilot.md) описывает историю его проверок.

## Проекты и проверка

В `projects/` находятся стартовые проекты, публичные примеры, авторские
решения и закрытые проверки. Публичная поставка отделена от материалов
преподавателя. Автоматическая проверка оценивает наблюдаемое поведение;
обязательные приёмы исходника и объяснение проверяет преподаватель.

Исходная подборка первых трёх лабораторных содержит восемь обязательных
позиций по схеме 3/2/3, без случайного выбора: приветствие, размер изображения,
принадлежность интервалу; подсчёт пробелов, экстремумы последовательности;
обратный вывод массива, вычитание среднего строки, устойчивая перестановка
строк. Дополнительные карточки банка не увеличивают обязательный состав.
Прежние 17 возможных вопросов и схема 6/4/4 относятся к старой поставке.
Остальные работы исходной базы используют ручную проверку; проверенная
поставка всей отобранной линии создаётся по этапам 4–5 текущего плана.
Новый запуск проектов и экспорта фиксируется отдельно в
[журнале](../docs/full-revision-progress.md). Подготовка среды и маршрут
проверки описаны в
[документации лабораторных](../docs/prairielearn-labs.md).

Готовая среда сборки помогает запустить решение. Требуемый результат,
обязательные API и существенные ограничения определяет каноническое
условие конкретной задачи. После правки условия проверяются появившиеся
обязанности студента и соответствие используемых проверок этому условию.

Для фиксированного API обязательны отдельная компиляция решения,
независимая рефлексивная предпроверка, компиляция зависимых unit-тестов
и проверка поведения — в этом порядке. Ошибка компиляции, несоответствие
API и неверный результат получают разные сообщения. Свободному консольному
решению не навязываются новый API, повторный вызов `main` в одной JVM
или запрет `System.exit`. Полные правила и ещё открытый выбор процессного
инструмента приведены в документации лабораторных.
