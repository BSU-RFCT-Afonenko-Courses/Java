# Общая поддержка проверок Java

Один исходник инфраструктуры используется публичными и закрытыми JUnit-наборами;
данные заданий и ожидаемые значения находятся в соответствующих наборах.
Материализация в проекты и проверка целевой поставки выполняются отдельно.

Список проектов задаёт `projects.json`. После проверки изменений выполните
`python3 tasks/test-support/materialize.py --write`, затем `--check`.
`materialized.json` фиксирует hashes обеих поставок. Неожиданная локальная
правка останавливает обновление до первой записи; символические ссылки и
пути вне корня отвергаются. Удаление ранее поставленных файлов требует
отдельного рассмотрения. Сам каталог `test-support/` исключён из ресурсов сайта.

`coursesupport.JavaProcess.run(Main.class, input, args...)` запускает новую JVM
с JDK текущего процесса, UTF-8, памятью 128 МиБ, временем 10 секунд и общим
лимитом stdout/stderr 65536 байт. Перегрузка с путём к классам позволяет явно
задать опубликованное имя входного класса, аргументы, рабочий каталог и лимиты.
Она возвращает раздельные stdout/stderr и код выхода. Ненулевой код сам по себе
не считается ошибкой: требуемый результат определяет условие задания.
Превышение времени или суммарного объёма даёт понятный `AssertionError`.
Программа вправе закончить работу, не прочитав весь stdin. Захват потоков
выполняется одновременно с записью ввода, без подмены глобальных `System.in/out`.
Helper завершает созданную им JVM; контроль всего дерева процессов принадлежит
внешнему runtime. Он не читает `/proc` и работает при штатном запрете этого пути.
Закрытие pipe выполняется владеющим им IO worker. После остановки прямого PID
helper ждёт не более секунды reaping и секунды IO cleanup; унаследованный
потомком pipe не продлевает это ожидание. Окончательное удаление такого потомка
и удерживаемых им дескрипторов обеспечивает внешний runtime.

`OutputNumbers.finiteNumbers` разбирает разделённые пробельными символами
конечные `double`; пустой текст даёт пустой массив. `finiteMatrix` дополнительно
проверяет точное положительное число строк и столбцов, сохраняя строки и
дробные значения. Внешние пробелы и завершающие переводы строк допускаются,
внутренняя пустая строка считается строкой. Точность, допуск, порядок строк и
ожидаемые значения сравнивает обычный JUnit-тест. Точные целые значения следует
разбирать как `long`, не через `double` и не округлением.

Полный набор тестов библиотеки запускается без скачивания зависимостей:

```bash
python3 tasks/test-support/check.py \
  --junit-jar "$PL_PLATFORM_ROOT/runtime/java25-junit-v1/junit-platform-console-standalone-1.14.1.jar"
```

Нужен JDK 25; `JAVA_HOME` выбирает конкретный JDK. Тесты проверяют отдельные
JVM, `System.exit`, UTF-8, аргументы и рабочий каталог, раздельные потоки,
заполненные pipes, время, суммарный объём и форму числовых/матричных ответов.
Это библиотека тестов, а не самостоятельная песочница: изоляцию недоверенного
решения обеспечивает внешний Platform runtime.

Проверки механизма поставки выполняются отдельно:

```bash
python3 -m unittest discover -s tasks/test-support -p test_materialize.py -v
```
