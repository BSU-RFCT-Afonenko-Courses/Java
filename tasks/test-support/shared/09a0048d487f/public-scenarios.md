# Открытые контрольные сценарии batch13

Все 22 наблюдения ниже — **PUBLIC**: по одному обычному и одному граничному
сценарию на каждую из одиннадцати задач. Это авторский договор входов и
ожидаемых результатов. Решения студентов здесь не запускались; фактический
результат, статус и русскую диагностику в результатах готовит технический
исполнитель. Никакой обязательный API или способ запуска не возникает
только из формы записи сценария.

Используются JDK 25 и UTF-8. Если пути и порядок аргументов свободны,
техническая проверка обращается к объявленному запуску решения или
подходящей обычной Java-привязке. Результат со свободным оформлением
сравнивается по смыслу. Неподготовленная привязка не доказывает ошибку
решения; недоступный через выбранный API результат предъявляется
демонстрацией и чтением. Обязательные File, массив, try-with-resources,
объяснение и собственный выбор текста не считаются доказанными одним выводом.

Здесь `\n` обозначает LF, а не два буквальных символа. Точное сохранение
разделителей требуется только там, где его задаёт условие. В задачах,
возвращающих выбранные физические строки, пустая строка отличается
от отсутствия строк: в файле нужны разделители, представляющие эти строки.
У свободных отчётов не назначается обязательный завершающий перевод строки.

## exr-files-transpose-file-matrix

### PUBLIC normal — Строки становятся столбцами

- **Что наблюдаем:** обе матрицы и обмен индексов.
- **Вход и состояние:** UTF-8-файл `1 2 3\n4 5 6\n7 8 9\n`;
  отдельный новый каталог и путь результата в нём.
- **Действие:** передать три пути аргументами в порядке, выбранном решением,
  выполнить преобразование.
- **Ожидается:** результат содержит исходную матрицу и транспонированную
  со строками `1 4 7`, `2 5 8`, `3 6 9`. Две части различимы по подписям;
  их конкретный текст свободен. Каталог и файл созданы; применение File
  и двумерного массива проверяется отдельно по исходнику.

### PUBLIC boundary — Матрица из одного элемента

- **Что наблюдаем:** минимальный допустимый размер.
- **Вход и состояние:** UTF-8-файл с одной строкой `-7` и отдельный новый выход.
- **Действие:** тот же выбранный запуск с новыми путями.
- **Ожидается:** исходная и транспонированная матрицы обе равны `[[-7]]`,
  каждая явно обозначена в свободно оформленном отчёте.

## exr-files-poem-word-frequency

Для двух следующих наблюдений выбран один допустимый вариант правил:
слово — непрерывная последовательность букв; сравнение без учёта регистра
с приведением букв к нижнему регистру. Это **пример выбора для сценария**,
а не общий обязательный алгоритм задачи. Для решения с другими заранее
объявленными допустимыми правилами ожидания пересчитываются по ним;
различие правил само по себе не является ошибкой.

Открытые данные — одна строка Максима Богдановича из «Романс» в издании
«Вянок», 1914: `Зорка Вэнэра ўзыйшла над зямлёю`.
Историческое написание сохранено. [Источник строки](https://be.wikisource.org/w/index.php?title=Вянок_(1914)/У_зачараваным_царстві/Романс&oldid=187700).
Короткий фрагмент служит контролю подсчёта; самостоятельный выбор
стихотворения и предъявление его источника остаются частью задания.

### PUBLIC normal — Нулевая частота и равные частоты

- **Что наблюдаем:** все слова списка, сортировку по частоте и устойчивость.
- **Вход и состояние:** UTF-8-файл с указанной строкой;
  список в порядке `зорка`, `няма`, `зямлёю`; правила объявлены выше.
- **Действие:** передать пути входа и выхода аргументами, список выбранным
  способом и выполнить подсчёт.
- **Ожидается:** результат этой физической строки по порядку:
  `няма: 0`, `зорка: 1`, `зямлёю: 1`. Двоеточие — обозначение пары
  в этом договоре, не обязательная сериализация отчёта.

### PUBLIC boundary — Строка без совпадений

- **Что наблюдаем:** сохранение нулей и исходного порядка при равенстве.
- **Вход и состояние:** тот же открытый файл; список `светлыя`, `згадкі`.
- **Действие:** выполнить подсчёт с теми же объявленными правилами.
- **Ожидается:** обе частоты равны 0, порядок остаётся
  `светлыя`, затем `згадкі`. Результат строки не пропускается.

## exr-files-poem-letter-word-frequency

В обычном примере буквы — буквенные кодовые точки Unicode; слово —
непрерывная последовательность букв. Для подсчёта выбран нижний регистр,
для обоих наборов — порядок первого появления в тексте. Другой заранее
объявленный допустимый выбор студента сохраняется; технический исполнитель
адаптирует ожидаемые данные к его правилам, а не подменяет их этим примером.

Открытый UTF-8-фрагмент — первые две строки стихотворения Адама Мицкевича
из издания 1899 года:

```text
Polały się łzy me czyste, rzęsiste,
Na me dzieciństwo sielskie, anielskie,
```

[Источник фрагмента](https://pl.wikisource.org/w/index.php?title=Polały_się_łzy_me...&oldid=3219602).
Фрагмент проверяет счётчики; собственное стихотворение, источник и выбор
правил предъявляются отдельно по условию.

### PUBLIC normal — Общий подсчёт двух строк

- **Что наблюдаем:** два общих набора частот и повтор слова в разных строках.
- **Вход и состояние:** приведённые две строки UTF-8, разделённые LF;
  допустим LF после второй строки. Правила объявлены выше.
- **Действие:** передать пути входа и выхода аргументами и выполнить подсчёт.
- **Ожидаемые слова в выбранном порядке:**

  | Слово | Частота |
  |---|---:|
  | polały | 1 |
  | się | 1 |
  | łzy | 1 |
  | me | 2 |
  | czyste | 1 |
  | rzęsiste | 1 |
  | na | 1 |
  | dzieciństwo | 1 |
  | sielskie | 1 |
  | anielskie | 1 |

- **Ожидаемые буквы в выбранном порядке:**
  `p:1, o:2, l:3, a:3, ł:2, y:3, s:8, i:8, ę:2, z:4, m:2, e:9, c:2, t:3, r:1, n:2, d:1, ń:1, w:1, k:2`.
  Это 11 вхождений слов и 60 букв. Форма двух разделов отчёта свободна.

### PUBLIC boundary — Пустой файл

- **Что наблюдаем:** отсутствие данных без выдуманных частот.
- **Вход и состояние:** пустой UTF-8-файл; те же объявленные правила.
- **Действие:** выполнить подсчёт в новый результат.
- **Ожидается:** пустой набор букв и пустой набор слов. Их оформление
  свободно: не навязывается нулевой размер файла с отчётом или фиксированная
  строка сообщения.

## exr-files-compare-files

### PUBLIC normal — Одинаковые файлы

- **Что наблюдаем:** равенство соответствующих байтов и сохранность входов.
- **Вход и состояние:** два отдельных UTF-8-файла с точным текстом `Java text`
  без финального перевода строки.
- **Действие:** запустить CompFiles с ровно двумя путями.
- **Ожидается:** консольный результат сообщает о совпадении. Текст сообщения
  свободен; оба файла сохранили прежние байты. Try-with-resources проверяется
  по исходнику.

### PUBLIC boundary — Одинаковое начало, разная длина

- **Что наблюдаем:** конец первого файла не подменяется равенством.
- **Вход и состояние:** первый UTF-8-файл — `Java`, второй — `Java text`,
  оба без финального перевода строки.
- **Действие:** тот же запуск с двумя путями.
- **Ожидается:** сообщено различие, оба входа неизменны. Это результат
  сравнения, а не файловый отказ.

## exr-files-sort-file-numbers

### PUBLIC normal — Отрицательные числа и повтор

- **Что наблюдаем:** порядок и кратность целых чисел.
- **Вход и состояние:** UTF-8-файл `7 -2 7 0 3 -5`; новый каталог и результат.
- **Действие:** выполнить выбранный запуск с явно заданными путями.
- **Ожидается:** `-5 -2 0 3 7 7`, между числами ровно один ASCII-пробел;
  последний перевод строки необязателен. Применение File и чтение до
  открытия результата наблюдаются отдельно.

### PUBLIC boundary — Границы int

- **Что наблюдаем:** корректный порядок крайних допустимых значений.
- **Вход и состояние:** UTF-8-файл
  `2147483647\t-2147483648\n2147483647` и новый выход.
- **Действие:** выполнить тот же выбранный запуск.
- **Ожидается:** `-2147483648 2147483647 2147483647`;
  последний перевод строки необязателен. Здесь `\t` обозначает табуляцию.

## exr-files-final-line-words

### PUBLIC normal — Суффиксы строк и слов

- **Что наблюдаем:** выбор последних строк, затем последних слов в каждой.
- **Вход и состояние:** UTF-8-файл с физическими строками
  `one two three`, `four five`, `six seven eight nine`; `m = 2`, `n = 2`.
- **Действие:** задать параметры и пути выбранным способом, сохранить результат.
- **Ожидается:** две строки в порядке `four five`, `eight nine`,
  слова каждой строки разделены одним пробелом.

### PUBLIC boundary — Ноль слов в двух выбранных строках

- **Что наблюдаем:** пустые результирующие строки отличаются от пустого файла.
- **Вход и состояние:** тот же трёхстрочный вход; `m = 0`, `n = 2`.
- **Действие:** выполнить выбор и сохранение в новый файл.
- **Ожидается:** ровно две пустые физические строки. Допустимы разделители
  строк выбранной среды; нельзя потерять обе строки или заменить их одной.

## exr-files-remove-short-words

### PUBLIC normal — Чётное и нечётное число кандидатов

- **Что наблюдаем:** максимальное чётное удаление и порядок оставшихся слов.
- **Вход и состояние:** две строки UTF-8:
  `one two elephant four` и `a cat dog bee house`.
- **Действие:** обработать строки и сохранить новый результат.
- **Ожидается:** две строки `elephant four` и `a`.
  В первой сохранено последнее из трёх подходящих слов; во второй удалены
  все четыре подходящих слова.

### PUBLIC boundary — Три кодовые точки вне BMP

- **Что наблюдаем:** длину в кодовых точках и сохранение очищенной строки.
- **Вход и состояние:** одна UTF-8-строка `😀😀😀 cat`.
  Первое слово содержит три кодовые точки U+1F600, второе — три буквы.
- **Действие:** выполнить обработку и сохранить новый результат.
- **Ожидается:** одна пустая физическая строка: оба слова имеют длину 3,
  поэтому удаляются оба. Шесть элементов char первого слова не меняют
  его требуемую длину. Представление этого входа не вводит новый алфавит:
  исходное условие разрешает UTF-8 и считает кодовые точки Unicode.

## exr-files-phone-owner-records

### PUBLIC normal — Объединение двух префиксов

- **Что наблюдаем:** отбор и исходный порядок записей.
- **Вход и состояние:** сохранённые UTF-8-записи
  `291234567;Анна`, `331234567;Борис`, `441234567;Вера`;
  `k = "29"`, `j = "33"`.
- **Действие:** выполнить отбор в новый файл выбранным запуском.
- **Ожидается:** первые две записи в прежнем порядке, каждая в исходном формате.
  Сохранение исходного набора студентом предъявляется отдельно.

### PUBLIC boundary — Одинаковые префиксы и повтор записи

- **Что наблюдаем:** различие повторного входа и двойного совпадения.
- **Вход и состояние:** строки `291234567;Анна`, `291234567;Анна`,
  `441234567;Вера`; `k = "29"`, `j = "29"`.
- **Действие:** выполнить отбор в новый файл.
- **Ожидается:** ровно два вхождения `291234567;Анна` в прежнем порядке.
  Каждое входное вхождение проходит один раз; ни удаления повторов,
  ни четырёх результатов быть не должно.

## exr-files-matching-line-numbers

### PUBLIC normal — Два полных совпадения

- **Что наблюдаем:** все строки и номера совпадений.
- **Вход и состояние:** три строки UTF-8: `alpha`, `beta`, `alpha`;
  аргумент поиска `alpha`, отдельный путь результата.
- **Действие:** передать путь и поиск аргументами, указать выбранный путь
  выхода и выполнить программу.
- **Ожидается:** в результате все три исходные строки в прежнем порядке
  и отдельный список номеров `1, 3`. Подписи и представление списка свободны.

### PUBLIC boundary — Пустая строка поиска

- **Что наблюдаем:** пустую физическую строку и сохранение краевого пробела.
- **Вход и состояние:** точный текст `alpha\n\n alpha\n`;
  поиск — пустая строка, переданная одним аргументом.
- **Действие:** тот же выбранный запуск; для Bash пустой аргумент — `''`.
- **Ожидается:** все три строки сохранены, включая пустую вторую
  и начальный пробел третьей. Список совпадений содержит только номер 2.

## exr-files-disk-help-menu

Открытый образец справки уже есть в исходном комплекте:
`tasks/projects/j25-files-disk-help-menu/student/examples/helpfile.txt`
на закреплённом Java-снимке 220857b6. Это PUBLIC ресурс, не закрытый эталон.
При технической подготовке для него сохраняется один канонический источник;
при другом собственном справочнике ожидания берутся из соответствующих тем.

### PUBLIC normal — Два последовательных запроса

- **Что наблюдаем:** поиск тем, порядок их текста и доступность общего ввода.
- **Вход и состояние:** открытый файл справки с темами `if` и `for`;
  экземпляр Help получил его имя через конструктор. Пользователь вводит
  сначала `if`, затем `for` через выбранное меню.
- **Действие:** получить оба выбора через getSelection() и показать темы
  через helpOn(String) в рамках решения студента.
- **Ожидается:** оба поиска дают true; напечатаны строки соответствующих тем
  в порядке файла. Второй выбор доступен, общий System.in не закрыт первым.
  Тип представления выбора, имена класса запуска и приглашения не фиксируются.

### PUBLIC boundary — Неизвестная тема и ошибка чтения

- **Что наблюдаем:** разные причины false.
- **Вход и состояние:** сначала тот же исправный файл и запрос `If`;
  затем отдельный Help с явно отсутствующим путём и запросом `if`.
- **Действие:** выполнить два вызова helpOn в этих состояниях.
- **Ожидается:** оба возвращают false. В первом сообщении объяснено отсутствие
  темы, во втором — файловый отказ. Точные сообщения свободны; файловая
  ошибка обработана внутри helpOn, а не выдана за найденную тему.

## exr-files-remove-java-comments

### PUBLIC normal — Комментарии и литералы

- **Что наблюдаем:** три вида комментариев и сохранение литералов.
- **Вход и состояние:** точные байты открытого
  `student/examples/publicInput.txt` проекта
  `tasks/projects/j25-files-remove-java-comments` на снимке 220857b6.
  Отдельный новый каталог и результат.
- **Действие:** удалить комментарии и записать новый UTF-8-файл.
- **Ожидается:** точные байты уже опубликованного
  `student/examples/publicExpected.txt` того же проекта, включая пробел
  в конце первой строки и оба CRLF. Имена ресурсов и их SHA указаны в
  source evidence; технический исполнитель переносит PUBLIC данные
  из одного канонического источника. Литералы сохраняются.

### PUBLIC boundary — Пустой комментарий между токенами

- **Что наблюдаем:** сохранение границы токенов.
- **Вход и состояние:** допустимый UTF-8 Java-текст
  `class Demo { int/**/x; }\n` с единственным LF в конце.
- **Действие:** выполнить то же преобразование в новый файл.
- **Ожидается:** точный текст `class Demo { int x; }\n`.
  Комментарий заменён одним U+0020; весь остальной текст и LF сохранены.
  Это опубликованная граница `int/**/x;`, помещённая в корректный Java-файл.
