# Специализированная проверка двух задач копирования

`check-copy.py` используется только byte-file-copy и character-file-copy.
Он не изменяет JavaProcess, CliPrecheck, manifests или другие 21 CLI-проекта.
Класс/пакет/форма main свободны: trusted --entry выбирает преподаватель;
настройку проверяет настоящий Java25 launcher --dry-run, без фиксированного API.
Source compilation, launch setup и наблюдаемое поведение имеют разные категории.

До первой записи проверяются пути и непустая выборка известных IDs.
Work должен не существовать и не пересекаться с project/sources/JDK/support;
никакой существующий каталог не очищается. Все опыты работают на копиях
в новых собственных подкаталогах. Каждый process ограничен временем/выводом,
исполняется с закрытым stdin и в новой JVM; System.exit не запрещён.

Пары ожидаемых UTF8-файлов заданы явно. Нормальные stdout/stderr/status
сохраняются как наблюдения, без обязательного status0. При IO-отказе нужен
непустой сигнал в любом канале, сохранность защищённого входа/выхода;
семантика сообщения, отсутствие ложного успеха и ресурсная техника
остаются ручной проверкой. Частичный выход при записи допустим.
Hardlink/symlink проверяются только при фактической поддержке ОС;
пропуск способности записывается отдельно, а не становится имитацией теста.
Invalid UTF8 и повторный main в одной JVM не добавляются к условиям.

Канарейки защиты и ошибочного выбора:

```bash
python test_check_copy.py
```

Они используют временные каталоги и копии; живые project/runtime не
передаются как work. Автоматический успех checker не означает принятие
explicit close или Reader/Writer/UTF8/TWR: эти требования читают в исходнике.
Примеры запуска и состав публичных/закрытых случаев — в README двух проектов.
