# Ручная часть reverse-array

Источник: принятый предметный договор `early-subject-contracts-review-input.md`, SHA256 `fc2957d35221e1194a381c3f8c184e1acca55052e7f328bda5ec119649e8f9bf`; независимая содержательная рецензия — `early-subject-review.md`.

Автоматический набор содержит четыре равновесных случая `ReverseArrayTest`; API-допуск и необязательный `PublicReverseDemoTest` не входят в знаменатель. Автоматическая доля остаётся 80%, ручная — 20%. Допустимая альтернатива `exitAfterOutput` завершает JVM через `System.exit(17)` после правильного вывода; запрет `System.exit` и требование нулевого кода завершения не добавляются. Пустой завершённый ввод проверяется по выбранному в исходнике примеру, а не по заранее назначенному массиву.

В сданном коде проверяются участие `int[]`, отсутствие записи в его компоненты ради обратного вывода и правильность ветви собственного примера. Алгоритм, вспомогательные методы и организация программы свободны. Новый отчёт или показ исходного массива не требуются.

`negative-controls/mutates-array` получает правильный stdout, но меняет компоненты перестановкой: ручной критерий не выполнен. `negative-controls/without-array` использует стек `ArrayDeque` и также получает правильный stdout, но вычисление не использует `int[]`: ручной критерий не выполнен. Их полный автоматический результат ожидаем и не является полным зачётом. Остальные предметные контроли имеют правильный API и обнаруживаются проверками вывода. `missing-api` проверяет только допуск и не запускает предметный набор.
