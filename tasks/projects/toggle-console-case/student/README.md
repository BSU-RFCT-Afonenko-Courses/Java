# Изменение регистра символов

Читайте текст из стандартного ввода до первой точки или конца ввода. Замените ASCII A–Z на a–z, а a–z на A–Z, используя разницу кодов 32. Остальные символы сохраните без изменения: цифры, знаки, пробелы, переводы строк, кириллицу и эмодзи. Точка не входит в результат; всё после неё игнорируется. Подсчитайте каждую изменённую ASCII-букву. Допустимо объявить `throws IOException` в `main`.

Вход и результат: ввод и вывод — UTF-8. Сначала выведите преобразованный текст, затем один дополнительный перевод строки, затем целое количество изменений и перевод строки. Ввод `AБяz 👋🙂.` даёт текст `aБяZ 👋🙂` и счётчик `2`. Немедленная точка или пустой ввод дают пустую строку и затем `0`. Не применяйте преобразование ко всем символам без проверки ASCII-диапазона.

## Исходник и запуск

В `src/main/java/Main.java` находится заготовка с `TODO`. Успешная
компиляция заготовки не означает, что решение готово: требуемое поведение
ещё нужно реализовать. Сохраните
точку входа `Main.main(String[] args)`; вспомогательные методы и классы
разрешены.

Откройте каталог, содержащий этот `README.md` и `src`. Выполните команды
инструментами JDK 25. После изменения исходника повторите компиляцию:

```bash
javac --release 25 -encoding UTF-8 -d out src/main/java/*.java
printf 'AБяz 👋🙂.' | java -cp out Main
printf '.' | java -cp out Main
```

Первый запуск должен напечатать `aБяZ 👋🙂`, затем на новой строке `2`. Второй должен напечатать пустую строку, затем `0`. Кириллица и эмодзи сохраняются; изменяются только буквы указанных ASCII-диапазонов.

В примерах вход передаётся командой `printf` оболочки POSIX (например, bash).
В другой оболочке можно сохранить тот же ввод в файле UTF-8 и перенаправить
его в программу. `printf ''` создаёт пустой поток с EOF.

Публичные примеры находятся в `src/test/java/PublicExamplesTest.java`
и используют JUnit 5. Они охватывают часть случаев; полные требования
задаёт условие выше. Компиляция не проверяет соответствие поведения
программы условию.
