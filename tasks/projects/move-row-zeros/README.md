# Проект: move-row-zeros

Преобразуйте каждую строку матрицы 3×3 так, чтобы нули располагались после всех ненулевых элементов. Взаимный порядок ненулевых элементов сохраняется. Допустимы преобразование на месте и создание нового массива.

Обязательный исходный пример: строки `(−3, 0, 3)`, `(2, −1, 0)`, `(1, 3, −2)`. При пустом стандартном вводе используйте именно его. Для дополнительной проверки разрешены любые матрицы **3×3 с целыми значениями −3…3**: передайте девять чисел через стандартный ввод построчно. Другие размеры, `null`, рваные матрицы и значения вне указанного диапазона не проверяются.

Выведите три строки по три числа, без подписей. Для обязательного примера результат: `(−3, 3, 0)`, `(2, −1, 0)`, `(1, 3, −2)`. Проверьте также строку, начинающуюся с нулей, строку без нулей и полностью нулевую строку.

Соберите `student/src/main/java/Main.java` командой `javac --release 25 -encoding UTF-8 -d out student/src/main/java/*.java`, затем запустите `java -cp out Main`. Для дополнительного входа передайте текст через stdin; без входа закройте stdin (EOF). Java 25. Вспомогательные методы и классы разрешены.

Публичные примеры: `student/src/test/java/PublicExamplesTest.java`. Их можно запускать JUnit 5 вместе с вашей программой; они показывают часть контракта и не заменяют все требования условия.

Для преподавателя: `reference/Main.java` — авторское решение, `tests/junit/ContractTest.java` — закрытые проверки, `tests/fixtures/` — ошибочные решения, `tests/contract-cases.json` — обязательные ожидаемые результаты их проверки. Компиляция starter успешна; его поведенческие тесты должны выявить незавершённое решение. Авторское решение должно пройти публичные и закрытые тесты. Каждый ошибочный пример должен скомпилироваться и дать хотя бы один поведенческий отказ. Фактические результаты полного прогона сохраняются в выводе штатной проверки вне исходного репозитория; порядок проверки описан в [текущей документации](../../../docs/prairielearn-labs.md).
