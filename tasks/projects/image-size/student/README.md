# Размер изображения

Изображение имеет `width` столбцов и `height` строк пикселей. Каждый пиксель
занимает `bytesPerPixel` байт; сжатие и служебные заголовки отсутствуют.
Вычислите точное количество байтов и размер в мебибайтах: 1 МиБ = 1 048 576 байт.

Стандартный ввод содержит три целых числа: `width height bytesPerPixel`.
Ширина и высота находятся в диапазоне от 1 до 100 000, число байтов на пиксель —
от 1 до 8. Вход заведомо соответствует этим условиям.
Выведите количество байтов как целое число, затем размер в МиБ как дробное
число с точкой. Для второго результата допустима абсолютная ошибка `1e-8`.

Примеры: `1024 1024 4` даёт `4194304 4.0`;
`50000 50000 3` — `7500000000 7152.557373046875`.
Также проверьте один пиксель. Выберите типы промежуточных вычислений так,
чтобы результат оставался точным для всех допустимых входных значений.

## Исходник и запуск

В `src/main/java/Main.java` находится заготовка с `TODO`. Успешная
компиляция заготовки не означает, что решение готово: требуемое поведение
ещё нужно реализовать. Сохраните
точку входа `Main.main(String[] args)`; вспомогательные методы и классы
разрешены.

Откройте каталог, содержащий этот `README.md` и `src`. Выполните команды
инструментами JDK 25. После изменения исходника повторите компиляцию:

```bash
javac --release 25 -encoding UTF-8 -d out src/main/java/*.java
printf '50000 50000 3' | java -cp out Main
```

Ожидаемые два числа: `7500000000 7152.557373046875`. Произведение уже превосходит диапазон `int`; один только широкий тип переменной результата не гарантирует правильности промежуточного вычисления.

В примерах вход передаётся командой `printf` оболочки POSIX (например, bash).
В другой оболочке можно сохранить тот же ввод в файле UTF-8 и перенаправить
его в программу. `printf ''` создаёт пустой поток с EOF.

Публичные примеры находятся в `src/test/java/PublicExamplesTest.java`
и используют JUnit 5. Они охватывают часть случаев; полные требования
задаёт условие выше. Компиляция не проверяет соответствие поведения
программы условию.
