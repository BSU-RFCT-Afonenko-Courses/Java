# gradeapp — отчёт по студентам

Завершите предоставленное консольное приложение `gradeapp`.
Реализуйте пять методов заготовки и предъявите работающий JAR с входными
файлами и граничными примерами.

## Команда и формат

Команда `grade.Main input threshold` получает ровно два аргумента:
путь UTF-8-файла и целый порог 0–100. Относительный путь разрешается
от рабочего каталога. Отчёт выводится в stdout, диагностика — в stderr.
Предоставленная точка входа проверяет число аргументов, порог и синтаксис
пути до чтения. Порог разбирается через `Integer.parseInt` без `strip`.

Каждая значимая строка файла содержит ровно три поля `id;name;score`.
Кавычки и экранирование не используются. `strip()` удаляет краевые
пробельные символы полей; балл разбирается как `int`. Строки, для которых
`isBlank()` возвращает `true`, пропускаются. Физический номер начинается
с 1 и учитывает каждую строку, включая пропущенные.

Предоставленная запись `grade.Student(String id, String name, int score)`
нормализует `id` и `name` через `strip`; они непустые и не содержат `;`,
CR и LF. Балл находится в диапазоне 0–100. Нулевые ссылки `id`/`name`
приводят к `NullPointerException`, остальные нарушения — к
`IllegalArgumentException`. Равенство записи включает все три компонента.
В каталоге нормализованные коды уникальны с учётом регистра:
`s1` и ` s1 ` — повтор, `s1` и `S1` — разные коды.

## Методы для реализации

Методы размещены в предоставленных классах пакета `grade`. Сохраните
их имена, доступ, параметры и возвращаемые типы. Проверяемые отказы
должны оставаться в объявленной области `throws`: допустимое сужение
сохраняет совместимость обычного вызывающего кода, который отдельно
обрабатывает указанные исключения. Список проверяемых исключений,
которые обязан учитывать клиент, расширяться не должен.

- `StudentParser`: `public static Student parse(String line, long number) throws DataFormatException`.
  Предусловия — ненулевая строка и положительный физический номер.
  Проверьте три поля, сохраняя возможное пустое последнее поле.
  Неверное число или нарушение ограничений `Student` оберните в
  `DataFormatException` с исходной причиной `NumberFormatException`
  или `IllegalArgumentException`. Сообщение начинается с
  `строка <number>:` и поясняет отказ. Для неверного числа полей
  сообщите отдельную ошибку формата; причина для неё необязательна.
- `StudentFiles`: `public static List<Student> read(Path path) throws IOException, DataFormatException`.
  Предусловие — ненулевой путь. Прочитайте UTF-8, пропустите пробельные
  строки, проверьте уникальность кодов. При повторе выбросьте
  `DataFormatException` с сообщением `строка <number>: повтор кода <id>`;
  причина для этого отказа необязательна. Отсутствие файла и повреждённый
  UTF-8 приводят к `IOException`. После успешного чтения и закрытия
  верните весь список в порядке входа. Пустой файл даёт пустой список.
  Список имеет самостоятельную структуру; `add`, `remove`, `set` и `sort`
  запрещены через `UnsupportedOperationException`. Частичный каталог
  при отказе не возвращается.
- `Reports`: `public static List<Student> selected(List<Student> students, int threshold)`.
  Предусловие — ненулевой список ненулевых допустимых `Student`.
  Порог вне 0–100 отклоняется через `IllegalArgumentException`, включая
  пустой вход. Отберите записи с `score >= threshold`; порядок — балл
  по убыванию, затем код по естественному порядку `String`.
  Состав и порядок исходного списка сохраняются. Результат имеет
  самостоятельную структуру: последующее изменение исходного списка
  его не меняет; `add`, `remove`, `set` и `sort` результата запрещены
  через `UnsupportedOperationException`. Неизменяемые элементы `Student`
  могут использоваться совместно; создание нового экземпляра списка
  само по себе не является требованием.
- `Reports`: `public static String line(Student student)`.
  Предусловие — ненулевой `Student`. Верните `id;name;score`
  без заголовка и перевода строки.
- `Main`: `static int run(Path input, int threshold) throws IOException, DataFormatException`.
  Сохраните пакетный доступ. Для уже проверенных пути и порога свяжите
  чтение, отбор и предоставленный `printReport`; верните его статус.
  Полезный вывод начинается после успешной загрузки и проверки всего каталога.

Готовы `Student`, `DataFormatException` с конструктором причины,
`Main.main`, `Main.run(String[])`, отображение ошибок, `printReport`
с проверкой `PrintStream.checkError`, сборка и открытые примеры.

## Внешний результат

Stdout содержит по одной строке `id;name;score` на выбранную запись,
без заголовка. Пустой каталог и пустой отбор дают пустой stdout и успех.
Коды завершения: 0 — успех; 2 — аргументы, порог или синтаксис пути;
3 — формат данных, диапазон балла или повтор кода; 4 — чтение или вывод.
При ошибке данных либо чтения stdout пуст; stderr поясняет отказ.
При отказе вывода уже переданная часть отчёта остаётся у получателя.
Системные потоки должны оставаться открытыми.

## Сборка и запуск

Установите JDK 25 и укажите его каталог в `JAVA_HOME`. Maven Wrapper загружает
Maven и зависимости; JDK выбирается из окружения. Из этого каталога:

```bash
sh ./build.sh --version
sh ./build.sh -DskipTests package
```

Проверьте, что Maven использует Java 25. Вторая команда компилирует
приложение и тестовые исходники, пропускает исполнение тестов и создаёт
`target/gradeapp.jar`. Заготовка собирается с TODO, но рабочий запуск
требует реализации их поведения.

После реализации:

```bash
sh ./build.sh test package
java -jar target/gradeapp.jar samples/students.txt 80
```

На Windows те же цели вызываются через `.\build.cmd`. `build.sh` требует
POSIX-оболочку, `unzip` и `sha256sum` либо `shasum`; Windows использует
PowerShell. Wrapper 3.3.4 загружает Maven 3.9.16 с проверкой контрольной
суммы. Для первой загрузки Maven, модулей сборки и JUnit нужен доступ
к Maven Central либо заранее подготовленный локальный кэш.

Скрипты `build.sh` и `build.cmd` сами создают `.mvn/wrapper` на основе
предоставленного `wrapper/maven-wrapper.properties`. POSIX-скрипт вызывает
`mvnw` через `sh`; дополнительных действий с правами `mvnw` не требуется.

После успешной реализации пример печатает в stdout:

```text
s10;Ada;90
s3;Ann;90
```

Stderr пуст, код завершения равен 0. При равных баллах код `s10` предшествует
`s3` по естественному порядку `String`. Числовая часть кода не выделяется.

Из другого рабочего каталога используйте реальные абсолютные пути:

```bash
java -jar /absolute/path/student/target/gradeapp.jar /absolute/path/student/samples/students.txt 80
```

Пути с пробелами заключайте в кавычки. Аргументов приложения по-прежнему два:
путь входа и порог. Перенаправление stdout в файл выполняет оболочка.

## Примеры и предъявление

`PublicExamplesTest` проверяет обычный отчёт, пустой вход, повтор кода
и предоставленную модель `Student`. Дополните демонстрацию баллами 0 и 100,
пробельными строками, кодами с разным регистром, поздней неверной строкой
с физическим номером 3, повтором после `strip`, отсутствующим файлом
и неверным порогом до чтения.

Предъявите Java-исходники, входные файлы и работающий JAR. Объясните
проверку уникальности, самостоятельную структуру результата `selected`
и границу начала полезного stdout. Цикл с сортировкой и Stream допустимы.
