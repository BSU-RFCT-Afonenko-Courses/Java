# Отчёт по студентам: завершение gradeapp

Приложение читает каталог студентов из UTF-8-файла и выводит записи, прошедшие порог балла.
Реализовать нужно пять методов предоставленной заготовки.

Данные, результаты и обязательные средства Java приведены в [условии
задания](../../bank/files.qmd#exr-j25-files-gradeapp-report). [Инструкция к стартовому
проекту](student/README.md) содержит порядок работы и требования к предъявлению решения.

## Работа с проектом

В `student/` находятся исходники, открытые примеры, входные файлы и Maven Wrapper. Заготовка
содержит пять методов с `TODO`; готовая точка входа проверяет аргументы, а `printReport`
выводит отчёт. После реализации методов выполните следующие команды из каталога `student/`:

```bash
sh ./build.sh test package
java -jar target/gradeapp.jar samples/students.txt 80
```

Приложение получает ровно два аргумента: путь UTF-8-файла и целый порог 0–100. Отчёт
выводится в stdout, диагностика — в stderr. Относительный путь файла отсчитывается от
рабочего каталога.

Нужен JDK 25, выбранный через `JAVA_HOME`. На Windows цели сборки вызываются через
`.\build.cmd`. Скрипты создают `.mvn/wrapper`; первая загрузка Maven и зависимостей требует
доступа к Maven Central либо подготовленного локального кэша. Maven Wrapper 3.3.4 использует
Maven 3.9.16 с проверкой SHA-256. Подробные требования оболочки приведены в студенческой
инструкции.

## Проверка преподавателем

В студенческий архив входит только содержимое `student/`, без созданных при сборке `.mvn/` и
`target/`. Преподавательская реализация находится в `reference/src/main/java/grade/`,
закрытые тесты — в `tests/junit/`, проверка API — в `tests/api/GradeAppApi.java`. Каталоги
`reference/`, `tests/` и `tools/` остаются у преподавателя.

По исходнику разберите обнаружение повторного кода студента, закрытие входного ресурса,
самостоятельность структуры результата и начало вывода после проверки всего каталога. Цикл с
сортировкой и Stream допустимы.

Для локальной проверки нужны JDK 25, Python 3 и каталог `platform/runtime/java25-junit-v1` с
JUnit, json-simple и `PlatformApiPrecheck.java`. Замените
`/absolute/path/platform/runtime/java25-junit-v1` своим путём. Из каталога проекта:

```bash
python tools/check.py \
  --runtime /absolute/path/platform/runtime/java25-junit-v1 \
  --work /tmp/gradeapp-reference
python tools/check-cases.py \
  --runtime /absolute/path/platform/runtime/java25-junit-v1 \
  --work /tmp/gradeapp-cases
```

Первый вызов проверяет `reference/src/main/java`. Для другой версии задайте `--sources`; для
заготовки это `--sources student/src/main/java`. Флаг `--public-only` выбирает открытые
примеры. `--work` должен указывать новый, ещё не существующий каталог вне проекта,
исходников и среды проверок. Для каждого повторного запуска выберите новый путь. Каталог JDK
задаётся через `JAVA_HOME` или `--java-home` в `check.py`.

Проверка отдельно компилирует решение, проверяет API, компилирует зависимые тесты и
запускает их. В `report.json` сохраняются команды, вывод, хеши и результаты этапов. Вызов
`Main.run(Path,int)` проверяется из пакета `grade`; совместимое сужение проверяемых
исключений в `throws` допустимо.

Второй вызов проверяет варианты из `tests/contract-cases.json`: допустимые решения и
заданные нарушения API, компиляции или поведения. Варианты обрабатываются независимо.
Проверки защиты рабочих путей и выбора вариантов запускаются отдельно:

```bash
GRADEAPP_RUNTIME=/absolute/path/platform/runtime/java25-junit-v1 \
  python tests/test_checker_guards.py
```

Эти проверки используют временные копии и проверяют сохранность чужих файлов, пересечение
путей и ошибки выбора вариантов. Исполнение `build.cmd` проверяется в Windows отдельно.
