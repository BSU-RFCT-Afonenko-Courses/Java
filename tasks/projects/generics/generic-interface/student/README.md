# Реализация обобщённого интерфейса

В `src/main/java/IGenIF.java` дан исходный интерфейс. Добавьте решение
в `src/main/java`; пакет интерфейса можно согласовать со своим решением.
Сохраните заданную связь типов и имена `IGenIF` и `MyClass`.

Нужен JDK 25. Откройте терминал в каталоге с этим README и папкой `src`.
Скомпилируйте все Java-исходники под `src/main/java`, включая вложенные
пакеты.

В Linux, Bash:

```bash
find src/main/java -type f -name '*.java' -exec javac --release 25 -encoding UTF-8 -d out -sourcepath src/main/java {} +
```

В PowerShell 7:

```powershell
$sources = @(Get-ChildItem -LiteralPath 'src/main/java' -Recurse -File -Filter '*.java' |
    ForEach-Object { $_.FullName })
javac --release 25 -encoding UTF-8 -d out -sourcepath src/main/java $sources
```

Сначала предъявите успешную компиляцию допустимого примера
с `Number, Integer`. Недопустимый пример с `Integer, Number` компилируйте
отдельно от корректного решения. Для отдельного набора исходников с такой
же структурой каталогов можно применить те же команды из его каталога.
Ожидается ошибка именно из-за нарушенной границы типа. Покажите сообщение
компилятора и объясните его; точная формулировка сообщения не фиксируется.
Запуск программы для этой демонстрации не требуется.

После изменения исходников повторите компиляцию. `out` создаётся
при компиляции и в исходный комплект не включается.

В комплекте есть обычные примеры
`examples/compile/positive/Good.java` и
`examples/compile/negative/Bad.java`. При необходимости адаптируйте
их расположение и параметры типов к своему допустимому решению.
Примеры не задают дополнительных требований к API. Компилируйте
их отдельно в описанном выше порядке. Если внешнему примеру недоступно
объявление из-за допустимой видимости, предъявите преподавателю
собственный пример той же границы типов.

Открытые наблюдения в [examples/scenarios.json](examples/scenarios.json)
помогают подобрать демонстрацию и не задают обязательный формат ввода.
Предъявите исходники и результаты предусмотренных условием действий.
Обязательные приёмы проверяются по коду, объяснение — в беседе.
Дополнительный письменный отчёт не требуется.
