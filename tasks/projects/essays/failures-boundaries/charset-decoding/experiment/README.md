# Неоднозначность результата декодирования с заменой

Завершите метод `Utf8Evidence.evidence()`: верните объект `Evidence` с двумя массивами байтов `malformed`, `valid` и строкой `expected`. Первый массив должен содержать недопустимое полное сообщение UTF-8, второй — корректное; каждый массив имеет длину от 1 до 4096 байт. Для обоих массивов выражение `new String(bytes, StandardCharsets.UTF_8)` должно возвращать одну и ту же строку `expected`. Строгий декодер с обеими политиками `CodingErrorAction.REPORT` должен отклонять `malformed` с исключением `CharacterCodingException` и декодировать `valid` в `expected`. Тем самым пара должна показывать, почему восстановить факт повреждения только по полученной строке невозможно. Изменяйте только `Utf8Evidence.java`, сохраняя сигнатуры типов и метода; вывод в консоль не требуется.

## Полный проект

`student/` содержит заготовку и открытые JUnit-примеры; `reference/` — авторское
решение; `tests/` — доверенный контракт и отрицательные fixtures. Нужны JDK 25
и совместимый Gradle. Из корня полного комплекта выполните:

```sh
gradle -p student test
gradle -p student -Preference -Pgrading test
```

Для implementation задания первая команда характеризует заготовку, вторая —
эталон. В test-design ошибочные реализации должны быть обнаружены тестами.
Отказы незавершённого ответа ожидаемы и не означают сбой инструмента.

Официальное оценивание и полная авторская проверка используют опубликованный
Platform runner по объявленному `project-check`; переданный student Gradle
не выполняется в grading job.
