# Копирование файла: символьные потоки

Программа копирует UTF-8-файл, заменяя обычные пробелы дефисами и сохраняя остальные символы
и разделители строк. В этой задаче используются `Reader`, `Writer` и `try` с ресурсами.

Данные, результаты и обязательные средства Java приведены в [условии
задания](../../bank/files.qmd#exr-j25-files-character-file-copy). [Инструкция к стартовому
проекту](student/README.md) содержит порядок работы и требования к предъявлению решения.

## Работа с проектом

В `student/` находятся заготовка программы и каталог `samples/` с примерами входных и
ожидаемых файлов. Заготовку можно заменить своей программой. Сборка и запуск описаны в
студенческой инструкции; нужен JDK 25. Имя класса запуска и допустимую форму `main` выбирает
автор решения.

Передайте пути исходного и выходного файлов согласно условию. Копирование сохраняет входной
файл. При ошибке открытия исходного файла существующий выходной файл остаётся неизменным.
При проверке совпадения файлов учитываются разные пути к одному файлу. Тексты сообщений и
код завершения выбирает автор решения; при файловой ошибке требуется понятная диагностика.

## Проверка преподавателем

Студенту выдаётся только `student/`. Каталоги `reference/` и `tests/` содержат
преподавательские реализации, проверки и варианты для проверки самих тестов. В
`tests/cases.json` перечислены сценарии; ожидаемые файлы хранятся вместе с проверками.

По исходнику проверьте явный выбор UTF-8, использование символьных потоков, порядок открытия
файлов и закрытие ресурсов. Сопоставьте диагностику с причиной файловой ошибки.

Автоматическая проверка сопоставляет содержимое файлов, сохранность входа и поведение при
файловых отказах. Требуемый способ работы с потоками проверяется по исходнику.

Для запуска нужны Python 3 и JDK 25. Из каталога проекта выполните команду для
предоставленной реализации; её класс запуска указан в `tests/contract-cases.json`:

```bash
python ../../test-support/check-copy.py \
  --project . --sources reference/single \
  --entry CharacterCopy \
  --work /tmp/character-file-copy-new-proof
```

При проверке другого решения задайте его каталог в `--sources` и выбранный класс запуска в
`--entry`. Проверяющий скрипт отдельно компилирует исходники, проверяет настройку запуска
через `--dry-run` и исполняет каждый сценарий в отдельной JVM. Ошибка настройки класса
запуска требует исправления преподавательской команды и отдельного разбора.

Флаг `--public` оставляет открытые сценарии; `--only` выбирает их идентификаторы из
`tests/cases.json` в доступной области. `--work` указывает новый внешний каталог, который не
пересекается с проектом, исходниками, JDK и проверяющими средствами. Существующие каталоги
сохраняются. Хеши исходников и данных записываются до и после проверки.
