# Проект: generic-queue

## Обобщённая очередь

Реализуйте `GenericQueue<T>` фиксированной вместимости с операциями
`void put(T value) throws QueueFullException` и
`T get() throws QueueEmptyException`. Класс, конструктор `GenericQueue(T[])`
и обе операции объявите `public`: контейнер предоставляет API клиенту.
Имя пакета, если он используется, выберите самостоятельно. `get` возвращает и удаляет самый ранний
из ещё хранимых элементов — порядок FIFO. Вместимость ограничивает число
элементов, хранимых одновременно: извлечение освобождает место для нового
добавления. Способ размещения элементов в массиве выберите самостоятельно.

Хранилище — массив `T[]`, переданный конструктору; его положительная длина
задаёт вместимость. Исходная очередь пуста. Фактический тип компонента
массива совпадает с аргументом типа очереди: для `GenericQueue<Number>`
передаётся `Number[]`; фактический `Integer[]` допускал бы запись только ссылок на `Integer` или `null`. Клиент после передачи не использует
массив напрямую и не добавляет `null`. Это предпосылки использования,
проверять их программно не требуется.

При полном состоянии `put` выбрасывает проверяемое `QueueFullException`,
при пустом `get` — проверяемое `QueueEmptyException`. Определите эти классы
исключений как открытые проверяемые наследники `Exception`.
Конструктор не объявляет проверяемых исключений; каждая операция объявляет
только указанный для неё checked-отказ. Отказ не меняет состояние очереди.
Способ формирования и текст сообщения исключения свободны.
Новые операции сверх конструктора, `put` и `get` не требуются.

Покажите работу со строками и целыми числами, обработку обоих отказов
и повторное добавление после извлечения из заполненной очереди.
Подготовка к объявлениям и обработке отказов:
раздел теории курса «Проверяемые исключения».
