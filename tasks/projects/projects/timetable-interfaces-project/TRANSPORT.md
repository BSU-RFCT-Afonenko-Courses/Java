# Связь проверки с собственным расписанием

| operation | Аргументы после model | Наблюдаемый результат |
|---|---|---|
| createSchedule, deleteSchedule | нет | действие над действительным расписанием; отсутствие действующих занятий после удаления; повторное создание наблюдается следующими операциями |
| createSubject, createTeacher | id, name | создание предмета/преподавателя |
| changeSubject, changeTeacher | id, newName | изменение названия той же сущности |
| deleteSubject, deleteTeacher | id | факт и исход действия по заранее объявленной политике, проверяемый последующими списками/выборками |
| subjects, teachers | нет | фактический список пар id/name, без навязанного порядка |
| initialGroup | id, name | установка исходной группы; это только создание исходных данных, не дополнительный CRUD групп |
| addLesson | lessonId, date, time, subjectId, teacherId, groupId, room, kind, carId | добавление настоящего дополнительного занятия; kind/carId используются только там, где имеют смысл для специализации |
| cancelLesson | lessonId | исключение занятия из действующего расписания |
| changeRoom | lessonId, room | изменение только аудитории соответствующего занятия |
| teacherLessons, groupLessons | соответствующий id | фактические занятия с их date/time/subject/teacher/group/room, проекции не отбирают заново |
| teacherCount, groupCount | соответствующий id | результат реального подсчёта решения, не size в адаптере |
| dayOff | date | применение собственной политики выходного |
| classLessons | classId | школьная выборка по классу |
| lessonsPerDayValid | classId, date | наблюдаемый исход проверки реального числа уроков относительно объявленного предела; boolean допускается как проекция фактического результата/отказа |
| setCarAvailable | carId, available | установка исходного состояния учебного автомобиля согласно собственной модели, не новая цель управления автопарком |
| practicalCarValid | lessonId | исход собственной проверки наличия автомобиля для практики |

Результат call имеет Object-тип только для передачи разных наблюдений. void-действия могут возвращать null; числовые результаты — Number, списки — List read-only проекций настоящих значений; пары id/name и поля занятия передаются в явно описанном порядке Object[] без собственной алгоритмики. Исключение/отказ решения не скрывается: тест проверяет объявленный исход вместе с состоянием модели. Для иной законной политики, которая отличается от reject/cascade, технический клиент сопоставляет её действительное состояние; строка operation не задаёт способ реализации.


Пары сущностей передаются как [id,name]. Занятие: [id,date,time,subjectId,teacherId,groupId,room,kind,carId]. Все текстовые поля — String, date/time — ISO, kind 0/1 означает теорию/практику. Это проекции настоящих значений. Собственные типы, даты, интерфейсы и сигнатуры модели свободны. Политики удаления/выходного, предел и модель автомобилей объявите до опыта; при другом законном выборе настраивается обычный проверяющий клиент.
