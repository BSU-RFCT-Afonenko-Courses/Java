## Авиакомпания: иерархия самолётов и сохранение объектов

Разработайте консольное приложение для учёта самолётов авиакомпании.
По составу парка оно должно вычислять суммарные характеристики,
упорядочивать самолёты и находить подходящий по расходу топлива.
Сохранённые сведения должны быть доступны после загрузки из файла.

Подготовка: классы и инкапсуляция ([Классы, инкапсуляция и инициализация](https://bsu-rfct-afonenko-courses.github.io/Java/theory/chapters/classes.html#sec-j25-theory-classes)),
наследование и полиморфизм, массивы и файловый ввод-вывод.
При выборе коллекции для хранения парка используйте
[Коллекции и способы хранения объектов](https://bsu-rfct-afonenko-courses.github.io/Java/theory/chapters/collections.html#sec-j25-theory-collections). Перед сохранением модели разберите сериализацию
объектов Java и назначение `static` и `transient` при выбранном способе
записи. Сначала получите результаты операций с парком в памяти;
затем сопоставьте их с результатами после сохранения и загрузки.

## Данные и операции

Определите иерархию самолётов и объект авиакомпании, содержащий парк.
Минимальный набор состоит из трёх самолётов с уникальными идентификаторами:

| Вид | Вместимость, мест | Грузоподъёмность, т | Дальность, км | Потребление, л/ч |
|---|---:|---:|---:|---:|
| Пассажирский | 150 | 12 | 3000 | 2400 |
| Грузовой | 2 | 20 | 4500 | 3000 |
| Пассажирский | 80 | 6 | 1800 | 1500 |

Данные учебные. Используйте предметные единицы последовательно.
Возможности приложения:

- подсчёт общей вместимости и грузоподъёмности всех самолётов компании;
- сортировка самолётов по дальности полёта;
- поиск самолёта, потребление горючего которого входит в заданный диапазон
  с включёнными границами;
- сохранение и загрузка объектов приложения в одном или нескольких файлах
  с применением сериализации Java;
- изменение и извлечение сохранённых сведений через отдельный класс-коннектор.

Коннектор должен сохранять обновлённую модель: после изменения параметра
самолёта и повторной загрузки приложение получает новое значение.
Способ сериализации, имена файлов, пакеты и сигнатуры операций выберите
самостоятельно. Объекты могут содержать `static`- и `transient`-поля;
покажите и объясните их значения после загрузки с учётом выбранного способа
сериализации.

## Устройство и демонстрация

Используйте классы, инкапсуляцию, наследование и полиморфизм. Иерархия
должна отражать виды самолётов; названия классов и их состав — предметные
роли. Распределите классы по пакетам и соблюдайте Java Code Conventions.
Консольное меню достаточно ограничить операциями задачи.
Параметры инициализации при желании можно хранить в файлах.

Для исходного набора проверьте суммы, порядок по дальности и отбор
в диапазоне `[1500, 2400]`. Затем сохраните и загрузите парк, измените
сведения через коннектор и повторите загрузку. По наблюдениям объясните,
какие данные составляют сохраняемое состояние самолёта и как ведут себя
выбранные `static`- и `transient`-поля. [1]

## Локальная работа

Используйте JDK 25. Разместите Java-файлы в `src/`, организовав выбранные
пакеты. Скомпилируйте все исходники в отдельный каталог `out`, затем
запустите свой класс командой `java -cp out <класс>`.
Имена классов, методы коннектора, путь к сохраняемому файлу и устройство
меню определяются вашим решением.

[Открытый сценарий](examples/README.md) содержит результаты для трёх
самолётов и последовательность проверки сохранения. На демонстрации
предъявите исходники, использованные данные и результаты операций.
