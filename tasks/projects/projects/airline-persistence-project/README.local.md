Вход проверки вызывает ваше решение и не задаёт бизнес-интерфейс. Дополнительные наблюдения static/transient настраиваются по выбранным реальным полям; обязательные setter в модели не требуются.

**Если выбрана стандартная сериализация**

При стандартном сохранении полей обычного класса `Serializable` в поток входят его нестатические поля без `transient`. Это правило относится к стандартному набору полей; собственное описание сохраняемых полей и код записи могут задавать другие действия. При стандартном восстановлении сохранённые значения берутся из потока. Поля `transient` первоначально получают значения по умолчанию; собственный код восстановления может установить другие значения. Поля `static` принадлежат классу в JVM и не входят в стандартный набор сохраняемых полей. [Состав полей: разделы 1.5 и 1.7](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/serial-arch.html#defining-serializable-fields-for-a-class).

При десериализации такой иерархии обычных классов вызывается конструктор без аргументов первого несериализуемого суперкласса; его поля инициализируются этим конструктором. [Восстановление: §3.1, шаг 12](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/input.html#the-objectinputstream-class). При собственной записи и восстановлении состояния объясните выбранные действия.
