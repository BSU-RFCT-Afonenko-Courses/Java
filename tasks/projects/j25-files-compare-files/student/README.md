## Утилита сравнения файлов

Создайте утилиту `CompFiles`, предназначенную для сравнения двух файлов. При запуске имена файлов передаются в командной строке. Утилита открывает оба файла, затем читает и сравнивает соответствующие байты. При обнаружении несовпадения файлы считаются различными. Если концы файлов достигнуты одновременно и несовпадений не было, файлы считаются совпадающими. Используйте `try` с ресурсами для автоматического закрытия файлов.

Для этой практической работы сравнивайте обычные текстовые файлы; результат сравнения выведите на консоль.

Для проверки подготовьте два одинаковых UTF-8-файла со строкой «Java text» и третью версию «Java test». Добавьте пару с одинаковым началом и разной длиной.

Передайте ровно два пути; относительные пути разрешаются от рабочего
каталога. Входные файлы остаются неизменными. Пустые файлы совпадают;
пустой и непустой различаются. Отказ открытия или чтения сопровождается
диагностикой и отдельным исходом: вывод о равенстве в этом случае не делается.
Покажите также отсутствующий файл. Текст сообщений выберите самостоятельно. [1]


## Локальная работа

JDK25: создайте свои .java в src, компилируйте все `javac -encoding UTF-8 -d out src/*.java`; запуск выбранного вами класса `java -cp out <класс>`. Соблюдайте только явно заданные карточкой имена/каналы/методы; project ZIP не вводит новых Main/пакета/public/static/helperAPI. Данные в examples/; пути с пробелами передавайте одним аргументом, пустой аргумент POSIX — `''`. Если канал/порядок аргументов свободен, укажите выбранный способ в демонстрации.
