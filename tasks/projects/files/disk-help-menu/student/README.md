# Справочная система, использующая диск

Разместите исходные Java-файлы в `src/main/java`. Сохраните классы
и сигнатуры, прямо заданные условием; остальные имена, пакеты
и вспомогательные методы выбирайте самостоятельно.

Нужен JDK 25. Откройте терминал в каталоге с этим README и папкой `src`.
Скомпилируйте все Java-исходники под `src/main/java`, включая вложенные
пакеты.

В Linux, Bash:

```bash
find src/main/java -type f -name '*.java' -exec javac --release 25 -encoding UTF-8 -d out -sourcepath src/main/java {} +
```

В PowerShell 7:

```powershell
$sources = @(Get-ChildItem -LiteralPath 'src/main/java' -Recurse -File -Filter '*.java' |
    ForEach-Object { $_.FullName })
javac --release 25 -encoding UTF-8 -d out -sourcepath src/main/java $sources
```

Для выбранного демонстрационного класса `HelpMenu` без пакета форма запуска:

```console
java -cp out HelpMenu
```

Подставьте фактическое имя своего класса; для класса в пакете используйте
полное имя. `HelpMenu` здесь — пример, не дополнительное требование.
Добавьте аргументы, которые нужны вашему запуску по условию. Пути с пробелами
передавайте одним аргументом в кавычках.

Подготовьте helpfile.txt в UTF-8 по формату условия. Передайте его имя
конструктору Help выбранным способом. Программу запуска разместите в
FileHelp.java; имя запускаемого класса свободно. Покажите темы, отсутствие темы,
отказ чтения и завершение меню.

После изменения исходников повторите компиляцию. `out` создаётся
при компиляции и в исходный комплект не включается.

После запуска решения выполните публичную самопроверку по инструкциям
в предоставленном [CHECKS.md](CHECKS.md).

Открытые проверки в `src/test/java` можно адаптировать к допустимому
API решения; пример привязки находится в `src/test/java/TaskBinding.java`.
Его имена и вид результата не задают дополнительных требований.
Для другого допустимого API согласуйте с преподавателем обычную
Java-привязку. Если локальные или закрытые элементы недоступны отдельному
проверяющему классу, предъявите их работу и исходник преподавателю.
Отсутствие готовой привязки само по себе не означает ошибку в решении.

Открытый клиент проверяет результаты двух опубликованных файловых
сценариев через выбранную привязку. Подробнее — в [BINDING.md](BINDING.md).
Предусмотренные условием подготовку данных, указание их источника,
обязательные приёмы и объяснение оценивает преподаватель.
Успех открытой проверки не подтверждает эти критерии автоматически.

Предъявите исходники, использованные входные данные и короткую демонстрацию.
Обязательные приёмы проверяются по коду, объяснение — в беседе.
Дополнительный письменный отчёт не требуется.
