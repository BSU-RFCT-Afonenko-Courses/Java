## Метод sum() с аргументом переменной длины

Создайте метод `int sum(int... values)`, суммирующий переданные значения `int`. Для демонстрации используйте значения, все промежуточные суммы которых помещаются в `int`; переданный массив не равен `null` и не меняется. Метод может быть статическим или экземплярным; содержащий его класс выбирайте самостоятельно. Вызовы `sum(3, -2, 4)` и `sum()` дают 5 и 0. Обход индексами и enhanced-for допустимы. [Источник 1]

## Работа с проектом

Разместите свои Java-файлы в `src/` с выбранной структурой пакетов. Имена вспомогательных классов, способ запуска демонстрации и не указанные условием части API выбирайте самостоятельно. Для компиляции нужен JDK 25. Обычный пример для каталога исходников: `javac --release 25 -encoding UTF-8 -d out src/ИМЯ.java`; при нескольких исходниках перечислите все файлы. Команда запуска относится к выбранной вами демонстрации.

Открытые сценарии находятся в `examples/scenarios.json`. Сдайте исходники и покажите работу; преподаватель привяжет конкретное решение обычным Java-клиентом. Его `TaskBinding` не является вашим обязательным API. Недоступные private/nested варианты сохраняют ручную проверку.

## Предъявление лабораторной


Покажите sum без аргументов, swap двух объектов и самопередачу, заполнение и оба отказа Stack, отбор без совпадений и на границе года/цены. Точные сигнатуры и сообщения задаёт каждая карточка; новые вспомогательные методы для демонстрации не обязательны. Способ обхода и отбора выбирайте самостоятельно в пределах условий. Требуемые классы, два конструктора моделей, методы, закрытый массив стека и порядок LIFO сохраняются. Объясните на ёмкости 2, почему отказ третьего push не меняет вершину и последующие pop дают B, A. Выберите одно содержательное решение для обсуждения в обычной защите; новый письменный отчёт не нужен.

Представьте исходные Java-файлы и демонстрацию обычных и существенных граничных случаев. Среда проверки — JDK 25. Обязательная техника проверяется по исходнику, объяснение — в беседе с преподавателем.
