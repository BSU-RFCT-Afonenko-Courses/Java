Цель — создать собственную модель Car и выполнить три предметных отбора.
Это кандидат одной обязательной пары Book/Car: студент завершает
один из двух доступных вариантов. Оба не объявляются независимыми
обязательными задачами; случайный выбор за студента не применяется.

Обязательны простое имя класса Car, закрытые поля свойств id, марки,
модели, года выпуска, цвета, цены и регистрационного номера;
два конструктора с разными наборами параметров, методы чтения/изменения
и toString(). Имена полей и методов доступа, пакет, параметры
конструкторов и предметно пригодные типы свойств свободны.
Конструктор без аргументов не требуется. Оба конструктора дают
допустимую запись; конструкторы не обязаны повторять эталон.

Входы: положительный целый id, год выпуска и текущий год 1..9999,
год выпуска не больше текущего; конечные неотрицательные цена
и её порог; непустые строковые свойства; n в 0..9999.
Массив, его элементы и тексты не null, пустой массив допустим.
Проверка неверных исходных данных не требуется.

Отдельные методы отбирают марку; модель с возрастом строго больше n;
год выпуска с ценой строго больше порога. Текущий год передаётся
параметром, возраст равен разности годов. Привязка к системным часам
не заменяет параметр. Равные возраст и цена исключаются.
Строки сравниваются целиком с учётом регистра, порядок исходного
массива сохраняется. Каждый подходящий повтор остаётся в подборке;
исходный массив и объекты не меняются.

Имена отбора, вид возвращаемой подборки и формат демонстрации свободны.
Исходные объекты и равнозначные копии допустимы; сравниваются свойства,
порядок и кратность, не identity записей результата. Единственные
имена findByBrand/getYear и единственный тип коллекции не навязываются.
Пустой результат явно обозначается свободным сообщением.

Демонстрация показывает три отбора, два подходящих автомобиля,
отсутствие совпадений, строгие границы возраста/цены и сохранность входа.
Публичный обычный сценарий использует [C1,C2,C1,C3] и текущий год 2025,
граничный — [C4], возраст ровно 5 и цену ровно 10. Это выбранные
публичные данные, а не обязанность использовать год 2025 во всех запусках.
Пустой массив и n=0 сохраняются среди допустимых случаев договора.

Среда — JDK 25 и консоль. Student-комплект не требует Gradle, Wrapper,
JUnit или Python. Размещение исходников в комплекте — src/main/java,
рекурсивные команды компиляции из проверенного технического фрагмента.
Имя Main в README является примером запуска, а не обязательным классом.
Пакеты и остальные свободные части организации сохраняются.

Сначала компилируется решение; заданный API наблюдается отдельно
от его поведения. Клиент проверки согласуется с допустимым API решения.
Свободные имена, видимость, размещение и оформление демонстрации
не заменяются именами эталона ради grader. Если допустимая организация
не позволяет обычному внешнему клиенту вызвать метод, используются
действительная демонстрация и предметное чтение; это не ошибка API.
Новый универсальный stdin-протокол и фиксированная сериализация
свободного результата не вводятся. Код клиента, тестов, запуска
и русской диагностики пишет technical. Неподготовленная привязка
не объявляется неправильным решением.

Предъявляются исходники и демонстрация предусмотренных случаев.
Обязательные приёмы проверяются по исходнику, понимание — в беседе;
для обсуждения лабораторной студент выбирает одно содержательное решение.
Дополнительный письменный отчёт не нужен. Публичный успех не заменяет
ручную часть. Точные данные двух открытых сценариев находятся
в author-drafts/java/batch3/public-scenarios.md; actual/status
и диагностика не заявлены выполненными. Закрытые проверки остаются
закрытыми. Баллы, веса и попытки этим договором не назначаются.
