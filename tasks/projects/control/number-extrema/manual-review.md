# Рубрика: наибольшее и наименьшее число

ID: `exr-control-number-extrema`. Редакция условия и её SHA256 указаны
в [контракте](contract.md). Основа — `teacher/common/rubric-template.md`.
Критерии не задают баллов и весов.

| Часть | Критерий | Достаточное свидетельство |
|---|---|---|
| Результат на допустимых данных | Найдены оба экстремума в нужном порядке; неположительное количество отклоняется | Одно число, набор отрицательных значений и `n = 0` |
| Ограничения и состояние | Начальные значения пригодны для любого `int`; обработано объявленное количество; при отказе не запрашивается последовательность | Разбор исходника и состояния после конкретного числа |
| Обязательные приёмы | Соблюдены JDK 25 и точка входа; конкретные цикл, средство чтения и способ хранения не назначены | Компиляция, входной метод и чтение заданного количества |
| Объяснение решения и границы | Студент связывает текущие максимум и минимум с уже обработанными числами, объясняет случай одного числа | Объяснение инициализации и выбранного шага обработки |
| Воспроизводимость предъявления | Исходники и команды воспроизводят положительный случай и отказ | Повторная компиляция и запуск с указанным stdin |

Смысловой ориентир: произвольный ноль не служит корректным начальным
экстремумом для любого набора. Максимум ноль ошибочен для всех
отрицательных чисел, минимум ноль — для всех положительных.
Инициализация первым элементом, граничными значениями типа и другие
корректные способы допустимы. Для одного числа оба экстремума равны ему.
При нулевом количестве отсутствует непустая последовательность,
для которой можно предъявить максимум и минимум.
Устный разбор состояния достаточен; обязательного письменного отчёта нет.

Автоматическая часть — 80%, ручная часть — 20%. API-допуск и открытые примеры баллов не дают. Ручные критерии исходной рубрики сохранены.
