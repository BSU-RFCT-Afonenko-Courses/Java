## Список книг для текущего просмотра и отчёта

Используйте готовый `course.examples.objects.Book` из
[Инвариант, создание и изменение состояния](https://bsu-rfct-afonenko-courses.github.io/Java/theory/chapters/classes.html#sec-j25-theory-classes-invariant): конструктор `Book(String title)`,
методы `title()`, `borrowed()`, `borrow()`. Новая книга доступна;
повторный `borrow` бросает `IllegalStateException`, сохраняя состояние.

Создайте собственный класс, владеющий закрытым изменяемым списком книг.
Конструктор получает ненулевой `List<Book>` без `null` и сохраняет
независимую копию его состава. Пустой список и повторные ссылки допустимы.
Предоставьте добавление ненулевой книги в конец и три способа получения
`List<Book>`; имена класса и методов выберите самостоятельно:

- живое представление текущего состава, запрещающее изменения через себя;
- самостоятельную изменяемую копию состава на момент вызова;
- снимок состава на момент вызова, запрещающий изменения через себя.

Используйте `Collections.unmodifiableList`, `new ArrayList<>(...)` и
`List.copyOf` по их назначению. Копируется состав списков; объекты `Book`
остаются общими. Изменение первоначального входного списка после создания
владельца не меняет его состав. Добавление через владельца отражается
в ранее полученном живом представлении; прежние копия и снимок сохраняют
состав. Изменяемая копия допускает независимые добавление и удаление.

Начните с одной книги, получите все три результата, добавьте вторую через
владельца: размеры текущего списка/view/copy/snapshot равны `2/2/1/1`.
Затем вызовите `borrow()` у первой книги и наблюдайте `borrowed() == true`
через все списки, которые её содержат. Попытки добавить книгу через view
и snapshot должны завершиться `UnsupportedOperationException`.
Объясните, кто владеет составом и какие ссылки остаются общими. Устройство
демонстрации свободно; новая identity результата `List.copyOf` не требуется.
Подготовка: [Один источник, представление, копия и снимок](https://bsu-rfct-afonenko-courses.github.io/Java/theory/chapters/collections.html#sec-j25-theory-collections-snapshots),
[Конструирование и свойства](https://bsu-rfct-afonenko-courses.github.io/Java/handbook/entries/lists.html#sec-j25-api-lists-factories).

## Работа с проектом

Разместите исходные Java-файлы в `src/` с выбранными именами и структурой пакетов. Для компиляции нужен JDK 25: `javac --release 25 -encoding UTF-8 -d out src/ИМЯ.java`; для нескольких файлов перечислите все исходники. Способ запуска демонстрации выбирайте самостоятельно. `examples/scenarios.json` содержит открытые наблюдения.

Преподаватель привязывает конкретное решение обычным Java-клиентом; его `TaskBinding` и выбранные в reference имена не являются дополнительным StudentAPI. Недоступное private/nested размещение сохраняет ручную проверку. Обязательная техника и объяснение проверяются по исходнику и на защите.

## Предъявление лабораторной


Представьте исходные Java-файлы и продемонстрируйте обычные и граничные
случаи из условий. Учёт должен обрабатывать произвольный массив кодов;
покажите повторные обращения и поиск отдельным равным ключом.
Для своего владельца списка отдельно объясните защиту входного состава,
живое представление, изменяемую копию и снимок. Изменение общей книги
проследите отдельно от добавления второй книги.

Пересечение и объединение сохраняют оба входных множества. Для скобок
обязателен стек; для сложения многочленов — `HashMap`, с числовым договором
из карточки. Имена свободных методов, классы демонстрации и формат показа
результатов выбирайте самостоятельно. Техника проверяется по исходнику,
объяснение — в беседе с преподавателем. Используется JDK 25; отдельный
большой отчёт не требуется.


Готовый учебный `course.examples.objects.Book` уже находится в `src/course/examples/objects/Book.java`; это явная зависимость из теории, а не новый API вашего владельца списка.
