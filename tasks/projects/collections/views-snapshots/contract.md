Цель — отделить владение составом списка от состояния общих книг.
Готовый course.examples.objects.Book уже предоставлен: Book(String),
title(), borrowed(), borrow(); повторный borrow даёт IllegalStateException
без смены состояния. Реальный исходник также отвергает null/blank название
через IllegalArgumentException; допустимые сценарии создают книги
с названиями, содержащими хотя бы один непробельный символ. Студент не переписывает этот класс.
Владелец списка, его имена/методы/пакет/видимость свободны; Catalogue
и view/copy/snapshot из binding — клиент конкретного образца.

Владелец хранит закрытый изменяемый список и получает List<Book>,
копируя состав независимо от входного списка. Список, элементы и
добавляемые ссылки не null; проверка неверных входов отдельно
не назначена. Пустой список и повторные ссылки допустимы, порядок
и повторения сохраняются. Добавление ненулевой книги идёт в конец.

Нужны три List<Book>: живое представление с запретом изменений через
него, независимая изменяемая копия состава, неизменяемый снимок состава
на момент вызова. Обязательны Collections.unmodifiableList,
new ArrayList<>(...) и List.copyOf по назначению. Изменение исходного
входного списка не меняет владельца. Позднее добавление владельцем
видно в ранее полученном view, а прежние copy/snapshot сохраняют состав.
Copy допускает независимое добавление и удаление. View/snapshot
отвергают добавление UnsupportedOperationException; запрет изменений
не ограничивается лишь add. Новый объект на каждый List.copyOf
не требуется; snapshot не проверяется через обязательное !=.

Копируется последовательность ссылок, а не объекты Book. Выдача общей
книги видна через все содержащие её списки; две ссылки на одну книгу
не превращаются в две книги и не удаляются как дубли. Book не получает
новых setters или API ради проверки. Не добавляются требования
глубокого копирования, потокобезопасности и concurrent modification.

Предъявляются исходники, последовательные изменения входного списка,
владельца и книги, размеры 2/2/1/1, изменяемость copy, запрет изменений
view/snapshot и объяснение схемы общих ссылок. Схема из исходного
README — часть беседы/демонстрации, отдельный письменный отчёт не нужен.
Готовый исходник student/src/course/examples/objects/Book.java совпадает
с handbook/examples/collections/course/examples/objects/Book.java;
canonical при интеграции — tasks/common/src/main/java/course/examples/objects/Book.java.
Technical поставляет generated copy в каждый нужный состав.

Исходная карточка явно target=manual. Использование обязательных средств,
владение и объяснение оцениваются преподавателем. Публичные наблюдения
не объявляются автоматическими тестами; успешный вывод не доказывает
источник представления или применённую операцию. Смена grading.method
не выполняется этой авторской партией.

Среда — JDK 25 и консоль, без студенческих Gradle/Wrapper/JUnit.
README содержит точные проверенные рекурсивные команды; Main — пример.
Технический клиент адаптируется к свободному API допустимого решения;
ошибка привязки означает необходимость настройки, не ошибку студента.
Вывод демонстрации не получает единственной сериализации ради checker.
