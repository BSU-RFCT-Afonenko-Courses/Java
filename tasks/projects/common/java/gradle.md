Для работы с программными задачами используется JDK 25. Условие и каноническая заготовка задают допустимый вход, результат, обязательные объявления и приёмы. Реализуйте алгоритм, структуры данных и незавершённые части самостоятельно. Вспомогательные классы, методы, способ хранения и демонстрацию выбирайте в этих пределах; размещайте их в исходниках, предусмотренных для сдачи. Имя `Main`, пакет и форма точки входа обязательны только там, где они прямо заданы условием или каноническим стартером.

Если стартер предоставляет отдельный вход для проверки, свяжите его со своим реальным решением. Он получает фактические аргументы и возвращает фактические объекты и результаты. Сохраняйте типы элементов, ссылки, состояние контейнеров и предметные отказы. Вход проверки не исправляет ответ и не маскирует изменение исходных данных копированием. Разрешённые условием временные копии и самостоятельные результаты внутри решения допустимы. Если разрешён собственный тип проверяемого исключения, его можно передать через доступный тип или преобразовать в соответствующее исключение внешнего входа, сохранив предмет отказа. Дополнительные поля и методы для проверки не нужны, если они не заданы условием.

В файловых задачах результатом служат настоящие файлы и действия программы. Свободный формат отчёта и диагностики сохраняется; вспомогательное чтение результата извлекает уже записанные данные. Передавайте вход через аргументы, стандартный ввод или файлы именно так, как задано в условии. Гарантированные предпосылки входа не требуют дополнительной проверки, если она не поручена.

Простую задачу можно выполнить с JDK 25 и любым редактором. Для задач с особой подготовкой или системой сборки следуйте условию и инструкции комплекта. Установка IDE или Gradle и запуск открытых проверок сами по себе не являются условием зачёта. Для предусмотренной комплектом сборки через Gradle нужен установленный Gradle 9.8. Откройте извлечённую папку с `settings.gradle` как Gradle-проект в IDE. Если комплект использует JUnit, зависимость объявлена в `build.gradle`: первое получение требует сети, последующие сборки доступны с `--offline` после заполнения кеша. Особые команды подготовки и сборки, если они нужны задаче, приведены в её условии и локальном дополнении.

Из корня обычного проекта можно выполнить `gradle classes` и, при наличии соответствующих задач, `gradle apiCheck` и `gradle test`. Проверка обязательных объявлений помогает обнаружить несовместимый интерфейс; открытые примеры помогают сопоставить вход и результат. Соблюдение обязательных приёмов, демонстрации и объяснения определяется условием и выбранной лабораторной. Успех самопроверки не заменяет ручную часть. Для независимых компиляционных версий и отрицательных примеров используйте раздельную сборку, указанную в условии или локальном дополнении.

Если программа читает стандартный ввод, запустите `gradle --console=plain -q run`, передайте данные и завершите ввод. Аргументы командной строки передаются отдельно: например, для задачи о сумме и произведении аргументов выполните `gradle --console=plain -q run --args="3 -2 4"`; ввод этих чисел через стандартный ввод аргументы не заменяет. Для собственного демонстрационного класса используйте `gradle --console=plain -q run -PmainClass=ИмяКласса`. Это удобство локального запуска; само по себе оно не назначает имя класса.

Команда `gradle classes` помещает классы решения в `build/classes/java/main`. Для прямого запуска после такой сборки укажите этот путь: например, `java -cp build/classes/java/main Main 3 -2 4` для задачи о сумме и произведении аргументов.

Если в условии показан запуск `java -cp out Main`, сначала скомпилируйте исходники в `out`. Из корня обычного проекта в оболочке Linux или macOS выполните:

```sh
mkdir -p out
find src/main/java -type f -name '*.java' -exec javac -d out --source-path src/main/java {} +
```

Команда включает вспомогательные классы во вложенных пакетах. Затем выполните команду запуска из условия, например `java -cp out Main 3 -2 4`. В Windows можно собрать тот же каталог исходников средствами IDE и указать `out` как каталог классов либо воспользоваться запуском через Gradle.

Отправляйте исходники, перечисленные в разделе «Сдача», с заданными именами, пакетами и относительными путями. У каждой задачи одна форма отправки: один или два файла заполняются в редакторах; три и более файла с плоской структурой загружаются отдельными файлами; три и более файла с деревом каталогов передаются одним ZIP с относительными путями. Скачанный комплект может содержать материалы сборки и самопроверки, которые не входят в ответ. Не включайте `.gradle`, `build`, `out`, кеши IDE и скачанные зависимости.
