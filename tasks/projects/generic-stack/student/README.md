## Обобщённый стек

Определите интерфейс `IGenStack<T>` с операциями
`void push(T value) throws StackFullException` и
`T pop() throws StackEmptyException`, затем реализуйте его для стека
фиксированной вместимости.
`pop` возвращает и удаляет последний помещённый элемент — порядок LIFO.
После извлечения место доступно для нового добавления.

Хранилище — массив `T[]`, переданный конструктору; его положительная длина
задаёт вместимость. Исходный стек пуст. Фактический тип компонента массива
совпадает с аргументом типа стека. Клиент после передачи не использует
массив напрямую и не добавляет `null`. Это предпосылки использования,
проверять их программно не требуется.

При полном состоянии `push` выбрасывает проверяемое `StackFullException`,
при пустом `pop` — проверяемое `StackEmptyException`. Определите эти классы
как наследников `Exception`. Дополнительные проверяемые отказы операций
не вводятся; их объявления в реализации должны соответствовать интерфейсу. Отказ не меняет состояние
стека. Внутренние поля и вспомогательные методы выберите самостоятельно.

Покажите работу со строками и целыми числами, обработку обоих отказов
и повторное добавление после извлечения из заполненного стека.
Подготовка к объявлениям и обработке отказов:
[Проверяемый отказ операции](https://bsu-rfct-afonenko-courses.github.io/Java/theory/chapters/exceptions.html#sec-j25-theory-exceptions-early-checked). [Источник 1]
