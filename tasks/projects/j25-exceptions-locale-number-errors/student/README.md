## Числа с разными локалями и собственное исключение

Прочитайте UTF-8-файл, содержащий по одной записи на строку: текст числа, табуляцию и тег локали BCP 47. Например, строки `1,5` + табуляция + `ru-BY` и `2.5` + табуляция + `en-US` дают сумму `4.0` и среднее `2.0`. Дополнительных пробелов вокруг полей нет.

Создайте метод чтения с параметром `Path` и `throws IOException`, возвращающий записи с исходным текстом числа и локали. Отдельный этап проверяет формат записи, тег локали и число, разбирает число целиком согласно локали и вычисляет сумму и среднее. Синтаксическую корректность тега проверяйте через `Locale.Builder`; локаль должна поддерживаться `NumberFormat`. NaN, бесконечности и результат за пределами конечного `double` недопустимы.

Определите собственное проверяемое исключение для ошибочной записи с номером строки и причиной. При ошибке прекратите обработку; для пустого файла сообщите об отсутствии данных, среднее не вычисляйте. Проверьте неверное число, пустое поле, неверный тег, слишком большое число и отсутствие файла. Чтение реализуется по этому условию; готовый компонент не предоставляется. [1]


## Локальная работа

JDK25, исходники в src. Выберите собственные классы/методы/представление записей/форму запуска; Main, public/static, имена Study/ReaderApp/TaskBinding не обязательны. Чтение и проверка — разные этапы; исключение хранит физический номер строки и причину. Данные в examples. Компиляция `javac -encoding UTF-8 -d out src/*.java`, запуск выбранного класса `java -cp out <класс>`.
