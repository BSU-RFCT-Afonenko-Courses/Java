# Программирование на Java

Курс получил оформление пятичастного [шаблона курса](https://github.com/Afonenko-Course-Tools/quarto-template-course): портал связывает теорию, задания, лекции, практику и справочник. Книги используют Cosmo, слайды — стандартную тему Reveal.js с навигацией курса. Предметные материалы Java и структура тем сохранены; разметка заданий согласована с текущим Core.

| Каталог | Содержание |
|---|---|
| `theory/` | Основная книга Java, прежде `book/` |
| `tasks/` | Общая книга заданий: рефераты `essays/`, лабораторные `exercises/`, контрольные `assessments/`, демонстрации и проекты |
| `lectures/` | Отдельные презентации лекций со ссылками на материалы |
| `practice/` | Отдельные презентации практических занятий и самопроверки |
| `handbook/` | Прежние приложения книги: библиотека, инструменты и справочные материалы |
| `index.qmd` | Портал и переходы к пяти частям |

## Сборка

Нужны Quarto 1.11.5 и CUE v0.17.1; исполняемые Java-проекты требуют JDK 25 или новее. Расширения включены в репозиторий. Команды выполняются из корня курса:

```sh
quarto render . --profile student --fail-if-warnings
quarto render . --profile full --fail-if-warnings
quarto preview --profile student --no-watch-inputs --no-browser --port 4200
```

Результаты — `_site-full/` и `_site-student/`; публикуйте студенческий сайт. `subprojects: [theory, tasks, lectures, practice, handbook]` задаёт пять самостоятельных проектов Quarto. Корневая сборка запускает их штатный render, собирает текущие результаты и согласует ссылки и поиск. Core проверяет учебную модель, Download создаёт объявленные стартовые ZIP-архивы. Каждую часть можно собрать непосредственно из её каталога; например, `cd tasks && quarto render . --profile student`. Повторные сборки сохраняют кэши `.quarto` и `_freeze`; после ошибки исправьте исходник и повторите команду.

## Материалы и ссылки

Внутри книги используются ссылки Quarto `@sec-id`, между частями — `@theory:sec-id`, `@tasks:sec-id`, `@handbook:sec-id` и `@portal:sec-portal-s1`. Все задания остаются в `tasks/`; лекции и практика ссылаются на их исходные условия. QRC автоматически собирает цели текущих публикаций; явные списки экспорта и ссылки на пути HTML не нужны. Для своей подписи используйте `{{< xref theory sec-theory-s1-map "Первый семестр" >}}`.

В `lectures/` и `practice/` каждый QMD — самостоятельная презентация Reveal.js со своими слайдами и HTML-страницей. Исходники нумеруются: `01-intro.qmd`, `02-language.qmd` и так далее. Допустимы части `01a-intro.qmd` и `01b-cont.qmd`: они также открываются отдельно.

Раздел презентации начинается заголовком `##`; слайды внутри него — заголовками `###`. Текст под `##` остаётся на начальном слайде раздела. Если за `##` сразу следует `###`, раздел начинается заставкой. Название группы навигации берётся из заголовка, без дополнительного атрибута. Идентификаторы `{#sec-…}` сохраняют ссылки. Только для Reveal настроены `shift-heading-level-by: -1`, `slide-level: 2` и `navigation-mode: linear`: штатные H1/H2 определяют разделы и слайды, стрелки проходят их последовательно. В книге исходные уровни заголовков сохраняются.

Порядок презентаций задаётся явным списком `project.render` в `_quarto.yml` соответствующей части, например:

```yaml
project:
  type: default
  render:
    - 01a-intro.qmd
    - 01b-cont.qmd
    - 02-language.qmd
```

Главная страница первого семестра ведёт к предметной карте `theory/semester-one.qmd` и показывает готовность пяти проектов. Новый учебный маршрут создаётся по [плану редакции](docs/semester-one-plan.md); точные темы, пути и схема ID записаны в [редакционном статусе](docs/semester-one-status.md). Материалы прежней структуры временно служат исходниками. Готовые презентации включаются в `project.render` и связываются QRC с картой. Для новых материалов используются смысловые ID с проектом и семестром; прежние ID и aliases ради совместимости не переносятся.

Таблица плана использует QRC-ссылки и нативные классы `.course-plan .striped .hover .responsive`, как в образце курса кибербезопасности. Оформление таблицы задаётся темой Quarto Cosmo.

Канонический банк включён через `essays/_metadata.yml`, `exercises/_metadata.yml` и `assessments/_metadata.yml`. Шестьдесят постановок рефератов собраны в 12 тематических документах; контрольные работы находятся в отдельных файлах и публикуются только в full. Проекты разнесены по назначению и теме: `tasks/projects/essays/<theme>/<task>/` и `tasks/projects/exercises/<theme>/<task>/`. У каждой банковской задачи есть собственные `difficulty` и положительное целое `time` в минутах. Семестр задаётся у тематического документа; сложность и время — у каждой задачи. Текущие оценки времени находятся в авторских декларациях заданий; учебная модель служит единственным источником для указателей и поставки.

Самостоятельные исследования имеют `statement-visibility="open"`, контрольные задачи — `restricted`. Core удаляет restricted условия, решения и ссылки назначений из student сайта; full сохраняет полный банк. Работы используют `.task-items`, их назначения по умолчанию required/individual. Профильные обёртки вокруг контрольных задач не нужны. Общие преподавательские инструкции находятся в полной книге на отдельной странице `tasks/teacher.qmd`; обёртки `content-visible/content-hidden` для student/full в авторских QMD не используются.

Открытая демонстрация Unicode находится вне банка: её обычные `exr`/`exm`/`sol`, пояснения и стартовые проекты сохраняют нативную публичную семантику. Банковские решения, если они добавляются, используют suffix-пару в том же QMD либо вложенную анонимную `.solution`; атрибут `for` к ним не применяется. Для обычного задания student ZIP содержит starter, full ZIP — полный проект; открытая demonstration выдаёт полный проект в обоих представлениях. Conditions — отдельный переносимый комплект условий с собственным README. Условия, starter и полный проект выбираются моделью без ручной resources map. Исходники открытого Git доступны независимо от аудитории сайта.

PrairieLearn экспортирует явно выбранные вопросы отдельной командой. Наличие платформенных параметров у старого задания не означает готовности его проекта к автоматической проверке. [Требования к текущему выпуску](docs/release-requirements.md) описывают границы банка, решений, работ и публикации. Параметры Java 25/JUnit, scoring и limits задаются общими `project-checks` profiles; отдельный `project-check` подключает проверку явно. HTML-сборка сама не запускает Java-проекты.

## Проверки

Проверки учебной модели выполняются расширениями при сборке. Core проверяет модель курса и контракты заданий, Reference Catalog разрешает межкнижные ссылки и проверяет экспорт целей, Download проверяет объявленные ресурсы и создаёт архивы. Реализация этих механизмов поставляется целыми пакетами расширений.

`CI/render.sh` собирает student → full → student на Quarto 1.11.5/CUE 0.17.1; установленные текущие pre/post hooks владельцев проверяют учебную модель, назначения, ресурсы и межпроектные ссылки в каждом запуске. Источники пакетов и полный состав установленных файлов записаны в [UPSTREAM.md](UPSTREAM.md), `providers.json` и `installed-packages.json`. История переноса сохраняется в Git.

Общие defaults target/role/visibility находятся в metadata каталогов. Явное значение
visibility переопределяет default, отличный явный target считается конфликтом;
`false` отменяет inherited default там, где это разрешено контрактом. Семестр
и difficulty группируют model-derived указатель постановок. Размещение работы
задаётся на `.task-items`; 60 защит связываются через `related-exercise` с конкретным
рефератом. Политика выбора и назначения темы определяется сервером, отдельно от
условий курса.

Для проверки проектов используйте `CI/check-projects.sh` с `PL_PLATFORM_ROOT`,
указывающим на exact released Platform checkout. Helper собирает declared inventory,
проверяет ready corpus на host/container и полностью проверяет выбранную native
delivery. Неготовые проекты видны в inventory; диагностический ready-only результат
не означает готовности всего банка. Private checks/references/receipts и журналы
сохраняются вне сайта. Published image digest берётся из Platform runtime registry;
версия и provenance установленного комплекта записаны в UPSTREAM/manifest.
